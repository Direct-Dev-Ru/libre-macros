## ТЗ: расширенный сбор многоэтажных заголовков (вертикальные объединения)

### Проблема
При сборе данных с листов встречаются “многоэтажные” заголовки, занимающие несколько строк, где ячейки объединены по вертикали (и иногда дополнительно по горизонтали) на разных уровнях.

### Цель
Расширить параметр **«Заголовок»** так, чтобы новый (расширенный) режим корректно строил итоговые имена столбцов, восстанавливая структуру многострочного заголовка с учётом вертикальных объединений.

### Обратная совместимость
- Если в параметре **«Заголовок»** задана **просто цифра** (в текущем “простом” формате) — поведение **не меняется**.
- Если параметр передаётся **в JSON** (как у других параметров, с вызовом визарда в “расширенном” формате) — используется новая логика.

### Параметры расширенного режима (визард)
1) **Диапазон строк заголовка**
   - форматы: `2-5` или `2:5`
2) **Разделитель для сборки заголовка по вертикали**
   - по умолчанию: пробел (`" "`)
   - выбирается пользователем

### Требования к алгоритму построения итоговых заголовков
1) **Не изменять исходные файлы**
   - всё формирование итоговых имён выполняется в памяти.
2) **Работа с объединениями**
   - при построении итогового заголовка нужно “учесть” вертикальное объединение, чтобы вклад каждой строки многоэтажного заголовка в итоговое имя не терялся.
3) **Как формируется итоговый заголовок**
   - Для каждого столбца:
     - берём значения строк диапазона заголовка;
     - учитываем, что при чтении через API (например, `getDataArray`) могут появляться пропуски;
     - внизу диапазона собираем итоговую строку заголовка по вертикали, используя заданный разделитель.
4) **Пустой итоговый заголовок**
   - Если итоговое имя получилось пустым, присваивать: `Column_A`, `Column_B`, `Column_C`, ...
5) **Повторяющиеся итоговые заголовки**
   - Если итоговые имена не уникальны, добавлять суффиксы: `_1`, `_2`, ...
   - нумерация начинается с `1` в порядке обнаружения.

### Область применения
Реализовать новую логику во всех режимах:
- сбор данных (везде, где используется параметр **«Заголовок»**),
- прямой доступ,
- UNO.

### Тестирование
В тесты добавить пример файла (или набор файлов) с таблицами, где есть:
- многоэтажные заголовки на 2–5 строк;
- вертикальные объединения на разных уровнях;
- вариант, где одновременно присутствует вертикальное и горизонтальное объединение на нескольких строках заголовка.

Проверки в тестах:
- корректная сборка итоговых имён столбцов с использованием разделителя;
- корректная генерация `Column_A/B/...` для пустых итоговых имён;
- корректная дисамбигуация повторов (`Имя_1`, `Имя_2`, ...);
- сценарий “простая цифра в Заголовке” работает как раньше.

### Критерии приемки
Считается выполненным, когда:
- расширенный режим (JSON/визард) правильно строит итоговые заголовки для многоуровневых заголовков с вертикальными объединениями;
- логика работает во всех требуемых ветках (сбор данных / прямой доступ / UNO);
- обратная совместимость сохранена (в “простом” режиме ничего не ломается);
- тестовые примеры покрывают описанные кейсы.
