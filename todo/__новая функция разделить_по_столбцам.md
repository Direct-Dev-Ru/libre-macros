# ТЗ: разделить_по_столбцам

Новая функция постобработки / финальной стадии (RANGE + FINAL; по возможности `Постобработка_xml`).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`).

**Имя ключа (fn):** `разделить_по_столбцам`  
**Синонимы / алиасы:** `разделить_столбец`, `split_column`, `разбить_столбец`.  
**Lib:** `lm_pp_range_split_by_columns` / `merge_final_split_by_columns`  
**Аналог Power Query:** **Split Column** → *By Delimiter* (разделитель; v1 — только этот режим).

**Цель:** в зоне данных листа результата взять **один** столбец, разбить текстовые значения по разделителю на несколько частей и записать части в **соседние столбцы** (с подготовкой места на листе). Опционально — распознавание чисел и дат в новых ячейках с соответствующим форматированием.

Обратная операция: `конкатенация_столбцов`. Размещение новых столбцов — семантика как у `переставить_столбцы` (`_начало_`, `_конец_`, `_перед_`, `_после_` + опорный столбец).

---

## 1. Принцип работы

1. Определить **область данных** (`data_range` + `header_row_range` от хоста).
2. Отфильтровать листы по `sheet` / `sheets`.
3. Разрешить **исходный столбец** `column` (имя / буква / 1-based индекс относительно data_range) — **ровно один**.
4. Разрешить **разделитель** `delimiter` (предустановка или произвольная строка).
5. Вычислить **позицию вставки** результирующих столбцов (`position` + опционально `relative_column`).
6. **Прочитать** прямоугольник данных в память (`getDataArray`).
7. **Разделить** значения исходного столбца в памяти (только строки **ниже** заголовка).
8. Определить **число новых столбцов** `n_new = max_parts − 1` (режим «заменить исходный») или `max_parts` (режим «сохранить исходный»).
9. **Подготовить место** на листе: `sheet.getColumns().insertByIndex(insert_at, n_new)` — пустые столбцы (как `_lm_pp_copy_columns_insert_uno`).
10. Собрать **итоговую матрицу** (расширенный прямоугольник) и записать **`setDataArray`**.
11. Записать **заголовки** новых столбцов (автоимена или `new_names`).
12. **Форматирование** новых столбцов: при `recognize_dates` / `recognize_numbers` — типизация и формат ячеек (см. §5).
13. Журнал: лист, исходный столбец, разделитель, вставлено столбцов, max_parts, строк обработано / пропущено.

Строка заголовков **не** участвует в split; в исходном столбце заголовок **не** делится (остаётся как есть или переименовывается только при `replace_source_header` — v2, в v1 заголовок исходного столбца не меняется).

## 2. Алгоритм разделения (подробно)

### 2.1. Чтение (`getDataArray`)

```text
(sc, sr, ec, er) ← адрес data_range
hr ← строка заголовка (из header_row_range)
src_col ← абсолютный 0-based индекс столбца column
src_idx ← src_col − sc   // индекс внутри матрицы

rng ← sheet.getCellRangeByPosition(sc, sr, ec, er)
data ← rng.getDataArray()   // tuple of tuples; data[0] — первая строка диапазона (может быть заголовок)
```

Перед чтением при `as_values: true` (default) — пересчёт книги (`calculateAll`), как у сортировки / `только_значения`.

**Материализация ячейки в текст для split:**

| Тип в ячейке | Поведение |
| ------------ | --------- |
| пусто | `""` → одна пустая часть `[""]` |
| текст (String) | строка как есть |
| число / дата (после as_values) | `cell_text` / локализованное отображение **или** `str(value)` — зафиксировать: **`_lm_cell_display_text`** (как у `замена_значений`) |
| формула | при `as_values=true` → значение; иначе — ошибка / skip по `non_text` |

### 2.2. Split в памяти

Для каждой строки `r` от `hr+1` до `er` (0-based в координатах листа; в `data` — смещение `r - sr`):

```python
raw = materialize_cell_text(data[r - sr][src_idx])
parts = split_by_delimiter(raw, delimiter, options)
rows_parts.append(parts)
max_parts = max(max_parts, len(parts))
```

**Функция `split_by_delimiter` (v1):**

| Параметр | Default | Поведение |
| -------- | ------- | --------- |
| `delimiter` | — | Строка-разделитель; спец. токены см. §3.2 |
| `split_mode` | `each` | `each` — каждое вхождение; `leftmost` — только первое (остаток в одной ячейке) |
| `trim_parts` | `true` | `strip()` каждой части |
| `collapse_empty` | `false` | `true` — схлопывать подряд идущие пустые части (как PQ «Split at each occurrence» vs custom) |
| `max_columns` | `0` | `0` = без лимита (столько столбцов, сколько max_parts по данным); `N>0` — не более N частей, лишнее склеить в последнюю |
| `quote_char` | `""` | v2: учёт кавычек; в v1 игнорируется |

**Пустые / без разделителя:**

- `"a|b|c"` → `["a","b","c"]`
- `"a"` → `["a"]` (одна часть → новых столбцов 0 в режиме replace)
- `""` → `[""]`
- `"a||b"` → `["a","","b"]` (пустая часть сохраняется)
- `"a|b|c"` при `max_columns=2`, `split_mode=each` → `["a","b|c"]`

**Нетекстовые ячейки** (`non_text`):

| Значение | Поведение |
| -------- | --------- |
| `skip` (default) | Строка не меняется; счётчик в логе |
| `empty` | Записать пустые части во все новые столбцы |
| `text` | Привести к строке и split |
| `fail` | Прервать шаг с ошибкой |

### 2.3. Подготовка места (вставка пустых столбцов)

Вычислить `insert_at` (0-based индекс столбца, **куда** вставляется первый **новый** столбец):

| `position` | `insert_at` |
| ---------- | ----------- |
| `_начало_` | `sc` — новые столбцы **слева** от data_range (исходный столбец сдвигается вправо на `n_new`) |
| `_конец_` | `ec + 1` — справа от текущего конца data_range |
| `_после_` | после `relative_column` (если не задан — **после исходного** `src_col`) |
| `_перед_` | перед `relative_column` (если не задан — **перед исходным** `src_col`) |

`relative_column` — один столбец (имя / буква / индекс); обязателен при `_перед_` / `_после_`, если опорный ≠ исходный (визард: combo заголовков).

**Число вставляемых столбцов:**

| `source_policy` | `n_new` |
| --------------- | ------- |
| `replace` (default) | `max(0, max_parts − 1)` — первая часть остаётся в исходном столбце |
| `keep` | `max_parts` — исходный столбец **не** перезаписывается; все части в новых столбцах |

```python
if n_new > 0:
    sheet.getColumns().insertByIndex(insert_at, n_new)
```

После вставки пересчитать `src_col`, `ec`, `src_idx`, если `insert_at <= src_col` (столбцы сдвинулись).

**Конфликт с существующими данными:** вставка UNO **сдвигает** столбцы вправо (как PQ); перезапись только в зоне data_range + новые столбцы. Столбцы справа от зоны вставки смещаются — ожидаемое поведение.

### 2.4. Сборка матрицы и `setDataArray`

1. Перечитать расширенный диапазон:

```text
new_ec ← ec + n_new   // с учётом сдвига индексов
read_rng ← sheet.getCellRangeByPosition(sc, sr, new_ec, er)
data ← read_rng.getDataArray()
```

2. Заполнить части (0-based `src_idx` после возможного сдвига):

**Режим `replace`:**

```text
data[r][src_idx] ← parts[0]
for i in 1 .. max_parts-1:
    data[r][insert_at + i - delta] ← parts[i]   // delta — смещение если insert_at > src_col
```

**Режим `keep`:**

```text
// src_idx не меняем
for i in 0 .. max_parts-1:
    data[r][insert_at + i] ← parts[i]
```

3. Запись:

```python
read_rng.setDataArray(data)
```

4. **Заголовки** новых столбцов (строка `hr`):

- если задан `new_names[]` — использовать (уникализировать через `_lm_pp_allocate_new_header_name`);
- иначе авто: `{ИсходныйЗаголовок}.1`, `.2`, … или `{ИсходныйЗаголовок}_1`, `_2` (зафиксировать в реализации: **`.1`, `.2`** — как PQ).

Исходный заголовок в режиме `replace` **не** переименовывается.

### 2.5. Форматирование после `setDataArray`

Применяется **только к новым столбцам** (и к исходному в `replace`, если первая часть типизируется). Заголовок не трогать.

| Флаг | Default | Поведение |
| ---- | ------- | --------- |
| `recognize_dates` | `true` | Для каждого **нового** столбца: если ≥ `_DIRECT_COPY_DT_COL_MATCH_MIN` (3) строк данных успешно разбираются как дата/время (`_direct_try_parse_datetime_text`, форматы `MERGE_XML_DATETIME_FORMATS`) — записать **date/datetime** в ячейки и применить формат даты (`формат_даты` / `_lm_pp_apply_date_format_column`) |
| `recognize_numbers` | `true` | Аналогично для чисел (`_direct_try_parse_number_text`); столбцы, уже распознанные как даты, **исключить**; формат числа — locale-aware (ru: запятая как десятичный) |

Если оба `false` — все части остаются **текстом** (String), без смены NumberFormat.

**Порядок:** сначала даты, потом числа (как `_direct_build_convert_column_sets_probe`).

Построчная типизация (альтернатива поколоночной эвристике, v1.1): типизировать каждую ячейку независимо — проще, но смешанный столбец останется текстом; **v1 — поколоночная эвристика ≥3 совпадений**.

## 3. Параметры (JSON, колонка C)

```json
[{
  "v": 1,
  "fn": "разделить_по_столбцам",
  "sheet": "Сводная",
  "column": "ФИО",
  "delimiter": ",",
  "position": "_после_",
  "relative_column": "ФИО",
  "source_policy": "replace",
  "recognize_numbers": true,
  "recognize_dates": true,
  "trim_parts": true,
  "max_columns": 0
}]
```

### 3.1. Общие поля листа

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `sheet` | string | Один лист; пусто — все листы результата |
| `sheets` | string[] | Список листов |
| `fn` | string | `разделить_по_столбцам` |
| `as_values` | bool | Материализовать формулы перед split (default `true`) |
| `non_text` | string | `skip` \| `empty` \| `text` \| `fail` (default `skip`) |

### 3.2. Исходный столбец и разделитель

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `column` | string | **Один** столбец для split (имя заголовка / буква / индекс) |
| `delimiter` | string | Разделитель; см. предустановки |
| `delimiter_preset` | string | Опционально: код preset (визард); в JSON может быть только `delimiter` |
| `split_mode` | string | `each` \| `leftmost` (default `each`) |
| `trim_parts` | bool | default `true` |
| `max_columns` | int | 0 = авто; иначе лимит частей |
| `source_policy` | string | `replace` \| `keep` (default `replace`) |

**Предустановки разделителя** (combo в визарде; в JSON хранится каноническое значение `delimiter`):

| Код preset | Подпись UI | `delimiter` |
| ---------- | ---------- | ----------- |
| `comma` | Запятая | `,` |
| `semicolon` | Точка с запятой | `;` |
| `tab` | Табуляция | `\t` |
| `space` | Пробел | ` ` |
| `pipe` | Вертикальная черта | `\|` |
| `custom` | Свой… | поле ввода `custom_delimiter` |

Спец. escape в JSON: `"\\t"`, `"\\n"`, `"\\|"`.

### 3.3. Размещение на листе

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `position` | string | `_начало_` \| `_конец_` \| `_перед_` \| `_после_` (default `_после_`) |
| `relative_column` | string | Опорный столбец для `_перед_` / `_после_`; default — исходный `column` |
| `new_names` | list | Заголовки новых столбцов (опционально) |

### 3.4. Форматирование

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `recognize_dates` | bool | default `true` |
| `recognize_numbers` | bool | default `true` |

Подсказка (hint):

```text

Исходный столбец читается в память, делится, результат записывается setDataArray.
Пустые столбцы вставляются автоматически. Даты/числа — по флагам распознавания.
```

## 5. Валидация

1. `column` пуст / не найден в data_range → ошибка.
2. `delimiter` пуст (и preset = custom без текста) → ошибка.
3. `position` ∈ `{_перед_, _после_}` и `relative_column` не найден → ошибка.
4. `max_columns` < 0 → ошибка.
5. `new_names` задан, но длина ≠ `n_new` → WARN + обрезка / дополнение автоименами.
6. `n_new > 0` и вставка выходит за лимит столбцов Calc (1024) → ошибка.
7. Нет строк данных (только заголовок) → OK, вставка столбцов только если max_parts > 1 на пустом теле — пропуск split, лог «нет данных».
8. Все строки `non_text=skip` → OK, «обработано 0 строк».

DEBUG: лист, column, delimiter, position, insert_at, n_new, max_parts, recognize_* , строк до/после.

## 6. Примеры

### 6.1. Классика: «Фамилия, Имя, Отчество»

**Вход:**

| ФИО |
| --- |
| Иванов, Иван, Иванович |
| Петров, Пётр, |

```json
[{
  "v": 1,
  "fn": "разделить_по_столбцам",
  "sheet": "Сводная",
  "column": "ФИО",
  "delimiter": ",",
  "position": "_после_",
  "relative_column": "ФИО",
  "source_policy": "replace"
}]
```

**Выход:**

| ФИО | ФИО.1 | ФИО.2 |
| --- | ----- | ----- |
| Иванов | Иван | Иванович |
| Петров | Пётр | |

### 6.2. Разделитель «;», в конец таблицы

```json
[{
  "v": 1,
  "fn": "разделить_по_столбцам",
  "column": "Код",
  "delimiter": ";",
  "position": "_конец_",
  "source_policy": "keep",
  "new_names": ["Код_1", "Код_2", "Код_3"]
}]
```

Исходный «Код» сохраняется; три новых столбца в конце data_range.

### 6.3. Только первое вхождение разделителя

```json
[{
  "v": 1,
  "fn": "разделить_по_столбцам",
  "column": "Путь",
  "delimiter": "/",
  "split_mode": "leftmost"
}]
```

`"a/b/c"` → `["a", "b/c"]` — два столбца.

### 6.4. Распознавание чисел и дат

**Вход:**

| Период |
| ------ |
| 01.02.2024 |
| 15.03.2024 |
| 100,5 |

```json
[{
  "v": 1,
  "fn": "разделить_по_столбцам",
  "column": "Период",
  "delimiter": "|",
  "recognize_dates": true,
  "recognize_numbers": true
}]
```

Если после split в столбце ≥3 дат — формат даты; в числовом столбце — числовой формат ru.

## 9. Граничные случаи

| Случай | Ожидание |
| ------ | -------- |
| Одна часть во всех строках | `n_new=0`, только setDataArray без insert (или insert 0) |
| Разное число частей по строкам | `max_parts` по максимуму; короткие строки — пустые хвосты |
| Исходный столбец = опорный, `_после_` | Новые столбцы сразу справа от исходного |
| `_начало_` + `replace` | Исходный сдвигается; первая часть в новом индексе src_col + n_new |
| Объединённые ячейки в столбце | WARN; читать отображаемое значение верхней-left |
| Широкая таблица (много split) | Лог max_parts; порог предупреждения (напр. > 50 столбцов) |
| `position=_конец_` + `keep` | Новые после ec; исходный не тронут |
| Delimiter = пробел в «Иван Иванов» | `["Иван","Иванов"]` при trim_parts |
| Tab в CSV-стиле | preset `tab` → `\t` |
| recognize_numbers=false, recognize_dates=false | Всё текст |
| Повторный запуск на том же листе | Split уже разделённого — пользовательская ответственность |
