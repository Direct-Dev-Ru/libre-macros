# Карта переменных источников (`Добавить_в_карту_переменных`)

## Назначение

На этапе **сбора данных**, пока книги-источники уже открыты (UNO) или доступны в direct/xml-фазе, заполнять **runtime-карту переменных** значениями из указанных ячеек источников.

Карта нужна последующим шагам постобработки (в первую очередь `применить_формулу`) для подстановки констант/значений из источников в текст формулы без ручного копирования.

Параметр задаётся на листе `Параметры_Объединения*` (активный лист группы). Это **не** постобработка: строки **не** кладутся в `Постобработка_Диапазон` / `Постобработка_xml` / `Финальная_обработка`.

Может быть **несколько строк** с одним именем параметра в A (как у `Ячейка_В_Столбец`, `ВПР`).


| Колонка | Значение                                                                                                                                             |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| A       | `Добавить_в_карту_переменных`                                                                                                                        |
| B       | `смотри в С` (маркер, как у `удаление_верхних_строк` / JSON-параметров) — **не оставлять пустой**, иначе `read_repeated_param_rows` пропустит строку |
| C       | JSON-массив блоков `[{…}, …]`                                                                                                                        |


Редактирование — через визард (`param_wizard`): поддиалог JSON-блоков (как у `Ячейка_В_Столбец`), кнопка «Параметры…».

Кодек: `libre_macros_param_codec.py` (`param_decode` / `param_encode`, **только JSON**).

---



## Отличие от `Ячейка_В_Столбец`


|             | `Ячейка_В_Столбец`                               | Карта переменных                                     |
| ----------- | ------------------------------------------------ | ---------------------------------------------------- |
| Результат   | новый столбец на листе с данными в каждой строке | **нет** столбца — значение в runtime-карте           |
| Потребитель | фильтры, формат, постобработка по заголовку      | плейсхолдер `<<Переменные.…>>` в `применить_формулу` |
| Когда       | нужно поле в таблице результата                  | нужна константа из источника в формуле               |


Обе функции могут читать одну и ту же ячейку источника разными путями.

## Согласование с парадигмой проекта


| Тема                   | Как в проекте                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Формат C               | массив блоков `[{…}]`, поля **snake_case**, `"v": 1`, `"fn": "добавить_в_карту_переменных"`                                                |
| Имя параметра A        | `Добавить_в_карту_переменных`; в JSON `fn` — нормализованный ключ (`добавить_в_карту_переменных`)                                          |
| Маски `file` / `sheet` | `text_match` / `merge_identity_key`, как у `Листы` / `Ячейка_В_Столбец` (`source_sheet`); пусто / `*` / `все` = все                        |
| Адрес ячейки           | поле `cell` — A1 (`B2`, `$C$1`); разбор как в соседних параметрах                                                                          |
| Ключ карты             | `имя~лист_источника~файл`, разделитель `~` (тильда **запрещена** в поле `name`)                                                            |
| Сегмент `файл`         | `cell_to_column_file_key(fpath, path_display)` — тот же display, что в `#Путь` / `format_source_path`                                      |
| Сегмент `лист`         | имя листа **источника** (не листа результата); для копий `N_Имя` — каноническое имя с листа источника                                      |
| Значение               | кортеж `(text, type_token)`; чтение ячейки — через `_snapshot_cell_content` (UNO) / эквивалент в direct                                    |
| `type_token`           | `empty` | `text` | `number` | `date` | `datetime` — вывод из `ctype` снимка (`EMPTY=0`, `VALUE=1`, `TEXT=2`, `FORMULA=3` + эвристика даты) |
| Этап заполнения        | при **первом** открытии источника / листа (рядом с prefetch `Ячейка_В_Столбец`), **до** постобработки диапазона                            |
| Потребитель v1         | только `применить_формулу` (`Постобработка_Диапазон`, `Постобработка_xml`, `Финальная_обработка`)                                          |
| xml_excel_ods          | заполнение в direct при чтении файла; карта в `_cw_cfg` / `settings` на весь run; доступна UNO-постобработке после reopen                  |

## Параметры JSON (колонка C)

Пример:

```json
[
  {
    "v": 1,
    "fn": "добавить_в_карту_переменных",
    "file": "*source_01*",
    "sheet": "Заказы",
    "cell": "A1",
    "name": "Филиал"
  },
  {
    "v": 1,
    "fn": "добавить_в_карту_переменных",
    "file": "*",
    "sheet": "*",
    "cell": "B2",
    "name": "Дата_отчета"
  }
]
```


| Поле    | Обязательно | Смысл                                                                                           |
| ------- | ----------- | ----------------------------------------------------------------------------------------------- |
| `v`     | да          | версия блока (`1`)                                                                              |
| `fn`    | да          | `добавить_в_карту_переменных`                                                                   |
| `file`  | нет         | маска **файла-источника** (`text_match`); пусто / `*` / `все` — любой файл в текущем шаге сбора |
| `sheet` | нет         | маска **листа источника**; пусто / `*` / `все` — все листы источника, попавшие в отбор сбора    |
| `cell`  | да          | адрес ячейки на листе источника                                                                 |
| `name`  | да          | логическое имя переменной (1-й сегмент ключа); без символа `~`                                  |


Несколько строк A с одним параметром **объединяются** в один список правил (порядок строк листа сохраняется).

Парсинг строк параметра: `read_repeated_param_rows` → из ячеек строки ищется JSON (`param_decode`), как в `build_cell_to_column_plan`.

## Структура runtime-карты

- **Хранение:** `_cw_cfg` (напр. `_MERGE_SOURCE_VARIABLES_MAP: dict[str, tuple]`), сброс в `merge_run_context_begin`, очистка после `_merge_run_pipeline_final_phase` (включая `Финальная_обработка`).
- **Не** писать на лист параметров и **не** персистить в файл книги (v1).
- **Ключ:** `имя~имя_листа_источника~файл_источника`  
Пример: `Филиал~Заказы~source_01.xlsx`
- **Значение:** `(text, type_token)`  
  - `text` — `cell_text` / `snap['text']` для подстановки;  
  - `type_token` — для будущих потребителей (v1 в формулу идёт только `text`).
- **Запись:** для каждой пары (источник × лист источника), прошедшей маски правила, читается `cell` → запись с полным ключом.
- **Коллизии:** повторная запись с тем же ключом — **последняя побеждает** (`предупреждение` в журнал сбора).



### Ограничения режимов

- `Текущие листы` **(involve):** внешние файлы не открываются — карта заполняется только из листов **текущей книги**, если правило это допускает (`file` пусто/`*` или маска совпала с путём «Эта_книга»).
- **Нет открытого источника:** правило для файла/листа пропускается (`предупреждение`), сбор не падает.

## Потребление в `применить_формулу`

Подстановка выполняется **до** `_lm_pp_expand_apply_formula_template` (на уровне шаблона формулы), чтобы не путать с `[Заголовок]{row_id}`.

### Синтаксис плейсхолдера

```text
<<Переменные.префикс_или_полный_ключ>>
```

Примеры:

- `<<Переменные.Филиал>>` — только имя (1 сегмент);
- `<<Переменные.Филиал~Заказы>>` — имя + лист источника;
- `<<Переменные.Филиал~Заказы~source_01.xlsx>>` — полный ключ.

Регистр при поиске — **без учёта** (`casefold`); в карте ключи хранятся в каноническом виде (как прочитано с листа/файла).

### Алгоритм резолва (v1)

1. Из плейсхолдера взять строку после `Переменные.` → `query`.
2. Разбить `query` и каждый ключ карты на сегменты по `~` (1–3 сегмента).
3. Ключ **подходит**, если сегменты `query` **попарно равны** началу ключа (длина `query` ≤ 3 сегментов).
  Не использовать «подстроку внутри сегмента» (`Филиал` ≠ `Филиал2`).
4. Если подходящих ключей **0** — **предупреждение** в журнал, плейсхолдер остаётся в формуле как есть (не молчать).
5. Если ключ **1** — взять его `text`.
6. Если ключей **несколько**:
  - отфильтровать по сегменту **листа результата** (имя листа, на котором выполняется `применить_формулу`, с учётом `N_` как у `cell_to_column_sheet_name_candidates`);
  - если после фильтра **ровно один** — взять его;
  - иначе — **предупреждение**; tie-break: **последний** по порядку заполнения карты (согласовано с коллизиями).



### Подстановка в формулу (v1)

- Вставляется `text` как есть (экранировать `"` внутри строки для формулы Calc).
- Числа/даты **без кавычек** по `type_token` — **вне объёма v1** (отдельная итерация).

## Точки выполнения


| Фаза                                                                                        | Действие                                            |
| ------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `merge_run_context_begin`                                                                   | сброс карты                                         |
| Сбор (UNO): открытие источника / листа                                                      | чтение `cell` по правилам → запись в карту          |
| `xml_excel_ods` (direct)                                                                    | то же при обходе файлов в `_direct_build_read_plan` |
| `Постобработка_Диапазон` / `Постобработка_xml` / `Финальная_обработка`: `применить_формулу` | резолв `<<Переменные.…>>`                           |
| `_merge_run_pipeline_final_phase` (конец run)                                               | очистка карты                                       |


Карта **должна** переживать reopen после `xml_excel_ods` (хранение в `_cw_cfg`, не в закрытом документе).

## Вне объёма v1

- Превью карты / визуальный конструктор ключей (только JSON-редактор блоков).
- Подстановка `<<Переменные.…>>` в других `fn`, кроме `применить_формулу`.
- Персист карты на служебный лист книги.
- Подстановка чисел/дат без кавычек по `type_token`.
- Per-file колонки B,C,D… с разными правилами на файл (только маски `file` внутри JSON).

## Примеры для ручной проверки

**Параметр (B =** `смотри в С`**, C = JSON):**

```json
[{"v":1,"fn":"добавить_в_карту_переменных","file":"*","sheet":"Заказы","cell":"A1","name":"Филиал"}]
```

**Формула:**

```text
=IF(<<Переменные.Филиал>>="Москва";D{row_id};E{row_id})
```

**Полный ключ** (несколько источников с одним именем):

```text
=<<Переменные.Курс~Справочник~rates.xlsx>>*D{row_id}
```
