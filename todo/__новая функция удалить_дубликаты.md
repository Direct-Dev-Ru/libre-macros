# ТЗ: удалить_дубликаты

Новая функция постобработки / финальной стадии (RANGE / FINAL; по возможности `Постобработка_xml`).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`).

**Имя ключа (fn):** `удалить_дубликаты`  
**Синоним в UI (опционально):** «убрать повторы строк», «dedup».

**Цель:** на листе результата в зоне данных оставить **по одной строке** на каждый уникальный ключ; остальные строки с тем же ключом **удалить** (или, опционально, записать результат на новый лист без удаления исходника).

Семантика ключа совместима с `количество_значений`: составной ключ из `key_columns`, нормализация `trim` / `case_sensitive`.

---



## 1. Принцип работы

1. Определить **область данных** на листе:
  - стандартный прямоугольник постобработки (`data_range` + `header_row_range` от хоста);
  - строка заголовков **не участвует** в сравнении и **не удаляется**.
2. По каждой строке данных построить **ключ уникальности**:
  - если задан `key_columns` — значения только этих столбцов;
  - если `key_columns` пуст / не задан — **все столбцы** диапазона данных (полное совпадение строки).
3. Пройти строки в выбранном порядке (`scan_order`) и отметить дубликаты:
  - `keep: first` (default) — оставить **первое** вхождение ключа, удалить последующие;
  - `keep: last` — оставить **последнее** вхождение, удалить предыдущие.
4. Удалить отмеченные строки **снизу вверх** (как `удаление_строк`), чтобы индексы не «плыли».
5. Записать в журнал: сколько строк было, сколько удалено, сколько уникальных ключей осталось.

Строка заголовков, служебные столбцы `#Путь` / `#ДатаВремяФайла` и прочие колонки **вне** `key_columns` при сравнении **не учитываются**, но **сохраняются** в оставшейся строке (как в Excel «Удалить дубликаты» по выбранным столбцам).

---



## 2. Формирование результата



### 2.1. Режимы записи (`output`)


| Значение            | Поведение                                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inplace` (default) | Удалить дубликаты **на том же листе** в зоне данных. Заголовок и столбцы вне диапазона не трогать.                                                                                    |
| `new_sheet`         | Прочитать зону данных, оставить уникальные строки в памяти, записать на лист `dest_sheet` с A1 (заголовок + тело). Исходный лист не менять. При занятом имени — суффикс `_2`, `_3`, … |
| `offset`            | Записать дедуплицированный блок на том же листе с `dest_cell`, **не** удаляя исходные строки. При пересечении с источником — ошибка (или `overwrite_overlap: true`).                  |


Для `inplace` и `offset` удаление строк применяется только при `output=inplace`. Для `new_sheet` / `offset` — только запись матрицы.

### 2.2. Ключ уникальности


| Режим                 | Параметры         | Смысл                                                                                         |
| --------------------- | ----------------- | --------------------------------------------------------------------------------------------- |
| По столбцам (default) | `key_columns`     | Список имён / букв / индексов столбцов; пусто — **все** столбцы data_range                    |
| Исключения            | `exclude_columns` | Альтернатива: «все, кроме» (взаимоисключимо с непустым `key_columns` в v1 — ошибка валидации) |


Нормализация значений ключа (как у `количество_значений`):


| Поле               | Default | Поведение                                                                                                                                                       |
| ------------------ | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `trim`             | `true`  | `strip()` для текстовых частей ключа                                                                                                                            |
| `case_sensitive`   | `false` | без учёта регистра при сравнении                                                                                                                                |
| `empty_key_policy` | `dedup` | `dedup` — все полностью пустые ключи считаются одним ключом; `unique` — каждая пустая строка уникальна (не удалять); `skip` — строки с пустым ключом не трогать |


Сравнение типов:


| `compare_as`     | Поведение                                                                           |
| ---------------- | ----------------------------------------------------------------------------------- |
| `text` (default) | Все части ключа приводятся к строке (`cell_text`); числа `1` и `1.0` могут совпасть |
| `strict`         | Учитывать тип ячейки: число ≠ текст с тем же отображением; даты по serial/value     |


Перед сравнением при `as_values: true` (default) формулы материализуются в значения (UNO / xml).

### 2.3. Какую строку оставить (`keep`)


| Значение          | Алгоритм                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| `first` (default) | Сканирование сверху вниз; при повторе ключа текущая строка → удалить                                   |
| `last`            | Сканирование снизу вверх; при повторе ключа текущая строка → удалить (эквивалент «оставить последнюю») |


`scan_order` (опционально, для тонкой настройки):


| Значение    | Смысл                    |
| ----------- | ------------------------ |
| `top_down`  | default для `keep=first` |
| `bottom_up` | default для `keep=last`  |


Явный `scan_order` переопределяет направление; `keep` по-прежнему задаёт, **какое** вхождение считается «выжившим».

### 2.4. Предварительная сортировка (`pre_sort`)

Опционально **до** дедупликации отсортировать тело данных по `sort_keys` (тот же формат, что у `сортировка`: `[{"column":"Дата","order":"desc"}, …]`).

- Заголовок не сортируется.
- Если `pre_sort` задан вместе с `keep: first`, «первой» станет строка с лучшим рангом после сортировки.
- Если `pre_sort` не задан — порядок оставшихся строк = порядок **выживших** вхождений в исходнике.

Рекомендация в UI: подсказка «для выбора «лучшей» строки при дубликатах — сначала сортировка, затем keep=first».

### 2.5. Маркировка вместо удаления (`mark_duplicates`)

не удалять, а добавить столбец `mark_column` (default `Дубликаты`):


| `mark_duplicates` | Поведение                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| `false` (default) | Удалять / переносить как в §2.1                                                                       |
| `true`            | Строки не удалять; в `mark_column` для **повторных** вхождений писать `1` / `Да`, для первого — пусто |


## 3. Параметры (JSON, колонка C)

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "sheet": "Сводная",
  "key_columns": ["ФИО", "Отдел"],
  "keep": "first",
  "trim": true,
  "case_sensitive": false
}]
```



### 3.1. Общие поля листа


| Поле     | Тип      | Описание                                |
| -------- | -------- | --------------------------------------- |
| `sheet`  | string   | Один лист; пусто — все листы результата |
| `sheets` | string[] | Список листов (альтернатива `sheet`)    |
| `fn`     | string   | `удалить_дубликаты`                     |




### 3.2. Ключ и сравнение


| Поле               | Тип    | Описание                                                                |
| ------------------ | ------ | ----------------------------------------------------------------------- |
| `key_columns`      | list   | Столбцы ключа; пусто — все столбцы data_range                           |
| `exclude_columns`  | list   | Все столбцы, кроме перечисленных (взаимоисключимо с `key_columns` в v1) |
| `trim`             | bool   | default `true`                                                          |
| `case_sensitive`   | bool   | default `false`                                                         |
| `compare_as`       | string | `text` | `strict` (default `text`)                                      |
| `empty_key_policy` | string | `dedup` | `unique` | `skip` (default `dedup`)                           |
| `as_values`        | bool   | Материализовать формулы перед сравнением (default `true`)               |




### 3.3. Выбор выжившей строки


| Поле         | Тип    | Описание                                                      |
| ------------ | ------ | ------------------------------------------------------------- |
| `keep`       | string | `first` | `last` (default `first`)                            |
| `scan_order` | string | `top_down` | `bottom_up` (опционально; default по `keep`)     |
| `pre_sort`   | list   | Опциональная сортировка до дедупа; элементы `{column, order}` |




### 3.4. Вывод


| Поле                | Тип    | Описание                                                    |
| ------------------- | ------ | ----------------------------------------------------------- |
| `output`            | string | `inplace` | `new_sheet` | `offset`                          |
| `dest_sheet`        | string | Для `new_sheet`                                             |
| `dest_cell`         | string | Якорь для `offset` (default `A1`)                           |
| `overwrite_overlap` | bool   | Разрешить перекрытие при `offset` (default `false`)         |
| `mark_duplicates`   | bool   | Только маркировка, без удаления (default `false`; см. §2.5) |
| `mark_column`       | string | Имя столбца маркера при `mark_duplicates=true`              |


---



## 4. Валидация

1. `key_columns` и непустой `exclude_columns` одновременно → ошибка.
2. Столбец из `key_columns` / `exclude_columns` не найден в диапазоне → ошибка.
3. `output=new_sheet` без `dest_sheet` → ошибка.
4. `output=offset` без `dest_cell` → ошибка.
5. `pre_sort` с некорректным столбцом / направлением → ошибка.
6. Нет строк данных (только заголовок) → предупреждение, шаг пропустить.
7. 0 удалённых строк → OK, запись в лог «дубликатов не найдено».
8. Слишком много строк (порог в коде, напр. > 500k) → ошибка / предупреждение.

DEBUG: лист, число строк до/после, `key_columns`, `keep`, удалено, уникальных ключей, `output`.

## 5. Примеры сценариев



### 5.1. Классика: дубликаты по ФИО (оставить первую)

**Вход:**


| ФИО     | Отдел | Сумма |
| ------- | ----- | ----- |
| Иванов  | IT    | 100   |
| Петров  | HR    | 200   |
| Иванов  | IT    | 150   |
| Сидоров | IT    | 300   |


```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "sheet": "Сводная",
  "key_columns": ["ФИО"],
  "keep": "first"
}]
```

**Выход (**`inplace`**):**


| ФИО     | Отдел | Сумма |
| ------- | ----- | ----- |
| Иванов  | IT    | 100   |
| Петров  | HR    | 200   |
| Сидоров | IT    | 300   |


Строка «Иванов / IT / 150» удалена (ключ `Иванов` уже был).

### 5.2. Составной ключ + оставить последнюю

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "key_columns": ["ФИО", "Отдел"],
  "keep": "last"
}]
```

Дубликат только если совпали **оба** поля; при `keep: last` остаётся строка с большим индексом.

### 5.3. Полное совпадение строки (все столбцы)

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "sheet": "Сводная"
}]
```

`key_columns` не задан → сравнивается вся строка data_range.

### 5.4. Сначала сортировка по дате, затем первая строка

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "key_columns": ["ФИО"],
  "pre_sort": [{"column": "Дата", "order": "desc"}],
  "keep": "first"
}]
```

После сортировки «первой» для каждого ФИО станет строка с **максимальной** датой.

### 5.5. Результат на новый лист

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "sheet": "Сводная",
  "key_columns": ["ФИО"],
  "output": "new_sheet",
  "dest_sheet": "Сводная_уник"
}]
```

Исходный лист без изменений; на `Сводная_уник` — заголовок + уникальные строки.

### 5.6. Игнорировать служебные столбцы при полном сравнении

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "exclude_columns": ["#Путь", "#ДатаВремяФайла", "Количество"]
}]
```

Строки считаются дубликатами, если совпали все столбцы **кроме** перечисленных.

## 6. Место в пайплайне и документация

- Секции: **Постобработка_Диапазон**, **Финальная_обработка**; xml — по возможности в `Постобработка_xml` (удаление строк в файле сложнее — в v1 допустимо только UNO).
- Логично ставить **после** `заполнение_вниз`, `замена_значений`, **до** `сортировка` / `зебра_диапазон` / `группировка_по_столбцу`, если оформление должно относиться к финальному набору строк.
- Если нужен порядок «лучшей» строки — `pre_sort` внутри шага или отдельный шаг `сортировка` **перед** `удалить_дубликаты`.
- Связь с `количество_значений`: та же нормализация ключа; можно сначала посчитать частоты, потом удалить дубликаты.
- Визард: `key_columns` (мультиселект столбцов), `keep`, опционально `pre_sort`, `output` / `dest_sheet`.
- После реализации: `docs/05_POSTPROCESS.md`, `docs/13_JSON_PARAMS.md`, `docs/15_PARAM_REFERENCE.md`, справка, пресеты в `param_wizard` / `manual_json_presets.py`.

**Реализация (ориентир):**

- UNO: `lm_pp_range_remove_duplicates` в `libre_macros_lib.py`; финал: `lm_final_remove_duplicates` в `libre_macros_values_lib.py`.
- Переиспользовать `_lm_pp_value_count_key_from_parts`, `_lm_pp_value_count_row_key`, `_lm_pp_resolve_column_list`.
- Удаление: тот же механизм, что у `удаление_строк` (пакетно снизу вверх).
- `param_codec`: `_normalize_remove_duplicates_block`; ключ в `JSON_ONLY_FNS`.

## 7. Граничные случаи (зафиксировать в реализации)


| Случай                                                      | Ожидание                                             |
| ----------------------------------------------------------- | ---------------------------------------------------- |
| Одна строка данных                                          | Ничего не удалять                                    |
| Все строки с уникальными ключами                            | Лог «удалено 0»                                      |
| Все строки с одинаковым ключом, `keep=first`                | Остаётся одна (верхняя)                              |
| Все строки с одинаковым ключом, `keep=last`                 | Остаётся одна (нижняя)                               |
| Пустой ключ, `empty_key_policy=dedup`                       | Одна пустая строка                                   |
| Пустой ключ, `empty_key_policy=unique`                      | Все пустые строки сохранить                          |
| Ключ только по `#Путь`, строки из разных файлов             | Не дубликаты                                         |
| Дубликат по ключу, но разные значения в неключевых столбцах | Удаляется вся строка; выжившая — по `keep`           |
| Объединённые ячейки в ключевом столбце                      | Читать отображаемое значение; WARN                   |
| Формулы в ключевых ячейках                                  | При `as_values=true` сравнивать результат            |
| `compare_as=strict`: текст `"1"` и число `1`                | Разные ключи                                         |
| После удаления нарушилась зебра / outline                   | Нормально; перекрасить следующими шагами             |
| `new_sheet` + лист уже существует                           | Суффикс `_2`, … или ошибка — как у `копировать_лист` |
| Несколько блоков JSON на разные листы                       | Фильтр по `sheet`, как у `сортировка`                |
