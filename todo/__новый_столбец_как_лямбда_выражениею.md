# ТЗ: столбец_по_лямбде

Новая функция постобработки / финальной стадии (RANGE + FINAL; по возможности `Постобработка_xml` / direct).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets` / опционально `sheet_expr`).

**Имя ключа (fn):** `столбец_по_лямбде`  
**Синонимы / алиасы:** `новый_столбец_лямбда`, `lambda_column`, `custom_column`, `вычислить_столбец`.  
**Lib:** `lm_pp_range_lambda_column` / `merge_final_lambda_column`  
**Аналог Power Query:** **Custom Column** (*Add Column → Custom Column*): произвольное выражение над полями строки в памяти.

**Цель:** добавить (или перезаписать) столбец, где **каждое значение** — результат Python-лямбды над данными текущей строки, соседних строк через смещение и уже обработанных строк выше (`upd_rows`). В ячейки пишутся **только значения** (не формулы Calc). Имя столбца — литерал или отдельная лямбда. Выбор листов — стандартные поля или лямбда над списком имён. Числовой/дата-формат столбца — по типу **первого** успешно вычисленного значения и глобальным настройкам; стиль заголовка — с соседа справа или слева.

**Отличие от соседних fn:**

| | `столбец_по_лямбде` | `условный_столбец` | `применить_формулу` | `конкатенация_столбцов` |
|--|---------------------|--------------------|--------------------|-------------------------|
| Язык | Python-лямбда (+ sugar `rows("…")`, `upd_rows("…")`) | JSON-правила If/Else | формула Calc | список столбцов + separator |
| Оценка | in-memory → значения в ячейки | in-memory | UNO / fillSeries | in-memory |
| Формат результата | авто по 1-му значению + GS | без автоформата v1 | клон соседа / явный format | без автоформата |
| Соседние/накопленные строки | `rows("Col")[-1]`, `upd_rows("Col")` и т.п. | нет (v1) | `{row-1}`, R[-1]C | нет |
| UX | текст лямбды | конструктор правил | ручная формула | выбор столбцов |
| Типичный кейс | вычисляемое поле, diff, concat expr | категория по порогам | UNO-формулы на листе | склеить ФИО |

`применить_формулу` остаётся для формул Calc и `{row_id}`; `условный_столбец` — для цепочек If без кода; `столбец_по_лямбде` — для произвольной логики на Python в памяти.

## 1. Принцип работы

1. Определить **область данных** (`data_range` + `header_row_range` от хоста).
2. Собрать кандидатов листов книги (или листов результата на FINAL).
3. Применить фильтр листов:
   - стандартно — `sheet` / `sheets` (как у прочих PP);
   - **или** `sheet_expr` — лямбда над массивом имён (см. §2.3).
4. Для каждого целевого листа:
   1. Материализовать формулы источника (`calculateAll` / эквивалент) и прочитать прямоугольник в память (`getDataArray`) — **внутренняя** подготовка, без параметра в JSON.
   2. Построить карту заголовок → индекс столбца.
   3. Вычислить **имя результирующего столбца** — `new_column` или `new_column_expr` (§2.2).
   4. Разместить столбец (`position`, `relative_column`) — паттерн `конкатенация_столбцов` / `условный_столбец`.
   5. Скомпилировать **основную лямбду** `expr` (§2.1, §3).
   6. Создать `upd_store` — накопитель уже обработанных строк для `upd_rows`.
   7. Для каждой **строки данных** (ниже заголовка, индекс `ri`) сверху вниз:
      - вызвать `fn(rows_ctx)` → значение ячейки;
      - при ошибке — политика `on_error` (§4.4);
      - запомнить **первое** успешное непустое значение для определения типа столбца (§4.5).
      - после вычисления строки обновить in-memory матрицу результата и вызвать `upd_store.commit(ri)`.
   8. Записать столбец **значениями** (`setDataArray` / точечная запись — предпочтительно один проход матрицы; формулы не пишутся).
   9. Применить форматирование (§4.5): заголовок — с соседа; тело столбца — единый NumberFormat по типу первого значения.
5. Журнал: лист, итоговое имя столбца, тип формата (`text`/`number`/`date`), строк обработано / ошибок / пропусков.

Строка заголовков **не** передаётся в `rows` как «текущая строка»; заголовок результата пишется отдельно после вычисления имени.

`upd_rows` для строки `ri` видит только строки **выше** (`< ri`), уже прошедшие обработку в текущем проходе. Это поведение должно совпадать с `замена_значений` и `текстовые_операции`.

## 2. Лямбды и синтаксический sugar

В JSON и визарде хранится **исходный** текст лямбды (как у `filter` в `удаление_листов`). Перед компиляцией выполняется **трансформация sugar → обычный Python**, затем **санация** (`lm_sanitize_code`, policy `standard`) и `eval` с ограниченным namespace (как `compile_sheet_name_filter`).

Общие правила:

- допустимы `lambda …:` и `def fn(…): … return …` (как у фильтра листов);
- параметр sugar **фиксирован**: `rows` для значений, `sheets` для выбора листов, `sheet` + `headers` для имени столбца (см. ниже);
- во всех лямбдах проекта действует единый стандарт helper'ов: `rows(...)`, `upd_rows(...)`, `upd_rows_seen(...)`, `upd_rows_count(...)`, `upd_rows_len()` — если контекст строковый;
- в sugar **запрещены** `import` и обращения к UNO (`doc`, `sheet.getCell…`) — только in-memory v1;
- после rewrite код должен проходить тот же санitizer, что inline-код в B/C.

### 2.1. Основная лямбда (`expr`) — значения столбца

**Обязательна.** Сигнатура sugar:

```text
lambda rows: <выражение>
```

`rows("ИмяСтолбца")` — accessor к **столбцу** в текущей строке диапазона (куда пишется результат).
`upd_rows("ИмяСтолбца")` — accessor к **последней уже обработанной** строке выше текущей.

| Sugar | Смысл | Python после rewrite (ориентир) |
| ----- | ----- | --------------------------------- |
| `rows("Name")` | значение столбца `Name` в **текущей** строке | `_lm_rows(_ri, "Name", 0)` |
| `rows("Name")[-1]` | значение в **предыдущей** строке данных | `_lm_rows(_ri, "Name", -1)` |
| `rows("Name")[-2]` | на 2 строки выше | `_lm_rows(_ri, "Name", -2)` |
| `rows("Name")[1]` | на 1 строку **ниже** (если уже есть в матрице) | `_lm_rows(_ri, "Name", 1)` |
| `rows(1)` / `rows("A")` | столбец по 1-based индексу / букве | `_lm_rows(_ri, 1, 0)` / `_lm_rows(_ri, "A", 0)` |
| `upd_rows("Name")` | значение `Name` в последней обработанной строке выше | `_lm_upd_rows(_ri, "Name", 0)` |
| `upd_rows("Name")[-1]` | значение `Name` в предпоследней обработанной строке | `_lm_upd_rows(_ri, "Name", -1)` |

Правила rewrite:

1. Паттерн `rows(<arg>)[<int>]` → `_lm_rows(_ri, <arg>, <int>)`, где `<arg>` — строковый литерал `"…"`, число или буква столбца.
2. Паттерн `rows(<arg>)` без индекса → `_lm_rows(_ri, <arg>, 0)`.
3. Паттерн `upd_rows(<arg>)[<int>]` → `_lm_upd_rows(_ri, <arg>, <int>)`.
4. Паттерн `upd_rows(<arg>)` без индекса → `_lm_upd_rows(_ri, <arg>, 0)`.
5. Rewrite — через AST (предпочтительно) или согласованный regex; не ломать строковые литералы и комментарии.
6. `_ri` — индекс строки данных (0-based относительно первой строки **после** заголовка) — подставляется closure при компиляции, **не** виден пользователю.

Поведение `_lm_rows(ri, col_token, row_offset)`:

- `target_ri = ri + row_offset`;
- если `target_ri < 0` или `target_ri >= n_data_rows` → `None` (или `""` — **зафиксировать: `None` → пустая ячейка**);
- разрешение `col_token`: как `_lm_pp_resolve_column_token` (имя заголовка, `'…'`, буква, 1-based индекс);
- значение ячейки — display-текст материализованной ячейки (`_lm_cell_display_text` / тот же путь, что `условный_столбец`; формулы источника читаются как значения);
- опционально числовой контекст: если оба операнда — числа после parse, арифметика Python; см. `result_type` (§4.4).

**Namespace eval** (дополнительно к `_lm_rows`):

- `re`, `datetime`, `date`, `timedelta` (как у фильтра листов);
- `len`, `str`, `int`, `float`, `round`, `min`, `max`, `abs`;
- `_lm_upd_rows`, `upd_rows_seen`, `upd_rows_count`, `upd_rows_len` — только если исполнитель работает по строкам последовательно и ведёт `upd_store`;
- **не** включать `sheet_name_date` / UNO в v1.

Примеры sugar → смысл:

```python
lambda rows: rows("Name") + " " + rows("Second_Name")
# текущая строка: склеить два столбца

lambda rows: rows("Qty") * rows("Price")
# произведение; при нечисловых — см. on_error / result_type

lambda rows: rows("Name")[-1] if rows("Name") == "" else rows("Name")
# если пусто — взять значение сверху (аналог fill-down логики)

lambda rows: not upd_rows_seen("ИНН", rows("ИНН"))
# первая строка по ИНН среди уже обработанных выше

lambda rows: upd_rows_len() == 0 or rows("Сумма") != upd_rows("Сумма")
# сумма отличается от последней обработанной строки
```

### 2.2. Лямбда имени столбца (`new_column_expr`)

**Опциональна.** Если задана — **игнорирует** литерал `new_column` (WARN в лог, если оба непустые).

Сигнатура sugar:

```text
lambda sheet, headers: <выражение → str>
```

| Аргумент | Тип | Описание |
| -------- | --- | -------- |
| `sheet` | str | имя текущего листа |
| `headers` | list[str] | заголовки столбцов data_range (слева направо) |

Вычисляется **один раз на лист** до цикла по строкам. Результат → `str.strip()`; пусто → ошибка.

Примеры:

```python
lambda sheet, headers: "Итого_" + sheet

lambda sheet, headers: headers[0] + "_copy"
```

Без sugar: обычный Python с теми же именами аргументов.

### 2.3. Лямбда выбора листов (`sheet_expr`)

**Опциональна.** Альтернатива / дополнение к `sheet` / `sheets`:

- если `sheet_expr` **пуст** — работает стандартный матчинг `sheet` / `sheets` (пусто = все листы результата);
- если **задан** — после начального списка кандидатов вызывается лямбда.

Сигнатура sugar:

```text
lambda sheets: <выражение>
```

| Аргумент | Тип | Описание |
| -------- | --- | -------- |
| `sheets` | list[str] | имена листов-кандидатов (книга или результат merge) |

Результат лямбды:

| Тип результата | Поведение |
| -------------- | --------- |
| `str` | один лист (имя должно быть в `sheets`) |
| `list` / `tuple` of str | подмножество листов |
| иное / пусто | ошибка валидации |

Примеры:

```python
lambda sheets: [s for s in sheets if s.startswith("Свод")]

lambda sheets: sheets[-1]

lambda sheets: s if (s := next((x for x in sheets if "лог" in x.casefold()), "")) else []
# walrus — только если пройдёт sanitizer; иначе классический for
```

Поля `sheet` / `sheets` при активном `sheet_expr` трактуются как **предфильтр** (сначала шаблоны / список, затем лямбда). Если оба пусты — в `sheets` передаётся полный список кандидатов.

**Не путать** с `filter` в `удаление_листов` (`lambda name: …` по одному имени) — здесь другая сигнатура (`sheets` — список).

## 3. Пайплайн компиляции

```text
исходный текст (expr | new_column_expr | sheet_expr)
  → parse_sheet_filter_code() / strip
  → rewrite_lambda_column_sugar(code, kind)   # новый helper в pythonpath
  → lm_sanitize_code_or_raise(policy=standard)
  → eval / exec в namespace kind-специфичный
  → callable
```

Отдельные функции (ориентир):

| Helper | Файл |
| ------ | ---- |
| `rewrite_lambda_column_sugar` | `libre_macros_lambda_column_lib.py` |
| `compile_lambda_column_expr` | там же |
| `compile_lambda_column_name` | там же |
| `compile_lambda_column_sheet_pick` | там же |
| `_lm_rows` | там же |
| `_lm_upd_rows` / `attach_upd_rows_helpers` | там же |

Ошибки компиляции / санации → сообщение в журнал с префиксом `столбец_по_лямбде:` и прерывание шага (или `on_error` на уровне листа — **зафиксировать: fail листа**).

## 4. Параметры (JSON, колонка C)

```json
[{
  "v": 1,
  "fn": "столбец_по_лямбде",
  "sheet": "Сводная",
  "new_column": "Полное_имя",
  "expr": "lambda rows: rows(\"Фамилия\") + \" \" + rows(\"Имя\")",
  "position": "_конец_",
  "on_error": "empty",
  "result_type": "auto"
}]
```

### 4.1. Общие поля листа

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `sheet` | string | Один лист; пусто — все (до `sheet_expr`) |
| `sheets` | string[] | Список листов / шаблонов |
| `sheet_expr` | string | Лямбда `lambda sheets: …` (§2.3) |
| `fn` | string | `столбец_по_лямбде` |

Поля `as_values` **нет** — функция всегда записывает значения, не формулы; материализация формул **источника** при чтении — обязательный внутренний шаг.

### 4.2. Столбец результата

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `new_column` | string | Имя столбца (обязателен, если нет `new_column_expr`) |
| `new_column_expr` | string | Лямбда `lambda sheet, headers: …` (§2.2) |
| `position` | string | `_начало_` \| `_конец_` \| `_перед_` \| `_после_` (default `_конец_`) |
| `relative_column` | string | Опорный столбец для `_перед_` / `_после_` |
| `output_policy` | string | `new` \| `replace` (default `new`) — как у `условный_столбец` |

### 4.3. Выражение

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `expr` | string | **Обязателен.** Основная лямбда (§2.1) |
| `lambda` | string | Алиас к `expr` (нормализация в кодеке → `expr`) |

Примеры:

```json
[{"v":1,"fn":"столбец_по_лямбде","new_column":"Первый_ИНН","expr":"lambda rows: rows(\"ИНН\") if not upd_rows_seen(\"ИНН\", rows(\"ИНН\")) else \"\""}]
[{"v":1,"fn":"столбец_по_лямбде","new_column":"Изм_сумма","expr":"lambda rows: rows(\"Сумма\") != upd_rows(\"Сумма\") if upd_rows_len() else True"}]
```

### 4.4. Ошибки и тип результата

| Поле | Default | Поведение |
| ---- | ------- | --------- |
| `on_error` | `empty` | при исключении в `expr` для строки: `empty` → пустая ячейка; `keep` → не менять (если столбец новый — пусто); `fail` → прервать лист |
| `result_type` | `auto` | `auto`: None → пусто; bool → `"Да"`/`"Нет"`; int/float → число; `date`/`datetime` → дата; иначе str; `text`: всегда str; `number`: parse или пусто |

### 4.5. Форматирование столбца (v1, без параметров в JSON)

Отдельных полей `format` / `as_values` в блоке **нет** — поведение фиксированное.

#### Чтение источника

Перед `getDataArray` — материализовать формулы в зоне данных (как у других in-memory PP). Это не опция пользователя: `rows("…")` всегда видит **значения**, не текст формул.

#### Тип столбца — по первому успешному значению

Обход строк данных сверху вниз; **первое** значение, для которого `expr` отработала без исключения и результат не `None` (пустая строка `""` **пропускается**, ищем дальше):

| Python-тип результата | Класс столбца | NumberFormat тела столбца |
| --------------------- | ------------- | ------------------------- |
| `int`, `float` (не `bool`) | `number` | `number_format` из **глобальных настроек** (`merge_global_settings.json` → `direct_options_from_global_settings` → `_direct_default_number_format`) |
| `datetime.date`, `datetime.datetime` | `date` | `default_date_format`; если есть компонента времени — `_direct_default_datetime_format()` |
| прочее (`str`, `bool`, …) | `text` | не менять (General / как после записи значения) |

Формат применяется **ко всему телу столбца** (строки данных `sr…er`) **одним** ключом — по типу первого «образцового» значения, даже если ниже встречаются другие типы (v1).

Если все строки пустые / только ошибки — тип `text`, NumberFormat тела не трогать.

Реализация: `_lm_pp_number_format_key(doc, fmt_string)` + `_lm_pp_apply_column_number_format_chunked` (как `применить_формулу` при явном `format`).

Источник строк формата:

```python
from libre_macros_global_settings_lib import direct_options_from_global_settings
# gs["number_format"], gs["default_date_format"]
# + libre_macros_direct_lib._direct_default_number_format / _direct_default_date_format
```

#### Формат заголовка — клон с соседа

Только **строка заголовка** (`header_row`), отдельно от тела:

1. Донор **справа**: столбец `target_col + 1`, если он существует в used area листа.
2. Иначе донор **слева**: столбец `target_col - 1`, если `target_col > 0`.
3. Скопировать визуальные свойства одной ячейки заголовка: `_lm_pp_copy_column_format_subrange(sheet, donor_col, target_col, h_sr, h_sr)`.

**Не** клонировать формат тела столбца с соседа (в отличие от `_lm_pp_finalize_derived_column` / `конкатенация_столбцов`): для данных — только автоформат по типу из §4.5.

При **перезаписи** существующего столбца (`output_policy=replace`) — заголовок не менять, если имя то же; формат заголовка не перекопировать.

## 5. Визард (`_SHEET_BLOCK_FORM_SCHEMAS`)

**Заголовок:** «Столбец по лямбде»  
**Кнопка:** «Параметры…» в постобработке RANGE / FINAL.

### 5.1. Поля формы

| Поле | Тип UI | Подпись | Примечание |
| ---- | ------ | ------- | ---------- |
| `new_column` | text | Имя столбца | обязательно, если нет expr имени |
| `new_column_expr` | text (multiline) | Имя столбца (лямбда) | hint: `lambda sheet, headers: …` |
| `expr` | text (multiline) | Выражение | обязательно; моноширинный шрифт желателен |
| `sheet_expr` | text (multiline) | Листы (лямбда) | опционально; `lambda sheets: …` |
| `position` | combo | Куда вставить | как у split / условный_столбец |
| `relative_column` | combo + headers | Опорный столбец | при `_перед_` / `_после_` |
| `on_error` | combo | При ошибке строки | пусто / не менять / стоп |
| `result_type` | combo | Тип результата | auto / текст / число |

Подсказка (hint):

```text
Аналог Power Query «Пользовательский столбец».
rows("Столбец") — значение в текущей строке; rows("Столбец")[-1] — в предыдущей.
В ячейки пишутся значения (не формулы). Числа и даты форматируются по глобальным настройкам
(тип — по первому вычисленному значению); стиль заголовка — с соседа справа или слева.
Код проверяется санацией; import и файлы запрещены. Calc-формулы на листе — «применить_формулу».
```

## 6. Валидация

1. Нет ни `expr`, ни алиаса `lambda` → ошибка.
2. Нет ни `new_column`, ни `new_column_expr` → ошибка.
3. `new_column` и `new_column_expr` оба непустые → WARN, приоритет у `new_column_expr`.
4. Sugar / Python не компилируется или не проходит санацию → ошибка с текстом sanitizer.
5. `sheet_expr` вернула имя вне кандидатов → ошибка.
6. Столбец из `rows("…")` не найден в заголовках → ошибка **на этапе compile** (статический список имён из sugar) или WARN + `None` на строке — **зафиксировать: ошибка compile, если имя в кавычках; буква/индекс — runtime None**.
7. `position` ∈ `{_перед_, _после_}` и `relative_column` не найден → ошибка.
8. `output_policy=replace` и столбец не найден → ошибка (или создать — **как у условный_столбец: создать при `new`**).
9. Циклическая зависимость: `new_column` совпадает с единственным источником в `expr` при первом создании — разрешено читать старые значения из снимка матрицы до записи (как `условный_столбец`).

DEBUG: лист, имя столбца, n_rows, n_errors, фрагмент rewrite (первые 200 символов).

## 10. Граничные случаи

| Случай | Ожидание |
| ------ | -------- |
| Первая строка данных, `rows("X")[-1]` | `None` → пустая ячейка |
| Столбец не найден | ошибка compile (имя в кавычках) |
| `expr` вернула `None` | пустая ячейка |
| Пустая строка `""` vs `None` | `""` записать как пустую строку |
| Формула в исходном столбце | читается материализованное значение |
| Первое значение — число, дальше текст | формат числа на весь столбец (v1) |
| Все значения пустые | формат тела не менять; заголовок — клон с соседа |
| Столбец в конце таблицы | заголовок — с `target_col - 1` |
| Столбец в середине | заголовок — с `target_col + 1` |
| Перезапись существующего `new_column` | значения заменены; заголовок не менять, если имя то же |
| Имя из `new_column_expr` совпало с существующим | перезапись значений |
| Объединённые ячейки | WARN; значение верхней-left |
| Очень длинный `expr` | OK; sanitizer по AST |
| Кириллица в `rows("Фамилия")` | OK; rewrite сохраняет Unicode |

## 11. Шаблоны готовых лямбд для пользователя

Ниже — короткие практические шаблоны для поля `expr`. Их можно копировать и адаптировать под свои заголовки.

### 11.1. Склейка двух столбцов

```python
lambda rows: str(rows("Фамилия") or "") + " " + str(rows("Имя") or "")
```

### 11.2. ФИО без лишних пробелов

```python
lambda rows: " ".join(x for x in [str(rows("Фамилия") or "").strip(), str(rows("Имя") or "").strip(), str(rows("Отчество") or "").strip()] if x)
```

### 11.3. Взять значение сверху, если текущая ячейка пуста

```python
lambda rows: rows("Статус") if str(rows("Статус") or "").strip() != "" else rows("Статус")[-1]
```

### 11.4. Пометка первого вхождения значения

```python
lambda rows: "первый" if not upd_rows_seen("ИНН", rows("ИНН")) else ""
```

### 11.5. Порядковый номер внутри уникальных значений

```python
lambda rows: upd_rows_count("Отдел", rows("Отдел")) + 1
```

### 11.6. Отметить изменение относительно предыдущей строки листа

```python
lambda rows: "изменилась" if rows("Статус") != rows("Статус")[-1] else ""
```

### 11.7. Отметить изменение относительно последней обработанной строки

```python
lambda rows: "новое значение" if upd_rows_len() == 0 or rows("Сумма") != upd_rows("Сумма") else ""
```

### 11.8. Разница с предыдущей строкой

```python
lambda rows: (float(rows("Сумма") or 0) - float(rows("Сумма")[-1] or 0)) if rows("Сумма")[-1] not in (None, "") else 0
```

### 11.9. Процент от другого столбца

```python
lambda rows: round(float(rows("Сумма") or 0) * 0.2, 2)
```

### 11.10. Флаг «пустая строка по ключевым полям»

```python
lambda rows: "пусто" if all(str(rows(c) or "").strip() == "" for c in ["ФИО", "Отдел", "Должность"]) else ""
```

### 11.11. Категория по порогу

```python
lambda rows: "крупный" if float(rows("Сумма") or 0) >= 100000 else "обычный"
```

### 11.12. Конкатенация с условием

```python
lambda rows: str(rows("Код") or "") + "-" + str(rows("Дата") or "") if str(rows("Код") or "").strip() != "" else ""
```

### 11.13. Нормализация телефона до цифр

```python
lambda rows: "".join(ch for ch in str(rows("Телефон") or "") if ch.isdigit())
```

### 11.14. Метка дубля

```python
lambda rows: "дубль" if upd_rows_seen("ИНН", rows("ИНН")) else ""
```

### 11.15. Нарастающий итог

```python
lambda rows: float(rows("Сумма") or 0) + (float(upd_rows("Нарастающий_итог") or 0) if upd_rows_len() else 0)
```

### Замечания к шаблонам

- `rows("Колонка")[-1]` — предыдущая строка **листа**.
- `upd_rows("Колонка")` — последняя **уже обработанная** строка выше.
- Для первой строки `rows(...)[-1]` и `upd_rows(...)` могут вернуть `None`.
- Для чисел безопаснее писать `float(... or 0)` или `int(... or 0)`.
- Если столбец результата ссылается сам на себя через `upd_rows("НовыйСтолбец")`, это допустимо для накопительных сценариев: каждая новая строка видит уже рассчитанные значения выше.

## 13. Ручная проверка (Calc)

1. Установить макросы; версия в журнале = текущая `MACRO_VERSION`.
2. Пример 7.1 — два столбца → склеенный ФИО.
3. Пример 7.2 — вторая строка повторяет «Статус» первой; первая — пусто.
4. Пример 7.3 — имя столбца по `headers[2]`.
5. Пример 7.4 — только листы «Свод*» получают столбец.
6. Повторный запуск — столбец не дублируется, значения пересчитаны.
7. `position=_после_` + `relative_column`.
8. FINAL — тот же JSON на финальном листе.
9. Битый `expr` — понятная ошибка санации в журнале.
10. Пример 7.5 — NumberFormat тела = `number_format` из глобальных настроек.
11. Столбец с `date`/`datetime` в первой непустой строке — `default_date_format`.
12. Новый столбец справа — заголовок визуально как у соседа слева; в конце таблицы — как у соседа слева.
13. (direct/xml) — те же значения и форматы, что UNO-ветка.
