# ТЗ: субвизард «Конструктор лямбда-выражения»

Общий вложенный диалог для сборки Python-лямбд с sugar (`rows` / `upd_rows` / …), без обязательного ручного набора кода. Результат — **исходный текст** выражения (как сейчас хранится в JSON), совместимый с `libre_macros_lambda_column_lib` / санацией / `<<Переменные.…>>`.

Связано с: [__новый_столбец_как_лямбда_выражениею.md](__новый_столбец_как_лямбда_выражениею.md), визарды `текстовые_операции` / `столбец_по_лямбде` / `замена_значений` / доп. фильтр источников, `_show_saved_lambda_manager_dialog`, профиль сохранённых лямбд.

---

## 1. Назначение

| Сейчас | Нужно |
|--------|--------|
| Однострочный/многострочный edit + combo сохранённых + «Сохранить» | То же **или** кнопка **«…» / «Конструктор»** → субвизард |
| Пользователь сам помнит sugar, кавычки у `<<Переменные>>`, `tr`, сигнатуру | Сборка из блоков: шаблон → столбцы → операторы → плейсхолдеры → проверка |
| Ошибки вроде `lambda rows: <<Переменные.X>>` (без кавычек) ловятся только на сборе | Предупреждение/автообёртка в конструкторе **до** OK |

**Цель:** снизить порог входа и число runtime-ошибок; не заменять power-user режим (сырой текст остаётся).

**Не цель v1:** визуальный Blockly / drag-and-drop AST; полноценный IDE; выполнение UNO/`doc`/`sheet` в лямбде.

---

## 2. Точки входа (потребители)

Субвизард вызывается из родительского визарда/формы; возвращает `(ok: bool, expr: str)`.

| Контекст | `kind` | Сигнатура / результат | Поля JSON |
|----------|--------|------------------------|-----------|
| `текстовые_операции` → **Лямбда фильтра** | `rows_predicate` | `lambda rows: …` → bool | `row_filter_lambda` |
| `текстовые_операции` → **Лямбда вычисления** | `rows_value` | `lambda rows: …` → text/number/bool→str | `ops[].expr` (`op=compute`) |
| `столбец_по_лямбде` → значение | `rows_value` | то же | `expr` |
| `столбец_по_лямбде` → имя столбца | `name` | `lambda sheet, headers: …` → str | `new_column_expr` |
| `создать_лист` / выбор листов | `sheets` | `lambda sheets: …` → str \| list | `sheet_name_expr` / `sheet_expr` |
| `замена_значений` / отбор строк | `rows_predicate` | как фильтр | filter-поля |
| доп. фильтр файлов | `file` | `lambda path/имя/…: …` → bool | `file_pick_lambda` |
| удаление/фильтр листов (имя) | `sheet_name` | `lambda name: …` → bool | `filter` |

v1 **обязательно:** `rows_predicate`, `rows_value`.  
v1 **желательно:** `sheets`, `name`.  
v2: `file`, `sheet_name` и прочие.

API (ориентир):

```python
def show_lambda_builder_dialog(
    parent_dialog,
    *,
    kind,                 # rows_predicate | rows_value | sheets | name | …
    initial_expr=u"",
    doc=None,
    sheet_name=u"",       # для списка заголовков
    headers=None,         # list[str] | None — если уже известны
    saved_lambdas=None,   # общий профиль
    title=None,           # override заголовка окна
):
    # → (True, expr) | (False, initial_или_пусто)
```

Родитель: кнопка рядом с edit лямбды (не вместо edit). После OK — подставить текст в edit и обновить pick сохранённых.

## 3. Режимы конструктора

В шапке субвизарда — combo **«Режим»** (или фиксирован вызывающим `kind`):

| Режим UI | `kind` | Что собираем |
|----------|--------|--------------|
| Фильтр строк | `rows_predicate` | условие True/False |
| Значение ячейки | `rows_value` | выражение → значение |
| Имя столбца | `name` | строка имени |
| Список листов | `sheets` | имя / список имён |
| … | … | по мере подключений |

При смене режима — предупреждение, если текст уже непустой и шаблон другой (не затирать молча).

## 4. UI (компактный, в стиле визардов проекта)

Окно: ширина ~560–640, высота по содержимому; `Sizeable=True`; peer через `_nested_subdialog_create_peer`.

### 4.1. Макет (сверху вниз)

1. **Краткая справка** (2–3 строки, `VerticalAlign=TOP`, без большого пустого поля): sugar, кавычки у переменных, `tr`.
2. **Режим** (если не зафиксирован) + **Шаблон** (combo пресетов).
3. **Сборка операндов** (основная зона):
   - слева: **Столбцы** — list/combo заголовков текущего листа (`columns_pick`-идеология: выбор → токен `'Имя'`);
   - кнопки вставки: `rows(…)`, `rows(…)[-1]`, `upd_rows(…)`, `upd_rows_seen`, `upd_rows_len`, `tr(…)`, `str(…)`, `.strip()`;
   - **Переменные** — combo имён из runtime/профиля карты (или подсказка `<<Переменные.name>>`) + кнопка **«Вставить в кавычках»** (обязательный безопасный путь) и опционально «как есть» (для чисел/уже в литерале).
4. **Операторы / предикаты** (для `rows_predicate`): `==`, `!=`, `>`, `<`, `in`, `not`, `and`/`or`, `пусто` / `непусто` (макросы → `.strip() == ""` / `!= ""`).
5. **Редактор выражения** — multiline edit (источник истины в диалоге); конструктор **дописывает** в позицию курсора или заменяет выделенное.
6. **Превью / проверка**:
   - кнопка **«Проверить»** → expand `<<Переменные>>` (если карта доступна) → sugar rewrite → sanitize → `compile_*`; сообщение OK / текст ошибки;
   - опционально v1.1: «пример на 1-й строке» при наличии `doc`+матрицы.
7. **Сохранённые** — тот же pick + «Сохранить…» → существующий `_show_saved_lambda_manager_dialog` (не дублировать менеджер).
8. Футер: **OK** / **Отмена** / **Справка** (`help_key`, напр. `лямбда_конструктор`).

### 4.2. Пресеты (`Шаблон`)

Пресеты зависят от `kind`. Примеры:

**`rows_predicate`:**

| Подпись | Черновик expr |
|---------|----------------|
| Столбец непустой | `lambda rows: str(rows("Столбец") or "").strip() != ""` |
| Столбец пустой | `lambda rows: str(rows("Столбец") or "").strip() == ""` |
| Значение = переменная | `lambda rows: tr(rows("Столбец")) == "<<Переменные.Имя>>"` |
| Смена группы | `lambda rows: rows("Столбец") != rows("Столбец")[-1]` |
| Уникальность (seen) | `lambda rows: not upd_rows_seen("Столбец", rows("Столбец"))` |
| Первая строка | `lambda rows: idx == 0` |
| Пустой / свой | `lambda rows: ` / текущий текст |

**`rows_value`:**

| Подпись | Черновик |
|---------|----------|
| Как есть (столбец) | `lambda rows: tr(rows("Столбец"))` |
| Trim + fallback | `lambda rows: tr(rows("Столбец") or "-").strip()` |
| Константа из переменной | `lambda rows: "<<Переменные.Имя>>"` |
| Склеить два столбца | `lambda rows: tr(rows("A")) + " " + tr(rows("B"))` |
| Пустой / свой | … |

Плейсхолдер `"Столбец"` / `"Имя"` в пресете после выбора реального столбца/переменной в UI **подменяется** (или подсвечивается как «замените»).

Константы пресетов — только в `pythonpath/*_cfg.py` (AO-фильтр entry-скриптов).

## 5. Правила вставки (важно)

1. **Заголовок столбца** из списка → в sugar всегда `rows('…')` / `rows("…")` с экранированием кавычек в имени.
2. **`<<Переменные.name>>`** по умолчанию вставлять **внутри строкового литерала**:
   - `"<<Переменные.name>>"` или `tr("<<Переменные.name>>")`;
   - отдельная кнопка «без кавычек» — только с явным предупреждением (для чисел / уже внутри `"…"`).
3. **`tr(…)`** — хелпер namespace: `None`→`""`, иначе unicode; рекомендовать в пресетах value/фильтров со `.strip()`.
4. Не вставлять `import`, UNO, обращение к `doc`/`sheet`.
5. Итоговая строка всегда начинается с `lambda …:` (или `def` — v2); если пользователь стёр сигнатуру — при OK предложить обернуть.

Подстановка переменных при **проверке/runtime** — как сейчас: `expand_source_variables_in_lambda_code` **до** compile (`for_formula=False`). Конструктор не меняет семантику expand, только UX кавычек.

## 6. Выходной контракт

- В JSON/родительский edit уходит **ровно** текст из редактора после OK (trim краёв, без принудительного pretty-print).
- Не сериализовать «дерево конструктора» в v1 — только expr string (обратная совместимость со всеми fn).
- Опционально позже: комментарий-маркер `# lm-builder:v1 …` — **не** в v1 (ломает sanitize/читаемость).

Валидация на OK:

| | Поведение |
|--|-----------|
| Пусто | для обязательных kind — запрет OK + сообщение |
| Не компилируется | запрет OK **или** «Всё равно» (pref: запрет + текст ошибки) |
| Предупреждение: плейсхолдер вне кавычек | диалог «исправить автоматически?» → обернуть в `"…"` |

Детект «плейсхолдер вне кавычек»: после грубого скана `<<…>>` не внутри `'`/`"` литерала (упрощённый парсер / regex с осторожностью).

## 7. Интеграция в существующие формы

### 7.1. Паттерн контролов (родитель)

Ряд лямбды:

`[Подпись] [Pick сохранённых] [Edit expr …………] [Сохранить] [Конструктор…]`

Или Edit на всю ширину, под ним кнопки. Не раздувать высоту `текстовые_операции` — компактные кнопки h=14–16.

### 7.2. Первые внедрения

1. `текстовые_операции`: **Лямбда вычисления** и **Лямбда фильтра**.
2. Sheet-block форма `столбец_по_лямбде` (поле `expr`).
3. Затем — остальные `lambda_*` / `expr` поля в `_SHEET_BLOCK_FORM_SCHEMAS` через единый `type: "lambda_expr"` (новый тип поля формы): edit + кнопки, `kind` из schema.

### 7.3. Код / файлы (ориентир)

| Что | Где |
|-----|-----|
| UI субвизарда | `param_wizard.py` → `_show_lambda_builder_dialog` (или тонкая обёртка + lib) |
| Пресеты, подписи кнопок, kind-мета | `libre_macros_param_wizard_cfg.py` |
| Compile/проверка | уже: `compile_rows_lambda` / `compile_lambda_column_*` |
| Сохранённые | `libre_macros_wizard_profile_lib.py` + существующий менеджер |
| Справка | `libre_macros_wizard_help_cfg.py` |

Логику пресетов/детекта кавычек по возможности вынести в `pythonpath/libre_macros_lambda_builder_lib.py`, чтобы не раздувать entry.

## 8. Заголовки и контекст листа

- Если родитель передал `sheet_name` / `headers` — использовать их.
- Иначе: активный лист документа / первый лист блока / пустой список + ручной ввод имени столбца.
- Кнопка **«Обновить столбцы»** при смене листа в родителе не обязательна в v1 (headers фиксируются на open).

Имена переменных для combo: из `_MERGE_SOURCE_VARIABLES_MAP` / order при открытом сборе; в режиме «только визард параметров» — из профиля / ручной ввод имени.

---

## 9. Критерии приёмки

1. Из `текстовые_операции` открывается конструктор для фильтра и для compute; OK подставляет expr в поле.
2. Пресет «Константа из переменной» даёт `lambda rows: "<<Переменные.…>>"`; сбор на листе `Для_Фильтра` заполняет столбец без `name '…' is not defined`.
3. Вставка столбца из списка даёт `rows("…")` с корректными кавычками.
4. «Проверить» ловит синтаксис/санацию до OK.
5. «Сохранить» / pick сохранённых работают как сейчас (общий список профиля).
6. Сырой edit в родителе по-прежнему редактируем вручную; конструктор не обязателен.
7. AO: константы не на уровне entry-модуля; flatten + `aoffice_compat_check` зелёные для затронутых скриптов.
8. Автотесты pytest **не** писать; проверка вручную в LibreOffice Calc.

---

## 11. Вне объёма v1

- Генерация лямбды с ИИ.
- Отдельное хранение AST конструктора в JSON.
- Поддержка произвольного Python без сигнатуры sugar.
- Изменение семантики `expand_source_variables` (автокавычки на runtime) — спорно; предпочтение UX в конструкторе, не тихая магия в expand (ломает числовые подстановки).

## 12. Примеры целевых выражений

```text
lambda rows: "<<Переменные.Фильтр_по_подразделению>>"

lambda rows: tr(rows("Фильтр_по_подразделению") or "").strip() or "<<Переменные.Фильтр_по_подразделению>>"

lambda rows: str(rows("Наименования Атрибутов") or "").strip() != ""

lambda rows: not upd_rows_seen("ИНН", rows("ИНН"))

lambda rows: tr(rows("Фамилия") or "") + " " + tr(rows("Имя") or "")
```
