# Постобработка «Разделение»

## Назначение

Параметр **`разделить_листы`** предназначен для разделения листа книги LibreOffice Calc на листы и/или книги по триггеру изменения значений указанных в настройках полей.

Параметр аналогичен **`ВПР`** и **`объединить_листы_в_один`** в части интеграции в unified pipeline (`processing_pipeline`, `kind=split_sheets`): отдельная строка A, JSON только в C, segment-splitter фазы диапазона (см. `docs/10_MERGE_ALGORITHM.md`, `docs/15_PARAM_REFERENCE.md`).

Настройка выполняется на листе **`Параметры_Объединения*`** (активный лист группы).

| Колонка | Значение |
| ------- | -------- |
| A | `разделить_листы` |
| B | обычно пусто (не ключ «Постобработка_Диапазон») |
| C | JSON с параметрами |

Редактирование — через визард (`param_wizard`, режим `split_sheets`), по аналогии с **`ВПР`** и **`объединить_листы_в_один`**.

Кодек: `libre_macros_param_codec.py` (`param_decode` / `param_encode`, только JSON).

Ниже — расхождения исходного черновика с текущей архитектурой и принятые правила для реализации.

| ---- | ---------------- | ------------- |

| Маркер книги | `эта_книга` в шаблоне | **`эта_книга`** (регистр не важен; в UI — «Эта книга», как у `Файлы-Источники`) |
| Пустой ключ | `__ПУСТО__` (разный регистр) | **`__ПУСТО__`** — как составные ключи ВПР (`_lm_vlookup_key_part`) |
| Подстановки | `ReplaceFields()` | общая функция в `pythonpath/` (snake_case, напр. `_lm_replace_fields`) |
| Нормализация имён | `NormalizePathComponent()` | общая функция в `pythonpath/` (snake_case) |
| Wizard | «аналогичен сводной таблице» | UX ближе к **`объединить_листы_в_один`** / **ВПР** (отдельный поддиалог, не `SheetBlockGrid` постобработки) |
| Этап выполнения | не задан | **`run_phase`** — явная точка запуска (см. ниже) |
| `header_row` | не описан | **1-based**, строка заголовков на листе-источнике (как у merge / ВПР) |
| `xml_excel_ods` | не описан | только **`run_phase=after_final`** (UNO после финала); иные фазы — ошибка валидации / визард не даёт выбрать |
| Порядок на листе | подразумевалась только сортировка данных | при `run_phase=after_postprocess` сохраняется **позиция строки** в pipeline относительно range / ВПР / merge (splitter) |
| Legacy | — | `fn=разделить_листы` под **`Финальная_обработка`** (B) — legacy; рекомендуемый UX — строка **A** |

## Параметры

Пример JSON (канонический формат хранения в C):

```json
[
    {
        "v": 1,
        "fn": "разделить_листы",
        "run_phase": "after_postprocess",
        "source": {
            "book": "эта_книга",
            "sheet": "Общий"
        },
        "split_books": ["Организация"],
        "split_sheets": ["Подразделение", "Участок"],
        "header_row": 1,
        "pre_sort": true,
        "book_template": "./Reports/[Организация].ods",
        "sheet_template": "[Подразделение]-[Участок]",
        "split_mode": "copy_range",
        "paste_formats": false,
        "copy_header": true,
        "create_folders": true,
        "overwrite_sheets": true,
        "append_if_exists": false,
        "save_immediately": false
    }
]
```

## Параметры JSON

### run_phase

**Точка запуска** разделения относительно мacro-этапов сбора (`collect_workbooks`).

Допустимые значения:

| Значение | Когда выполняется | Типичный сценарий |
| -------- | ----------------- | ----------------- |
| `after_collect` | После **первичного сбора** (копирование данных, «Ячейка_В_Столбец», `удаление_верхних_строк`), **до** встроенного оформления и pipeline постобработки | Разделить «сырой» лист до сетки/зебры/сортировок |
| `after_postprocess` | После **постобработки** (pipeline: range ↔ splitters ↔ row), **до** `Финальная_обработка` | **По умолчанию.** Данные уже оформлены; при этом строка A сохраняет **позицию splitter'а** среди шагов range (как ВПР / merge) |
| `after_final` | После **`Финальная_обработка`** (материализация сводных, финальные шаги по книге) | Разделение «готового» отчёта перед выдачей пользователю |

Правила:

* Значение по умолчанию — **`after_postprocess`**.
* При **`after_postprocess`**: шаг участвует в `processing_pipeline` (`kind=split_sheets`); порядок относительно `Постобработка_Диапазон` / `ВПР` / `объединить_листы_в_один` задаётся **номером строки** на листе параметров (как у других splitter'ов).
* При **`after_collect`** и **`after_final`**: шаг **не** выполняется внутри range-фазы pipeline; запуск откладывается до соответствующей macro-фазы. Порядок нескольких строк `разделить_листы` с одним `run_phase` — по номеру строки на листе.
* Несколько блоков в C одной строки (массив JSON) — **не поддерживается** на v1: один блок на строку A (как у merge / ВПР в JSON-режиме).

Примеры:

```
after_collect
after_postprocess
after_final
```

Примеры

эта_книга
```

---

### source.sheet

Имя листа-источника в **книге результата** сбора.

---

### header_row

Строка заголовков на листе-источнике (**1-based**, как в Calc и у `объединить_листы_в_один`).

* Используется для поиска колонок в `split_books` / `split_sheets` по **имени заголовка**.
* Пусто — авто (первая строка данных диапазона / `_merge_result_header_row`).
* При `copy_header=true` эта строка копируется в каждый результирующий лист.

---

### split_books

Список полей (имена столбцов по заголовку), изменение совокупности значений которых приводит к созданию новой книги по `book_template`.

Если совокупное значение пусто — ключ **`__ПУСТО__`** (как у ВПР).

Если `book_template` = `эта_книга`, то `split_books` **игнорируется** — разделение только по листам в текущей книге.

Порядок полей имеет значение.

Примеры:

```
["Организация"]
```

или

```
["Регион", "Организация"]
```

---

### split_sheets

Список полей, изменение совокупности значений которых приводит к созданию нового листа.

Если совокупное значение пусто — ключ **`__ПУСТО__`**.

Порядок полей имеет значение.

Например:

```
["Подразделение", "Участок"]
```

---

### book_template

Определяет, в какую книгу помещаются результаты разделения.

Допустимые значения:

* **`эта_книга`** — результаты в текущей книге результата; новые файлы не создаются; `split_books` игнорируется.
* Путь или шаблон пути к новой книге (относительно каталога книги параметров, как у `Файлы-Источники`).

Подстановки: `[ИмяКолонки]` — значение из текущей строки данных.

Примеры:

```
эта_книга
./Reports/[Организация].ods
D:\Reports\[Год]\[Организация].xlsx
```

При шаблоне пути: при смене ключа по `split_books` создаётся или открывается соответствующая книга. Для **первой** строки данных ключ считается изменённым.

```

Например

```
[Подразделение]
```

или

```

```

---

### split_mode

Способ формирования результата.

Допустимые значения:

#### copy_range

Создаётся новый лист. Копируются оформление листа, ширины столбцов, необходимые свойства; затем переносятся только строки текущего блока.

**Рекомендуемый режим по умолчанию** (`split_mode: "copy_range"`).

Преимущества: скорость, малый расход памяти, много блоков.

Опционально (`paste_formats: true`): после заполнения каждого листа-блока —
скопировать **первую строку данных** источника в буфер и выполнить спецвставку
**только форматов** (`InsertContents` Flags=`T`) на диапазон данных нового листа.

#### copy_sheet

Полностью копируется исходный лист; затем удаляются строки вне текущего блока.

Преимущества: максимальное сохранение оформления (страница, объединения, УФ, формулы).

Недостатки: память и время при большом числе листов.

---

### pre_sort

Предварительно отсортировать исходный лист по `split_books`, затем по `split_sheets` (по возрастанию).

Если `false`, данные должны быть **уже отсортированы** (см. алгоритм).

---

### copy_header

Копировать строку заголовков (`header_row`) в каждый результирующий лист.

---

### create_folders

Автоматически создавать отсутствующие каталоги для `book_template`.

---

### overwrite_sheets

Перезаписывать существующие листы (очистка / замена содержимого).

---

### append_if_exists

Если книга уже существует — дописывать новые листы (не пересоздавать файл целиком).

---

### save_immediately

`true` — сохранять каждую целевую книгу сразу после записи блока; `false` — сохранить все открытые книги по завершении шага.

## Очистка имен

После подстановки все имена должны быть очищены от недопустимых символов.

### Имя листа

Удаляются или заменяются символы

```text
: \ / ? * [ ]
```

При необходимости длина имени ограничивается значением, совместимым с Excel (31 символ).

---

### Компоненты пути и имя файла

Очистка должна учитывать используемую операционную систему.

#### Linux

Запрещен символ

```text
/
```

#### Windows

Запрещены символы (в коде ниже — литералы, не HTML):

```text
< > : " / \ | ? *
```

а также зарезервированные имена

```text
CON
PRN
AUX
NUL
COM1...COM9
LPT1...LPT9
```

Рекомендуется единая функция в `pythonpath/` (например ``_lm_normalize_path_component(name, kind="sheet"|"path")``) с учётом платформы.

## Алгоритм работы

### Привязка к этапам сбора

```text
Сбор данных → [run_phase=after_collect] → оформление → pipeline постобработки
    → [run_phase=after_postprocess] → Финальная_обработка → [run_phase=after_final]
```

Исходный диапазон должен быть отсортирован по полям разделения (или включить `pre_sort`).

Порядок ключей сортировки:

```
split_books… → split_sheets…
```

Во время прохода по строкам вычисляются два составных ключа (разделитель `|`, как у ВПР).

#### Ключ книги

Из полей `split_books`. Пример: `Организация` или `Регион|Организация`.

#### Ключ листа

Из полей `split_sheets`. Пример: `Подразделение|Участок`.

При изменении ключа книги:

* сохраняется предыдущая книга;
* при необходимости открывается существующая либо создается новая книга.

При изменении ключа листа:

* создается новый лист;
* либо открывается существующий лист согласно настройкам.

После этого текущая строка переносится в целевой лист.

После завершения обработки сохраняются все открытые книги либо каждая сразу (`save_immediately`).

Журнал: лист «Сбор_книг_лог» (`append_collect_log` / `_merge_log_postprocess` / `_merge_log_final_processing` в зависимости от `run_phase`).

## Способы переноса данных

### copy_range

1. Создается новый лист.
2. Копируется оформление листа-источника.
3. Копируются ширины столбцов.
4. При необходимости копируются высоты строк и другие свойства листа.
5. Переносятся только строки, принадлежащие текущему блоку.

Данный режим рекомендуется использовать по умолчанию как наиболее быстрый и экономичный по памяти.

---

### copy_sheet

1. Полностью копируется исходный лист.
2. После копирования удаляются строки, не принадлежащие текущему блоку.

Этот режим обеспечивает максимально полное сохранение оформления, но требует значительно больше памяти и времени.

## Рекомендуемая архитектура

Разделение на модули в `pythonpath/` (entry-скрипты — тонкие обёртки, см. правила AO 2026):

| Компонент | Модуль (черновик) | Назначение |
| --------- | ----------------- | ---------- |
| Кодек JSON | `libre_macros_param_codec.py` | `_normalize_split_sheets_block`, валидация `run_phase` |
| Оркестрация | `libre_macros_split_lib.py` (новый) | `lm_split_sheets_run(doc, spec, run_context)` |
| Подстановки | общий helper | `_lm_replace_fields` |
| Имена / пути | общий helper | `_lm_normalize_path_component`, `_lm_sanitize_sheet_name` |
| Книги | split_lib | открытие / создание / save по `book_template` |
| Листы | split_lib | create / overwrite / append |
| Перенос | split_lib | `copy_range` / `copy_sheet` |
| Точки вызова | `collect_workbooks.py` | хуки после collect / в pipeline / после final |

Точки вызова в `collect_workbooks.py`:

1. **`after_collect`** — после `Ячейка_В_Столбец` и `удаление_верхних_строк`, до `apply_result_sheet_formatting`. В этом случае если листы результата разделения попадают в эту же книгу 
их надо включить во все пайплайны обработки
2. **`after_postprocess`** — в `_apply_book_pipeline_range_phase` (текущий splitter) **или** отложенно после row-фазы, если строка стоит после всех `Постобработка_Строка` *(уточнить при реализации: «после постобработки» = после всего pipeline, а не только range)*.
В этом случае если листы результата разделения попадают в эту же книгу 
их надо включить в пайплайн финальной обработки.
3. **`after_final`** — в `_merge_run_final_processing_phase` после прочих шагов финала.
