# ТЗ: нормализация_текста

Новая функция постобработки / финальной стадии (RANGE + FINAL; по возможности `Постобработка_xml`).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`) + **стек подфункций** `ops[]`.

**Имя ключа (fn):** `нормализация_текста`  
**Синонимы / алиасы (опционально):** `нормализовать_текст`, `normalize_text`.  
**Lib:** `lm_pp_range_normalize_text` / `merge_final_normalize_text`  
**Цель:** в указанных столбцах зоны данных листа результата **последовательно** применить стек текстовых преобразований к каждой ячейке (как pipeline Power Query / «очистка текста»).

Заголовок **не** обрабатывается. Нетекстовые ячейки (числа, даты, пустые) — по политике `non_text` (default: пропуск). Формулы перед обработкой материализуются при `as_values: true` (default).

Близкий overlap с `замена_значений` (`squeeze_spaces`, токены `_РЕГИСТР_*_`): эта функция **не заменяет** замену по find/replace, а даёт явный стек нормализаций; общие хелперы (`strip` / `\s+` → один пробел) — переиспользовать из lib, не дублировать логику в двух местах без нужды.

---



## 1. Принцип работы

1. Определить **область данных** (`data_range` + `header_row_range` от хоста).
2. Отфильтровать листы по `sheet` / `sheets` (стандартный матчинг: имя / индекс / префикс `N_` у копий).
3. Разобрать `columns` (имена / буквы / индексы относительно data_range). Пустой список → ошибка валидации (в отличие от «все столбцы» у дедупа: нормализация «всего» опасна).
4. Для каждой ячейки тела в выбранных столбцах:
  - получить текстовое представление (`cell_text` / строка после `as_values`);
  - если ячейка пустая / не текст — см. `non_text`;
  - прогнать **упорядоченный** стек `ops[]` слева направо;
  - записать результат **inplace** в ту же ячейку (v1).
5. Журнал: лист, столбцы, число ячеек обработано / пропущено / ошибок по op.

Порядок строк A в секции постобработки (несколько блоков с одним `fn`) — как у прочих PP: сверху вниз. Внутри одного блока главный UX — `ops`.

## 2. Стек подфункций (`ops`)

Каждый элемент — объект:

```json
{"op": "<имя>", …параметры op…}
```

Допустимо краткое строковое сокращение `"trim"` ≡ `{"op":"trim"}` (визард всегда пишет объект).

Пустой `ops` → ошибка валидации. Неизвестный `op` → ошибка. Ошибка внутри одной ячейки (например, битый base64):


| `on_error`       | Поведение                                                                                                                                |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `keep` (default) | Оставить исходное значение ячейки (или значение **до** упавшего op — зафиксировать: **до упавшего op**, уже применённые ops сохраняются) |
| `skip_cell`      | Как `keep` + счётчик в логе                                                                                                              |
| `empty`          | Записать пустую строку                                                                                                                   |
| `stop`           | Прервать функцию по листу с ошибкой в журнале                                                                                            |


Рекомендация v1: `on_error` на уровне блока; при необходимости позже — per-op `on_error`.

### 2.1. Каталог `op` (v1)



#### 1. `trim` — обрезать края

Убрать все **пробельные** символы (`str.strip` / Unicode whitespace) слева и справа. Внутри строки не трогать.

Параметров нет.

#### 2. `collapse_ws` — края + схлопывание внутри

1. `strip` краёв;
2. любая последовательность пробельных символов (`\s+`, включая NBSP `\u00A0`, таб, перевод строки) → **один** обычный пробел `U+0020`.

Алиас в UI: «Убрать лишние пробелы».  
Синоним JSON: `squeeze_spaces` (для родства с `замена_значений`).

Параметры:


| Поле       | Default | Смысл                                                 |
| ---------- | ------- | ----------------------------------------------------- |
| `to_space` | `" "`   | На что заменять серии whitespace (обычно один пробел) |




#### 3. `case` — регистр (как Power Query / Excel)


| `mode`                  | Поведение                                                                        |
| ----------------------- | -------------------------------------------------------------------------------- |
| `lower`                 | весь текст в нижний регистр                                                      |
| `upper`                 | весь текст в верхний                                                             |
| `proper` / `capitalize` | каждое слово с заглавной (Unicode word boundaries; пробелы как разделители)      |
| `sentence`              | первая буква предложения заглавная, остальное lower (простая эвристика по `.?!`) |
| `toggle`                | инверсия регистра каждого символа (a↔A)                                          |


Обязателен `mode`. Локаль: Unicode `casefold`/`upper`/`lower` Python3; для кириллицы — стандартное поведение Python (без турецкой i-логики в v1).

#### 4. `lang_homoglyphs` — языковая нормализация омоглифов

**Шаг A — определить доминирующий язык ячейки** среди `{ru, en}`:

- Считать «буквенные» символы: латиница `A-Za-z`, кириллица `А-Яа-яЁё`.
- Доля RU = (число кириллических) / (число буквенных); EN аналогично.
- Язык = `ru`, если доля RU ≥ доли EN; иначе `en`.
- Если буквенных символов **0** — op no-op (вернуть как есть).
- Параметр `min_letter_ratio` (default `0.0`): если доля букв в тексте ниже порога — no-op (защита коротких кодов/артикулов). 

**Шаг B — замена одиночных омоглифов неосновного алфавита:**

Таблица пар «одинаковое / близкое начертание» (минимум v1):


| Латиница | Кириллица |
| -------- | --------- |
| `a`/`A`  | `а`/`А`   |
| `c`/`C`  | `с`/`С`   |
| `e`/`E`  | `е`/`Е`   |
| `o`/`O`  | `о`/`О`   |
| `p`/`P`  | `р`/`Р`   |
| `x`/`X`  | `х`/`Х`   |
| `y`      | `у`       |
| `K`      | `К`       |
| `M`      | `М`       |
| `T`      | `Т`       |
| `B`      | `В`       |
| `H`      | `Н`       |


Регистр целевого символа = регистр исходного (латинская `A` → кириллическая `А`).

**Правило «одиночный»:** символ неосновного алфавита заменяется, если он **не образует run длины ≥ 2** подряд из того же неосновного алфавита.

Примеры (доминирует RU):


| Вход                          | Выход                                                                      | Почему                                                |
| ----------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------- |
| `aвтомат`                     | `автомат`                                                                  | одиночная лат. `a`                                    |
| `сaйт`                        | `сайт`                                                                     | одиночная `a`                                         |
| `USB-порт`                    | `USB-порт`                                                                 | run `USB` (латиница ≥2) не трогать; `-порт` кириллица |
| `iPhone` при RU-доминировании | зависит от долей; при смешанном коротком токене — см. `protect_latin_runs` |                                                       |


Параметры:


| Поле                 | Default | Смысл                                                                                        |
| -------------------- | ------- | -------------------------------------------------------------------------------------------- |
| `extended_pairs`     | `false` | расширенная таблица пар                                                                      |
| `protect_latin_runs` | `true`  | не трогать непрерывные латинские runs ≥ 2 (и симметрично кириллические при доминировании EN) |
| `force_lang`         | `null`  | `ru` | `en` — не определять по долям, всегда этот язык                                       |


Граница v1: только RU↔EN омоглифы; греческий / прочие — вне scope.

#### 5. `reverse` — перевернуть символы

`s[::-1]` по Unicode code points (не grapheme clusters в v1 — зафиксировать; для emoji/комбинирующих — известное ограничение).

Параметров нет.

#### 6. `base64_encode`

Текст ячейки → UTF-8 bytes → Base64 (ASCII string).  
Параметр `urlsafe` (default `false`): `urlsafe_b64encode` без переносов.

#### 7. `sha256`

SHA-256 от UTF-8 текста → hex (64 символа). Опционально `format`: `hex` (default) | `base64`.

#### 8. `base64_decode`

Base64 → UTF-8 строка.  
Пробелы/переносы в входе игнорировать (strip + убрать whitespace).  
При ошибке декодирования — `on_error` блока.  
`urlsafe` (default `auto`): пробовать стандартный, затем urlsafe.

**Политика:** реализация **только** во встроенной lib (`pythonpath`), не в user-eval / `functions_pp.py` плагинах — sanitize запрещает `base64` в пользовательском коде (`docs/16_CODE_SANITIZE.md`).

#### 9. `encrypt` / `decrypt` — симметричное шифрование с ключом

Назначение: обратимое сокрытие текста столбца (не «военный» crypto).

**Алгоритм v1 (рекомендация):** Fernet (`cryptography`) **или** простой AES-128-CBC + HMAC, если зависимость тяжёлая для AO — зафиксировать при реализации один вариант и версию формата префикса, например:

```text
lm1:<base64 ciphertext>
```

чтобы `decrypt` отличал «уже шифр» от обычного текста.

Ключ задаётся одним из способов (приоритет сверху вниз, взаимоисключающие поля — ошибка если задано >1):


| Поле       | Формат          | Смысл                                                 |
| ---------- | --------------- | ----------------------------------------------------- |
| `key`      | string          | литерал ключа / пароля                                |
| `key_cell` | string | object | ссылка на ячейку **книги результата**                 |
| `key_file` | string          | путь к текстовому файлу (первая строка = ключ; UTF-8) |


Форматы `key_cell`:

- строка как в формулах: `"Секреты!B2"`, `"Параметры_Объединения!C10"`;
- объект: `{"sheet":"Секреты","cell":"B2"}` или `{"sheet":"…","col":2,"row":2}` (1-based как в UI).

Если лист в ссылке не указан — активный / текущий лист постобработки.

Вывод ключа из пароля: `SHA-256(password)[:32]` (или PBKDF2 при `kdf: "pbkdf2"` — v1.1).  
Параметр `encoding` результата encrypt: всегда текстовая оболочка `lm1:…` в ячейке.

**Политика безопасности (явно в UI):**

- ключ и ciphertext попадают в книгу / JSON параметров — не для секретов высокой ценности;
- только встроенная lib; не логировать ключ в DEBUG целиком (маскировать).

## 3. Параметры блока (JSON, колонка C)

```json
[{
  "v": 1,
  "fn": "нормализация_текста",
  "sheet": "Сводная",
  "columns": ["ФИО", "Комментарий"],
  "ops": [
    {"op": "trim"},
    {"op": "collapse_ws"},
    {"op": "case", "mode": "proper"},
    {"op": "lang_homoglyphs"}
  ],
  "as_values": true,
  "non_text": "skip",
  "on_error": "keep"
}]
```

Пример со стеком «очистка → шифр»:

```json
[{
  "v": 1,
  "fn": "нормализация_текста",
  "sheet": "Сводная",
  "columns": ["Паспорт"],
  "ops": [
    {"op": "trim"},
    {"op": "encrypt", "key_cell": "Секреты!B1"}
  ]
}]
```



### 3.1. Общие поля


| Поле               | Тип           | Описание                                                                 |
| ------------------ | ------------- | ------------------------------------------------------------------------ |
| `fn`               | string        | `нормализация_текста`                                                    |
| `sheet` / `sheets` | string / list | фильтр листов; пусто — все                                               |
| `columns`          | list          | столбцы для обработки (**обязательно**, ≥1)                              |
| `ops`              | list          | упорядоченный стек подфункций (**обязательно**, ≥1)                      |
| `as_values`        | bool          | default `true` — формулы → значения до обработки                         |
| `non_text`         | string        | `skip` (default) | `coerce` (привести к тексту) | `error`                |
| `on_error`         | string        | `keep` | `skip_cell` | `empty` | `stop`                                  |
| `empty_cells`      | string        | `skip` (default) | `process` (гнать ops и по пустым — обычно бесполезно) |




### 3.2. Поля элементов `ops`

См. §2.1. Общие для всех: `op` (обязательно).

## 4. Визард

Форма sheet-block (`_SHEET_BLOCK_FORM_SCHEMAS`):

1. **Лист** — стандартный picker `sheet` / все.
2. **Столбцы** — `columns_pick` (мультивыбор по заголовкам активного превью).
3. **Стек операций** — новый тип поля UI `ops_stack`:
  - список строк: иконка/имя op + краткие параметры;
  - кнопки **Добавить** / **Удалить** / **Выше** / **Ниже**;
  - двойной клик / «Изменить» — мини-диалог параметров op (`case.mode`, `encrypt.key_*`, …);
  - каталог «Добавить»: пункты §2.1 с человекочитаемыми RU-подписями:


| `op`              | Подпись в UI              |
| ----------------- | ------------------------- |
| `trim`            | Обрезать пробелы по краям |
| `collapse_ws`     | Убрать лишние пробелы     |
| `case`            | Регистр…                  |
| `lang_homoglyphs` | Омоглифы RU/EN            |
| `reverse`         | Перевернуть текст         |
| `base64_encode`   | Base64: кодировать        |
| `base64_decode`   | Base64: декодировать      |
| `sha256`          | SHA-256                   |
| `encrypt`         | Зашифровать               |
| `decrypt`         | Расшифровать              |


1. Чекбоксы/комбо: `as_values`, `non_text`, `on_error` (можно в «Дополнительно»).

Без нового виджета `ops_stack` v1 можно временно править JSON вручную в C — нежелательно; заложить виджет в объём реализации.

## 6. Валидация

1. Нет `columns` / пустой список → ошибка.
2. Столбец не найден в data_range → ошибка.
3. Пустой `ops` → ошибка.
4. Неизвестный `op` или `case` без `mode` → ошибка.
5. У `encrypt`/`decrypt` не задан ни один источник ключа → ошибка.
6. Задано >1 из `key` / `key_cell` / `key_file` → ошибка.
7. `key_cell` / `key_file` не резолвится (нет листа, пустая ячейка, нет файла) → ошибка до обхода ячеек.
8. `non_text=error` и встречена нетекст → ошибка / `on_error`.
9. Нет строк данных → предупреждение, skip.

DEBUG: лист, columns, ops summary, обработано/пропущено/ошибок; ключ **не** печатать.

## 7. Примеры сценариев



### 7.1. ФИО: пробелы + proper + омоглифы

**Вход:** `aлександров  иван`

```json
[{
  "v": 1,
  "fn": "нормализация_текста",
  "sheet": "Сводная",
  "columns": ["ФИО"],
  "ops": [
    {"op": "collapse_ws"},
    {"op": "lang_homoglyphs"},
    {"op": "case", "mode": "proper"}
  ]
}]
```

**Выход:** `Александров Иван`

### 7.2. Только trim краёв

```json
"ops": [{"op": "trim"}]
```

 `текст`  → `текст`; внутренние двойные пробелы сохраняются.

### 7.3. Base64 round-trip

```json
"ops": [
  {"op": "base64_encode"},
  {"op": "base64_decode"}
]
```

Должно вернуть исходный Unicode-текст (модуль нормализации whitespace у encode нет).

### 7.4. Шифр столбца ключом из ячейки

```json
[{
  "v": 1,
  "fn": "нормализация_текста",
  "columns": ["Секрет"],
  "ops": [
    {"op": "trim"},
    {"op": "encrypt", "key_cell": "Ключи!A1"}
  ]
}]
```

Обратно: тот же `key_cell` + `{"op":"decrypt", …}`.

## 9. Вне scope / позже

- Grapheme-aware `reverse`, нормализация Unicode NFKC как отдельный op.

- Асимметричное шифрование, хранение ключей в OS keyring.
- Запись результата в другой столбец / лист (`output` как у дедупа) — при необходимости v1.1 (`dest_column`).
- Per-op `on_error`, условные ops (`if_lang`).
- Плагинные пользовательские ops через `functions_pp.py` — только если sanitize позволит; иначе нет.
