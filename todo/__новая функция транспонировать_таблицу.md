# ТЗ: транспонировать_таблицу

**Статус:** реализовано (UNO RANGE/FINAL с **3.10.694**; `result_headers` — **3.10.695**; подробная справка визарда — **3.10.696**). Xml-фаза — этап 2 (вне v1).

Новая функция постобработки / финальной стадии (как остальные RANGE/ROW/FINAL и при необходимости `Постобработка_xml`).
Визард: стандартно — блок на все листы или на выбранный лист (`sheet` / `sheets`).

**Имя ключа (fn):** `транспонировать_таблицу`  
**Цель:** перевернуть прямоугольный диапазон данных на листе (строки ↔ столбцы) и записать результат по выбранным правилам.

Документация: [docs/05_POSTPROCESS.md](../docs/05_POSTPROCESS.md), [docs/13_JSON_PARAMS.md](../docs/13_JSON_PARAMS.md), [docs/15_PARAM_REFERENCE.md](../docs/15_PARAM_REFERENCE.md).
Сценарий: `test/collect_workbooks/workbooks/16_transpose_table.xltx`.

---

## 1. Принцип работы

1. Определить **область-источник** на листе результата:
   - либо явный диапазон (`range` / углы),
   - либо «использованный» прямоугольник от строки заголовков / первой строки данных до последней непустой (как у других функций по UsedArea / эвристике листа).
2. Прочитать значения в память (предпочтительно одним `getDataArray` / аналог в xml-фазе).
3. Построить **матрицу-транспонирование**: `out[c][r] = in[r][c]` (0-based в памяти).
4. Записать результат согласно режиму вывода (на месте / новый лист / сдвиг).
5. Пустые ячейки сохраняются как пустые; типы (число/дата/текст) по возможности не ломать (UNO: Value/String; xml: типы ячеек openpyxl/odf).
6. Форматирование (ширины, стили ячеек) **по умолчанию не копируется** — только значения; опциональный флаг `with_formatting` (если реализуемо без лишней сложности; иначе — только значения + запись в лог «форматирование не переносится»).

Транспонирование **не** меняет смысл «заголовков»: после операции бывшая первая строка становится первым столбцом (и наоборот), если не задан режим «без первой строки/столбца» или режим `headers_from_column` (§2.4).

## 2. Формирование результата

### 2.1. Режимы записи (`output`)

| Значение | Поведение |
|----------|-----------|
| `inplace` (по умолчанию) | Очистить исходный прямоугольник (или весь лист по флагу) и записать транспонированную матрицу **на том же листе**, начиная с левого верхнего угла исходного диапазона. Если новая ширина/высота **не совпадает** со старой — расширить/сузить используемую область; ячейки вне нового прямоугольника в старых границах очистить. |
| `new_sheet` | Создать лист `dest_sheet` (при конфликте имён — суффикс `_2`, `_3`, … как у `копировать_лист`) и записать туда с A1. Исходный лист не трогать. |
| `offset` | Записать на том же листе, начиная с якорной ячейки `dest_cell` (например `E1`), **не** затирая источник, если overlap нет. При пересечении с источником — ошибка в лог и пропуск шага (или режим `overwrite_overlap: true`). |

### 2.2. Размер

- Вход: `R` строк × `C` столбцов → выход:
  - обычное транспонирование: `C` строк × `R` столбцов;
  - `headers_from_column` (§2.4): `C` строк × `(R−1)` столбцов.
- Ограничение: если произведение ячеек слишком велико (порог в коде, напр. > 5e6) — ошибка в лог, шаг не выполнять.
- Для `inplace` предупреждение в лог, если новая ширина/высота ≠ старым (область «плывёт»).

### 2.3. Заголовки и служебные колонки

Опции (можно комбинировать):

- `skip_header_row` (bool, default false) — не включать первую строку источника в транспонирование (остаётся на месте только при `output≠inplace`; при `inplace` — спорный случай: **запретить** вместе с `inplace` или трактовать как «транспонировать только тело, заголовок удалить»).
- `skip_first_column` (bool) — аналогично для первого столбца.
- Рекомендация ТЗ: при `inplace` флаги `skip_*` **не допускать** (ошибка валидации); разрешать только для `new_sheet` / `offset`.

Служебные столбцы `#Путь` / `#ДатаВремяФайла`: если попадают в диапазон — транспонируются как обычные ячейки (без спецлогики), если пользователь явно включил их в `range`.

### 2.4. Режим «заголовки из колонки» (`headers_from_column`)

Нужен, когда **имена столбцов результата** должны взяться из **значений колонки** источника (обычно первой — ФИО, код, метка строки), а **текущая строка заголовков источника отбрасывается** и в результат не попадает.

**Вход (пример):**

| (заголовок) | Имя | Q1 | Q2 | Q3 |
|-------------|-----|----|----|----|
|             | Иван | 5 | 3 | 8 |
|             | Пётр | 2 | 7 | 1 |

или эквивалентный диапазон `A1:D3`:

| A    | B | C | D |
|------|---|---|---|
| Имя  | Q1| Q2| Q3 | ← текущий заголовок **отбросить** |
| Иван | 5 | 3 | 8 |
| Пётр | 2 | 7 | 1 |

**Выход при `headers_from_column: true` (колонка-источник заголовков = первая в диапазоне):**

| Иван | Пётр |
|------|------|
| 5    | 2    |
| 3    | 7    |
| 8    | 1    |

Алгоритм (источник `R`×`C`, 0-based; строка `0` — текущий заголовок диапазона):

1. Выбрать **колонку меток** `k`: поле `header_column` (номер / буква / имя из строки заголовка диапазона); по умолчанию — **первый столбец** диапазона (`k = 0`).
2. **Отбросить** всю строку заголовка источника (индекс `0`) — её значения **не** пишутся в результат.
3. Новая строка заголовков результата: `[S[1][k], S[2][k], …, S[R-1][k]]` — значения колонки `k` по строкам данных (длина `R−1`).
4. Тело: все столбцы **кроме** `k`, строки данных `1..R−1` → матрица `(R−1)`×`(C−1)` → **транспонировать** → `(C−1)`×`(R−1)`.
5. Итог: **`C` строк × `(R−1)` столбцов** (1 строка новых заголовков + `C−1` строк тела).

Если в строке данных ячейка метки пустая — в заголовок результата пишется пустая строка (как есть); дубликаты меток **допускаются** (два столбца с одинаковым заголовком), без авто-суффиксов.

**Связь с `skip_*`:**

| Комбинация | Правило |
|------------|---------|
| `headers_from_column: true` | Строка заголовка источника всегда отбрасывается; отдельный `skip_header_row: true` **избыточен**, но не ошибка (эквивалент). |
| `headers_from_column` + `skip_first_column` | **Запретить**, если `skip_first_column` относится к той же логике «вырезать столбец до транспонирования» без замены на заголовки — конфликт семантики. В v1: при `headers_from_column: true` флаг `skip_first_column` **не допускать** (ошибка валидации). |
| `inplace` + `headers_from_column` | **Разрешить** (в отличие от «голых» `skip_*`): результат переписывает прямоугольник по правилам `output=inplace`. |

Визард: checkbox «Заголовки из колонки» + поле «Колонка меток» (`header_column`, пусто = первая в диапазоне).

## 3. Параметры (JSON, колонка C)

Общий каркас блока:

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Отчет","output":"new_sheet","dest_sheet":"Отчет_T","header_row":1}]
```

### 3.1. Общие поля листа

| Поле | Тип | Описание |
|------|-----|----------|
| `sheet` | string | Один лист; пусто — все листы результата (как у других sheet-block). |
| `sheets` | string[] | Список листов (альтернатива `sheet`). |
| `fn` | string | `транспонировать_таблицу` |

### 3.2. Область источника

| Поле | Тип | Описание |
|------|-----|----------|
| `range` | string | Явный диапазон A1-нотации, напр. `A1:F20`. Если задан — имеет приоритет. |
| `header_row` | int (1-based) | Строка, с которой начинать авто-диапазон (по умолчанию 1). |
| `data_start` | int (1-based) | Первая строка данных; пусто = `header_row`. |
| `columns` | list | Ограничить набор столбцов (имя / буква / индекс / маска `*`), как в других функциях. Пусто — все столбцы до последней непустой в зоне. |

Авто-диапазон без `range`: от `(min col..max col)` × `(header_row или data_start .. last non-empty row)` в пределах листа.

### 3.3. Вывод

| Поле | Тип | Описание |
|------|-----|----------|
| `output` | string | `inplace` \| `new_sheet` \| `offset` |
| `dest_sheet` | string | Имя листа-приёмника при `new_sheet` |
| `dest_cell` | string | Якорь записи при `offset` (A1) |
| `overwrite_overlap` | bool | Разрешить перекрытие с источником при `offset` (default false) |
| `clear_source` | bool | При `offset`/`new_sheet` дополнительно очистить исходный диапазон (default false) |
| `with_formatting` | bool | Пытаться перенести оформление (default false; может быть не реализовано в v1) |

### 3.4. Флаги содержимого

| Поле | Тип | Описание |
|------|-----|----------|
| `skip_header_row` | bool | См. §2.3 |
| `skip_first_column` | bool | См. §2.3 |
| `headers_from_column` | bool | Режим §2.4: новая шапка = значения колонки меток; текущий заголовок диапазона отбросить (default false) |
| `header_column` | int / string | Колонка меток для §2.4: 1-based индекс **в диапазоне**, буква (`A`) или имя из строки заголовка диапазона. Пусто / не задано — **первый столбец** диапазона. Игнорируется, если `headers_from_column` ≠ true |
| `result_headers` | list / string | Кастомные имена столбцов результата при `headers_from_column=false`: добавляются **сверху** после транспонирования. Алиас `new_headers`. При `headers_from_column` игнорируется |
| `as_values` | bool | Перед транспонированием материализовать формулы в значения (default true для предсказуемости) |

## 4. Валидация и ошибки

В начале шага (до записи):

1. Лист не найден / диапазон пуст → проблема в лог, пропуск.
2. `output=new_sheet` без `dest_sheet` → ошибка.
3. `output=offset` без `dest_cell` → ошибка.
4. `inplace` + `skip_header_row`/`skip_first_column` **без** `headers_from_column` → ошибка валидации.
5. `headers_from_column: true` + `skip_first_column: true` → ошибка валидации.
6. `headers_from_column: true`, а `header_column` не найден в диапазоне / вне границ → ошибка.
7. `headers_from_column: true`, но в диапазоне меньше 2 строк или меньше 2 столбцов → ошибка (нечего строить).
8. Перекрытие при `offset` и `overwrite_overlap=false` → ошибка.
9. Слишком большой диапазон → ошибка.

Подробный DEBUG (как у других fn): размер RxC → результат (при обычном транспонировании CxR; при `headers_from_column` — `C × (R−1)`), режим вывода, `headers_from_column` / `header_column`, имя листа, угол записи.

## 6. Примеры

Транспонировать использованный блок на месте:

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Матрица","output":"inplace","header_row":1}]
```

На новый лист, только столбцы A–D:

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Матрица","output":"new_sheet","dest_sheet":"Матрица_T","range":"A1:D50"}]
```

Рядом с исходником:

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Матрица","output":"offset","dest_cell":"H1","range":"A1:C10"}]
```

Заголовки результата = значения первой колонки диапазона, старая шапка отброшена:

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Анкеты","output":"new_sheet","dest_sheet":"Анкеты_T","range":"A1:D50","headers_from_column":true}]
```

То же, но метки брать из колонки `B` (или по имени заголовка `"Код"`):

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Анкеты","output":"inplace","headers_from_column":true,"header_column":"B","header_row":1}]
```

Кастомные имена столбцов результата (без `headers_from_column`):

```json
[{"v":1,"fn":"транспонировать_таблицу","sheet":"Матрица","output":"new_sheet","dest_sheet":"Матрица_H","result_headers":["Метка","Строка1","Строка2"]}]
```
