# ТЗ: обновить ВПР (join_type anti/semi)

Расширение существующей функции `ВПР` (VLOOKUP / LEFT join) в части `join_type`.

Текущий функционал:
- `join_type=left` — LEFT OUTER JOIN;
- `join_type=full` — FULL OUTER JOIN (two-pass + union справа).

Нужно добавить:
- `join_type=semi`;
- `join_type=anti`.

---

## 1. Где в проекте

- Визард: блок `ВПР` в `param_wizard` (комбобокс join type).
- Код: `lm_vlookup_join_sheets` и связанные helpers в `libre_macros_lib.py` (а также direct/xml ветки при наличии).

Проверка совместимости:
- нормализация join_type уже есть (left/full); расширить.
- UI должна показывать новые значения (на русском и с алиасами).

---

## 2. Контракт JSON (v1)

Сохраняем текущую структуру VLOOKUP и расширяем только `join_type`.

Пример (форма в JSON-кодеке, галочка “Сохранять как JSON”):

```json
[
  {
    "v": 1,
    "fn": "впр",
    "join_type": "semi",
    "left_sheet": "Merge",
    "right_sheet": "Справочник",
    "join_keys": ["'Код_позиции'"],
    "extract_cols": ["'Цена'"],
    "fill_text": "#Н/Д",
    "trim_keys": true
  }
]
```

### 2.1. Новые значения `join_type`

- `semi` — Semi join:
  - включать только строки левой таблицы, у которых ключ найден в правой таблице;
  - unmatched left удаляются из результата;
  - извлечённые колонки берутся как для обычного left join (по текущим правилам мульти-совпадений).
- `anti` — Anti join:
  - включать только строки левой таблицы, у которых ключ **не** найден в правой таблице;
  - строки, у которых match есть, удаляются;
  - извлечённые колонки заполняются `fill_text` (и подсветка — по текущим правилам).

---

## 3. Поведение для мульти-совпадений (важно для v1)

В vlookup есть UX-флаги:
- `Заполнять_дубли` (да/нет);
- `Мульти_совпадение_в_одну_ячейку` (да/нет).

В v1 для semi/anti предполагается:
- сохранять текущие правила обработки мульти-совпадений в случае наличия match (semi) и отсутствия match (anti);
- для anti join всё извлечённое равно `fill_text`, поэтому флаги мульти-совпадений не влияют на значения (но подсветку всё равно можно применять).

---

## 4. Изменения в UI

В визарде `ВПР` добавить в выбор join type:
- “Полное соединение” (full) — уже есть;
- “Левое соединение” (left) — уже есть;
- **“Полусоединение (semi)”** — новый пункт;
- **“Антисоединение (anti)”** — новый пункт.

Также поддержать алиасы в парсинге:
- `semi`, `полу`, `semi_join`, `semi outer` (если есть принятая конвенция — как у left/full);
- `anti`, `анти`, `anti_join`.

---

## 5. Проверка (ручная, в Calc)

1. Подготовить лист `Merge` с ключом `Код_позиции` и 5-10 строк.
2. Подготовить лист `Справочник` с частичным перекрытием ключей.
3. Прогнать ВПР в трёх режимах:
   - `left`,
   - `full`,
   - `semi` и `anti`.
4. Проверить:
   - semi: в результате только строки с match;
   - anti: в результате только unmatched left;
   - extract-cols в anti должны быть `fill_text`.
