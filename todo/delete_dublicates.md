# ТЗ: выбор столбцов результата в `удалить_дубликаты`

Доработка существующей постобработки `удалить_дубликаты`: дать пользователю возможность указать, какие столбцы оставить в результате после определения повторяющихся строк.

> В проекте уже есть `удалить_дубликаты` (RANGE / FINAL), выбор `key_columns`, выбор первого/последнего вхождения и режимы вывода `inplace` / `new_sheet` / `offset` / маркировка. Базовая семантика удаления описана в [__новая функция удалить_дубликаты.md](__новая%20функция%20удалить_дубликаты.md). Это ТЗ **не вводит вторую функцию дедупликации**: оно уточняет выбор столбцов результирующей таблицы и удобство выбора столбцов в визарде.

---

## 1. Цель и пользовательский сценарий

Пользователь задаёт один или несколько столбцов, по которым строки считаются дубликатами, выбирает, какое вхождение оставить, и отдельно задаёт состав результирующей таблицы:

- оставить все исходные столбцы;
- оставить только явно выбранные столбцы;
- оставить только столбцы ключа анализа дубликатов.

Пример: найти повторы по «ИНН», оставить последнее вхождение, а в результате оставить только «ИНН», «Наименование» и «Статус».

Выбор ключей сравнения и выбор столбцов результата — два независимых набора. `exclude_columns` исключает столбцы только из сравнения и не должен пониматься как список столбцов результата.

---

## 2. Совместимость с существующей операцией

1. Имя функции, алиасы, поддержка RANGE / FINAL, фильтры `sheet` / `sheets`, алгоритм сравнения ключей и способы выбора выжившей строки остаются прежними.
2. Если новые параметры отсутствуют, результат должен совпадать с текущим поведением: сохраняются все исходные столбцы в исходном порядке.
3. Все существующие JSON-блоки, включая сохранённые профили и старые книги, продолжают работать без миграции.
4. Новые настройки управляют только составом столбцов вывода. Они не меняют, какие строки считаются дубликатами и какую строку оставлять.
5. Новая возможность доступна во всех режимах вывода, которые уже поддерживает текущая операция. Для режима маркировки ограничения описаны в §5.

## 3. Параметры JSON

### 3.1. Новые поля

| Поле | Тип | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `result_columns` | string | `all` | Политика выбора столбцов результата: `all`, `selected` или `key_columns` |
| `output_columns` | list[string] | отсутствует | Список столбцов результата; обязателен при `result_columns: "selected"` |

Пример:

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "sheet": "Клиенты",
  "key_columns": ["'ИНН'"],
  "keep": "last",
  "result_columns": "selected",
  "output_columns": ["'ИНН'", "'Наименование'", "'Статус'"],
  "output": "new_sheet",
  "dest_sheet": "Клиенты_уник"
}]
```

### 3.2. Политики результата

| `result_columns` | Поведение |
| --- | --- |
| `all` | Оставить все столбцы исходного `data_range`, в исходном порядке. Значение по умолчанию и поведение старых блоков. |
| `selected` | Оставить только столбцы из `output_columns`; обязательный список должен содержать хотя бы один столбец. |
| `key_columns` | Оставить только фактические столбцы ключа сравнения после разрешения `key_columns` / `exclude_columns`. |

Порядок столбцов результата:

- `all` — исходный порядок столбцов на листе;
- `selected` — исходный порядок столбцов на листе, а не порядок добавления токенов в визарде;
- `key_columns` — исходный порядок столбцов на листе.

Это сохраняет привычный порядок таблицы и не делает порядок кликов в мультивыборе скрытым способом перестановки столбцов.

### 3.3. Определение ключевых столбцов

Используются существующие правила `удалить_дубликаты`:

- задан непустой `key_columns` — ключ состоит из перечисленных столбцов;
- `key_columns` пуст и `exclude_columns` пуст — ключ состоит из всех столбцов `data_range`;
- `key_columns` пуст и задан `exclude_columns` — ключ состоит из всех столбцов, кроме исключённых;
- непустые `key_columns` и `exclude_columns` одновременно запрещены существующей валидацией.

При `result_columns: "key_columns"` выводятся именно фактически разрешённые столбцы ключа. Поэтому при пустом `key_columns` и непустом `exclude_columns` результат содержит все столбцы, кроме исключённых; если оба списка пусты — все исходные столбцы.

Пустой `key_columns` в режиме `key_columns` не считается ошибкой: он имеет те же значения по умолчанию, что и при сравнении (полная строка, за вычетом `exclude_columns`, если они заданы).

## 4. Алгоритм

1. Получить `data_range` и строку заголовков от хоста. Заголовок не участвует в сравнении строк.
2. Разрешить `key_columns` и, если выбран режим `selected`, `output_columns` относительно заголовков текущего целевого листа.
3. Проверить режим вывода, совместимость параметров и наличие всех запрошенных столбцов **до изменения листа**.
4. По существующему алгоритму дедупликации определить выжившие строки с учётом `keep`, `pre_sort`, нормализации ключа и политики пустых ключей.
5. После отбора строк выполнить проекцию: оставить только столбцы, заданные `result_columns`.
6. Сформировать заголовок и тело результата из тех же исходных строк и записать их согласно `output`.
7. Записать в журнал количество входных строк, удалённых повторов/помеченных строк, выбранные ключевые столбцы, режим состава столбцов и число столбцов до/после.

Важный инвариант: выбор результирующих столбцов **не участвует** в вычислении ключа, кроме режима `result_columns: "key_columns"`, который только определяет состав вывода. Например, если ключ — `ИНН`, а вывод — `Наименование`, одинаковые ИНН всё равно приводят к одной выжившей строке, хотя столбца ИНН в результате может не быть.

### 4.1. Порядок строк

Сохраняется существующая семантика:

- `keep: "first"` — выживает первое вхождение;
- `keep: "last"` — выживает последнее вхождение;
- результат сохраняет исходный порядок выживших строк после применения существующего `pre_sort` (если он задан).

`pre_sort`, `scan_order`, `trim`, `case_sensitive`, `compare_as`, `empty_key_policy` и `as_values` остаются независимыми от проекции столбцов.

## 5. Поведение по режимам вывода

### `output: "inplace"`

- Дедупликация и выбор столбцов выполняются в границах исходного `data_range`.
- При `result_columns: "all"` действует текущее поведение без изменения столбцов.
- При `selected` / `key_columns` выбранные столбцы уплотняются слева в порядке исходного листа; заголовок и значения строк записываются в уплотнённую область.
- Оставшаяся справа часть исходного `data_range` очищается от содержимого, чтобы в таблице не оставались старые заголовки и значения отброшенных столбцов.
- Не удалять физические столбцы листа и не сдвигать содержимое вне исходного `data_range`. Ячейки и данные за пределами этого диапазона должны остаться нетронутыми.
- При изменении состава столбцов предупредить пользователя в подсказке формы, что операция изменяет исходную таблицу на месте.

### `output: "new_sheet"`

- Исходный лист не меняется.
- На новом листе записываются заголовок и выжившие строки только с результирующими столбцами.
- Существующие правила имени листа и обработки занятого имени сохраняются.

### `output: "offset"`

- Исходный блок не удаляется и не изменяется.
- В `dest_cell` записывается компактный блок заголовков и выживших строк только с результирующими столбцами.
- Проверка пересечения `dest_cell` с исходным блоком и `overwrite_overlap` сохраняют существующую семантику; проекция не должна обходить эту защиту.

### `mark_duplicates: true`

Режим маркировки не удаляет строки. В v1 для него разрешено только `result_columns: "all"`; сочетание с `selected` или `key_columns` должно завершаться понятной ошибкой валидации до записи, чтобы не менять раскладку исходных строк и маркер. Расширение проекции для маркировки — вне объёма этой задачи.

## 6. Разрешение столбцов и правила визарда

### 6.1. Поля формы

В существующей форме «Удалить дубликаты» добавить:

| Поле | Тип UI | Подпись | Поведение |
| --- | --- | --- | --- |
| `key_columns` | `columns_pick` | Столбцы ключа | Существующее поле; участвует в сравнении |
| `exclude_columns` | `columns_pick` | Не учитывать при сравнении (опц.) | Существующее поле; только для формирования ключа |
| `keep` | combo | Оставить | Существующий выбор «Первую» / «Последнюю» |
| `result_columns` | combo | Столбцы результата | «Все исходные» / «Выбранные» / «Только ключевые» |
| `output_columns` | `columns_pick` | Оставить столбцы | Видимо и активно только при `result_columns = selected` |

Для `output_columns`:

- список заголовков формируется по листу, указанному для блока; в `sheet`-режиме — по заголовкам этого листа;
- разрешён также ручной ввод имён столбцов;
- выбор накапливается: каждый пункт добавляется к уже выбранным токенам;
- выбор из списка сериализуется как quoted exact-токен `'Имя столбца'`;
- ручной ввод поддерживает разделители `,` и `;`; если имя содержит запятую, использовать `;` или кавычки;
- справа доступны `×` (удалить последний выбранный столбец) и `××` (очистить список);
- разбор и отображение выполняются существующими helper-ами `columns_pick`; не использовать голый `split(",")`.

Те же правила `columns_pick` обязательны для `key_columns` и `exclude_columns`. В подсказке явно разделить понятия «столбцы для сравнения» и «столбцы, которые останутся в таблице».

### 6.2. Несколько целевых листов

Если блок применён к нескольким листам:

- значения `key_columns` и `output_columns` разрешаются отдельно на каждом листе;
- список выбора в форме берётся из заголовков выбранного листа-контекста; ручной ввод остаётся доступен;
- если токен отсутствует хотя бы на одном целевом листе, для этого листа записать понятную ошибку/пропуск по текущей политике обработки ошибок, не подменять столбец похожим;
- выполнение на других листах продолжать согласно существующему поведению операции.

### 6.3. Заголовки и неоднозначность

- Имена столбцов разрешаются по существующим правилам токенов заголовков, кавычек, букв и индексов.
- Если токен по имени неоднозначно соответствует нескольким столбцам, завершить обработку этого листа понятной ошибкой; не выбирать первое совпадение молча.
- Повторное указание одного и того же столбца в `output_columns` не должно дублировать столбец в результате; нормализовать список до уникальных разрешённых индексов с сохранением первого указания.
- Пустой токен или пустой список в `selected` — ошибка валидации, а не молчаливый переход к `all`.

## 7. Ошибки и журналирование

До модификации листа проверить:

1. допустимость `result_columns` (`all`, `selected`, `key_columns`);
2. наличие непустого `output_columns`, если выбран `selected`;
3. разрешение всех токенов на листе;
4. отсутствие конфликтов `key_columns` и `exclude_columns` по существующим правилам;
5. совместимость `mark_duplicates` с `result_columns`;
6. корректность режима вывода и доступность адреса назначения — по существующим правилам.

При ошибке не должно оставаться частично перестроенной таблицы. В журнале для успешного листа указывать как минимум:

- лист;
- число строк до обработки, число оставленных строк и число удалённых дублей (или помеченных строк);
- ключевые столбцы;
- `result_columns` и фактический список столбцов вывода;
- число столбцов до/после;
- режим вывода и адрес/имя назначения, если применимо.

Для старых JSON-блоков журналы не обязаны менять формат, если новый режим не выбран.

## 8. Примеры

### 8.1. Совместимый старый режим: оставить все столбцы

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "key_columns": ["'ИНН'"],
  "keep": "first",
  "result_columns": "all"
}]
```

`result_columns` можно опустить: `all` — значение по умолчанию.

### 8.2. Оставить выбранные столбцы на новом листе

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "key_columns": ["'ИНН'"],
  "keep": "last",
  "result_columns": "selected",
  "output_columns": ["'Наименование'", "'Статус'"],
  "output": "new_sheet",
  "dest_sheet": "Клиенты_уник"
}]
```

Если ключ «ИНН» не включён в `output_columns`, он используется для дедупликации, но не записывается в результат.

### 8.3. Оставить только столбцы ключа

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "key_columns": ["'Регион'", "'Код'"],
  "keep": "first",
  "result_columns": "key_columns",
  "output": "inplace"
}]
```

В исходной области останутся только «Регион» и «Код»; прочие ячейки исходного `data_range` справа от уплотнённой таблицы будут очищены, а содержимое вне диапазона не сдвинется и не изменится.

### 8.4. Сравнить по полной строке, вывести без служебного столбца

```json
[{
  "v": 1,
  "fn": "удалить_дубликаты",
  "exclude_columns": ["'#Путь'"],
  "result_columns": "key_columns",
  "output": "new_sheet",
  "dest_sheet": "Уникальные_данные"
}]
```

Ключом остаются все столбцы, кроме `#Путь`; на новом листе записываются те же столбцы ключа. Если нужно убрать `#Путь` только из результата, но учитывать его при дедупликации, использовать `result_columns: "selected"` и явно перечислить `output_columns`.

## 9. Критерии приёмки

1. Старый JSON без `result_columns` / `output_columns` сохраняет все исходные столбцы и выдаёт тот же результат, что до доработки.
2. `all` сохраняет исходный состав и порядок столбцов.
3. `selected` выводит только перечисленные столбцы, без повторов, в порядке исходных столбцов; ключ дедупликации от этого не меняется.
4. `key_columns` выводит фактический ключ сравнения; корректно работают случаи пустого `key_columns` и непустого `exclude_columns`.
5. `keep: first` и `keep: last` продолжают выбирать правильную строку, включая разные значения неключевых полей.
6. `inplace` уплотняет столбцы в пределах `data_range`, очищает отброшенный хвост и не удаляет/не сдвигает ячейки вне `data_range`.
7. `new_sheet` и `offset` записывают только результирующие столбцы; исходник не меняется в `new_sheet`, исходный блок не меняется в `offset`.
8. Визард накапливает выбранные столбцы, сохраняет кавычки токенов, поддерживает ручной ввод и кнопки `×` / `××`.
9. Не найденный или неоднозначный столбец даёт понятную ошибку до частичной модификации листа.
10. `mark_duplicates: true` с `result_columns != all` отклоняется до записи с русским сообщением.
11. Поведение RANGE / FINAL и существующие правила выбора листов не регрессируют.

---

## 10. Проверка и документация

### Сценарии проверки

- Дубликаты по одному и составному ключу; `keep=first` и `keep=last` при разных значениях неключевых столбцов.
- Каждая политика результата: `all`, `selected`, `key_columns`.
- Пустой ключ, `exclude_columns`, отсутствие строк данных, все уникальные строки.
- Все три режима записи: `inplace`, `new_sheet`, `offset`; контроль ячеек за пределами исходного диапазона.
- Формула в ключевом поле при `as_values=true`.
- Визард: список заголовков заданного листа, мультивыбор, ручной ввод, кавычки, `×` и `××`.
- Старые блоки JSON и режим `mark_duplicates`.

Проверять вручную в LibreOffice/AlterOffice; для повторяемого сценария допустим существующий headless harness проекта. Новые pytest-тесты не создавать.
