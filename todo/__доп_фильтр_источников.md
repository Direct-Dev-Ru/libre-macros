# ТЗ: доп. фильтр файлов-источников

Расширение **`Доп_Параметры_Источника`** (book / CSV / XML): после отбора по основной маске пути дополнительно сузить список файлов по дате или лямбда-фильтру.

Связано с: `libre_macros_source_extra_lib.py`, `libre_macros_csv_source_lib.py`, `libre_macros_xml_source_lib.py`, разворот путей в `collect_workbooks.py`.

---

## 1. Назначение

| Сейчас | Нужно |
|--------|--------|
| Маска + exclude_mask (+ recurse) | То же + **доп. фильтр** по дате создания / модификации или лямбде |
| — | Опционально: фильтр **в каждом подкаталоге** отдельно vs **по всему** отобранному множеству |

Пример: маска `*.csv` + recurse → все CSV во вложенных папках → доп. фильтр «самый новый по дате модификации» **в каждом подкаталоге** → по одному файлу на папку.

---

## 2. Где живёт параметр

В блоках **`Доп_Параметры_Источника`** (и эквивалентах для CSV/XML source-extra), рядом с уже существующими полями (`exclude_mask`, recurse и т.д.).

Новые поля блока (имена JSON — латиница, стабильные):

| Поле | Тип | Default | Смысл |
|------|-----|---------|--------|
| `file_pick` | string | `all` | Режим доп. фильтра |
| `file_pick_scope` | string | `all` | Область применения |
| `file_pick_lambda` | string | `""` | Выражение лямбды (только если `file_pick=lambda`) |

Существующий `exclude_mask` **не заменяется** — доп. фильтр применяется **после** маски включения и exclude.

---

## 3. Режим `file_pick`

| Код | Подпись в визарде (RU) |
|-----|------------------------|
| `all` | Все (умолчание) |
| `newest_ctime` | Новый по дате создания |
| `oldest_ctime` | Старый по дате создания |
| `newest_mtime` | Новый по дате модификации |
| `oldest_mtime` | Старый по дате модификации |
| `lambda` | Лямбда-фильтр |

Для режимов даты: из кандидатов оставляется **один** файл (или по одному на scope — см. §4) с экстремумом `st_ctime` / `st_mtime`.

Платформа: на Linux `st_ctime` — смена метаданных, не «дата создания Windows»; в подсказке визарда указать: «дата создания — по возможности ОС; иначе ctime». Не падать, если ctime недоступен — fallback на mtime + запись в журнал.

---

## 4. Область `file_pick_scope`

| Код | Подпись | Поведение |
|-----|---------|-----------|
| `all` | Все подкаталоги вместе | После маски: один экстремум (или лямбда) по **всему** списку |
| `per_subdir` | В рамках подкаталога | Группировка по **родительскому каталогу** файла; в каждой группе — свой экстремум / своя лямбда |

При `file_pick=all` поле scope игнорируется (все файлы после exclude).

Корень (файлы прямо в базовой папке источника) — отдельная группа при `per_subdir`.

---

## 5. Лямбда-фильтр

- Синтаксис и сахара — **как у других лямбд проекта** (колонки/формулы сбора; единый evaluator).
- Контекст файла (минимум v1):

| Имя | Смысл |
|-----|--------|
| `путь` / `path` | полный путь |
| `имя` / `name` | basename |
| `каталог` / `dir` | dirname |
| `mtime` | unix time модификации |
| `ctime` | unix time «создания»/ctime |
| `размер` / `size` | размер байт |

- Подстановка **`<<Переменные.…>>`** из карты переменных **до** eval (в т.ч. значения из [ручного ввода](карта_переменных_ручной_ввод.md), если диалог уже отработал).
- Результат: truthy → файл остаётся; иначе отбрасывается.
- При `per_subdir`: лямбда применяется **внутри** каждой группы (не выбирает «одного победителя», а фильтрует список группы). Если нужен «один файл по лямбде» — пользователь пишет условие с экстремумом сам или комбинирует с date-режимом в v2.

**v1 уточнение для date vs lambda:**  
- date-режимы → leave **1** file per scope;  
- lambda → leave **N** files (filter).  
Не смешивать в одном прогоне два режима.

---

## 6. Порядок пайплайна отбора файлов

1. Базовый путь + include-маска (+ recurse).
2. `exclude_mask` (если задан).
3. `file_pick` + `file_pick_scope` (+ `file_pick_lambda`).
4. Дальше — чтение книг / CSV / XML как сейчас.

Пустой список после доп. фильтра → как сейчас при «нет файлов»: сообщение в журнале, без падения всего сбора (если так принято для пустой маски).

---

## 7. Визард

В форме «Доп. параметры источника» (book / CSV / XML):

- combo **«Доп. фильтр файлов»** → `file_pick` (подписи §3);
- combo **«Область фильтра»** → `file_pick_scope` (подписи §4); disabled при `all`;
- edit **«Лямбда»** → `file_pick_lambda`; visible/enabled только при `file_pick=lambda`;
- hint: переменные карты, поля `путь`/`mtime`/…; для date — scope.

Регистрация полей в `_SOURCE_EXTRA_*` / schema CSV-XML extra (cfg в `pythonpath/`).

---

## 8. Acceptance (ручная проверка в Calc)

1. Три CSV в одной папке, маска `*.csv`, `newest_mtime` + `all` → один самый новый.
2. Две подпапки с CSV, `newest_mtime` + `per_subdir` → по одному файлу из каждой.
3. `oldest_ctime` — ожидаемый файл (с оговоркой Linux ctime).
4. `lambda`: например `имя` содержит подстроку из `<<Переменные.X>>` после ручного ввода / карты.
5. `file_pick=all` — поведение как до фичи (регрессия).

---

## 9. Вне объёма v1

- Несколько победителей по дате (top-N).
- Фильтр по размеру отдельным режимом (только через лямбду).
- Сравнение дат между разными корнями источников одной строкой «Файлы-Источники» с несколькими путями — каждый корень обрабатывается своим списком кандидатов.
