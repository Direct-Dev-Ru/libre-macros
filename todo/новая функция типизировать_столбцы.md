# ТЗ: типизировать_столбцы (Change type)

Новая функция постобработки / финальной стадии (RANGE + FINAL; по возможности `Постобработка_xml`).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`).

**Имя ключа (fn):** `типизировать_столбцы`  
**Синонимы / алиасы:** `типизировать`, `change_type`, `convert_column_types`.  
**Lib (план):** `lm_pp_range_type_columns` / `merge_final_type_columns`.  
**Цель:** привести значения в выбранных столбцах к заданному типу (text/number/date/boolean) с предсказуемой политикой ошибок.

---

## 1. Контракт JSON (v1)

```json
[
  {
    "v": 1,
    "fn": "типизировать_столбцы",
    "columns": ["'Сумма'", "'Количество'"],
    "target_type": "number",
    "on_error": "keep", 
    "number_policy": {
      "allow_comma_decimal": true,
      "strip_spaces": true
    }
  }
]
```

### 1.1. Поля

- `columns` — `columns_pick` (или `columns="all"` если допустимо в v1).
- `target_type` — combo:
  - `text`
  - `number`
  - `date`
  - `boolean`
- `on_error` — combo:
  - `keep` — оставить как есть;
  - `empty` — очистить ячейку;
  - `fail_step` — ошибка шага (остановить/отметить как fail).
- Пакет политики парсинга (опционально):
  - для `number`:
    - `strip_spaces` (default true)
    - `allow_comma_decimal` (default true)
    - `thousand_sep` (опционально)
  - для `date`:
    - `format_hint` (литерал, если пользователь знает шаблон входа)
    - `max_year_shift` (опционально, если нужны эвристики)
  - для `boolean`:
    - `true_values` / `false_values` (массив строк, по умолчанию: `да/нет`, `истина/ложь`, `1/0`, `true/false`)

---

## 2. Принцип работы (ожидаемое поведение)

1. Определить `data_range` и `header_row_range` из хоста.
2. Материализовать формулы в значениях (как в других PP-шагов с `as_values`).
3. Для каждой строки данных и каждой колонки из `columns`:
   - взять исходное значение;
   - если значение пустое — оставить пустым (v1);
   - иначе попытаться распарсить/преобразовать под `target_type`;
   - при успехе записать значение с сохранением типа UNO (или корректным представлением в xml-ветке);
   - при неуспехе применить `on_error`.
4. Журнал:
   - сколько конвертировано;
   - сколько пропущено (пустые/нецелевые);
   - сколько ошибок по `on_error=empty` / `fail_step`.

---

## 3. Ограничения v1

- Преобразование выполняется **для одного `target_type` на шаг** (per-step).
- В v1 не требуется поддержка “пер-колонка target_type”.
- Форматирование (number/date formats, ширины, стили) — вне scope v1.
  - (опционально) можно оставить расширение: применить формат по выбору пользователя как отдельный шаг `формат_столбцы`.

---

## 4. UX

В визарде:
- `columns` — `columns_pick`;
- `target_type` — combo на русском;
- `on_error` — combo на русском;
- политики парсинга — “Параметры…” (опционально, с дефолтами).

---

## 5. Ручная проверка (в Calc)

1. Подготовить столбцы:
   - числа как строки (`"1 234,56"` / `"1234.56"`),
   - даты в разных форматах,
   - boolean как строки (`"да"`, `"нет"`, `"true"`).
2. Прогнать `типизировать_столбцы` для `number/date/boolean`.
3. Проверить:
   - успешные конвертации и корректные типы;
   - поведение при ошибке согласно `on_error`.
