# ТЗ: условный_столбец

Новая функция постобработки / финальной стадии (RANGE + FINAL; по возможности `Постобработка_xml` / direct).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`).

**Имя ключа (fn):** `условный_столбец`  
**Синонимы / алиасы:** `условный_столбец_добавить`, `conditional_column`, `if_column`.  
**Lib:** `lm_pp_range_conditional_column` / `merge_final_conditional_column`  
**Аналог Power Query:** **Conditional Column** (*Add Column → Conditional Column*): цепочка If / Else If / Otherwise без написания формул Calc.

**Цель:** по декларативным правилам «если столбец … оператор … значение → результат» вычислить **новый** (или перезаписать существующий) столбец **значениями в памяти**, без протяжки `=IF(…)` по листу.

**Отличие от `применить_формулу`:**

| | `условный_столбец` | `применить_формулу` |
|--|-------------------|---------------------|
| Язык | JSON-правила + операторы | формула Calc |
| Оценка | in-memory по `getDataArray` | UNO-формулы / `as_values` |
| UX | визард: столбец / оператор / значение | ручной ввод формулы |
| Типичный кейс | категория, статус, бакет | арифметика, ссылки на соседние строки |

`применить_формулу` остаётся для сложных выражений; `условный_столбец` — для типовых «If Column … Then …» из PQ.

---

## 1. Принцип работы

1. Определить **область данных** (`data_range` + `header_row_range` от хоста).
2. Отфильтровать листы по `sheet` / `sheets`.
3. При `as_values: true` (default) — `calculateAll`, материализовать формулы.
4. Разрешить имя результирующего столбца `new_column` (создать или найти).
5. Разобрать `rules[]` (упорядоченный список) и `otherwise`.
6. **Прочитать** прямоугольник в память (`getDataArray`).
7. Для каждой **строки данных** (ниже заголовка):
   - пройти `rules` сверху вниз;
   - при первом сработавшем правиле взять `then` / `then_column`;
   - иначе — `otherwise` / `otherwise_column` (если `otherwise` задан как conditional-блок — оценивается рекурсивно по его `rules`).
   - записать значение в ячейку результата (в матрице).
8. При необходимости **вставить** новый столбец на лист (`position` + `relative_column`), записать заголовок.
9. **`setDataArray`** (или точечная запись столбца — на усмотрение реализации; предпочтительно один проход матрицы).
10. Журнал: лист, `new_column`, число правил, строк обработано / иначе / ошибок сравнения.

Строка заголовков **не** участвует в оценке правил.

## 2. Алгоритм оценки правил

### 2.1. Модель правила (v1)

Одно правило — **одна** проверка (как в UI PQ Conditional Column):

```text
IF  [column]  [op]  [value | value_column]  THEN  [then | then_column]
```

Цепочка:

```text
IF rule0 …
ELSE IF rule1 …
…
ELSE otherwise
```

**Короткое замыкание:** первое истинное правило побеждает; остальные не смотрятся.

### 2.2. Операторы (`op`)

| Код JSON | Подпись UI | Смысл |
| -------- | ---------- | ----- |
| `eq` | равно | `left == right` после нормализации |
| `ne` | не равно | |
| `contains` | содержит | подстрока (текст) |
| `not_contains` | не содержит | |
| `starts_with` | начинается с | |
| `not_starts_with` | не начинается с | |
| `ends_with` | заканчивается на | |
| `not_ends_with` | не заканчивается на | |
| `gt` | больше | числовое / дата / текстовое — см. `compare_as` |
| `ge` | больше или равно | |
| `lt` | меньше | |
| `le` | меньше или равно | |
| `is_blank` | пусто | `value` не нужен |
| `is_not_blank` | не пусто | `value` не нужен |

Алиасы в кодеке (нормализация): `equals`→`eq`, `=`→`eq`, `<>`→`ne`, `>=`→`ge`, и т.п.

### 2.3. Левая и правая части сравнения

| Поле | Описание |
| ---- | -------- |
| `column` | Столбец слева (обязателен, кроме… нет — всегда обязателен) |
| `value` | Литерал справа (строка / число / bool в JSON) |
| `value_column` | Столбец справа вместо литерала (взаимоисключимо с `value` в v1) |

Для `is_blank` / `is_not_blank`: `value` и `value_column` **игнорируются**.

**Пустая ячейка слева:**

| `blank_left` | Default | Поведение |
| ------------ | ------- | --------- |
| `as_empty` (default) | — | левая часть = `""` / пусто; `is_blank` → true; текстовые op по `""` |
| `skip_rule` | — | правило считается **ложным** (переход к следующему) |
| `fail` | — | ошибка шага |

### 2.3.1. Сравнение со значением другого столбца (`value_column`)

`value_column` позволяет сравнивать `column` не с литералом `value`, а со
значением второго столбца в **той же строке**.

Правила v1:

- задаётся **или** `value`, **или** `value_column`;
- одновременное заполнение обоих полей — ошибка валидации;
- `value_column` разрешается так же, как `column` (имя заголовка, буква, индекс);
- сравнение выполняется построчно: `left = row[column]`, `right = row[value_column]`.

Примеры:

```json
{"column":"Цена1","op":"eq","value_column":"Цена2","then":"Равны"}
```

```json
{"column":"Дата_факт","op":"gt","value_column":"Дата_план","then":"Просрочка"}
```

```json
{"column":"Комментарий","op":"contains","value_column":"Ключевое_слово","then":"Совпало"}
```

### 2.4. Результат правила (`then`)

| Поле | Описание |
| ---- | -------- |
| `then` | Литерал результата |
| `then_column` | Взять значение из столбца той же строки |

Ровно одно из двух обязательно для каждого правила. Аналогично для хвоста:

| Поле | Описание |
| ---- | -------- |
| `otherwise` | Литерал, если ни одно правило не сработало (default `""`) **ИЛИ** вложенный conditional-блок (в v1 поддерживается) |
| `otherwise_column` | Столбец-источник для «иначе» (только если `otherwise` не conditional-блок) |

Если заданы и литерал, и `*_column` — приоритет у `*_column` + WARN в лог (или ошибка валидации — **ошибка** в v1).

В v1 поддерживается «вложенный ELSE», то есть `otherwise` может быть объектом с тем же контрактом ветки:

```json
{
  "rules": [ /* иначе IF / ELSE IF цепочка */ ],
  "otherwise": "Литерал финального otherwise",
  "otherwise_column": "Столбец финального otherwise"
}
```

Это эквивалентно `ELSE IF ruleN ... ELSE ...` без использования формул Calc.

### 2.5. Нормализация сравнения

| Поле | Default | Поведение |
| ---- | ------- | --------- |
| `trim` | `true` | `strip()` текстовых сторон перед сравнением |
| `case_sensitive` | `false` | для текстовых op (`eq`, `contains`, …) |
| `compare_as` | `auto` | `auto` \| `text` \| `number` \| `date` |
| `as_values` | `true` | материализовать формулы до чтения |

**`compare_as`:**

| Значение | Поведение |
| -------- | --------- |
| `auto` (default) | для `gt`/`ge`/`lt`/`le` — попытка числа, затем даты, иначе текст; для `eq`/`contains`/… — текст |
| `text` | всё как строка (`cell_text` / `_lm_cell_display_text`) |
| `number` | парсить число; неуспех → правило ложно (или `non_comparable`) |
| `date` | парсить дату; аналогично |

| `non_comparable` | Default | Поведение |
| ---------------- | ------- | --------- |
| `false` (default) | — | правило не сработало |
| `fail` | — | прервать шаг |

Числа: locale-aware (ru: запятая), как у `recognize_numbers` / direct parse.  
Даты: те же хелперы, что у split / xml (`_direct_try_parse_datetime_text`).

### 2.6. Размещение столбца результата

Как у `конкатенация_столбцов` / `количество_значений` / split:

| `output_policy` | Поведение |
| --------------- | --------- |
| `new` (default) | Создать столбец `new_column`, если нет; если есть — **перезаписать** значения (заголовок не менять) |
| `replace` | То же, но имя может совпадать с существующим исходным (явная перезапись выбранного столбца: `new_column` = целевой) |

| `position` | Default | Как у `разделить_по_столбцам` |
| ---------- | ------- | ---------------------------- |
| `_конец_` | default | справа от data_range |
| `_начало_` | | слева |
| `_перед_` / `_после_` | | относительно `relative_column` |

Если столбец уже существует — вставка **не** выполняется, пишем в найденный индекс.

## 3. Параметры (JSON, колонка C)

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "sheet": "Сводная",
  "new_column": "Категория",
  "position": "_конец_",
  "trim": true,
  "case_sensitive": false,
  "compare_as": "auto",
  "rules": [
    {"column": "Сумма", "op": "ge", "value": 10000, "then": "Крупный"},
    {"column": "Сумма", "op": "ge", "value": 1000, "then": "Средний"},
    {"column": "Статус", "op": "eq", "value": "Отмена", "then": "Отменён"}
  ],
  "otherwise": "Мелкий"
}]
```

### 3.1. Общие поля листа

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `sheet` | string | Один лист; пусто — все листы результата |
| `sheets` | string[] | Список листов |
| `fn` | string | `условный_столбец` |
| `as_values` | bool | default `true` |

### 3.2. Столбец результата

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `new_column` | string | Имя столбца результата (обязателен) |
| `position` | string | `_начало_` \| `_конец_` \| `_перед_` \| `_после_` (default `_конец_`) |
| `relative_column` | string | Опорный столбец для `_перед_` / `_после_` |
| `output_policy` | string | `new` \| `replace` (default `new`) |

### 3.3. Правила и иначе

| Поле | Тип | Описание |
| ---- | --- | -------- |
| `rules` | object[] | Упорядоченный список правил (может быть пустым → всё = `otherwise`) |
| `otherwise` | any | Литерал «иначе» (default `""`) ИЛИ conditional-блок: `{"rules":[...], "otherwise":..., "otherwise_column":...}` (в v1 поддерживается) |
| `otherwise_column` | string | Столбец «иначе» (только если `otherwise` НЕ conditional-блок) |

Элемент `rules[]`:

| Поле | Тип | Обязателен |
| ---- | --- | ---------- |
| `column` | string | да |
| `op` | string | да |
| `value` | any | да*, кроме blank-op |
| `value_column` | string | альтернатива `value` |
| `then` | any | да* |
| `then_column` | string | альтернатива `then` |

\* для `is_blank` / `is_not_blank` — `value` не нужен; `then` / `then_column` — нужен один.

### 3.4. Сравнение

| Поле | Тип | Default |
| ---- | --- | ------- |
| `trim` | bool | `true` |
| `case_sensitive` | bool | `false` |
| `compare_as` | string | `auto` |
| `blank_left` | string | `as_empty` |
| `non_comparable` | string | `false` |

Глобальные `trim` / `case_sensitive` / `compare_as` можно **переопределить** на уровне правила теми же ключами (v1.1; в v1 — только блок верхнего уровня).

## 4. Визард (`_SHEET_BLOCK_FORM_SCHEMAS`)

**Заголовок:** «Условный столбец»  
**Кнопка:** «Параметры…» в постобработке RANGE / FINAL.

### 4.1. Поля формы (верх)

| Поле | Тип UI | Подпись | Примечание |
| ---- | ------ | ------- | --------- |
| `new_column` | text | Имя нового столбца | обязательно |
| `position` | `combo` | Куда вставить | подписи как у split / переставить |
| `relative_column` | `combo` + headers | Опорный столбец | при `_перед_` / `_после_` |
| `otherwise` | text | Иначе (значение) | литерал |
| `otherwise_column` | `combo` + headers | Иначе из столбца | пусто = использовать `otherwise` |
| `trim` | `bool` | Обрезать пробелы | |
| `case_sensitive` | `bool` | Учитывать регистр | |
| `compare_as` | `combo` | Сравнение как | auto / текст / число / дата |

### 4.2. Список правил (UX)

Правила — **накопительный** UI (эталон: сортировка `keys`, не сырой JSON):

1. Блок «Добавить правило»:
   - `column` — combo заголовков;
   - `op` — combo с **русскими** подписями (`CONDITIONAL_OP_CHOICES`);
   - `value` — text **или** переключатель «из столбца» → `value_column` combo;
   - `then` — text **или** «из столбца» → `then_column`.
2. Кнопка **«+»** добавляет правило в список (снизу).
3. Список выбранных правил (read-only строки вида `Сумма ≥ 1000 → Крупный`).
4. Кнопки **`×`** (удалить последнее) и **`××`** (очистить все) — как у `columns_pick`.
5. Порядок = порядок в JSON; в v1 **без** drag-reorder (при необходимости — удалить и набрать заново; v2 — ↑↓).

Сериализация: `_text_to_block_field` / отдельный helper → `rules: [...]`.

Подсказка (hint):

```text
Аналог Power Query «Условный столбец».
Правила сверху вниз: первое совпадение побеждает; иначе — поле «Иначе».
Значения пишутся в память (не формулы Calc). Для сложных выражений — «применить_формулу».
```

Константы UI — только в `libre_macros_param_wizard_cfg.py`:

- `CONDITIONAL_OP_CHOICES` — `(code, label)`;
- `CONDITIONAL_COMPARE_AS_CHOICES`;
- `CONDITIONAL_POSITION_CHOICES` (переиспользовать общие position labels).

Регистрация (после реализации):

1. `_PP_RANGE_MAP_SPEC` / `_FINAL_MAP_SPEC` (`libre_macros_collect_cfg.py`);
2. `_FALLBACK_PP_RANGE_CHOICES` / `_FALLBACK_FINAL_CHOICES` + REST hints;
3. `_SHEET_BLOCK_FORM_FNS` + schema (`libre_macros_param_wizard_cfg.py`);
4. `_normalize_conditional_column_block` + `JSON_ONLY_FNS` (`libre_macros_param_codec.py`); алиасы в `normalize_fn_key`;
5. импорт в `libre_macros_lib.py` / `libre_macros_values_lib.py`;
6. пресет сценария во визарде (опционально).

## 5. Валидация

1. `new_column` пуст → ошибка.
2. `rules` не список → ошибка.
3. Правило без `column` / `op` → ошибка.
4. `op` неизвестен → ошибка.
5. `op` не blank-тип и нет ни `value`, ни `value_column` → ошибка.
6. Одновременно `value` и `value_column` (непустые) → ошибка.
7. Нет ни `then`, ни `then_column` → ошибка.
8. Одновременно `then` и `then_column` → ошибка (то же для otherwise).
9. Столбец из правила / `*_column` не найден в data_range → ошибка.
10. `position` ∈ `{_перед_, _после_}` и `relative_column` не найден (при вставке нового) → ошибка.
11. `rules` пуст и нет `otherwise` / `otherwise_column` → WARN, заполнить пустыми строками.
12. Циклическая ссылка `new_column` как `value_column` / `then_column` при **создании** нового столбца → ошибка; при перезаписи существующего — разрешено (чтение старого значения до записи — из исходной матрицы).
 13. Если `otherwise` является conditional-блоком (объект с ключом `rules`):
     - `otherwise_column` на верхнем уровне должен быть пуст/отсутствовать (иначе ошибка валидации v1);
     - внутри nested conditional-блока должны быть валидны `rules` и финальные `otherwise` / `otherwise_column` по тем же правилам.

## 6. Примеры

### 6.1. Бакеты по сумме (классика PQ)

**Вход:**

| Товар | Сумма |
| ----- | ----- |
| A | 15000 |
| B | 2500 |
| C | 100 |

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "new_column": "Категория",
  "rules": [
    {"column": "Сумма", "op": "ge", "value": 10000, "then": "Крупный"},
    {"column": "Сумма", "op": "ge", "value": 1000, "then": "Средний"}
  ],
  "otherwise": "Мелкий"
}]
```

**Результат:** Крупный / Средний / Мелкий.

Порядок правил важен: сначала ≥10000, иначе ≥1000 попал бы в «Средний» и крупный тоже.

### 6.2. Текст: contains + статус

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "new_column": "Группа",
  "rules": [
    {"column": "Наименование", "op": "contains", "value": "ООО", "then": "Юрлицо"},
    {"column": "Наименование", "op": "starts_with", "value": "ИП", "then": "ИП"}
  ],
  "otherwise": "Прочее"
}]
```

### 6.3. Сравнение двух столбцов + результат из столбца

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "new_column": "Выбор",
  "rules": [
    {
      "column": "Цена1",
      "op": "lt",
      "value_column": "Цена2",
      "then_column": "Поставщик1"
    }
  ],
  "otherwise_column": "Поставщик2"
}]
```

### 6.4. Пустые ячейки

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "new_column": "Флаг",
  "rules": [
    {"column": "Комментарий", "op": "is_blank", "then": "Нет комментария"},
    {"column": "Комментарий", "op": "is_not_blank", "then": "Есть"}
  ],
  "otherwise": ""
}]
```

### 6.5. Вставка после конкретного столбца

```json
[{
  "v": 1,
  "fn": "условный_столбец",
  "new_column": "Уровень",
  "position": "_после_",
  "relative_column": "Сумма",
  "rules": [
    {"column": "Сумма", "op": "gt", "value": 0, "then": "Положительный"}
  ],
  "otherwise": "Ноль/отрицательный"
}]
```

### 6.6. ELSE как вложенная цепочка rules (nested ELSE IF в v1)

```json
[
  {
    "v": 1,
    "fn": "условный_столбец",
    "new_column": "Категория",
    "rules": [
      { "column": "Сумма", "op": "ge", "value": 10000, "then": "Крупный" }
    ],
    "otherwise": {
      "rules": [
        { "column": "Сумма", "op": "ge", "value": 1000, "then": "Средний" }
      ],
      "otherwise": "Мелкий"
    }
  }
]
```

## 7. Место в пайплайне

- Секции: **Постобработка_Диапазон**, **Финальная_обработка**; xml/direct — желательно в v1 (чистая логика на матрице, без формул листа).
- Логично **после** `замена_значений` / `нормализация_текста` / `разделить_по_столбцам` (когда уже есть чистые поля для условий).
- **До** `удалить_дубликаты` / `группировать_строки`, если категория входит в ключ или группировку.
- **Альтернатива:** `применить_формулу` с `=IF(…)` — оставить для формул с `{row_id}` и карты переменных.

Связь с roadmap: сейчас в матрице PQ помечено как «низкий» через workaround формулой; отдельная fn поднимает UX до уровня PQ Conditional Column без Calc IF.

## 9. Граничные случаи

| Случай | Ожидание |
| ------ | -------- |
| `rules` пуст | все строки = `otherwise` |
| Ни одно правило не сработало | `otherwise` / `otherwise_column` |
| `1` (число) vs `"1"` (текст) при `compare_as=auto` и `eq` | как текст после display — могут совпасть; при `number` — оба → 1.0 |
| Дата в ячейке vs `"01.02.2024"` в `value` | `compare_as=date` или `auto` на `ge`/`le` |
| `contains` на числе | привести left к тексту |
| Формула в исходном столбце | при `as_values=true` — значение; иначе display/formula text по политике host |
| Перезапись `new_column`, который есть в `then_column` | читать из **снимка** до записи |
| Очень много правил (50+) | OK; лог hit counts |
| Объединённые ячейки | WARN; значение верхней-left |
| `is_blank` и пробелы при `trim=true` | `"   "` → blank |
| Булево JSON `true`/`false` в `then` | записать как текст `"TRUE"`/`"FALSE"` или bool UNO — зафиксировать: **строка как в PQ output text**, либо нативный тип если `then` number/bool в JSON |

**Фиксация типов записи `then` (v1):**

| JSON-тип `then` / `otherwise` | В ячейку |
| ----------------------------- | -------- |
| string | String |
| number (int/float) | Double / число |
| bool | String `"Да"` / `"Нет"` **или** bool — **выбрать: `"Да"`/`"Нет"`** (дружелюбно RU) |
| null | пустая ячейка |
