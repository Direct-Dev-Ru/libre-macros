# ТЗ: анкета_в_таблицу

Новая функция постобработки / финальной стадии (RANGE / FINAL; по возможности `Постобработка_xml`).
Визард: блок на выбранный лист (режим «все листы» допустим, но на практике анкета обычно на одном листе).

**Имя ключа (fn):** `анкета_в_таблицу`  
**Синоним в UI (опционально):** «анкетная форма → таблица», «вопросы/ответы → wide».  
**Обратная операция:** [новая функция таблица_в_анкету.md](новая%20функция%20таблица_в_анкету.md) (`таблица_в_анкету`) — wide-строки снова в пары «вопрос → ответ».

**Цель:** на листе в **двух колонках** идут пары «вопрос → ответ»; такие пары могут **повторяться блоками** вниз по листу (один и тот же набор вопросов снова и снова). Нужно «перевернуть» данные в **широкую таблицу**:

- **столбцы** = уникальные формулировки вопросов из колонки вопросов (+ опционально поля из шапки листа и/или шапки блока);
- **строки** = отдельные «анкеты» / блоки ответов.

**Шапка (preamble)** бывает двух уровней (можно комбинировать):

1. **Шапка листа** (типичный случай) — один раз в начале листа: служебный диапазон строк (название формы, реквизиты опроса, инструкции). Задаётся **абсолютными номерами строк** на листе + отдельно указывается, **с какой строки начинаются анкеты**. Значения шапки листа общие для всех строк wide-таблицы (копируются в каждую строку-анкету) либо только вырезаются из потока (`ignore`).
2. **Шапка блока** (опционально) — тот же по структуре кусок **перед каждым** комплектом Q/A (номер бланка, дата экземпляра). Повторяется вниз по листу; границы — относительно старта блока.

---

## 1. Исходная форма (вход)

### 1.1. Только пары вопрос/ответ

| A (вопрос)        | B (ответ)   |
|-------------------|-------------|
| ФИО               | Иванов      |
| Возраст           | 30          |
| Город             | Казань      |
| ФИО               | Петров      |
| …                 | …           |

### 1.2. Шапка листа + анкеты ниже (основной случай)

Один раз вверху листа — служебный блок; ниже с явной строки — поток анкет (пары Q/A, возможно с повторяющейся шапкой блока).

| Строка | A / содержимое              | Смысл |
|--------|---------------------------|--------|
| 1–4    | Название опроса, период, орг. | **шапка листа** (`sheet_preamble_row_from`…`to`) |
| 5      | (пусто / разделитель)     | вне шапки, до анкет |
| 6      | ФИО → Иванов              | **начало анкет** (`forms_start_row` = 6) |
| 7      | Возраст → 30              | тело |
| …      | …                         | … |
| N      | ФИО → Петров              | следующая анкета |

Обязательно задать **два** якоря:

1. диапазон строк шапки листа (`sheet_preamble_row_from` / `sheet_preamble_row_to`);
2. строку начала анкет (`forms_start_row`) — с неё идёт нарезка блоков; всё выше, кроме шапки, в Q/A не входит.

### 1.3. С повторяющейся шапкой **каждого** блока (дополнительно)

На каждую анкету: сначала N строк шапки экземпляра, затем пары Q/A; затем снова шапка + пары.

| Строка | A                         | B            | Смысл |
|--------|---------------------------|--------------|--------|
| 1      | Бланк №                   | 1001         | шапка блока |
| 2      | Дата                      | 01.02.2026   | шапка блока |
| 3      | ФИО                       | Иванов       | тело |
| …      | …                         | …            | … |
| 8      | Бланк №                   | 1002         | шапка блока |
| 9      | Дата                      | 02.02.2026   | шапка блока |
| 10     | ФИО                       | Петров       | тело |

Можно совместить с §1.2: сначала шапка листа (строки 1–K), `forms_start_row` = K+1, а внутри потока анкет ещё и `block_preamble_*`.

Шапка (листа или блока) может занимать **не только** колонки вопрос/ответ — см. `*_preamble_mode` и `*_preamble_fields`.

Правила узнавания потока:

1. Колонка вопросов и колонка ответов — `question_column`, `answer_column`.
2. Чтение **сверху вниз**; для нарезки анкет — с `forms_start_row` (если задан) иначе с `start_row`.
3. **Шапка листа** (§2.0.A) читается один раз из абсолютного диапазона; в поток блоков не входит.
4. **Шапка блока** (§2.0.B), если задана — вырезается в начале **каждого** блока перед парным Q/A.
5. Пустые строки — разделители или пропуск (`blank_row_policy`).
6. Пустой вопрос + непустой ответ — WARN; `orphan_answer`.

## 2. Принцип разбиения на блоки (анкеты)

Блок = одна будущая **строка** wide-таблицы = пары вопрос/ответ (+ значения шапки листа / шапки блока в столбцах).

### 2.0. Шапка (`preamble`): лист и/или блок

#### 2.0.A. Шапка листа (scope = `sheet`) — приоритетный сценарий

**Назначение:** один диапазон строк на весь лист (обычно сверху). Не участвует в `block_mode`. Нужно указать:

| Что | Параметры | Смысл |
|-----|-----------|--------|
| Где лежит шапка | `sheet_preamble_row_from` + `sheet_preamble_row_to` (1-based **номера строк листа**) | Абсолютный диапазон; включительно |
| Откуда анкеты | `forms_start_row` (1-based) | Первая строка потока анкет (тело / шапка блока). Должна быть **строго ниже** `sheet_preamble_row_to` (или равенство запрещено — валидация) |
| Как читать | `sheet_preamble_mode` | те же смыслы, что у блочной: `qa_pair` \| `fixed_cells` \| `ignore` |
| Ячейки | `sheet_preamble_fields` | для `fixed_cells`: адреса **абсолютные на листе** (`"B2"`, `"D3"`) или относительно `sheet_preamble_row_from` — зафиксировать в реализации один вариант; в ТЗ default = **абсолютные A1-адреса листа** |

Порядок на листе:

1. Прочитать шапку листа из `[sheet_preamble_row_from … sheet_preamble_row_to]` → набор полей (общие для всех анкет).
2. Нарезать блоки **только** начиная с `forms_start_row` (до `end_row`).
3. В каждую строку wide подставить одни и те же значения шапки листа (префикс столбцов, если `preamble_columns_first`).

Если шапка листа не нужна — поля `sheet_preamble_*` / `forms_start_row` не задавать; тогда старт потока = `start_row` (как раньше).

`has_header_in_source`: относится к строке **в зоне анкет** (первая строка потока — заголовки «Вопрос/Ответ»), не к шапке листа.

#### 2.0.B. Повторяющаяся шапка блока (scope = `block`)

**Назначение:** перед каждым комплектом Q/A — одинаковый по высоте кусок (номер бланка и т.п.).

| Способ | Параметры | Смысл |
|--------|-----------|--------|
| Фиксированная высота | `block_preamble_rows` (int > 0) | Первые N строк **каждого** блока — шапка |
| Диапазон внутри блока | `block_preamble_row_from` + `block_preamble_row_to` (1-based **внутри блока**) | То же явными номерами шаблона |
| До маркера тела | `block_preamble_until_question` | С начала блока до (не включая) этой формулировки |

Синонимы для совместимости черновика: `preamble_rows` ≡ `block_preamble_rows`, `preamble_row_from/to` ≡ `block_preamble_*`, `preamble_until_question` ≡ `block_preamble_until_question`, `preamble_mode` ≡ `block_preamble_mode` (если нет `sheet_preamble_*`). В новой схеме предпочтительны имена с префиксом `block_` / `sheet_`.

#### Как читать значения (`sheet_preamble_mode` / `block_preamble_mode`)

| Режим | Поведение |
|-------|-----------|
| `qa_pair` (default) | Те же `question_column` / `answer_column`: строки шапки — пары «метка→значение» → столбцы wide |
| `fixed_cells` | Список `{cell, as}`; для листа — абсолютные ячейки; для блока — относительно **первой строки блока** |
| `ignore` | Только вырезать из потока / не путать с Q/A; в результат не писать |

#### Связь с `block_mode`

1. Шапка **листа** уже отрезана; `block_mode` работает только на `[forms_start_row … end_row]`.
2. Старт блока → если есть block-preamble, отнести к нему N строк (или до маркера) → остальное тело Q/A до следующего старта.
3. `block_start_question` — ключ **тела** (или первой строки после block-preamble), не строки шапки листа.
4. `questions_per_block` — только пары тела (без block-preamble); опционально `block_total_rows` = block-preamble + тело.

#### Столбцы результата из шапки

Порядок по умолчанию (`preamble_columns_first: true`): столбцы **шапки листа** → столбцы **шапки блока** → вопросы тела.  
Дубликат имени — `duplicate_question` / WARN.

### 2.1. Стратегия `block_mode`

| Режим | Как режется поток пар |
|-------|------------------------|
| `by_repeat_key` (рекомендуемый default) | Задать `block_start_question` — вопрос, с которого начинается каждая анкета (часто первый в списке, напр. «ФИО»). Новый блок начинается каждый раз, когда снова встречается этот вопрос (после хотя бы одной пары текущего блока). |
| `by_blank_row` | Новый блок после одной (или N) полностью пустых строк. |
| `fixed_size` | Ровно `questions_per_block` подряд идущих непустых пар = один блок (если на листе строго одинаковая длина анкеты). |
| `by_unique_cycle` | Новый блок, когда очередной вопрос **уже встречался в текущем блоке** (детектор цикла по множеству вопросов текущего блока). Удобно, если стартовый вопрос не фиксирован, но набор в блоке без повторов. |

Если одновременно заданы конфликтующие режимы — приоритет явного `block_mode`; остальное игнорировать с WARN в лог.

### 2.2. Неполные блоки

- В конце листа блок без полного набора вопросов — **всё равно** писать строку (пустые ячейки в недостающих столбцах), если `keep_partial_blocks: true` (default true).
- При `false` — неполный блок отбросить + запись в лог.

### 2.3. Повтор вопроса внутри одного блока

Если в одном блоке один и тот же вопрос встретился дважды:

| `duplicate_question` | Поведение |
|----------------------|-----------|
| `last` (default) | Побеждает последнее значение |
| `first` | Оставить первое |
| `concat` | Склеить ответы через `concat_sep` (default `"; "`) |
| `error` | Проблема в лог, блок пропустить |

## 3. Формирование wide-таблицы (результат)

### 3.1. Столбцы

1. Собрать **упорядоченный** список уникальных вопросов:
   - порядок = порядок **первого появления** вопроса при чтении листа сверху вниз (стабильный, предсказуемый);
   - либо порядок из явного `column_order` (список строк-вопросов); вопросы вне списка — в конец (если `extra_questions: append`) или отбросить (`drop`).
2. Имена столбцов результата = текст вопроса (как в источнике), с опциями нормализации (см. §4).
3. Опционально ведущие служебные столбцы:
   - `block_index` (1-based номер анкеты),
   - `source_start_row` (первая строка блока на исходном листе, включая шапку),
   - поля из шапки листа / шапки блока (§2.0),
   - поля из `carry_columns` — значения из других колонок исходника на строке старта блока или на строке ключа (см. §4).

### 3.2. Строки

Каждый блок → одна строка: для каждого столбца-вопроса подставить ответ из пары блока; нет пары → пусто.

### 3.3. Куда писать (`output`)

| Значение | Поведение |
|----------|-----------|
| `new_sheet` (default) | Лист `dest_sheet`; при занятом имени — `_2`, `_3`, … |
| `inplace` | Очистить область записи на том же листе и записать wide с `dest_cell` (default A1). **Опасный** режим, если перекрывает источник: при overlap без `clear_source_first` — ошибка. |
| `replace_sheet` | Очистить весь лист `sheet` и записать wide с A1 (исходные пары пропадают). |

После записи: при необходимости зарегистрировать лист в очереди оформления (как после `копировать_лист` / merge), чтобы дальше работали автофильтр / ширины / freeze.

### 3.4. Строка заголовков результата

Первая строка wide = имена столбцов (вопросы + служебные).  
`header_row` на **выходе** всегда 1 относительно угла записи; это не путать с `header_row` входа.

## 4. Параметры (JSON)

```json
[{
  "v": 1,
  "fn": "анкета_в_таблицу",
  "sheet": "Опрос",
  "question_column": "A",
  "answer_column": "B",
  "sheet_preamble_row_from": 1,
  "sheet_preamble_row_to": 4,
  "sheet_preamble_mode": "qa_pair",
  "forms_start_row": 5,
  "block_mode": "by_repeat_key",
  "block_start_question": "ФИО",
  "output": "new_sheet",
  "dest_sheet": "Опрос_таблица"
}]
```

### 4.1. Лист и колонки источника

| Поле | Тип | Описание |
|------|-----|----------|
| `sheet` / `sheets` | string / string[] | Лист(ы) с анкетой |
| `question_column` | col-ref | Колонка вопросов (обязателен) |
| `answer_column` | col-ref | Колонка ответов (обязателен; ≠ question) |
| `start_row` | int 1-based | Начало чтения, если нет `forms_start_row` (default 1 или 2 при `has_header_in_source`) |
| `forms_start_row` | int 1-based | **С какой строки листа начинаются анкеты** (нарезка блоков). Если задан — имеет приоритет над `start_row` для потока Q/A |
| `end_row` | int | Конец; пусто — до последней непустой в question/answer |
| `has_header_in_source` | bool | Первая строка **потока анкет** — заголовки «Вопрос/Ответ», не данные (default false) |

### 4.2. Шапка листа (один раз на лист)

| Поле | Тип | Описание |
|------|-----|----------|
| `sheet_preamble_row_from` / `sheet_preamble_row_to` | int | Абсолютный диапазон строк шапки на листе (включительно). Оба заданы → шапка листа активна |
| `sheet_preamble_mode` | string | `qa_pair` \| `fixed_cells` \| `ignore` (default `qa_pair`) |
| `sheet_preamble_fields` | list | Для `fixed_cells`: `[{"cell":"B2","as":"Период"}, …]` — **абсолютные** адреса на листе |
| `preamble_columns_first` | bool | Столбцы шапок (лист, затем блок) левее тела (default true) |

Без `sheet_preamble_row_from/to` шапки листа нет. При наличии диапазона **рекомендуется** явно задать `forms_start_row` (иначе default = `sheet_preamble_row_to + 1`, WARN если не задан вручную).

### 4.3. Повторяющаяся шапка блока

| Поле | Тип | Описание |
|------|-----|----------|
| `block_preamble_rows` | int | Число строк шапки в **начале каждого** блока; 0 / нет — нет |
| `block_preamble_row_from` / `block_preamble_row_to` | int | Альтернатива: строки **внутри блока** (1-based); приоритет над `block_preamble_rows` |
| `block_preamble_until_question` | string | Шапка блока до (не включая) этой формулировки |
| `block_preamble_mode` | string | `qa_pair` \| `fixed_cells` \| `ignore` |
| `block_preamble_fields` | list | Для `fixed_cells`: `cell` относительно старта блока |
| `block_total_rows` | int | Для `fixed_size`: полная высота экземпляра = block-preamble + тело |

Синонимы без префикса `block_` (`preamble_rows`, …) — см. §2.0.B.

### 4.4. Нарезка блоков

| Поле | Тип | Описание |
|------|-----|----------|
| `block_mode` | string | `by_repeat_key` \| `by_blank_row` \| `fixed_size` \| `by_unique_cycle` |
| `block_start_question` | string | Для `by_repeat_key`; обычно **первый вопрос тела** |
| `blank_rows_to_split` | int | Для `by_blank_row` (default 1) |
| `questions_per_block` | int | Для `fixed_size` — пары **тела** (без block-preamble), если нет `block_total_rows` |
| `keep_partial_blocks` | bool | default true |
| `duplicate_question` | string | `last` \| `first` \| `concat` \| `error` |
| `concat_sep` | string | Для `concat` |
| `orphan_answer` | string | `skip` \| `attach_prev` (default `skip`) |
| `blank_row_policy` | string | `split` \| `skip` \| `ignore` — смысл пустых строк вне `by_blank_row` |

### 4.5. Нормализация текста вопроса (для ключа столбца и матчинга)

| Поле | Тип | Описание |
|------|-----|----------|
| `trim_questions` | bool | default true |
| `collapse_spaces` | bool | сжать повторные пробелы (default true) |
| `ignore_case` | bool | сравнение вопросов без регистра (default false); **отображаемое** имя столбца — как при первом появлении |
| `normalize_question` | string | доп. режим: `none` \| `lower` \| `title` (только для ключа сопоставления) |

Ответы: `trim_answers` (default true); типы числа/даты по возможности сохранить (если ячейка уже число — не превращать в текст).

### 4.6. Порядок и состав столбцов

| Поле | Тип | Описание |
|------|-----|----------|
| `column_order` | string[] | Явный порядок вопросов-столбцов |
| `extra_questions` | string | `append` \| `drop` (default `append`) |
| `add_block_index` | bool | Колонка `#Блок` / `block_index` в начале (default false) |
| `add_source_row` | bool | Колонка с номером стартовой строки блока (default false) |
| `carry_columns` | list | Доп. колонки исходника: значение брать с строки `block_start` или `key_row`. Элемент: `{"column":"C","as":"Филиал","from":"block_start"}` |

### 4.7. Вывод

| Поле | Тип | Описание |
|------|-----|----------|
| `output` | string | `new_sheet` \| `inplace` \| `replace_sheet` |
| `dest_sheet` | string | Для `new_sheet` |
| `dest_cell` | string | Угол записи для `inplace` (default `A1`) |
| `clear_source_first` | bool | Перед `inplace` очистить использованный диапазон пар |

## 5. Валидация

1. `question_column` / `answer_column` не заданы или совпадают → ошибка.
2. `by_repeat_key` без `block_start_question` → ошибка.
3. `fixed_size` без положительного `questions_per_block` и без согласованного `block_total_rows` → ошибка.
4. Задан только один из `sheet_preamble_row_from` / `sheet_preamble_row_to` → ошибка; `from` > `to` → ошибка.
5. `forms_start_row` ≤ `sheet_preamble_row_to` (при активной шапке листа) → ошибка («анкеты пересекают шапку листа»).
6. `sheet_preamble_mode=fixed_cells` без `sheet_preamble_fields` → ошибка; то же для `block_preamble_*`.
7. `block_preamble_rows` < 0 или `block_preamble_row_from` > `block_preamble_row_to` → ошибка.
8. Конфликт способов границы шапки блока → приоритет: `block_preamble_until_question` > `block_preamble_row_from/to` > `block_preamble_rows`; WARN.
9. После разбора 0 блоков → предупреждение, лист результата не создавать (или только заголовок — `create_empty`).
10. Число уникальных вопросов (тело + шапки qa_pair) = 0 → ошибка.
11. Слишком широкая таблица (напр. > 500 столбцов) → ошибка/предупреждение с порогом в коде.

DEBUG: диапазон шапки листа, `forms_start_row`, высота block-preamble, число пар тела, блоков, столбцов (лист/блок/тело), `block_mode`, dest.

## 8. Граничные случаи (зафиксировать в реализации)

| Случай | Ожидание |
|--------|----------|
| Только один блок на лист | Одна строка данных + заголовок |
| Вопросы в разном порядке в разных блоках | Столбцы по первому появлению глобально; в строке значения по имени вопроса |
| В блоке N меньше вопросов, чем уникальных глобально | Пустые ячейки |
| В блоке «лишний» вопрос, нигде больше не встречавшийся | Новый столбец (если `extra_questions=append`) |
| Ответ — формула | При UNO желательно `as_values` (параметр, default true) перед сборкой |
| Объединённые ячейки в колонке вопросов | Читать отображаемое/верхнее значение объединения; WARN в лог |
| Шапка листа задана, `forms_start_row` нет | Default = `sheet_preamble_row_to + 1`; WARN |
| Между шапкой листа и `forms_start_row` есть строки | Не читать как Q/A (пропуск «дыры») |
| Шапка блока есть только у первого экземпляра | `keep_partial_blocks` + пустые столбцы шапки блока; WARN «block preamble shorter» |
| Высота шапки блока плавает | Предпочтительно `block_preamble_until_question` |
| `block_start_question` совпал со строкой шапки блока | WARN; ключ из тела или увеличить block-preamble |
| Поля шапки листа попали в поток анкет | Не должны: поток только с `forms_start_row` |
