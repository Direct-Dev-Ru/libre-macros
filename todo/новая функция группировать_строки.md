# ТЗ: группировать_строки (group by)

> **Статус (3.10.715):** реализовано — `lm_pp_range_group_by_rows` / `merge_final_group_by_rows`,
> визард, docs, сценарий `17_group_by_rows.xltx`.

Новая функция постобработки / финальной стадии (RANGE + FINAL).
Визард: блок на выбранный лист или на все листы (`sheet` / `sheets`).

**Имя ключа (fn):** `группировать_строки`  
**Синонимы / алиасы:** `group_by`, `group by`, `groupby`.  
**Lib:** `lm_pp_range_group_by_rows` / `merge_final_group_by_rows`.  
**Аналог Power Query:** Group By (*Transform → Group By*).

---

## Цель

Сжать таблицу: заменить набор строк группами по ключам, и для каждой группы посчитать набор агрегатов (SUM/COUNT/…).

В отличие от `группировка_по_столбцу` (SUBTOTAL/outline), эта функция **уменьшает число строк** (in-memory hash map) до количества уникальных ключей.

---

### Пример A — ключ `Отдел` + `Месяц` (`output=inplace`)

JSON (сжато):

```json
[{"v":1,"fn":"группировать_строки",
  "key_columns":["'Отдел'","'Месяц'"],
  "aggregations":[
    {"op":"sum","column":"'Сумма'","as":"Сумма"},
    {"op":"count","as":"Количество"}
  ],
  "output":"inplace"}]
```

**Результат** (4 группы; порядок — по первому появлению ключа):

| Отдел | Месяц | Сумма | Количество |
|-------|-------|------:|-----------:|
| МСУЗ | Январь | 160 | 3 |
| МСУЗ | Февраль | 200 | 1 |
| ИТ | Январь | 105 | 3 |
| Склад | Февраль | 100 | 3 |

Как сложилось:

| Группа | Строки | Сумма | Count |
|--------|--------|------:|------:|
| МСУЗ / Январь | 100 + 50 + 10 (`мсуз`) | 160 | 3 |
| МСУЗ / Февраль | 200 | 200 | 1 |
| ИТ / Январь | 30 + 70 + 5 (`  ИТ  `) | 105 | 3 |
| Склад / Февраль | 40 + ~~нечисло~~ + 60 | 100 | 3 |

Столбцы `ID` и `Комментарий` в результат **не** попадают (только ключи + `aggregations[].as`).

## 1. Контракт JSON (v1)

```json
[
  {
    "v": 1,
    "fn": "группировать_строки",
    "key_columns": ["'Отдел'", "'Месяц'"],
    "aggregations": [
      {"op": "sum", "column": "'Сумма'", "as": "Сумма"},
      {"op": "count", "column": "'ID'", "as": "Количество"}
    ],
    "output": "inplace",
    "dest_sheet": "Свод",
    "sort_keys": false,
    "key_trim": true,
    "key_case_sensitive": false,
    "skip_empty_keys": true
  }
]
```

### 1.1. Поля

- `key_columns` — **columns_pick**, список столбцов ключа. Минимум 1.
- `aggregations` — массив объектов:
  - `op` — один из: `sum`, `count`, `min`, `max`, `avg`, `first`/`last`.
  - `column` — **columns_pick**; для `count`:
    - если `column` задан — считать непустые значения;
    - если `column` отсутствует/пустой — считать строки (как `COUNT(*)`).
  - `as` — литерал названия выходного столбца.
- `output`:
  - `inplace` — заменить исходный прямоугольник на сгруппированную таблицу;
  - `new_sheet` — записать в `dest_sheet` (A1).
- `dest_sheet` — имя листа назначения (используется только при `output=new_sheet`).
- `sort_keys` — сортировать результат по ключам (по умолчанию `false`).
- `key_trim` — применять `trim` к строковым ключам (по умолчанию `true`).
- `key_case_sensitive` — чувствительность к регистру для строковых ключей (по умолчанию `false`).
- `skip_empty_keys` — не создавать группы для строк, у которых **любая** часть ключа (после trim) пустая (по умолчанию `true`).

## 2. Принцип работы (ожидаемое поведение)

1. Определить `data_range` и `header_row_range` из хоста.
2. Прочитать матрицу в память (`getDataArray` + materialize формул по политике `as_values` если требуется).
3. Построить ключ группы:
   - tuple значений по `key_columns`;
   - нормализация строк: trim, при необходимости casefold.
4. В проходе по строкам данных:
   - создать запись в hash map для ключа при первом появлении;
   - обновлять агрегаты.
5. Сформировать выходную матрицу:
   - колонки: `key_columns` + все `aggregations[].as`;
   - одна строка на ключ.
6. Записать результат:
   - `inplace`: очистить область и записать по левому верхнему углу источника;
   - `new_sheet`: записать с A1.
7. Журнал:
   - число исходных строк данных,
   - число групп,
   - число пропущенных строк при `skip_empty_keys=true`.

## 3. Поддержка типов и nil-значений (v1)

- `sum/avg`:
  - по входу пытаться интерпретировать значения как число;
  - если значение пустое/не число — для `sum` пропустить, для `avg` не включать в делитель.
- `count`: считать непустые значения по заданной `column` (для `column`=None — строки целиком).
- `min/max`: сравнивать как числа, если распознано, иначе как строки (лексикографически).

Политика ошибок/нераспознаваний — по умолчанию `skip` (без падения шага).

## 4. UX
