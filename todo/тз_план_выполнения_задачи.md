# ТЗ: план выполнения задачи (todo_task)

**Статус:** ТЗ согласовано (к реализации).

**Объект:** серия макросов `todo_task` (`macro-lib/todo_task.py`, `pythonpath/todo_task_*`).

**Связано с:** лист задач «Задачи…», скрытые листы `__Удаленные_Задачи`, `__План_задач`, `__Архив_план`, справочники `__Справочники_задачи`, диалог редактирования задачи (`show_todo_task_edit_dialog`).

---

## 1. Цель

Дать пользователю возможность вести **план выполнения задачи** — иерархический перечень этапов с датами, длительностью в **рабочих днях**, ответственными и результатом.

Требования верхнего уровня:

1. План хранится на **скрытом служебном листе** книги, привязка к задаче — по **GUID**.
2. При **удалении задачи** строки плана архивируются на скрытый лист `__Архив_план`, затем удаляются с `__План_задач` (см. п. 6).
3. Визард плана — **на весь экран**, с **табличной частью** и редактированием строк.
4. Вызов — **кнопка в диалоге редактирования/создания задачи**; подпись кнопки:
   - **«Создать план»** — если для GUID ещё нет ни одного пункта;
   - **«Редактировать план»** — если пункты уже есть.
5. Максимальная **автоматизация дат**: следующий этап наследует начало от окончания предыдущего; учёт **выходных** и **праздников** из справочника; авторасчёт **длительности** в рабочих днях; агрегация по **итоговым пунктам** (1 ← 1.1 + 1.2 + …).

## 3. Модель данных

### 3.1. Скрытый лист планов

| Параметр | Значение |
|---|---|
| Имя листа (константа) | `__План_задач` (скрытый, не защищается паролем «Задачи») |
| Строка заголовков | 1 (как у таблицы задач — поиск в первых 20 строках допустим, но по умолчанию строка 1) |
| Данные | со 2-й строки, **несколько строк на один GUID** (по одной на пункт плана) |
| Сортировка в листе | по `GUID` → по `sort_key` (числовой порядок иерархии) |

### 3.2. Колонки таблицы плана

| id (в коде) | Заголовок на листе | Тип | Обяз. | Описание |
|---|---|---|---|---|
| `guid` | GUID задачи | текст | да | Копия `GUID Строки` родительской задачи |
| `item_no` | Пункт | текст | да | Номер: `1`, `1.1`, `1.2`, `2`, … |
| `is_summary` | Итоговый пункт | да/нет | да | `Да` / пусто. Итоговый пункт **не редактируется** в части дат/длительности — вычисляется из подпунктов |
| `date_start` | Дата начала | дата | для листового | Формат отображения: `ДД.ММ.ГГГГ (ДеньНедели)` |
| `date_end` | Дата окончания | дата | для листового | То же |
| `duration_wd` | Длительность, раб. дни | число | для листового | Целое ≥ 1; пересчитывается при смене дат |
| `assignees` | Ответственные | текст | нет | Свободный текст или ФИО из справочника исполнителей |
| `result_doc` | Результат / отчётный документ | текст | нет | |
| `criticality` | Критичность | текст | нет | Combo из справочника «Критичность плана» (п. 4.3) |
| `sort_key` | Порядок | число | служебная | Для сортировки: `1` → `1.0`, `1.1` → `1.1`, `1.2` → `1.2`, `2` → `2.0` |
| `parent_item` | Родитель | текст | служебная | Для `1.1` → `1`; для `1` → пусто |
| `row_id` | ID строки плана | текст | служебная | UUID строки плана (для стабильной идентификации при перенумерации) |
| `created_at` | Создано | дата-время | служебная | |
| `modified_at` | Изменено | дата-время | служебная | |

**Листовой пункт** — `is_summary` пусто/false: даты, длительность, ответственные, результат редактируются.

**Итоговый пункт** — `is_summary = Да`: пункт-группа (`1` с детьми `1.1`, `1.2`):

- `date_start` = min(дата начала дочерних листовых и итоговых подпунктов);
- `date_end` = max(дата окончания …);
- `duration_wd` = количество **рабочих дней** в объединённом интервале `[date_start … date_end]` **или** сумма длительностей дочерних — **зафиксировать в реализации вариант (а)**: календарная длительность интервала в рабочих днях (см. п. 5.4);
- `assignees` / `result_doc` — не агрегируются автоматически (остаются как ввёл пользователь или пусто).

### 3.3. Индекс в памяти

При открытии визарда для GUID `G`:

```python
plan_rows = load_plan_by_guid(doc, G)  # list[dict]
has_plan = len(plan_rows) > 0
```

Для кнопки в диалоге задачи достаточно `count_plan_items(guid) > 0`.

### 3.4. Скрытый лист архива планов `__Архив_план`

При удалении задачи все строки её плана **копируются** сюда (только значения), затем удаляются с `__План_задач`.

| Параметр | Значение |
|---|---|
| Имя листа | `__Архив_план` (скрытый, без защиты «Задачи») |
| Заголовки | все колонки плана (п. 3.2) **плюс** служебные: |
| `archived_at` | Дата и время архивации |
| `source_sheet` | Имя листа, с которого удалена задача |
| `task_name` | Наименование задачи на момент удаления (для поиска в архиве) |

Строка архива = одна строка плана; у одного GUID при удалении может попасть несколько строк подряд с одинаковыми `archived_at` / `source_sheet` / `task_name`.

Образец реализации: `_archive_deleted_task` + `_ensure_deleted_tasks_sheet`.

## 4. Справочники

### 4.1. Праздники (новый блок на `__Справочники_задачи`)

| Параметр | Значение |
|---|---|
| Заголовок блока (строка 1) | `Праздники` |
| Данные | одна колонка: дата `ДД.ММ.ГГГГ` или дата Calc; со 2-й строки |
| Пустые / дубликаты | игнорировать |
| Редактирование | через существующий «Задача: справочники» (добавить блок в сканер справочников) |

**Рабочий день** = понедельник–пятница **и** дата **не** в списке праздников.

Выходные (сб/вс) обрабатываются так же, как в `default_due_parts()`.

### 4.2. Ответственные

Источник для combo в визарде: колонка исполнителей справочника (как в диалоге задачи) + ручной ввод.

### 4.3. Критичность

**Отдельный справочник** `Критичность плана` на листе `__Справочники_задачи` (колонка с заголовком в строке 1). Значения по умолчанию при первом создании блока:

- `Низкая`
- `Средняя`
- `Высокая`

В визарде — `ComboBox` с этим списком + пустое значение. Матрица приоритетов задачи **не используется**.

## 5. Бизнес-логика дат и длительности

### 5.1. Нормализация даты «влево»

При вводе или программной установке `date_start` / `date_end`:

1. Разобрать дату.
2. Пока дата **не** рабочий день — сдвинуть на **один день назад** («влево»).
3. Записать в ячейку/модель с отображением дня недели (как в колонке «Срок исполнения» задачи: `ДД.ММ.ГГГГ` + день недели).

Если после сдвига дата оказывается «в прошлом» относительно сегодня — **предупреждение**, но не блокировать (план может описывать уже начатые работы).

### 5.2. Связь дат соседних этапов

При изменении `date_end` пункта `N` (листовой или итоговый с известными детьми):

- для следующего по `sort_key` **листового** пункта того же уровня иерархии (или следующего корневого `2` после `1.x`):
  - `date_start` следующего = **следующий рабочий день** после `date_end` текущего;
  - если у следующего уже была `date_end`, пересчитать `duration_wd` или сдвинуть `date_end` (режим — см. 5.3).

При добавлении новой строки «после» выбранной:

- `date_start` новой = следующий рабочий день после `date_end` предыдущей;
- `duration_wd` по умолчанию = `1`;
- `date_end` = `date_start` + (`duration_wd` − 1) рабочих дней (интервал включительный).

### 5.3. Режим пересчёта при изменении длительности / конца

| Пользователь меняет | Поведение по умолчанию |
|---|---|
| `date_start` | Пересчитать `date_end` из `duration_wd` (конец = start + duration − 1 раб. дней) |
| `duration_wd` | Пересчитать `date_end` от `date_start` |
| `date_end` | Пересчитать `duration_wd` = число раб. дней в [start … end] включительно |

Переключатель в визарде (v1 опционально, v2 желательно): **«Фиксировать длительность»** / **«Фиксировать дату окончания»**.

### 5.4. Расчёт `duration_wd`

```text
duration_wd(start, end) =
  количество дат d, где start <= d <= end и d — рабочий день
```

Для итогового пункта `1` с детьми `1.1`, `1.2`:

```text
date_start(1) = min(date_start(1.1), date_start(1.2), …)
date_end(1)   = max(date_end(1.1), date_end(1.2), …)
duration_wd(1) = duration_wd(date_start(1), date_end(1))
```

После любого изменения листового пункта — **пересчитать вверх** всех предков-итоговых (`1` для `1.2` и т.д.).

### 5.5. Общий модуль

```python
# todo_task_plan_lib.py (эскиз API)
is_workday(d, holidays) -> bool
snap_workday_left(d, holidays) -> date
next_workday(d, holidays) -> date   # первый рабочий день СТРОГО после d
add_workdays(start, n, holidays) -> date  # start + (n-1) рабочих дней включительно
workdays_between(start, end, holidays) -> int
```

Кэш праздников на время сессии визарда.

## 6. Удаление задачи и плана

### 6.1. `todo_task_delete`

После успешного `_archive_deleted_task` и **до** `removeByIndex`:

1. Прочитать GUID и наименование удаляемой строки.
2. **`_archive_plan_by_guid(doc, guid, source_sheet, task_name)`** — скопировать все строки плана с `__План_задач` на `__Архив_план` (значения + `archived_at`, `source_sheet`, `task_name`).
3. **`delete_plan_by_guid(doc, guid)`** — физически удалить строки плана с `__План_задач`.
4. Если шаг 2 или 3 не удался — **прервать удаление задачи** (как при сбое архива задачи).

Порядок важен: сначала архив плана, потом удаление с рабочего листа планов, потом удаление строки задачи.

### 6.2. Восстановление из архива

**Не в v1.** Архив только для хранения; отдельная команда «восстановить план» не предусмотрена.

## 7. Копирование, перемещение, слияние

| Операция | План |
|---|---|
| **Копировать задачу** (`todo_task_copy`) | План **не копируется** (новый GUID → пустой план) |
| **Переместить** без «Копировать» | GUID сохраняется → план **остаётся** привязанным |
| **Переместить** с «Копировать» | Новый GUID на приёмнике → план **не копируется** (как при `todo_task_copy`) |
| **Слияние** (`todo_task_merge`) | Строки плана **не синхронизируются** через свод |

## 8. Пользовательский интерфейс

### 8.1. Кнопка в диалоге задачи

Место: `show_todo_task_edit_dialog`, **между** «Комментарии» и кнопками ОК/Отмена (или отдельная строка над ОК).

| Условие | Текст кнопки |
|---|---|
| `count_plan_items(guid) == 0` | `Создать план` |
| иначе | `Редактировать план` |

Поведение:

- Для **новой** задачи (`use_default_due=True`): GUID уже создан до диалога → план можно создать сразу; при **отмене** диалога задачи GUID очищается → удалить и черновик плана, если успели сохранить.
- Кнопка открывает визард плана **модально** поверх диалога задачи; по закрытии визарда — вернуться в диалог задачи (не закрывать редактирование задачи).
- Если пользователь нажал ОК в задаче без открытия плана — план не создаётся.

Константы подписей — `todo_task_plan_cfg.py`: `PLAN_BTN_CREATE`, `PLAN_BTN_EDIT`.

### 8.2. Визард плана (полноэкранный)

| Параметр | Требование |
|---|---|
| Размер | ~90–95% рабочей области экрана (`Toolkit.getScreenSize()` / аналог), центрирование |
| Заголовок | `План выполнения: {краткое наименование задачи}` |
| Тема | `_theme_todo_dialog`, шрифт из `general.dialog_font_pt` |

**Структура окна:**

```text
┌─ Заголовок / наименование задачи / GUID (только чтение) ─────────────┐
├─ Панель инструментов: [+ Пункт] [+ Подпункт] [↑] [↓] [Удалить строку] ┤
├─ Табличная часть (прокрутка) ─────────────────────────────────────────┤
│ Пункт │ Итог │ Начало │ Окончание │ Дн. │ Ответств. │ Результат │ Крит. │
│  1    │  Да  │ ...    │ ...       │  5  │ ...       │ ...       │ ...   │
│  1.1  │      │ ...    │ ...       │  2  │ ...       │ ...       │ ...   │
├─ Статус / подсказка (рабочие дни, праздники) ─────────────────────────┤
├─ [Сохранить]  [Отмена] ────────────────────────────────────────────────┘
```

### 8.3. Табличная часть

**v1 — рекомендуемая реализация** (совместимость LO/AO):

- `UnoControlScrollBar` + фиксированный набор видимых строк (виртуализация при > N строк);
- на строку — набор контролов (`Edit`, `CheckBox`, `ComboBox`, кнопка календаря для дат);
- активная строка подсвечивается; Tab переходит по ячейкам.

**Альтернатива v2:** временно активировать скрытый лист `__План_задач` в отдельном окне — **не рекомендуется** (защита, UX).

Колонки таблицы = п. 3.2 (без служебных `guid`, `sort_key`, `row_id` в UI).

**Визуальная группировка** под итоговым пунктом (отступы, сворачивание) — **не в v1**. Параллельные этапы (`1.1`, `1.2` с общим родителем) допустимы; отображаются плоским списком с номерами пунктов.

Редактирование:

- Двойной клик / фокус — ввод в ячейке;
- Итоговый пункт: чекбокс «Итоговый»; при включении — блокировка дат/длительности, очистка ручных дат;
- При выключении итогового — снова листовой, автозаполнение дат по правилам п. 5.

### 8.4. Команды панели

| Кнопка | Действие |
|---|---|
| **+ Пункт** | Добавить корневой пункт (`max(целая часть item_no) + 1`) |
| **+ Подпункт** | К выбранному итоговому/корневому `N` добавить `N.1`, `N.2`, … |
| **↑ / ↓** | Изменить порядок среди соседей; перенумеровать `item_no` и `sort_key` |
| **Удалить строку** | Удалить пункт; если итоговый с детьми — запрос подтверждения каскада |

При первом **«Создать план»** — предложить шаблон:

- один итоговый пункт `1` (итоговый) + один листовой `1.1` **или**
- пустая таблица с одной строкой `1.1` (на выбор в ТЗ реализации: **по умолчанию одна строка `1.1`**).

### 8.5. Сохранение

- **Сохранить** — валидация → запись на `__План_задач` (полная замена строк данного GUID).
- **Отмена** — откат к состоянию на входе в визард.
- Валидация минимум:
  - уникальность `item_no` в рамках GUID;
  - у листового: `date_start <= date_end`;
  - итоговый пункт имеет ≥ 1 дочерний или помечен как листовой без детей (пустой итоговый — предупреждение);
  - `item_no` соответствует иерархии (`1.2` → родитель `1`).

## 9. Связь плана со сроком задачи (v1)

После успешного **«Сохранить»** в визарде плана:

1. Вычислить `plan_due = max(date_end)` по всем пунктам плана (листовым и итоговым с заполненной датой окончания).
2. Если `plan_due` пуст — диалог синхронизации **не показывать**.
3. Иначе — запрос (пример текста):

   > «Установить срок исполнения задачи по дате окончания плана — ДД.ММ.ГГГГ (день недели)?»

   - **Да** — записать `plan_due` в колонку «Срок исполнения» строки задачи (формат как у существующих сроков, с днём недели).
   - **Нет** — срок задачи не менять.

4. В любом случае при сохранении плана обновить у **строки задачи** служебные поля редактирования (как после «Задача: редактировать»):
   - «Дата и Время Редактирования» — текущее время;
   - «Отредактировано» — ФИО владельца из настроек (или пользователь ОС).

То есть сохранение плана считается правкой задачи, даже если пользователь отказался менять срок.

Вызов из визарда: передать `sheet`, `cols`, `row` задачи; внутри — `_stamp_task_timestamps` + `_stamp_task_owner` (с `is_new=False`) и при согласии — запись срока.

Константы диалога — `todo_task_plan_cfg.py`: `PLAN_SYNC_DUE_TITLE`, `PLAN_SYNC_DUE_MSG`.

## 13. Приёмка (критерии готовности)

### 13.1. Хранение

1. Лист `__План_задач` создаётся при первом сохранении плана, скрыт.
2. Для одной задачи (GUID) — несколько строк; повторное открытие визарда показывает те же данные.
3. Удаление задачи: строки плана попадают на `__Архив_план` и исчезают с `__План_задач`.

### 13.2. UI

4. В диалоге редактирования кнопка «Создать план» / «Редактировать план» в зависимости от наличия пунктов.
5. Визард открывается на весь экран; таблица прокручивается при > 10 строк.
6. Редактирование строки: даты, длительность, ответственные, результат, критичность, признак итогового.
7. Итоговый пункт пересчитывает даты/длительность при изменении подпунктов.

### 13.3. Рабочие дни

8. Суббота/воскресенье при вводе даты сдвигаются влево до пятницы (если не праздник).
9. Дата из справочника «Праздники» не считается рабочим днём.
10. `duration_wd` для 1 рабочего дня: start = end.
11. Начало следующего этапа = следующий рабочий день после окончания предыдущего (при включённой цепочке).

### 13.4. Иерархия

12. Пункты `1`, `1.1`, `1.2` отображаются и сортируются правильно.
13. Итоговый `1` при детях `1.1` (2 дн.) и `1.2` (3 дн.) показывает объединённый интервал и корректную длительность.

### 13.5. Срок задачи и архив

14. После сохранения плана — предложение подставить срок задачи по `max(date_end)`; при отказе срок не меняется.
15. После сохранения плана — обновлены «Дата и Время Редактирования» и «Отредактировано» у строки задачи.
16. Копия задачи и «Переместить» с «Копировать» — план не переносится.

### 13.6. Регрессии

17. Удаление/добавление/редактирование задачи без плана — без изменений поведения.
18. AO 2026: entry `todo_task.py` без модульных констант; compat check без WARN на новых entry.

## 15. Согласованные решения

| Вопрос | Решение |
|---|---|
| Архив плана при удалении задачи | **Да** — на скрытый лист `__Архив_план`, затем удаление с `__План_задач` |
| Копирование плана при «Переместить» + «Копировать» | **Нет** — как при копии задачи; план не переносится |
| Критичность | **Отдельный справочник:** Низкая, Средняя, Высокая |
| Синхронизация срока задачи | **v1:** после сохранения плана — предложить подставить срок; всегда обновить «Отредактировано» и дату редакции задачи |
| Визуальная группировка этапов | **Не в v1** — плоский список с номерами `1`, `1.1`, `1.2` |

## 16. Краткая шпаргалка для разработчика

- План = `__План_задач`, архив = `__Архив_план`, ключ **GUID задачи**.
- Визард только из диалога задачи; кнопка **Создать / Редактировать**.
- Рабочие дни = пн–пт минус **Праздники**; ввод даты — snap **влево**.
- Следующий этап: start = next_workday(prev.end).
- Итоговый пункт: даты и duration из детей, вверх по дереву.
- Удалил задачу → план в **архив**, с рабочего листа планов снят.
- Копия / перемещение с копированием → план **не** переносится.
- Сохранил план → предложить срок задачи; **всегда** обновить «Отредактировано» у задачи.
- Критичность: **Низкая / Средняя / Высокая** (отдельный справочник).
