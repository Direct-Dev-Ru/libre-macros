# ТЗ: копирование_диапазонов

Новая функция **финальной** обработки (FINAL; также допускается RANGE на листе результата).
Копирует прямоугольник / строку(и) / столбец(цы) с одного листа книги результата на другой лист (или несколько листов) в указанную точку вставки.

**Имя ключа (fn):** `копирование_диапазонов`  
**Синонимы / алиасы:** `копировать_диапазон`, `copy_ranges`, `copy_range`, `вставить_диапазон`.  
**Lib:** `lm_final_copy_ranges` / `merge_final_copy_ranges`  
(+ при RANGE: `lm_pp_range_copy_ranges` / `merge_pp_range_copy_ranges`, тонкая обёртка на тот же core).  
**Не** путать с:

- `копировать_значения` — материализация формул → значения **на том же** диапазоне;
- `копировать_переместить_лист` — целая вкладка;
- `разделить_листы` / `split_mode=copy_range` — разбиение по ключу в новые книги/листы.

**Цель:** после сбора/постобработки одним JSON-шагом перенести блок ячеек «откуда → куда» с режимом **замены** или **вставки со сдвигом** (добавление строк/столбцов перед якорем).

---

## 0. Возможность — да

| Механизм | Назначение |
| -------- | ---------- |
| UNO `getDataArray` / `setDataArray` | Копия **вычисленных значений** (default `content=values`) |
| UNO `getFormula` / `setFormula` / `FormulaLocal` | Копия **формул** при `content=formulas` (ячейка за ячейкой или clipboard) |
| UNO clipboard + `pasteCellRange` / `.uno:Copy` / `.uno:Paste` | Формулы с автосдвигом ссылок Calc + опционально форматы (reuse `_lm_pp_copy_range_to_clipboard`, `_lm_pp_paste_cell_range_formulas_only`) |
| `Rows.insertByIndex` / `Columns.insertByIndex` | Режим `insert` — сдвиг места под блок |
| `lm_pp_copy_sheet_register_pending` + `_merge_involve_extra_sheet_names` | Вовлечь лист-приёмник в скоп следующих шагов pipeline |
| `XCellRangeMovement` / `moveRange` | Не использовать для v1 (только copy, не cut) |

**Эталон v1:**
1. раскрыть источник → snapshot содержимого по политике `content`;
2. подготовка места на приёмнике (`replace` / `insert`);
3. запись;
4. **вовлечь** приёмник(и) и расширить скоп столбцов листа для следующих шагов (§3.4).

`with_formatting: true` — best effort через clipboard paste; при ошибке — содержимое без форматов + запись в журнал.

Ограничения v1:

- только листы **текущей книги результата** (не внешние файлы);
- один блок = один источник → один или несколько приёмников;
- вырезание (`cut`) / обмен диапазонами — **вне scope**;
- объединение ячеек (merge) на приёмнике при insert — best effort / предупреждение в лог;
- при `content=formulas` межлистовые относительные ссылки могут «поехать» — см. §3.3.

---

## 1. Принцип работы

1. Прочитать блок(и) JSON `копирование_диапазонов` из колонки C (`param_decode`).
2. Для каждого блока:
   1. Найти лист-источник (`source_sheet`).
   2. Раскрыть область источника (`source` / `source_range` / `source_rows` / `source_columns`) → прямоугольник `(sc, sr, ec, er)`.
   3. Прочитать содержимое по политике `content` (значения / формулы; §3.3) и при необходимости форматы.
   4. Раскрыть список листов-приёмников (`dest_sheets` / `dest_sheet`).
   5. Для каждого приёмника:
      - разобрать якорь `dest_cell` (A1) → левый верх вставки;
      - применить `mode` (`replace` / `insert`);
      - записать блок;
      - **вовлечь** лист в скоп следующих шагов и учесть новые столбцы (§3.4);
   6. Опционально очистить источник (`clear_source`) — один раз после всех успешных приёмников.
3. Журнал: источник, размер, приёмники, режим, `content`, статус вовлечения.

Шаг **меняет** ячейки книги результата (в отличие от `отправить_по_почте`).

## 2. JSON-блок (колонка C)

```json
[{
  "v": 1,
  "fn": "копирование_диапазонов",
  "source_sheet": "Сводная",
  "source_range": "A1:D20",
  "dest_sheets": ["Отчет", "Архив"],
  "dest_cell": "B3",
  "mode": "replace",
  "content": "values",
  "with_formatting": false,
  "clear_source": false,
  "involve_dest": true,
  "header_row": 1
}]
```

| Поле | Тип | Default | Смысл |
| ---- | --- | ------- | ----- |
| `source_sheet` | str | обязателен | Лист-источник (exact; без glob в v1) |
| `source_range` | str | `""` | A1-диапазон: `B2:D10`, одна ячейка `A1`, столбец `C:C`, строка `5:5` |
| `source_rows` | list/str | `""` | Альтернатива: строки 1-based (`"2:10"`, `"2,5,7"`, `[2,3,4]`) — все столбцы used-area или пересечение с `source_columns` |
| `source_columns` | list/str | `""` | Альтернатива: столбцы (`"A:C"`, `"B,D"`, `["A","C"]`, имена заголовков в `'…'`) |
| `dest_sheet` | str | `""` | Один лист-приёмник |
| `dest_sheets` | list | `[]` | Несколько приёмников (если задан — приоритетнее `dest_sheet`) |
| `dest_cell` | str | `"A1"` | Якорь левого верхнего угла вставки (A1) |
| `mode` | enum | `replace` | `replace` \| `insert` |
| `insert_axis` | enum | auto | Только для `insert`: `rows` \| `cols` \| `auto` |
| `content` | enum | `values` | Что копировать из ячеек с формулами: `values` \| `formulas` (§3.3) |
| `with_formatting` | bool | `false` | Копировать оформление (clipboard; best effort) |
| `clear_source` | bool | `false` | После успешной вставки очистить исходный прямоугольник |
| `create_missing_dest` | bool | `false` | Создать лист-приёмник, если нет (имя как задано) |
| `involve_dest` | bool | `true` | После копирования вовлечь приёмник(и) в скоп следующих шагов (§3.4) |
| `header_row` | int | из pipeline / `1` | 1-based строка заголовков **на приёмнике** для регистрации скопа / `sheets_info` |
| `sheet` | str | — | (RANGE-контекст) лист текущего шага; **не** заменяет `source_sheet` / `dest_*` |

Приоритет раскрытия источника (первый заданный выигрывает):

1. `source_range` (явный A1);
2. `source_rows` + `source_columns` (оба → пересечение; один → полоса по used-area листа);
3. ошибка валидации, если ничего не задано.

Алиасы полей при нормализации кодека:

- `source` → `source_range`;
- `from_sheet` → `source_sheet`;
- `to_sheet` / `target_sheet` → `dest_sheet`;
- `to_sheets` / `target_sheets` → `dest_sheets`;
- `anchor` / `at` → `dest_cell`;
- `paste_mode` → `mode`;
- `as_values` / `только_значения` → `content=values`;
- `keep_formulas` / `формулы` → `content=formulas`.

Нормализация:

- `mode`: `replace`/`overwrite`/`замена` → `replace`; `insert`/`append`/`сдвиг`/`добавление` → `insert`;
- `content`: `values`/`value`/`значения`/`as_values` → `values`; `formulas`/`formula`/`формулы`/`keep_formulas` → `formulas`;
- `dest_sheets` — список имён (строка через `,` / `;` → list);
- `dest_cell` — trim, обязателен валидный A1 (одна ячейка, не диапазон);
- `source_range` — trim; пустой при наличии rows/columns допустим;
- `with_formatting` / `clear_source` / `create_missing_dest` / `involve_dest` — bool через `lm_parse_bool_param`;
- `header_row` — int 1-based; пусто → не писать в блок (runtime возьмёт из pipeline / default 1).

### 2.1. Примеры

Минимум — замена блока на другом листе:

```json
[{"v":1,"fn":"копирование_диапазонов","source_sheet":"Сводная","source_range":"A1:C10","dest_sheet":"Отчет","dest_cell":"A1","mode":"replace"}]
```

Строки источника → вставка со сдвигом строк на приёмнике:

```json
[{
  "v":1,
  "fn":"копирование_диапазонов",
  "source_sheet":"Данные",
  "source_rows":"2:50",
  "dest_sheet":"Сбор",
  "dest_cell":"A2",
  "mode":"insert",
  "insert_axis":"rows"
}]
```

Столбец → несколько листов:

```json
[{
  "v":1,
  "fn":"копирование_диапазонов",
  "source_sheet":"Справочник",
  "source_columns":["'Код'","'Название'"],
  "dest_sheets":["Лист1","Лист2"],
  "dest_cell":"F1",
  "mode":"replace"
}]
```

Целый столбец A1-синтаксисом + очистка источника:

```json
[{
  "v":1,
  "fn":"копирование_диапазонов",
  "source_sheet":"Temp",
  "source_range":"B:B",
  "dest_sheet":"Итог",
  "dest_cell":"D1",
  "mode":"replace",
  "clear_source":true
}]
```

## 3. Режимы вставки (`mode`)

### 3.1. `replace` (замена)

1. Якорь `dest_cell` = левый верх.
2. Записать матрицу `H×W` поверх существующих ячеек приёмника.
3. Ячейки вне нового прямоугольника **не** трогать.
4. Пересечение с источником на **том же** листе:
   - если source и dest — один лист и прямоугольники пересекаются — сначала полный snapshot источника в память, затем запись (как безопасный copy overlap);
   - при `clear_source` и overlap — очищать только исходные ячейки **вне** области записи (или запретить `clear_source` при overlap: ошибка валидации — проще и предсказуемее для v1).

**Рекомендация v1:** при `source_sheet == dest_sheet` и пересечении диапазонов + `clear_source=true` → ошибка валидации.

### 3.2. `insert` (добавление / сдвиг места)

1. Определить ось сдвига (`insert_axis`):
   - `rows` — вставить `H` строк **перед** строкой якоря; блок пишется начиная с якоря (после сдвига якорь указывает на первую вставленную строку);
   - `cols` — вставить `W` столбцов **перед** столбцом якоря;
   - `auto` (default):
     - если источник — одна строка / только `source_rows` без columns → `rows`;
     - если источник — один столбец / только `source_columns` без rows → `cols`;
     - иначе → `rows` (явнее для «табличных» блоков).
2. UNO: `sheet.Rows.insertByIndex(row0, H)` / `sheet.Columns.insertByIndex(col0, W)`.
3. Записать значения в образовавшееся место от якоря.
4. Содержимое ниже/правее якоря сдвигается; данные не затираются.

### 3.3. Сводка

| mode | Место под блок | Существующие данные в зоне |
| ---- | -------------- | -------------------------- |
| `replace` | не создаётся | перезаписываются |
| `insert` | вставляются строки или столбцы | сдвигаются |

### 3.3. Формулы в источнике (`content`)

Если в исходном диапазоне есть ячейки с формулами (`CellContentType.FORMULA` / непустой `getFormula`), поведение задаёт **`content`**:

| `content` | Поведение |
| --------- | --------- |
| `values` (default) | В приёмник пишется **вычисленный результат** (как `копировать_значения` / `getDataArray`). Формулы на приёмнике **не** появляются. Числа/даты/текст сохраняются по типу результата. |
| `formulas` | В приёмник пишутся **сами формулы**. Эталон: clipboard copy источника → paste formulas на якорь (Calc сам сдвигает относительные ссылки относительно нового положения). Fallback: поклеточно `getFormula` → запись через `_lm_pp_apply_formula_*` / `setFormula` **без** автосдвига ссылок (в лог — «формулы как текст, ссылки не сдвинуты»). |

Правила:

1. Обычные значения (числа, текст, даты без формулы) копируются как есть в обоих режимах.
2. Пустые ячейки остаются пустыми.
3. Ошибки вычисления (`#ИМЯ?`, `#ДЕЛ/0!`, …):
   - при `values` — в приёмник попадает **отображаемая ошибка/значение ячейки как есть** (не пересчитывать заново на приёмнике);
   - при `formulas` — копируется текст формулы; пересчёт уже на приёмнике.
4. Ссылки на **другой лист** (`Сводная!A1`) в режиме `formulas` сохраняются как в формуле источника (clipboard обычно не ломает sheet-qualified refs).
5. Относительные ссылки **внутри** скопированного блока при `formulas`+clipboard должны остаться согласованными после вставки; при fallback без clipboard — риск «поехавших» ссылок → предупреждение в журнал.
6. `with_formatting: true` не меняет семантику `content`: форматы — отдельно, поверх values/formulas.
7. Сочетание `content=formulas` + `clear_source=true` на том же листе с overlap — как и для values: **запретить** в v1.

Пример «заморозить» формулы в значения на другом листе:

```json
[{
  "v":1,
  "fn":"копирование_диапазонов",
  "source_sheet":"Расчет",
  "source_range":"E2:E100",
  "dest_sheet":"Отчет",
  "dest_cell":"C2",
  "content":"values",
  "mode":"replace"
}]
```

Пример перенести формулы (с автосдвигом ссылок Calc):

```json
[{
  "v":1,
  "fn":"копирование_диапазонов",
  "source_sheet":"Шаблон",
  "source_range":"A1:D20",
  "dest_sheet":"Рабочий",
  "dest_cell":"A1",
  "content":"formulas",
  "mode":"replace"
}]
```

### 3.4. Вовлечение приёмников и столбцов в скоп следующих шагов

После успешной записи на лист-приёмник блок по умолчанию **обязан** сделать так, чтобы этот лист (и новые столбцы на нём) участвовали в **текущем скопе** pipeline — как после `копировать_лист` / materialize сводной.

#### 3.4.1. Зачем

Иначе последующие шаги `Постобработка_*` / `Финальная_обработка` (сетка, автофильтр, формат столбцов, `столбец_по_лямбде`, …):

- в режиме **«Текущие листы» / involve** — **пропустят** приёмник, если его нет в `_MERGE_INVOLVED_SHEET_NAMES`;
- на уже вовлечённом листе — могут не увидеть **новые столбцы**, если `data_range` / `end_col` / header-кэш остались старыми.

#### 3.4.2. Что делать при `involve_dest: true` (default)

Для **каждого** успешно записанного `dest_sheet`:

1. **Регистрация листа в очереди pending** (как `копировать_лист`):
   - вызвать `lm_pp_copy_sheet_register_pending(dest_name, header_row_0, source_sheet_name=source_sheet)`;
   - `header_row` из блока (1-based → 0-based); если не задан — взять header источника / текущий header приёмника / `0`.
2. **Дописать в involve-набор** (если активен режим involve / набор уже непуст):
   - `_merge_involve_extra_sheet_names([dest_name])` (через безопасный вызов из collect / shim; при отсутствии режима — no-op, как сейчас в helper).
3. **Расширить скоп столбцов текущего листа-приёмника** для следующих шагов того же прогона:
   - если вставка/замена затронула столбцы правее прежнего `end_col` used-area / data_range — обновить границы листа в runtime-контексте (`sheets_info.end_col` / пересчёт used-area перед следующим шагом);
   - если `mode=insert` + `insert_axis=cols` — столбцы, сдвинутые вправо, и новые колонки блока считаются частью текущего диапазона листа;
   - имена заголовков в строке `header_row` приёмника (если якорь/блок пересекает строку заголовков) должны быть видимы следующим шагам с `columns_pick` / resolve column token **без** ручного «перевовлечения» листа.
4. В журнал: `involve=Отчет,Архив; cols+=2` (или `involve=skip` при `involve_dest=false`).

#### 3.4.3. Когда `involve_dest: false`

Только запись ячеек; лист/столбцы **не** добавляются в pending/involve. Нужен редкий случай «тихая подложка», которую следующие шаги не должны трогать.

#### 3.4.4. Инварианты

- Вовлечение **не** создаёт копию листа и не меняет режим сбора — только runtime-скоп текущего прогона.
- Уже вовлечённый лист повторно в pending не дублировать (`lm_pp_copy_sheet_register_pending` уже идемпотентен по имени).
- Если приёмник = источник (copy на том же листе) — involve всё равно обновить границы столбцов/строк после insert; pending по имени можно не плодить повторно.
- Созданный через `create_missing_dest` лист **обязан** пройти involve (иначе следующий шаг его не увидит).

## 4. Раскрытие источника

### 4.1. `source_range` (A1)

Поддержать:

| Запись | Смысл |
| ------ | ----- |
| `A1:D10` | прямоугольник |
| `A1` | одна ячейка |
| `3:3` / `3:7` | строки целиком в пределах used-area (или до max col источника, если used пуст — ошибка) |
| `C:C` / `B:D` | столбцы целиком в пределах used-area |
| `$B$2:$D$10` | то же (игнор `$`) |

Парсер: reuse / расширить `_lm_pp_parse_cell_a1_ref` + разбор диапазона (`:`); для `C:C` — отдельная ветка.

### 4.2. `source_rows` / `source_columns`

- Строки: 1-based; диапазон `2:10`; список `2,5,7` — в v1 **только непрерывный** диапазон min..max (дыры между 2 и 7 заполняются); несвязанные мульти-полосы — вне scope / ошибка «нужен непрерывный блок».
- Столбцы: буквы, 1-based индексы, имена заголовков (`columns_pick` / `canonicalize_column_token_list_for_store`); непрерывный блок min..max col.
- Если заданы оба — пересечение.
- Если задан только один — вторая ось = used-area листа (эвристика как у других pp).

### 4.3. Пустой / слишком большой источник

- Нет непустых границ / used-area пуст → ошибка блока.
- Порог размера (напр. > 5e6 ячеек) → ошибка, не выполнять.

## 5. Визард (sheet-block form)

Регистрация в `_SHEET_BLOCK_FORM_FNS` + `_SHEET_BLOCK_FORM_SCHEMAS`.

| id | type | Подпись | Примечание |
| -- | ---- | ------- | ---------- |
| `source_sheet` | combo | Лист-источник | `choices_from_sheets` |
| `source_range` | edit | Диапазон A1 | hint: `A1:D10`, `B:B`, `2:5` |
| `source_rows` | edit | Строки (альт.) | если range пуст |
| `source_columns` | columns_pick | Столбцы (альт.) | заголовки листа-источника; накопление |
| `dest_sheets` | edit / sheet-list | Листы-приёмники | накопление имён через `,` / `;` (не columns_pick) |
| `dest_cell` | edit | Якорь A1 | default `A1` |
| `mode` | combo | Режим | «Замена» / «Вставка со сдвигом» |
| `insert_axis` | combo | Ось сдвига | «Авто» / «Строки» / «Столбцы»; активно при `mode=insert` |
| `content` | combo | Содержимое | «Значения (без формул)» / «Формулы» |
| `with_formatting` | bool | С оформлением | default false |
| `clear_source` | bool | Очистить источник | default false |
| `create_missing_dest` | bool | Создать лист, если нет | default false |
| `involve_dest` | bool | Вовлечь приёмник в следующие шаги | default true |
| `header_row` | edit | Строка заголовков приёмника | 1-based; для регистрации скопа |

Hints на русском:

- копируется блок с листа-источника на один или несколько листов-приёмников;
- **Замена** — поверх ячеек от якоря; **Вставка** — сначала сдвиг строк/столбцов, потом запись;
- если в источнике есть формулы: по умолчанию копируются **значения**; режим «Формулы» переносит сами формулы (ссылки сдвигает Calc);
- после копирования приёмник **вовлекается** в текущий скоп листа для следующих шагов (сетка, форматы, лямбды по новым столбцам); снимите галочку, если лист трогать дальше не нужно;
- диапазон: все ячейки прямоугольника; разделители в параметрах строк/столбцов — `,` / `;`;
- при нескольких `dest_sheets` один и тот же блок вставляется в каждый лист в один и тот же `dest_cell`.

Маппинг label↔code — `_block_field_to_text` / `_text_to_block_field` + словари в `libre_macros_param_wizard_cfg.py`.

Fallback: `_FALLBACK_FINAL_CHOICES` + `_FALLBACK_FINAL_REST_HINTS` (+ RANGE при регистрации в `_PP_RANGE_MAP_SPEC`).

## 7. Журнал

Примеры:

- `копирование_диапазонов | ok | Сводная!A1:D20 → Отчет!B3; mode=replace; content=values; 20×4; involve=Отчет`
- `копирование_диапазонов | ok | Расчет!E2:E100 → Отчет!C2; content=values; formulas_src=99 → values`
- `копирование_диапазонов | ok | Шаблон!A1:D20 → Рабочий!A1; content=formulas; paste=clipboard; involve=Рабочий`
- `копирование_диапазонов | ok | Данные!rows 2:50 → Сбор!A2; mode=insert/rows; dest=1; involve=Сбор`
- `копирование_диапазонов | ok | Справочник!B:C → Лист1!F1, Лист2!F1; mode=replace; sheets=2; cols+=2; involve=Лист1,Лист2`
- `копирование_диапазонов | предупреждение | content=formulas; clipboard failed → formulas as text (no ref shift)`
- `копирование_диапазонов | ошибка | source_sheet=НетТакого: лист не найден`
- `копирование_диапазонов | ошибка | source_range=ZZ:YY: некорректный A1`
- `копирование_диапазонов | ошибка | dest_sheets пуст`
- `копирование_диапазонов | ошибка | overlap + clear_source запрещены на одном листе`
- `копирование_диапазонов | пропуск | пустая C`

## 8. Безопасность / UX

- Не читать внешние файлы; только текущий `doc`.
- Не удалять листы; `clear_source` — только очистка значений (и форматов опционально) в исходном прямоугольнике.
- При `create_missing_dest` не затирать существующий лист с тем же именем.
- Большие блоки — порог + сообщение в журнал.
- Consent отдельный не нужен (шаг уже в сценарии финала).

## 10. Вне scope v1

- Cut / перемещение с очисткой как транзакция «перенос»
- Несвязанные мульти-диапазоны (A1:B2 + D5:E6 за один блок)
- Копирование с внешнего файла / другой открытой книги
- Условное копирование по `row_filter` / лямбде
- Автоподбор dest_cell («под таблицей», «в конец used-area») — можно добавить позже как `dest_cell: "_конец_"`
- PDF / экспорт; только ячейки Calc
- Синхронизация именованных диапазонов / графиков / автофильтра на приёмнике
- Ручной rewrite ссылок формул (кроме того, что делает clipboard Calc)
- `content=array` / CSE / динамические массивы как отдельная семантика

## 11. Связь с roadmap

Закрывает типовой сценарий «собрать → поправить на служебном листе → перенести блок на итоговые вкладки» без ручного Copy/Paste.
Смежно с `копировать_лист` (целая вкладка) и `объединить_листы_в_один` (append таблиц); здесь — **точный прямоугольник и якорь**.
После переноса столбцов приёмник остаётся в том же runtime-скопе, что и после `копировать_лист` / involve — следующие шаги видят новые колонки.
