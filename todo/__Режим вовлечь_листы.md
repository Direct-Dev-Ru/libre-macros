# ТЗ: режим «Вовлечь листы» для источника `эта_книга`

**Статус:** реализовано (с **3.10.265**; актуальная ревизия docs — **3.10.281**). Описание для пользователя — [docs/04_DATA_COLLECTION.md](../docs/04_DATA_COLLECTION.md) §2.1.

## 1. Назначение

Добавить **специальный режим сбора**, в котором при источнике **`эта_книга`** указанные листы **не копируются и не объединяются**. Они только **вовлекаются** в дальнейший конвейер: попадают в список листов результата (`sheets_info`) и к ним применяются **встроенное оформление (по правилам preexisting)**, **постобработка** (`Постобработка_*`, `ВПР`, `объединить_листы_в_один`, `разделить_листы`, …) и **`Финальная_обработка`**.

**Типичная боль сейчас:** чтобы прогнать постобработку по уже готовым листам текущей книги, приходится ставить `Файлы-Источники = эта_книга` и режим «Копирование листов» / «На один лист» / «На разные листы» — макрос **создаёт копии или Merge**, дублирует данные, меняет имена (`N_ИмяЛиста`). Нужен режим «обработать как есть».

**Имя режима (A=`Режим`, B=значение):** `Вовлечь листы`  
Синонимы (нормализация без учёта регистра / пробелов / `_`): `вовлечь_листы`, `involve_sheets`, `passthrough`, `без_копирования`, `только_обработка`.

Каноническая константа: `MERGE_MODE_INVOLVE = "вовлечь листы"` (рядом с `MERGE_MODE_ONE` / `MANY` / `COPY` в `libre_macros_collect_cfg.py`).

## 2. Согласование с текущей архитектурой

| Тема | Сейчас | После добавления режима |
| ---- | ------ | ----------------------- |
| Источник `эта_книга` | Работает во всех трёх режимах как обычный файл: данные **читаются/копируются** в Merge / Merge_N / копии вкладок | Без изменений для ONE/MANY/COPY. Новый режим — **четвёртая** ветка диспетчера |
| `Файлы-Источники` | Пути / маски / маркеры из `_MERGE_CURRENT_BOOK_MARKERS` | Для `Вовлечь листы` — **только** маркер текущей книги (одна ячейка или несколько одинаковых → один источник). Распознавание — **гибкая нормализация** (§4.4). Внешние пути → ошибка валидации |
| Параметр `Листы` | Фильтр листов **источника** при копировании/слиянии | Фильтр **каких вкладок текущей книги вовлечь** (NAME / INDEX / ALL / шаблоны — как сейчас) |
| Служебные листы | В `эта_книга` уже исключаются (`Параметры_Объединения*`, журнал, …) | То же: служебные **никогда** не вовлекаются, даже если попали в фильтр |
| Сбор данных | `merge_on_*` создаёт/заполняет листы результата | **Пропуск** фазы переноса данных: нет `importSheet`, нет записи в `Merge`, нет обрезки/ячейка_в_столбец на этапе сбора |
| `sheets_info` | Строится по созданным/скопированным листам | Строится по **существующим** листам, прошедшим фильтр (`_merge_build_sheets_info_from_sheets` или аналог) |
| Preexisting formatting | `_merge_sheet_skip_default_formatting` — листы, бывшие в книге до сбора, без оформления «по умолчанию» | Вовлечённые листы **все** preexisting → default-оформление **не** навязывать; явные шаги постобработки/финала — **да** |
| `Ячейка_В_Столбец`, `#Путь`, `#ДатаВремяФайла` | Для COPY уже почти не применимы | В режиме вовлечения — **игнорировать** (не ошибка; в лог — «не применимо») |
| `Пропуск_строк_источника`, `Столбцы`, `Начало_*`, `Число_*` | Участвуют в копировании | **Не используются** на этапе сбора (не ошибка). `Строка_Заголовков` — **используется** для `header_row` в `sheets_info` / pipeline |
| `Способ_переноса` / `xml_excel_ods` | Ветка переноса | Для вовлечения — **игнорировать** (нет переноса). Если задан `xml_excel_ods` — предупреждение в лог или мягкая ошибка визарда «не сочетается» |
| `maybe_clear_sheets` / предварительное удаление | Перед сбором по `Листы_не_удалять` | В режиме **«Вовлечь листы» всегда подавляется** (как `Листы_не_удалять=*`). Параметр `Листы_не_удалять` на листе **игнорируется** для предварительной очистки. См. §6 |
| Оркестратор `collect_pack` | Несколько листов параметров подряд | Идеальный второй/третий шаг плана: первый конфиг собрал листы, следующий — **вовлечь** их и дооформить / финализировать |
| AO 2026 | — | Логика в `pythonpath` / существующем `collect_workbooks.py`; entry не раздувать |

Связанные места: `run_collect_merge`, `parse_collect_settings`, `expand_source_files` / `is_current_book_marker`, `_iter_sheet_slots_current_book`, `_merge_build_sheets_info_from_sheets`, `_merge_apply_builtin_then_book_pipeline`, `apply_result_book_postprocessing_pipeline`, `maybe_clear_sheets`, финальная обработка, `docs/04_DATA_COLLECTION.md`, `docs/15_PARAM_REFERENCE.md`.

## 3. Семантика режима

### 3.1. Что делает

```
0. Режим INVOLVE → не вызывать maybe_clear_sheets (всегда)
1. Прочитать Файлы-Источники → только маркер текущей книги (§4.4)
2. По параметру «Листы» + исключению служебных → список имён вкладок
3. Если список пуст → ошибка («нет листов для вовлечения»)
4. Для каждого имени: найти лист в текущей книге; нет → ошибка (§5 strict)
5. Собрать sheets_info (header_row из Строка_Заголовков / block)
6. Пропустить merge_on_* полностью
7. Запустить тот же хвост, что после обычного сбора:
   - (опц.) встроенное оформление с учётом preexisting-skip
   - processing_pipeline (постобработка + splitters)
   - Финальная_обработка
8. Журнал: «вовлечено N лист(ов): …»
```

### 3.2. Чего **не** делает

- Не открывает внешние файлы.
- Не создаёт `Merge` / `Merge_N` / `1_Имя` копии.
- Не копирует ячейки, строки, оформление с «источника» на «результат» — источник **и есть** результат.
- Не меняет имена вовлечённых вкладок (если это явно не сделает шаг `переименовать_лист` в постобработке/финале).
- **Не удаляет листы** на этапе подготовки/сбора: `maybe_clear_sheets` и любая предварительная очистка неслужебных вкладок **не вызываются** (см. §6).

### 3.3. Инвариант

После успешного вовлечения (до шагов постобработки/финала, которые сами создают/удаляют вкладки) **набор вкладок книги** совпадает с набором **на входе** в запуск: предварительное удаление **не** меняет книгу.

Явные шаги `удаление_листов` / `скрытие_листов` / `переименовать_лист` / `разделить_листы` / `копировать_лист` в постобработке и `Финальная_обработка` по-прежнему **разрешены** (это уже осознанные действия конфига, не «очистка перед сбором»).

## 4. Параметры на листе `Параметры_Объединения*`

### 4.1. Обязательные / значимые

| Параметр (A) | Роль в режиме «Вовлечь листы» |
| ------------ | ----------------------------- |
| `Файлы-Источники` | Только маркер текущей книги (§4.4). Примеры B: `эта_книга`, `Эта-книга`, `ThisWorkbook` |
| `Режим` | `Вовлечь листы` |
| `Листы` | Какие вкладки вовлечь: имена, шаблоны (`Отчет*`), номера, `Все` |
| `Строка_Заголовков` | 1-based строка заголовков **на вовлекаемом листе** (для pipeline / ВПР / сетки). Per-file колонки B/C… — как сейчас; при одном источнике достаточно B |
| `Постобработка_*` / `ВПР` / `объединить_листы_в_один` / `разделить_листы` | Обычная семантика; `sheet` в JSON — имена **вовлечённых** (и созданных шагами) листов |
| `Финальная_обработка` | Как сейчас, по книге / фильтрам листов |
| `Отображение_прогресса`, `MERGE_DEBUG` | Как сейчас |
| `Листы_не_удалять` | На **предварительную** очистку **не влияет** (очистка подавлена). Можно оставить пустым |

### 4.2. Игнорируемые (не ошибка)

`Столбцы`, `Начало_Строка`, `Начало_Столбец`, `Число_Строк`, `Число_Столбцов`, `Пропуск_строк_источника`, `Ячейка_В_Столбец`, `Источник_в_первой_колонке`, `Дата_источника_*`, `Способ_переноса` (и C у строки Режим), `MERGE_PASTE_FORMATS`, параметры xml-convert, относящиеся только к переносу, значение `Листы_не_удалять` (для pre-clear).

Визард: для режима «Вовлечь листы» эти поля **скрыть или задизейблить** с подсказкой «не используются»; у `Листы_не_удалять` — «в этом режиме листы перед запуском не удаляются».

### 4.3. Минимальный рабочий лист параметров

| A | B | C |
| - | - | - |
| `Файлы-Источники` | `эта_книга` | |
| `Режим` | `Вовлечь листы` | |
| `Листы` | `Сводка`, `Детализация` | |
| `Строка_Заголовков` | `1` | |
| `Постобработка_Диапазон` | `сетка` | `[{"v":1,"fn":"сетка","sheet":"Сводка","width":1,…}]` |
| `Финальная_обработка` | `автофильтр` | `[{"v":1,"fn":"автофильтр","sheets":["Сводка","Детализация"]}]` |

### 4.4. Маркер текущей книги (нормализация)

Распознавание через `is_current_book_marker` (желательно **общее** для всех режимов, не только involve): после `strip` привести к каноническому ключу и сравнить с набором канонов.

**Нормализация входной строки:**

1. `strip`, lower-case (Unicode);
2. убрать пробелы, табы, `_`, `-`, `.` (и подряд идущие разделители);
3. опционально: схлопнуть ё→е для сравнения ру-форм.

**Канонические ключи (после нормализации):**

| Семья | Канон | Примеры ввода (все → True) |
| ----- | ----- | -------------------------- |
| RU | `этакнига` | `эта_книга`, `Эта_Книга`, `эта-книга`, `Эта-Книга`, `этакнига`, `Эта книга`, `эта  книга`, `ЭТА_КНИГА` |
| EN this | `thisworkbook` / `thisbook` | `ThisWorkbook`, `This_Workbook`, `This-Workbook`, `this workbook`, `ThisBook`, `this_book`, `THIS-BOOK` |
| EN current | `currentworkbook` / `currentbook` / `current` | `CurrentWorkbook`, `current_book`, `Current-Book`, `current` |

Каноническая запись в ячейку при автоподстановке визарда / кросс-ОС правке: по-прежнему **`Эта_книга`** (`MERGE_CURRENT_BOOK_MARKER`), если локаль RU; для EN-UI допустимо писать `ThisWorkbook`.

**Не** считать маркером: пути (`C:\…`, `./file.ods`), маски (`*.xlsx`), пустую строку, случайные слова (`книга`, `workbook` без this/current/эта).

Расширить `_MERGE_CURRENT_BOOK_MARKERS` / логику `is_current_book_marker` так, чтобы перечисленные формы работали и в ONE/MANY/COPY (обратная совместимость: старые `эта_книга` / `this_book` / `current_book` / `current` остаются валидными).

## 5. Правила валидации (`parse_collect_settings` / превалидация оркестратора)

| Условие | Результат |
| ------- | --------- |
| `Режим` = вовлечь, в источниках есть значение, не прошедшее `is_current_book_marker` (§4.4) | Ошибка: «Режим «Вовлечь листы» допускает только источник эта_книга / ThisWorkbook» |
| Источников после expand несколько, и среди них не-маркер | Ошибка (то же) |
| Несколько ячеек-маркеров (любые формы §4.4) | Свести к **одному** логическому источнику (не дублировать вовлечение) |
| `Листы` пусто / не резолвится ни в один неслужебный лист | Ошибка: «Нет листов для вовлечения» |
| Имя из фильтра отсутствует в книге | **Строго:** ошибка валидации с перечислением отсутствующих (предпочтительно). Альтернатива soft — только warning + пропуск; для v1 зафиксировать **strict** |
| Служебный лист явно указан по имени | Пропуск + запись в лог «служебный, пропущен»; если после фильтра пусто — ошибка |
| `xml_excel_ods` при вовлечении | Warning в лог / визард не предлагает; сбор не блокировать |

## 6. Запрет предварительного удаления листов

**Требование:** в режиме **«Вовлечь листы»** макрос **не удаляет** вкладки книги на этапе подготовки к запуску.

| Механизм | Поведение |
| -------- | --------- |
| `maybe_clear_sheets` | **Не вызывать** (или no-op / `suppress_pre_clear=True` всегда при `mode == INVOLVE`) |
| Эквивалент оркестратора | Как `suppress_pre_clear` на plan[1+], но здесь — **даже при единственном** листе параметров и даже если в плане involve идёт первым |
| Параметр `Листы_не_удалять` | Для pre-clear **игнорируется** (не нужно писать `*`) |
| Диалог «удалить неслужебные?» (оркестратор / одиночный запуск) | **Не показывать** при involve: удалять нечего по правилам режима |
| `удаление_листов` / `скрытие_листов` в постобработке и финале | **Разрешены** — явный шаг конфига, не pre-clear |

В журнале при старте involve: `очистка листов: пропущена (режим «Вовлечь листы»)`.

Пример (раньше был опасным — теперь безопасен без `Листы_не_удалять`):

```
Файлы-Источники: эта_книга
Режим: Вовлечь листы
Листы: Отчет
Листы_не_удалять: (пусто)
→ «Отчет» остаётся; запускается постобработка
```

## 7. Примеры сценариев

### Пример 1. «Только сетка и автофильтр на готовых листах»

Книга уже содержит `Продажи` и `Остатки` (заполнены вручную или прошлым сбором). Нужно оформить без копирования.

```
Файлы-Источники | эта_книга
Режим            | Вовлечь листы
Листы            | Продажи | Остатки
Строка_Заголовков| 1       | 1
Постобработка_Диапазон | сетка | [{"v":1,"fn":"сетка","whole_row":false,…}]
Финальная_обработка    | автофильтр | …
```

**Ожидание:** данные на `Продажи`/`Остатки` те же; появились сетка/фильтр; новых `1_Продажи` нет.

---

### Пример 2. Второй шаг оркестратора после внешнего сбора

**Лист `Параметры_Объединения_1` (сбор):**

```
Файлы-Источники | C:\data\*.xlsx
Режим            | Копирование листов
Листы            | Заказы
…
```

**Лист `Параметры_Объединения_2` (дооформление):**

```
Файлы-Источники | This_Workbook
Режим            | Вовлечь листы
Листы            | *_Заказы   (или конкретные 1_Заказы, 2_Заказы)
Строка_Заголовков| 1
Постобработка_Диапазон | зебра | …
Финальная_обработка    | сводная | …
```

`collect_pack`: план `[…_1, …_2]` → первый создаёт копии, второй вовлекает их и строит сводные **без** повторного importSheet и **без** предварительного удаления вкладок на шаге 2.

---

### Пример 3. Вовлечь один лист → `объединить_листы_в_один` не нужен; сразу ВПР + финал

```
Файлы-Источники | эта_книга
Режим            | Вовлечь листы
Листы            | Общий
Строка_Заголовков| 3
ВПР              | (JSON: dest_sheet=Общий, …)
Финальная_обработка | переименовать_лист | [{"v":1,"fn":"переименовать_лист","from":"Общий","to":"Отчёт_итого"}]
```

**Ожидание:** ВПР правит существующий `Общий`, затем переименование; копии листа нет.

---

### Пример 4. Шаблон имён + исключение служебных

Вкладки: `Параметры_Объединения`, `Сбор_книг_лог`, `Отчет_СЗФО`, `Отчет_ЦФО`, `Справка_макроса`.

```
Листы | Отчет*
```

Вовлечены только `Отчет_СЗФО`, `Отчет_ЦФО`.

```
Листы | Все
```

То же (служебные отфильтрованы `_is_service_sheet`).

---

### Пример 5. Чего **не** делать этим режимом (антипример)

Нужно слить три внешних файла на `Merge` → режим **«На один лист»**, не «Вовлечь листы».

Нужна независимая копия вкладки из этой же книги под другим именем → режим **«Копирование листов»** + `эта_книга` (как сейчас), либо шаг `копировать_лист` в постобработке.

«Вовлечь» = **in-place обработка**, не клонирование.

---

### Пример 6. Разделение уже готового листа

```
Файлы-Источники | эта-книга
Режим            | Вовлечь листы
Листы            | Реестр
Строка_Заголовков| 1
разделить_листы  | (JSON: source.sheet=Реестр, book_template=эта_книга, split_sheets=[…], run_phase=after_postprocess)
```

Сбор «нулевой»; pipeline сразу видит `Реестр` в `sheets_info` и выполняет split → follow-up pp/final на новых листах (существующая логика `эта_книга` у split).

---

### Пример 7. Варианты написания маркера

Все строки ниже — валидный единственный источник для режима:


## 8. UI / визард

| Элемент | Поведение |
| ------- | --------- |
| Список «Режим» | Пункт **«Вовлечь листы»** |
| Подсказка | «Без копирования, объединения и предварительного удаления листов: вкладки текущей книги (эта_книга / ThisWorkbook) сразу идут в постобработку и финальную обработку.» |
| `Файлы-Источники` | При выборе режима — подставить / зафиксировать «Эта_книга» (или `ThisWorkbook` в EN); FilePicker внешних файлов скрыть или блокировать |
| Поля диапазона/столбцов | Скрыть или disabled |
| `Строка_Заголовков` | Оставить видимой |

```
# этап 1 / оркестратор
if mode == MERGE_MODE_INVOLVE:
    suppress_pre_clear = True   # не вызывать maybe_clear_sheets

def merge_involve_sheets(target_doc, sheet_specs, sheet_kind, blk, report):
    slots = list(_iter_sheet_slots_current_book(target_doc, sheet_specs, sheet_kind))
    if not slots:
        report.problem("Нет листов для вовлечения")
        return False
    sheets = []
    for slot in slots:
        sh = target_doc.Sheets.getByName(slot["source_name"])  # уже в этой книге
        sheets.append(sh)
        report.log_stat("(текущая книга)", slot["source_name"], …, "вовлечение", "без копирования")
    sheets_info = _merge_build_sheets_info_from_sheets(target_doc, sheets, blk)
    # preexisting snapshot: все вовлечённые уже в книге — skip default formatting
    _merge_apply_builtin_then_book_pipeline(target_doc, sheets_info, report=report)
    return True
```

## 10. Критерии приёмки (ручная проверка в Calc)

Автотесты не писать.

1. Только маркер текущей книги + `Вовлечь листы` + два существующих листа → постобработка применена **на них**; число вкладок не выросло из‑за копирования.
2. Внешний путь в `Файлы-Источники` → ошибка до сбора, книга не менялась.
3. `Листы = Несуществующий` → ошибка валидации.
4. `Листы = Параметры_Объединения` → пропуск служебного; если других нет — ошибка «нет листов».
5. `Листы = Все` → все неслужебные вовлечены; журнал перечисляет имена.
6. После вовлечения шаг `переименовать_лист` / `удаление_листов` в финале работает как обычно.
7. Режим «Копирование листов» + `эта_книга` (старое поведение) **не сломан** — по-прежнему создаёт копии.
8. В оркестраторе: лист1 COPY из файлов, лист2 INVOLVE по маске → на втором шаге нет повторного копирования, pp/final второго конфига отрабатывают.
9. Пустой pipeline (нет постобработки и финала) → вовлечение no-op по данным, успех, в логе список вовлечённых (**успех + лог**).
10. Involve при пустом `Листы_не_удалять` и наличии «лишних» неслужебных вкладок → **ни одна** вкладка не удалена pre-clear; вовлечённые на месте.
11. Маркеры `эта-книга`, `этакнига`, `ThisWorkbook`, `This_Workbook`, `current` — все принимаются; `книга` / `Workbook` — нет.

## 11. Вне объёма v1

- Вовлечение листов из **внешней** книги без копирования (потребуется открытие read-only и опасность править чужой файл).
- Режим «вовлечь + сразу переименовать пачкой» отдельным синтаксисом `Листы`.
- Запрет явного `удаление_листов` в финале при involve (сейчас разрешён).
- Смешение в одном запуске маркера текущей книги (involve) и внешних файлов (merge).
