# Roadmap: обработка данных (ориентир — Power Query)

Документ фиксирует **приоритеты развития** libre-macros как ETL-слоя поверх LibreOffice Calc: что уже покрыто, какие пробелы относительно Power Query (PQ), в каком порядке закрывать и на какие ТЗ в `todo/` опираться.

**Не цель:** полная копия PQ. **Цель:** типовые сценарии «собрать книги → очистить → свести → оформить» без ручного копирования и без отдельного PQ в Excel.

**Ограничения проекта** (для всех пунктов roadmap):

- параметры постобработки — **только JSON** в колонке C (`param_decode` / `param_encode`);
- проверка — **вручную в Calc** после переустановки макросов; автотесты в `test/` не добавлять;
- entry-скрипты — совместимость AO 2026 (`aoffice_flatten_defs`, `aoffice_compat_check`);
- логика — в `pythonpath/`, точки входа — тонкие обёртки.

**Соглашение по ТЗ в `todo/`:** реализованные спеки переносятся в файлы с префиксом `__` (архив); активные ТЗ — без префикса.

## 1. Сводная матрица: PQ vs libre-macros

| Область PQ | В проекте сейчас | Пробел / приоритет |
|------------|------------------|-------------------|
| Источники (файлы, папки, листы) | Сбор книг, маски, `Разделить_листы`, direct/xml, режим **«Вовлечь листы»** | **Средний** — доп. фильтр по дате/лямбде → [доп_фильтр_источников.md](доп_фильтр_источников.md) |
| Append / union таблиц | Объединение листов, `#Путь`, служебные колонки | Низкий |
| Join / merge | ВПР: left + **full**; lookup по ключам | **Средний** — нет anti/semi |
| Группировка + агрегаты | `группировка_по_столбцу` (SUBTOTAL/outline), `количество_значений`, сводная | **Высокий** — нет in-memory `group by` (сжатие строк) |
| Unpivot (столбцы → строки) | — | **Высокий** |
| Pivot (строки → столбцы) | Сводная таблица + `LIST_ROWS` / `as_values` | Средний — другая модель, не «шаг pipeline» |
| Remove duplicates | **`удалить_дубликаты`** (RANGE/FINAL/xml) | ✅ Закрыто |
| Split column | **`разделить_по_столбцам`** (delimiter v1); **`конкатенация_столбцов`** | **Средний** — fixed width / by chars |
| Transpose | ✅ | Реализовано → [__новая функция транспонировать_таблицу.md](__новая%20функция%20транспонировать_таблицу.md) |
| Replace values | `замена_значений` (+ лямбды `match_expr` / `row_filter`) | Низкий |
| Text normalize / trim / case | **`текстовые_операции`** (алиас `нормализация_текста`, стек `ops[]`) | Низкий — расширять ops по мере нужды |
| Change type | `преобразовать_числа`, эвристики при чтении | **Средний** — нет явной типизации столбцов |
| Fill down / up | **`заполнение_вниз`** (значение); **`заполнение_вниз_вычислить`** (формула) | **Средний** — нет fill **up** |
| Replace errors / try | — | **Средний** |
| Add column / custom formula | `применить_формулу`, **`столбец_по_лямбде`**, **`условный_столбец`**, `Ячейка_В_Столбец` | Низкий |
| Parameters / variables | **Карта переменных** v1 + глобальные переменные + шаблоны в rename | **Средний** — ручной ввод + потребители (§ фаза E) → [карта_переменных_ручной_ввод.md](карта_переменных_ручной_ввод.md) |
| Applied steps / preview | Журнал, визард JSON, вкладка «Глобальные» | **Низкий** (UX, долгий горизонт) |
| Conditional columns | **`условный_столбец`** | ✅ Закрыто |
| Copy ranges / rearrange | **`копирование_диапазонов`** (FINAL + RANGE) | Низкий — v1 есть |

### Фаза C — «Агрегация и join»

**Цель:** заменить ручные промежуточные листы и тяжёлые формулы.

| # | Задача | Приоритет | PQ-анalog | Статус |
|---|--------|-----------|-----------|--------|
| C1 | **`группировать_строки`** (group by, сжатие) | P0 | Group By | ТЗ не создано; есть только `группировка_по_столбцу` (SUBTOTAL) |
| C2 | Расширение **ВПР / join**: anti, semi | P1 | Merge kinds | left + full ✅; anti/semi — backlog |
| C3 | **`сводка_плоская`** (pivot без UI сводной) | P2 | Pivot column (упрощённый) | — |

**C1 — минимальный контракт v1:**

```json
{
  "v": 1,
  "fn": "группировать_строки",
  "key_columns": ["Отдел", "Месяц"],
  "aggregations": [
    {"column": "Сумма", "op": "sum"},
    {"column": "ID", "op": "count", "as": "Количество"}
  ],
  "output": "new_sheet",
  "dest_sheet": "Свод"
}
```

- Ключ — семантика как у `количество_значений` / dedupe (`trim`, `case_sensitive`).
- Результат: одна строка на ключ + агрегированные столбцы.
- Реализация: in-memory hash map по data_range; для больших таблиц — порог ячеек + запись в журнал.

## 4. Рекомендуемый порядок работ (очередь)

```
B1 unpivot → B3 transpose → C1 group by → C2 anti/semi join
    → D1–D2 types/errors → fill up (D3) → E expand placeholders
```

**Обоснование (актуализировано):**

1. **Dedupe + normalize + split + conditional + lambda column** — закрыты; типовый «после сбора» сценарий уже собирается из существующих fn.
2. **Unpivot + transpose** — главные пробелы «shape» для широких отчётов (месяцы в столбцах → длинный формат).
3. **Group by (сжатие строк)** — закрывает «сводки» без ручной сводной; отличается от `группировка_по_столбцу` (SUBTOTAL).
4. Anti/semi join — реже full, но снимают боль с шаблонов «найти отсутствующих».
5. Типизация, replace errors, fill up — polish перед UX-фазой F3–F4.

## 6. Метрики «догнали PQ для своих задач»

Считать roadmap выполненным для **обработки данных**, когда без PQ можно пройти цепочку:

1. Сбор 10+ однотипных xlsx по маске (или **вовлечь** готовые листы `эта_книга`).
2. Пропуск мусорных строк/столбцов, rename по шаблону с `[Строка(первая,1)]` и `<<Переменные.Курс>>`.
3. Split «ФИО» → фамилия/имя; **текстовые_операции** (normalize).
4. Unpivot месяцев; group by с SUM и COUNT. ← **п. 4–5 ещё не закрыты**
5. Dedupe по составному ключу. ← ✅
6. Join справочника (anti/semi — опционально). ← частично (left/full)
7. Типизация дат/чисел, replace errors. ← **не закрыто**
8. Финальное оформление (градиент, печать) — уже есть.

**Текущий прогресс по метрике:** ~5 из 8 шагов закрыты полностью; unpivot, in-memory group by и типизация — главные блокеры.
