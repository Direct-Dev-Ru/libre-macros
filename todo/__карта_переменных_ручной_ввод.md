# ТЗ: ручной ввод в карту переменных

Расширение карты переменных: параметр на листе `Параметры_Объединения*`, который **до** (или вместо) чтения ячеек источников запрашивает значение у пользователя через кастомный диалог и кладёт его в runtime-карту.

Связано с: [__Карта_переменных.md](__Карта_переменных.md), [тз по расширению плейсхолдеров_карты_переменных_v2.md](тз%20по%20расширению%20плейсхолдеров_карты_переменных_v2.md).

---

## 1. Назначение

| Сейчас | Нужно |
|--------|--------|
| Значение в карту — только из ячейки источника (`Добавить_в_карту_переменных`) или глобальных | То же + **ручной ввод** пользователем при запуске сбора |
| — | Значение может участвовать в **фильтре файлов-источников** и в формулах / плейсхолдерах `<<Переменные.…>>` |

**Ключ карты:** сегменты файла и листа — служебная фраза **`ручной_ввод`** (не имя реального файла/листа).

Пример ключа: `Филиал~ручной_ввод~ручной_ввод`  
Плейсхолдер: `<<Переменные.Филиал>>` (как у обычной карты; доп. уточнение `лист`/`файл` = `ручной_ввод` при необходимости).

---

## 2. Параметр на листе

| Колонка | Значение |
|---------|----------|
| A | `Ручной_ввод_в_карту_переменных` (алиасы: `ручной_ввод`, `manual_variable_input`) |
| B | `смотри в С` |
| C | JSON-массив блоков `[{…}]` |

Несколько строк с одним A — как у `Добавить_в_карту_переменных` (legacy).
Предпочтительно: **одна** строка, в C — JSON-массив нескольких блоков (визард «+ Блок»).

`fn` в JSON: `ручной_ввод_в_карту_переменных`.

---

## 3. Поля блока JSON

| Поле | Тип | Обязательно | Смысл |
|------|-----|-------------|--------|
| `v` | int | да | `1` |
| `fn` | string | да | `ручной_ввод_в_карту_переменных` |
| `name` | string | да | Имя переменной в карте (тильда запрещена) |
| `value_kind` | string | нет | `scalar` (по умолчанию) \| `list` — одно значение или список |
| `data_type` | string | нет | `text` (default) \| `number` \| `date` \| `datetime` \| `bool` |
| `format` | string | нет | Подсказка формата ввода (например `ДД.ММ.ГГГГ`, `#0.00`); для `date`/`number` — парсинг |
| `choices` | list/str | нет | Фиксированный список значений (combo); пусто — свободный ввод |
| `prompt` | string | нет | Текст/подсказка в диалоге |
| `title` | string | нет | Заголовок диалога; по умолчанию имя переменной / «Ввод переменной» |
| `required` | bool | нет | `true` (default) — пустое значение запрещено (Cancel = отмена сбора) |
| `default` | any | нет | Начальное значение в поле ввода |

Пример (скаляр + список выбора):

```json
[{
  "v": 1,
  "fn": "ручной_ввод_в_карту_переменных",
  "name": "Филиал",
  "value_kind": "scalar",
  "data_type": "text",
  "choices": ["Север", "Юг", "Центр"],
  "prompt": "Выберите филиал для фильтра источников",
  "title": "Филиал",
  "required": true
}]
```

Пример (список значений):

```json
[{
  "v": 1,
  "fn": "ручной_ввод_в_карту_переменных",
  "name": "Коды",
  "value_kind": "list",
  "data_type": "text",
  "prompt": "Коды через запятую или по одному в строке",
  "required": true
}]
```

Для `list`: в карту пишется сериализованное представление (согласовать: JSON-массив строк или строка с `;` — **зафиксировать в реализации: JSON-массив в text + `type_token=text`**, либо отдельный `type_token=list` если потребители готовы). Рекомендация v1: **одна строка с разделителем `;`**, `type_token=text`, чтобы `<<Переменные.Коды>>` сразу шёл в маски/формулы.

## 4. Порядок выполнения (критично)

Расположение строки параметра на листе решает момент показа диалога:

1. Если строка **`Ручной_ввод_…` стоит до строки «Файлы-Источники»** (и связанных параметров расширения масок) — диалог показывается **до** разбора/глоба источников, чтобы значение уже было в карте при:
   - фильтре путей / масках с `<<Переменные.…>>`;
   - `Доп_Параметры_Источника` (лямбда-фильтр файлов — см. [доп_фильтр_источников.md](доп_фильтр_источников.md));
   - любых ранних шагах, читающих карту.
2. Если строка **после** файлов — диалог после разрешения списка файлов, но **до** постобработки (как минимум до RANGE/формул, использующих карту).

**v1 правило:** собрать все блоки `ручной_ввод_…` в порядке строк листа; каждый блок → один диалог в этом порядке. Блоки «до файлов» — пакет **до** `resolve sources`; блоки «после» — пакет после resolve, до merge/postprocess.

Cancel на обязательном поле → прервать сбор с понятным сообщением в журнале.

---

## 5. UX диалога

- Стиль проекта: как остальные inner-диалоги визарда / сбора.
- **Жёлтая подсветка title** (как у предупреждающих диалогов проекта).
- Поля:
  - scalar + без `choices` → edit (multiline при длинном prompt — по желанию);
  - scalar + `choices` → combo;
  - list → multiline edit (токены через `,` / `;` / перевод строки).
- Кнопки: **OK** / **Отмена**.
- Валидация `data_type` / `format` на OK; при ошибке — сообщение, диалог не закрывать.

Реализация UI — в `pythonpath/` (не модульные константы в entry), совместимость AO 2026.

---

## 6. Визард

Поддиалог параметров (кнопка «Параметры…» у строки):

- слева список **Блоки** (`+ Блок` / `Удалить`) — несколько переменных в **одной** строке листа, C = JSON-массив;
- справа поля выбранного блока:
  - `name` — edit;
  - `value_kind` — combo: «Одно значение» / «Список»;
  - `data_type` — combo: текст / число / дата / дата-время / логическое;
  - `format` — edit;
  - `choices` — columns_pick-подобный накопительный список или multiline;
  - `prompt`, `title` — edit;
  - `required` — checkbox;
  - `default` — edit.
- на OK: имена обязательны, без тильды, без дубликатов (casefold).

Запись в C — только JSON. Несколько строк параметра по-прежнему допустимы (legacy).

Несколько блоков в одной строке → при сборе по одному runtime-диалогу на `name` (как раньше).

---

## 7. Acceptance (ручная проверка в Calc)

1. Строка ручного ввода **выше** «Файлы-Источники»; в маске файла — `*<<Переменные.Филиал>>*`; после OK диалога подтягивается ожидаемый набор файлов.
2. `choices` → combo; Cancel при `required=true` → сбор не стартует.
3. Значение доступно в `применить_формулу` как `<<Переменные.Имя>>`.
4. В журнале / debug карты ключ содержит `ручной_ввод`.

---

## 8. Вне объёма v1

- Повторный ввод при resume / втором прогоне без перезапуска книги.
- Маскированный ввод (пароль).
- Зависимость choices от другой переменной (каскад).
