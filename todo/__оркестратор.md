# ТЗ: `collect_pack` как оркестратор листов параметров

**Статус:** реализовано. Описание — [docs/18_ORCHESTRATOR.md](../docs/18_ORCHESTRATOR.md).

## 1. Назначение

Переделать точку входа **`collect_pack`** (имя экспорта и привязка в меню **не менять**) так, чтобы макрос по смыслу был **оркестратором** запусков сбора по листам группы **`Параметры_Объединения*`** (в разговорной формулировке — «Параметры обработки»).

Сейчас (`collect_workbooks.py`):

```python
def collect_pack(event=None):
    if not collect_workbooks(event):
        return False
    collect_reset_db_ranges(event)
    return True
```

То есть всегда: один запуск `collect_workbooks` (активный / единственный лист параметров) → всегда `collect_reset_db_ranges` (сброс DatabaseRange / smart-table через двойное переоткрытие).

**Цель:** перед запуском показать диалог; дать выбрать **один или несколько** листов параметров, **порядок** их выполнения и опционально — вызывать ли `collect_reset_db_ranges` в конце.

## 2. Согласование с текущей архитектурой

| Тема | Сейчас | После переделки |
| ---- | ------ | ---------------- |
| Имя макроса / `g_exportedScripts` | `collect_pack` | **без изменений** |
| `collect_workbooks` | отдельная точка входа «один конфиг» | контракт внешнего API **не менять**. Оркестратор для каждого выбранного листа: делает лист **активным**, `set_run_param_sheet`, затем вызывает тот же путь сбора, что и `collect_workbooks`. Если на листе параметров способ показа динамики = **Диалог** — прогресс-диалог показывается **на каждую итерацию**; пользователь может **отменить текущую** итерацию (остальные не запускать) |
| Несколько `Параметры_Объединения*` | `resolve_param_sheet_for_run`: нужен **активный** лист группы | для **`collect_pack`**: диалог выбора/порядка; заранее активировать лист не обязательно |
| Один лист параметров | запуск без выбора | диалог **упрощённый** (подтверждение + галочка переоткрытия) |
| `collect_reset_db_ranges` | всегда после успешного сбора | галочка на диалоге оркестратора (**по умолчанию вкл.**); при мульти — **один раз** в конце, если галочка вкл. и **выполнен хотя бы один** лист параметров (даже если цепочка оборвалась на следующем) |
| Каноническое имя листов | префикс `Параметры_Объединения` | то же; в UI — «лист параметров» / «Параметры_Объединения» |
| Предварительное удаление листов (`maybe_clear_sheets` и правила «Листы_не_удалять» / очистка неслужебных) | по настройкам **текущего** листа параметров | при **двух и более** листах в плане: правила предварительного удаления отрабатывать **только по первому** листу плана. На последующих итерациях предварительное удаление неслужебных листов **подавлять**, независимо от текста на следующем листе параметров. Функции удаления **внутри** постобработки / `Финальная_обработка` (`удаление_листов` и т.п.) на каждом листе **разрешены** и выполняются как обычно. **Если в книге ≥2 листов параметров, а запускается только один** (оркестратор с одним выбранным или legacy `collect_workbooks`) и «Листы_не_удалять» **не задан** — перед default-очисткой **спросить** (Да = удалить, Нет = сбор без удаления; удобно при повторном этапе) |
| Журнал | лист **`Сбор_книг_лог`** (`MERGE_LOG_SHEET_NAME`) | **один** лист параметров в плане → как сейчас, `Сбор_книг_лог`. **Несколько** в плане → отдельный журнал на каждую итерацию: `Сбор_книг_лог_1`, `Сбор_книг_лог_2`, … (номер = порядковый номер в плане запуска). Служебные имена журналов включать в «не удалять» |
| Persist настроек диалога | нет | JSON в каталоге конфигураций пресетов визарда (`~/.config/libre-macros/collect_workbooks/` или тот же helper, что `merge_param_presets.json`); ключ записи — **абсолютный путь** к текущей книге |
| AO 2026 | entry в `Scripts/python/` | логика диалога и цикла — в `pythonpath/`; `collect_pack` — тонкая обёртка |

Связанные функции: `list_param_sheet_names`, `set_run_param_sheet`, `get_run_param_sheet`, `resolve_param_sheet_for_run`, `collect_workbooks` / `collect_workbooks_run`, `collect_reset_db_ranges`, `maybe_clear_sheets`, `append_collect_log` / `reset_collect_log`.

Документация-контекст: `docs/04_DATA_COLLECTION.md` §1.1, `docs/09_ARCHITECTURE.md`, `docs/06_PARAM_WIZARD.md` (каталог пресетов).

## 3. Сценарии UI

### 3.1. В книге **несколько** листов `Параметры_Объединения*`

Диалог оркестратора:

1. **Список** всех листов группы (имена как на вкладках).
2. Для каждого — **включить/выключить** участие (чекбокс).
3. **Очередность** среди отмеченных (кнопки «Выше» / «Ниже»; минимум Up/Down).
4. Можно отметить один или несколько.
5. Галочка **«Переоткрытие (сброс DatabaseRange)»** → `collect_reset_db_ranges` — **по умолчанию включена**.
6. Кнопка **«Сохранить настройки»** — запись JSON в каталог конфигураций (см. §3.5).
7. Кнопки **Запустить** / **Отмена**.

Порядок списка **по умолчанию** (если нет сохранённой записи): **порядок вкладок** книги слева направо (`doc.Sheets` по индексу), не алфавитная сортировка.

Пустой выбор: «Запустить» неактивна или сообщение «Выберите хотя бы один лист».

### 3.2. В книге **ровно один** лист `Параметры_Объединения*`

Диалог **вырождается** в подтверждение:

- Текст: **«Будет запущен сбор с параметрами листа „…“»** (реальное имя).
- Галочка переоткрытия — **по умолчанию включена** (подгрузить из JSON, если есть запись для пути книги).
- Опционально та же кнопка **«Сохранить настройки»** (хотя бы состояние галочки).
- **Запустить** / **Отмена**.

Без списка и без настройки порядка.

### 3.3. Листов параметров **нет**

Как у `collect_workbooks`: сообщение об отсутствии `Параметры_Объединения*`. Диалог оркестратора не показывать.

### 3.4. Отмена диалога оркестратора

«Отмена» / закрытие → `collect_pack` возвращает `False`, сбор и reset не выполняются.

### 3.5. Сохранение / загрузка настроек диалога

| Правило | Деталь |
| ------- | ------ |
| Каталог | Тот же, что пресеты визарда: `…/libre-macros/collect_workbooks/` (см. `_WP_PRESETS_SUBDIR` / consent helper) |
| Файл | отдельный, напр. `collect_pack_orchestrator.json` (не смешивать с `merge_param_presets.json`) |
| Ключ записи | абсолютный путь к файлу текущей книги |
| Книга не сохранена на диск | «Сохранить настройки» → ошибка: сначала сохраните книгу |
| При открытии диалога | если есть запись для пути — восстановить: список enable, порядок, галочку reset; иначе defaults (все включены или как решите в UI — **рекомендация:** все включены, порядок вкладок, reset=on) |
| Содержимое JSON (черновик) | `{ "v": 1, "books": { "/abs/path.ods": { "sheets": [{"name":"…","enabled":true}, …], "reset_db": true } } }` |

## 4. Семантика галочки переоткрытия

| Состояние | Действие |
| --------- | -------- |
| Вкл. (default) | **Один раз в конце** всей сессии `collect_pack`: вызвать `collect_reset_db_ranges`, если **хотя бы одна** итерация сбора успешно дошла до конца |
| Выкл. | Не вызывать |

Уточнения:

- Запрашивается **только на форме оркестратора** (не на каждом листе параметров).
- Если итерация 1 ок, итерация 2 отменена пользователем в прогресс-диалоге или упала — при включённой галочке reset **всё равно выполняется** (был выполнен хотя бы один лист).
- Если **ни одна** итерация не стартовала успешно (отмена на оркестраторе, ошибка превалидации JSON до цикла, ошибка на первом же листе до полезной работы) — reset **не** вызывать.
- `collect_reset_db_ranges` no-op при отсутствии DatabaseRange — нормально.
- Цель reset — актуальная книга результата (`get_run_target_doc` после последнего шага).

Подпись UI: **«Переоткрытие (сброс DatabaseRange)»**.

## 5. Интеграция с `collect_workbooks`

### 5.1. Что не ломать

- Меню / контекст **«Обработка книг»** → `collect_workbooks` — один конфиг; при нескольких листах по-прежнему нужен активный.
- `collect_reset_db_ranges`, `collect_workbooks_reopen` — отдельные экспорты.

### 5.2. Порядок работы оркестратора

0. **Превалидация** выбранных листов (или единственного): до цикла прогнать разбор JSON/параметров (`parse_collect_settings` или эквивалент по каждому листу плана). При ошибке десериализации / валидации — **не начинать** сбор, сообщение **где** (имя листа, строка/параметр) и **что** не так.
1. Перед каждым шагом: активировать лист, `set_run_param_sheet(name)`, назначить лист журнала (`Сбор_книг_лог` или `Сбор_книг_лог_N`).
2. Вызвать внутренний runner сбора **без** повторного диалога оркестратора.
3. Прогресс **Диалог** (если задан на этом листе параметров) — на **каждую** итерацию; отмена в нём = прервать очередь (предыдущие результаты сохранить).
4. Consent / лицензия — **один раз** на сессию `collect_pack`.
5. Книгу результата между шагами **не закрывать**.

### 5.3. Предварительное удаление листов (мульти)

```
если len(plan) == 1:
    maybe_clear_sheets / правила — как сейчас по этому листу
иначе:  # два и более
    на plan[0]: maybe_clear_sheets по правилам первого листа
    на plan[1..]: подавить предварительную очистку неслужебных листов
    удаление_листов / скрытие_листов в финале каждого листа — без ограничений
```

### 5.4. Ошибка во время цикла (после превалидации)

Если итерация N вернула `False` (ошибка сбора, отмена диалога прогресса) — очередь останавливается; уже выполненные листы **не откатываются**; reset — по правилу §4 (если был успех хотя бы на одном предыдущем / текущем — уточнить: «успешно завершённая итерация»).

**Критерий «выполнен»:** итерация вернула успех (`True`) от runner’а сбора.

### 5.5. Журналы

| План | Имя листа журнала |
| ---- | ----------------- |
| 1 лист | `Сбор_книг_лог` |
| N≥2, i-я итерация (1-based) | `Сбор_книг_лог_{i}` |

В начале итерации — сброс/создание соответствующего листа журнала; писать метку имени листа параметров.

## 7. Критерии приёмки (ручная проверка в Calc)

Автотесты не писать.

1. Один `Параметры_Объединения` → диалог-подтверждение, reset вкл. → сбор + `collect_reset_db_ranges`; журнал `Сбор_книг_лог`.
2. Галочка снята → сбор без reset.
3. Несколько листов → список; два отмечены, порядок изменён → выполняются в этом порядке; журналы `Сбор_книг_лог_1`, `Сбор_книг_лог_2`.
4. Один из трёх отмечен → только он; журнал как при единичном (`Сбор_книг_лог`), если в плане один лист.
5. Отмена на диалоге оркестратора → ничего не запускается.
6. Итерация 1 ок, итерация 2 ошибка/отмена прогресса → результаты 1 на месте; при включённом reset — reset **вызывается**; 3-й не стартует.
7. Битый JSON на одном из выбранных — превалидация, цикл не начинается, reset нет.
8. Мульти: предварительная очистка листов только по правилам **первого** в плане; на втором `maybe_clear_sheets` не сносит результаты первого; `удаление_листов` в финале второго — работает.
9. «Сохранить настройки» без сохранённой книги → ошибка; после Save книги → JSON пишется; повторный открытие диалога восстанавливает выбор/порядок/галочку.
10. Export `collect_pack` без переименования; `collect_workbooks` без изменения правила активного листа.

## 9. Краткий алгоритм `collect_pack` (целевой)

```
doc = активная книга Calc
names = list_param_sheet_names(doc)   # порядок вкладок
если names пуст → сообщение, return False

загрузить saved = JSON[path(doc)] если книга сохранена и запись есть

если len(names) == 1:
    диалог-подтверждение (имя, reset из saved или on)
иначе:
    диалог списка (выбор/порядок из saved или defaults, reset)

если отмена → return False

plan = упорядоченные enabled имена
если plan пуст → сообщение, return False

превалидация parse_collect_settings по каждому name в plan
если ошибка → сообщение, return False

any_ok = False
для i, name в enumerate(plan, start=1):
    активировать лист name
    set_run_param_sheet(name)
    назначить журнал: Сбор_книг_лог если len(plan)==1 иначе Сбор_книг_лог_{i}
    suppress_pre_clear = (len(plan) > 1 и i > 1)
    ok = collect_workbooks_для_листа(name, suppress_pre_clear=…)
    если ok: any_ok = True
    иначе: break   # отмена прогресса / ошибка сбора

если галочка reset и any_ok:
    collect_reset_db_ranges(event)

return any_ok   # или True только если весь plan прошёл — зафиксировать: return True если весь plan ok, иначе False; reset при any_ok
```

**Итоговый код возврата (зафиксировано):** `True`, только если **все** итерации плана успешны; иначе `False`. Reset при `reset && any_ok` — независимо от полного успеха цепочки.

## 10. Зафиксированные решения

| # | Решение |
| - | -------- |
| 1 | Порядок списка по умолчанию — **вкладки книги**, не sort по имени |
| 2 | Перед каждой итерацией лист параметров **активировать** |
| 3 | Имя журнала — каноническое **`Сбор_книг_лог`** (+ суффикс `_N` при мульти) |
| 4 | Reset при мульти — один раз в конце, если **хотя бы одна** итерация успешна |
| 5 | Persist — кнопка «Сохранить настройки» + автозагрузка при открытии диалога |
