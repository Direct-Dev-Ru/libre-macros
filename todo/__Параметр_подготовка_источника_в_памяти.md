# ТЗ: параметр «Подготовка источника в памяти» для ODS / XLS(X)

**Статус:** реализовано (v3.10.346).  
**Аналог по CSV:** `Доп_Параметры_Источника` с `delimiter` / `encoding` / `copy_whole_sheet` — источник читается без UNO в матрицу → `setDataArray` (см. `docs/04_DATA_COLLECTION.md` §5.1, `docs/15_PARAM_REFERENCE.md`).

---

## 1. Назначение

Добавить в **`Доп_Параметры_Источника`** флаг **«подготовка источника в памяти»** для книг **`.ods`**, **`.xls`**, а также **`.xlsx` / `.xlsm`** (тот же путь чтения через бандлы, что уже используется в `xml_excel_ods`).

**Боль сейчас:** при режимах «На один лист» / «На разные листы» и способах **`Буфер_по_заголовкам`** / **`Буфер_по_позиции`** источники открываются через UNO (`open_source` / Calc). На больших файлах и при многих источниках это медленно и тяжело по памяти GUI.

**Цель:** по явному флагу читать источник **прямым доступом к файлу** (бандл-библиотеки) → собрать **матрицу значений в памяти** → записать на лист(ы) результата через **`setDataArray`** (как у CSV-матрицы), **без** открытия книги-источника в Calc.

По умолчанию поведение **не меняется** (флаг выключен / отсутствует).

---

## 2. Где задаётся

| Место | Значение |
| ----- | -------- |
| Параметр A | `Доп_Параметры_Источника` |
| Колонки | B, C, D… по файлам (как сейчас: пустая ячейка → fallback на B) |
| Формат | JSON-объект в ячейке (не массив блоков постобработки) |
| Визард | субдиалог `show_source_extra_param_dialog` — новое поле combo для не-CSV |

Пример (книга, минимальный):

```json
{"prepare_source_in_memory": true}
```

Пример (книга, полный набор v1 UI):

```json
{
  "prepare_source_in_memory": true,
  "values_mode": "cached",
  "merged_cells": "top_left",
  "trim_empty": true,
  "convert_types": "in_memory",
  "chunk_rows": 50000
}
```

JSON **не смешивать** наборы ключей разных типов источника в одном объекте из визарда:

- книга → только ключи §3 (book-extra);
- CSV → только `delimiter` / `encoding` / `copy_whole_sheet`.

Для CSV отдельный флаг памяти **не нужен** (матрица уже default; исключение — `copy_whole_sheet: true` в «Копирование листов»). Ручной JSON с лишними ключами парсер может игнорировать, но UI их не предлагает.

## 3. Параметры книги (JSON)

Главный тумблер + субпараметры **только** для ODS / XLS(X/M). Имеют смысл в основном при `prepare_source_in_memory: true`; при `false` визард может их **задизейблить**, но в JSON оставлять допустимо (исполнитель игнорирует).

### 3.1. Главный флаг

| Роль | Значение |
| ---- | -------- |
| Канон JSON | `prepare_source_in_memory` |
| Подпись в визарде | `Подготовка источника в памяти` |
| Синонимы | `подготовка_источника_в_памяти`, `prepare_in_memory`, `source_in_memory`, `матрица_в_памяти` |
| Тип | bool |
| По умолчанию | `false` |
| Разбор | `_parse_source_extra_bool` |

### 3.2. Субпараметры — **рекомендуется в UI v1**

Компактный субдиалог (~6 полей), по духу как CSV (3 поля), но про чтение книги и лимиты RAM.

#### `values_mode` — что брать из ячейки

| | |
| - | - |
| Подпись | `Значения ячеек` |
| Канон | `values_mode` |
| Синонимы | `cell_values`, `значения` |
| Default | `cached` |

| code | Подпись (RU) | Смысл |
| ---- | ------------ | ----- |
| `cached` | Кэш / вычисленные (по умолчанию) | openpyxl `data_only=True`; в ODS — отображаемое/сохранённое значение. Как Calc «значения» |
| `formulas` | Текст формул | В матрицу строка формулы (`=A1+B1`), не результат. Полезно для аудита / отчётов-шаблонов |
| `prefer_cached` | Кэш, иначе формула | Если кэша нет (файл сохранён без пересчёта) — подставить текст формулы, не пусто |

**Зачем:** типичная ловушка Excel/Calc — «открыли через бандл, а столбцы с формулами пустые». Явный режим снимает сюрприз.

#### `merged_cells` — объединённые ячейки

| | |
| - | - |
| Подпись | `Объединённые ячейки` |
| Канон | `merged_cells` |
| Синонимы | `merges`, `объединения` |
| Default | `top_left` |

| code | Подпись | Смысл |
| ---- | ------- | ----- |
| `top_left` | Только левая верхняя (как Calc) | Значение в первой клетке объединения; остальные пустые |
| `fill` | Размножить на всё объединение | Каждая клетка merge получает то же значение — удобно для «шапка через merge» + буфер по позиции / матчинг столбцов |

**Зачем:** отчёты 1С/Excel часто пишут заголовок группы в merge; без `fill` строки «теряют» ключ при позиционном сборе.

#### `trim_empty` — обрезка пустого хвоста

| | |
| - | - |
| Подпись | `Обрезать пустые края` |
| Канон | `trim_empty` |
| Синонимы | `trim_trailing_empty`, `обрезать_пустые` |
| Тип | bool |
| Default | `true` при `prepare_source_in_memory`, иначе N/A |

Убрать хвостовые полностью пустые строки/столбцы после чтения used-range (Excel часто раздувает диапазон до 1M строк «по следу форматирования»).

**Зачем:** без этого матрица в RAM = OOM на «пустом» хвосте; с `Число_Строк` на листе параметров дублируется частично, но per-file default «подрезать» безопаснее.

#### `convert_types` — где конвертировать числа и даты

| | |
| - | - |
| Подпись | `Числа и даты` |
| Канон | `convert_types` |
| Синонимы | `types`, `типы`, `convert_numbers_dates`, `convert_where` |
| Default | `in_memory` |

**Инвариант (жёстко):** текст→число/дата — **ровно в одном месте**: либо в памяти на чанке перед сливом, либо позже UNO по листу результата. **Нельзя** делать оба прохода (двойная конвертация / порча уже числовых ячеек).

| code | Подпись (RU) | Смысл |
| ---- | ------------ | ----- |
| `in_memory` | В памяти (по умолчанию) | На каждом чанке — проход как у CSV-матрицы (`_merge_csv_convert_matrix_numbers_dates` / правила `MERGE_XML_CONVERT_TO_NUMBERS` + форматы дат). На лист — уже числа/`datetime`. UNO-конвертацию для этих строк/листов **не вызывать** (skip-метка, аналог CSV-матрицы) |
| `uno` | Оставить для UNO | В чанк — «как прочитал» бандл. После `setDataArray` — **один** UNO-проход чисел/дат на результате. В памяти конвертацию **не делать** |
| `no` | Не конвертировать | Ни в памяти, ни UNO (ведущие нули, коды) |
| `keep_text` | Всё текстом в памяти | Принудительно unicode перед записью; UNO-конвертацию тоже **не** запускать |

Синонимы при разборе: `yes` / `true` / `да` / `auto` → `in_memory` (для пути «в памяти» auto = сразу в RAM, без отложенного UNO).

#### `chunk_rows` — лимит строк в одном накопителе

| | |
| - | - |
| Подпись | `Строк в чанке памяти` |
| Канон | `chunk_rows` |
| Синонимы | `memory_chunk_rows`, `max_chunk_rows`, `лимит_строк_чанка` |
| Тип | int ≥ 1 |
| Default | **`50000`** |

Не собирать в RAM миллионостроковую таблицу целиком.

```
chunk = новый пустой накопитель
для каждой строки источника (после trim / merge-fill / фильтра столбцов):
    добавить строку в chunk
    если len(chunk) >= chunk_rows:
        [если convert_types=in_memory → сконвертировать только этот chunk]
        слить chunk на лист результата (setDataArray / append к out_row)
        освободить ссылки на chunk (del / обнулить)
        chunk = новый пустой накопитель   # новый объект → GC может забрать старый
хвост chunk → то же слияние + освобождение
```

- Размер одного объекта в RAM ≈ `chunk_rows` строк (+ служебные колонки).
- Слив **инкрементальный**; порог — фаза накопления при чтении (не путать с `MERGE_COPY_ROW_CHUNK` при UNO-записи буфера).
- JSON `0` / отрицательное / пусто → подставить **50000** (не «без лимита»).
- Константа: `SOURCE_EXTRA_DEFAULT_CHUNK_ROWS = 50000` в cfg (`pythonpath`), не голый литерал в entry.

**Зачем:** отчёты 200–500k строк обрабатываются пакетами; пик памяти стабилен.

### 3.3. Субпараметры — **опционально / backlog UI**

| Ключ | Default | Смысл |
| ---- | ------- | ----- |
| `max_cols` | `0` | Потолок столбцов в чанке сверх col_specs; warning при обрезке |
| `hard_max_rows` | `0` (= нет) | Абсолютный потолок **всего** источника: stop + `report.problem` (не путать с `chunk_rows`) |
| `skip_hidden_sheets` | `false` | Не читать скрытые вкладки при «Все» / шаблоне |
| `skip_hidden_rows` | `false` | Пропуск скрытых строк (soft-ignore, если бандл не умеет) |
| `empty_as` | `""` | Пустые ячейки в чанке: `""` \| `null` |
| `datetime_format` | `""` | Override маски дат при `convert_types=in_memory` |
| `password` | — | Пароль книги (редко; backlog) |

### 3.4. Хелперы

`source_extra_prepare_in_memory(extra)`, `source_extra_values_mode(extra)`, `source_extra_convert_types(extra)`, `source_extra_chunk_rows(extra)`, … — рядом с CSV-getter'ами **или** общий `libre_macros_source_extra_lib.py`.

Разбор bool — общий `_parse_source_extra_bool`.

## 4. Когда флаг действует

### 4.1. Условия включения пути «матрица»

Одновременно:

1. Для файла-источника `prepare_source_in_memory == true`.
2. **Режим** ∈ {`На один лист`, `На разные листы`}  
   (`MERGE_MODE_ONE` / `MERGE_MODE_MANY`).
3. **Способ_переноса** ∈ {`Буфер_по_заголовкам`, `Буфер_по_позиции`}  
   (`MERGE_TRANSFER_CLIPBOARD_HEADERS` / `MERGE_TRANSFER_CLIPBOARD_POSITION`).
4. Тип файла ∈ {`.ods`, `.xls`, `.xlsx`, `.xlsm`} (локальный путь; URL/smb — см. §7).

Тогда:

```
файл → бандл-чтение (потоково / по строкам)
     → накопление chunk (≤ chunk_rows, default 50000)
     → [convert_types=in_memory: конвертация только этого chunk]
     → слив на лист результата setDataArray → новый chunk (освобождение RAM)
     → [convert_types=uno: после всех сливов — один UNO-проход типов на результате;
        convert_types=in_memory|no|keep_text: UNO-конвертацию не повторять]
```

Источники **не** открывать через `open_source` / UNO для переноса данных.

### 4.2. Когда флаг **игнорируется** (без ошибки, лог «не применимо»)

| Контекст | Поведение |
| -------- | --------- |
| Режим `Копирование листов` | Обычный `importSheet` / текущий путь; флаг не меняет семантику (для CSV по-прежнему `copy_whole_sheet`) |
| Режим `Вовлечь листы` | Нет переноса с внешнего файла |
| `Способ_переноса` = `По_API` | Оставить UNO `getDataArray`/`setDataArray` как сейчас (флаг не активирует бандл-путь в v1; опционально — предупреждение в лог) |
| `Способ_переноса` = `xml_excel_ods` | Уже прямой путь в файл результата; флаг не дублировать / игнорировать |
| Флаг `false` / отсутствует | Без изменений |

### 4.3. Per-file семантика

Флаг читается **из доп. параметров конкретного файла** (`per_file_source_extra[fi]`).  
В одном запуске часть источников может идти через UNO, часть — через матрицу (как разные `delimiter` у CSV).

## 5. Алгоритм (v1)

Эталон записи на результат: ветка CSV  
`_merge_load_csv_source_matrix` → `_merge_append_csv_matrix_to_target`  
(`collect_workbooks.py`).

### 5.1. Чтение и чанки (не одна гигантская матрица)

| Расширение | Бандл / API | Заметка |
| ---------- | ----------- | ------- |
| `.xlsx`, `.xlsm` | `openpyxl_bundled` (`load_workbook`, `read_only=True`, предпочтительно потоковый `iter_rows`) | Уже в `libre_macros_direct_lib` |
| `.ods` | `odf_bundled` / odfpy | Как `_direct_ods_read_*`; по возможности не материализовать весь лист сразу |
| `.xls` (BIFF) | **Отдельное решение** (§8) | openpyxl **не** читает `.xls` |

Выбор листа — по `Листы` / `per_file_sheet_specs` / блокам — та же семантика, что при UNO-сборе.

Накопитель: объект `chunk` на ≤ `chunk_rows` (default 50000). После слива — **новый** объект; старый отпускать, чтобы GC освободил память. Не хранить список всех чанков файла.

`merged_cells=fill` / `trim_empty` — на этапе формирования строк **до** попадания в chunk (или на границах чанка аккуратно: trim хвоста — на последнем чанке / после EOF).

### 5.2. Запись чанка

- **Буфер_по_заголовкам** — матчинг по шапке (шапка с первого чанка / probe), `ensure_target_headers`, append по колонкам.
- **Буфер_по_позиции** — прямоугольник в порядке столбцов (как `_merge_csv_write_matrix_by_position`), `out_row` растёт между чанками.
- Внутри слива чанка допустим доп. подчанк `MERGE_COPY_ROW_CHUNK` для `setDataArray`.
- Служебные `#Путь`, `#ДатаВремяФайла`, `Ячейка_В_Столбец` — из метаданных файла / заранее снятых значений, без повторного `open_source`.

### 5.3. Числа и даты — взаимоисключение

См. **`convert_types`** (§3.2):

| Режим | В памяти на chunk | UNO после записи |
| ----- | ----------------- | ---------------- |
| `in_memory` | да | **нет** (лист/диапазон в skip-списке конвертации) |
| `uno` | нет | **да** (один проход) |
| `no` / `keep_text` | нет (keep_text — только stringify) | **нет** |

### 5.4. Лог

Префикс `[MEM]` / `[ODS-MEM]` / `[XLS-MEM]`: путь, `chunk_rows`, номер чанка, строк в чанке, ms convert, ms write, режим headers/position, `convert_types`.

## 6. Визард — **два независимых субдиалога**

**Жёсткое правило UX:** субдиалог для ODS / XLS(X/M) **полностью отдельный** от CSV. Не добавлять поля книг в CSV-диалог и наоборот; не показывать «общую» форму с обоими наборами параметров.

Диспетчер по расширению пути из «Файлы-Источники» (колонка):

| Источник | Субдиалог | Поля |
| -------- | --------- | ---- |
| `.csv` | текущий `show_source_extra_param_dialog` (CSV-only) | разделитель, кодировка, «переносить всем листом» (`delimiter` / `encoding` / `copy_whole_sheet`) |
| `.ods`, `.xls`, `.xlsx`, `.xlsm` | **новый** субдиалог `show_source_extra_book_param_dialog` | поля §3.1–3.2 (см. ниже) |
| путь пуст / неизвестное расширение | отдельная лёгкая заглушка или выбор типа; **не** смешивать CSV+book на одном экране | подсказка задать путь источника |

Точка входа визарда (`kind == 'source_extra'`): по `_source_extra_is_csv_path` / `_source_extra_is_book_path` вызвать **разные** функции; общая обёртка только для peer/footer/OK-Cancel.

### 6.1. Субдиалог книги (ODS / XLS / XLSX / XLSM)

- Заголовок: «Доп. параметры источника (книга)» / с буквой колонки.
- Hint: путь файла + краткое пояснение про ONE/MANY + буфер.
- Поля (все combo / да-нет, подписи на русском; code в JSON отдельно):

  1. **Подготовка источника в памяти** — Нет / Да (`prepare_source_in_memory`)
  2. **Значения ячеек** — кэш / формулы / кэш иначе формула (`values_mode`) — enable при Да
  3. **Объединённые ячейки** — только левая верхняя / размножить (`merged_cells`) — enable при Да
  4. **Обрезать пустые края** — Нет / Да (`trim_empty`) — enable при Да; default Да
  5. **Числа и даты** — в памяти / оставить для UNO / не конвертировать / всё текстом (`convert_types`) — enable при Да
  6. **Строк в чанке памяти** — combo или числовое поле; пресеты `10000` / `25000` / `50000` (default) / `100000` (`chunk_rows`) — enable при Да

- При «Подготовка… = Нет» остальные контролы disabled; предпочтительно **не писать** выключенные субключи в JSON.
- **Нет** полей разделителя, кодировки, `copy_whole_sheet`.
- Сериализация: только book-ключи, напр.:

```json
{
  "prepare_source_in_memory": true,
  "values_mode": "cached",
  "merged_cells": "fill",
  "trim_empty": true,
  "convert_types": "in_memory",
  "chunk_rows": 50000
}
```
### 6.2. Субдиалог CSV

- Без изменений по смыслу; **не** добавлять `prepare_source_in_memory` в CSV-форму (для CSV матрица уже default).
- Сериализация: как сейчас, только CSV-ключи.

### 6.3. Реализация

- Константы выборов книги — отдельно в `libre_macros_param_wizard_cfg.py` (напр. `_SOURCE_EXTRA_PREPARE_IN_MEMORY_CHOICES`), не на уровне entry.
- Не раздувать один `show_source_extra_param_dialog` ветками `if is_csv` с разными контролами на одной модели — два диалога, общий код вынести в хелперы размера/peer при необходимости.
- Choices: `_SOURCE_EXTRA_PREPARE_IN_MEMORY_CHOICES`, `_SOURCE_EXTRA_VALUES_MODE_CHOICES`, `_SOURCE_EXTRA_MERGED_CELLS_CHOICES`, `_SOURCE_EXTRA_TRIM_EMPTY_CHOICES`, `_SOURCE_EXTRA_CONVERT_TYPES_CHOICES`, `_SOURCE_EXTRA_CHUNK_ROWS_CHOICES` + `SOURCE_EXTRA_DEFAULT_CHUNK_ROWS` в cfg.

## 7. Ограничения и краевые случаи

| Тема | Правило |
| ---- | ------- |
| Удалённые пути (`smb://`, URL) | В v1 — **не** включать бандл-путь (ошибка или fallback на UNO + запись в журнал). Прямой доступ только к локальным файлам (как у `xml_excel_ods`) |
| `эта_книга` | Флаг не нужен / игнор: данные уже в текущем документе |
| Память | Пик ≈ `chunk_rows` (default 50000), не весь лист; после слива — новый накопитель. `hard_max_rows` — аварийный стоп |
| Оформление источника | Как у CSV-матрицы: **значения**, не стили ячеек источника |
| Фильтры столбцов / пропуск строк | Через уже существующие `Столбцы`, `Пропуск_строк_источника`, блоки — на матрице, не через UNO |
| Смешение с `По_API` | v1: флаг не активируется; можно позже унифицировать запись |

## 8. Особенность `.xls`

`openpyxl` читает только OOXML (`.xlsx`/`.xlsm`). Для **`.xls`** в ТЗ зафиксировать один из вариантов реализации (выбрать при реализации, отразить в docs):

| Вариант | Суть | Плюс / минус |
| ------- | ---- | ------------ |
| **A (предпочтительно для единообразия с direct)** | Однократная конвертация `.xls` → временный `.xlsx` (уже есть задел в экосистеме direct / Calc filter), далее openpyxl → матрица; temp удалить | Без нового бандла; возможен краткий UNO/фильтр только на конвертацию |
| **B** | Бандл `xlrd` (или аналог) → матрица напрямую | Чистый Python; вес бандла, поддержка только чтения |
| **C** | Для `.xls` флаг в v1 **не поддерживать** — сообщение «только ods/xlsx; xls — UNO» | Быстрый ship; неполная формулировка запроса |

Рекомендация ТЗ: **A** или **B**; в UI для `.xls` флаг показывать, если выбран A/B.

**Реализовано:** вариант **A** — `.xls` → temp `.xlsx` через `_merge_convert_xls_to_xlsx_via_uno`, далее openpyxl → матрица; temp удаляется.

`.ods` — только `odf_bundled`, без конвертации в xlsx на этапе чтения (если уже есть готовое чтение строк в `libre_macros_direct_lib`).

## 11. Критерии приёмки (ручная проверка в Calc)

Автотесты не писать (`json-only-manual-testing`).

1. **Default:** ODS + «На один лист» + «Буфер_по_заголовкам», доп. параметры пустые / `{"prepare_source_in_memory":false}` — результат как до изменения (UNO).
2. **Флаг включён:** тот же сценарий с `{"prepare_source_in_memory":true}` — данные на Merge совпадают по значениям (с учётом типов), в журнале/консоли — чтение через бандл / матрицу, источник в UI Calc не мелькает как открытая книга (или открывается заметно реже).
3. **Буфер_по_позиции:** ODS/XLSX, флаг on — столбцы по позиции, без матчинга имён.
4. **На разные листы:** несколько листов/файлов, флаг on — раскладка листов как при обычном MANY.
5. **Per-file:** один файл с флагом, второй без — смешанный проход без падения.
6. **Игнор:** флаг on + «Копирование листов» / `По_API` / `xml_excel_ods` — без регрессии, в логе «не применимо» при необходимости.
7. **`.xls`:** по выбранному варианту §8 — либо матричный путь, либо явное сообщение.
8. **Визард книга:** отдельный субдиалог с полями §3.1–3.2; без CSV-полей; при «Подготовка = Нет» субполя disabled; JSON в B/C/….
9. **Визард CSV:** без изменений; book-ключи на экране не появляются.
10. **merged_cells=fill:** источник с merge-шапкой — значения размножены, буфер по позиции не «дырявый».
11. **trim_empty + chunk_rows:** файл с раздутым used-range / >50k строк — в логе несколько чанков по ≤50000; пик RAM не растёт линейно с полным числом строк.
12. **values_mode=formulas:** в Merge видны строки формул, не пустые кэши.
13. **convert_types=in_memory:** числа/даты на листе корректны; повторный UNO-проход типов для этих данных **не** выполняется (проверить по логу / skip).
14. **convert_types=uno:** в чанках сырые значения; после сбора срабатывает UNO-конвертация **один** раз; в памяти convert не логируется.
