# ТЗ: отправить_по_почте

Новая функция **финальной** обработки (FINAL-only; не RANGE).
Не меняет ячейки книги результата — сохраняет вложение во временный файл и открывает **новое письмо** в почтовом клиенте ОС для ручной отправки пользователем.

**Имя ключа (fn):** `отправить_по_почте`  
**Синонимы / алиасы:** `email`, `mailto`, `send_mail`, `почта`.  
**Lib:** `lm_final_send_mail` / `merge_final_send_mail`  
**Не** добавлять в `_LM_FINAL_RANGE_SPEC` (это не range-обёртка) — отдельный `lm_final_*` в `libre_macros_final_lib.py`, как `копировать_лист`.

**Цель:** после сбора/постобработки одним шагом финала подготовить вложение (вся книга или выбранные листы) и показать пользователю окно «Новое сообщение» с заполненными полями (кому / тема / тело / вложение), без автоматической отправки на SMTP.

---

## 0. Возможность — да

| Механизм | ОС | Вложение | UI compose |
| -------- | -- | -------- | ---------- |
| UNO `com.sun.star.system.SimpleSystemMail` | Windows (Outlook / default MAPI) | да (`setAttachement` + file URL) | да (`sendSimpleMailMessage(msg, 0)`) |
| UNO `com.sun.star.system.SimpleCommandMail` | Linux / macOS (Thunderbird и др.) | зависит от клиента/бэкенда | да |
| Fallback Shell: `outlook.exe /a "…" /m "…"` | Windows + Outlook | да | да |
| Fallback Shell: `thunderbird -compose "…,attachment=file://…"` | Win/Linux/macOS | да | да |
| `mailto:` URI | все | **нет** надёжных вложений | только to/subject/body |

**Эталон v1:** UNO Simple*Mail → при ошибке fallback Shell по `client` из JSON.  
**Не** слать письмо молча (`NO_USER_INTERFACE`) — только открыть compose.

Ограничения (зафиксировать в журнале / docs):

- клиент должен быть установлен и быть default mail handler (или явно выбран в параметрах);
- вложение = **файл на диске** (сначала `storeToURL` / экспорт копии);
- некоторые Linux-клиенты плохо принимают вложения через SimpleCommandMail — нужен fallback Thunderbird;
- автоматическая отправка без UI **вне scope** v1 (безопасность / consent).

## 1. Принцип работы

1. Прочитать блок(и) JSON `отправить_по_почте` из колонки C (`param_decode`).
2. Определить ОС (`sys.platform` / `os.name`) и стратегию клиента (`client` + `os` из блока, иначе auto).
3. Собрать **файл вложения** во временный каталог:
   - `attach: whole_book` — сохранить копию текущей книги результата;
   - `attach: sheets` — новая временная книга только с выбранными листами (копия вкладок), затем сохранить;
   - `attach: none` — письмо без файла (редко).
4. Сформировать UNO `XSimpleMailMessage`: `recipient`, `cc`, `bcc`, `subject`, `body`, `setAttachement([fileUrl])`.
5. Вызвать `sendSimpleMailMessage(msg, 0)` — показать UI клиенту.
6. Журнал: ОС, клиент, путь вложения, число листов, статус открытия compose.
7. Временный файл **не удалять сразу** (клиент читает асинхронно); опционально пометить для очистки на следующем запуске / в конце сессии.

Шаг **идемпотентен относительно данных книги**: не трогает листы/ячейки результата.

## 2. JSON-блок (колонка C)

```json
[{
  "v": 1,
  "fn": "отправить_по_почте",
  "attach": "whole_book",
  "sheets": ["Отчет", "Сводная"],
  "format": "ods",
  "filename": "Результат_{date}",
  "to": ["user@example.com"],
  "to_source_sheet": "Сотрудники",
  "to_source_range": "B2:B200",
  "cc": [],
  "bcc": [],
  "subject": "Отчет за {date}",
  "body": "Во вложении результат обработки.",
  "client": "auto",
  "os": "auto",
  "show_ui": true
}]
```

| Поле | Тип | Default | Смысл |
| ---- | --- | ------- | ----- |
| `attach` | enum | `whole_book` | `whole_book` \| `sheets` \| `none` |
| `sheets` | list | `[]` | Имена листов при `attach=sheets` (как у `удаление_листов`: exact / `*glob*` через существующий sheet-filter) |
| `format` | enum | `ods` | `ods` \| `xlsx` \| `pdf` (pdf v1 — опционально / позже) |
| `filename` | str | из имени книги | Имя файла без пути; плейсхолдеры `{date}`, `{time}`, `{book}` |
| `to` / `cc` / `bcc` | list[str] | `[]` | Адреса; в UI — многострочный / через `;` |
| `to_source_sheet` | str | `""` | Лист книги результата, откуда дочитать список получателей для `to` |
| `to_source_range` | str | `""` | A1-диапазон на `to_source_sheet`; читаются все ячейки диапазона |
| `subject` | str | `""` | Тема |
| `body` | str | `""` | Текст письма (plain) |
| `client` | enum | `auto` | `auto` \| `system` \| `outlook` \| `thunderbird` \| `mapi` |
| `os` | enum | `auto` | `auto` \| `windows` \| `linux` \| `macos` — подсказка визарду / валидация; runtime всё равно сверяет с реальной ОС |
| `show_ui` | bool | `true` | v1 всегда `true`; `false` зарезервирован / ошибка валидации |

Нормализация кодека:

- `to`/`cc`/`bcc` — список строк (если пришла одна строка — `split` по `;` / `,`);
- `to_source_sheet` / `to_source_range` — trim; если заполнено только одно из двух полей, блок невалиден;
- `sheets` — через `_normalize_sheet_name_list` / существующий фильтр листов;
- `attach` / `client` / `os` / `format` — lowercase + алиасы (`книга`→`whole_book`, `листы`→`sheets`, `вся_книга`→`whole_book`).

Дочитка `to` из диапазона:

1. Если заданы `to_source_sheet` и `to_source_range`, исполнитель читает **все непустые значения** ячеек указанного диапазона листа результата.
2. Каждое значение ячейки делится по `,` и `;`.
3. Каждый токен `trim()`-ится и проходит проверку:
   - либо email вида `xxx@some.ru`;
   - либо строка, похожая на ФИО вида `Иванов Иван Иванович`.
4. Валидные токены добавляются в `to` в конец списка, сохраняя порядок обхода диапазона.
5. Невалидные токены пропускаются; в журнале фиксируется количество пропусков и примеры первых невалидных значений.
6. Дубликаты убираются с сохранением порядка:
   - email — сравнение без учёта регистра;
   - ФИО — сравнение по trim + схлопнутым внутренним пробелам.

Пример минимальный:

```json
[{"v":1,"fn":"отправить_по_почте","attach":"whole_book","to":["boss@corp.local"],"subject":"Отчет"}]
```

Пример «только листы + Outlook»:

```json
[{
  "v":1,
  "fn":"отправить_по_почте",
  "attach":"sheets",
  "sheets":["Итог"],
  "format":"xlsx",
  "client":"outlook",
  "os":"windows",
  "to":["a@b.c"],
  "subject":"Итог"
}]
```

Пример `to` из диапазона:

```json
[{
  "v":1,
  "fn":"отправить_по_почте",
  "attach":"whole_book",
  "to":["boss@corp.local"],
  "to_source_sheet":"Сотрудники",
  "to_source_range":"B2:B200",
  "subject":"Итог"
}]
```

## 3. Визард (sheet-block form)

Регистрация в `_SHEET_BLOCK_FORM_FNS` + `_SHEET_BLOCK_FORM_SCHEMAS`.

Схема UI (`libre_macros_param_wizard_cfg.py`):

| id | type | Подпись | Примечание |
| -- | ---- | ------- | ---------- |
| `attach` | combo | Что вложить | `whole_book`→«Всю книгу», `sheets`→«Выбранные листы», `none`→«Без вложения» |
| `sheets` | combo/list или edit с фильтром листов | Листы | Видимо/активно при `attach=sheets`; накопление имён листов (не columns_pick) — как у sheet-list спец-форм |
| `format` | combo | Формат файла | ODS / XLSX (+ PDF later) |
| `filename` | edit | Имя файла | hint про `{date}` / `{book}` |
| `to` | edit (multiline) | Кому | `;` между адресами |
| `to_source_sheet` | combo | Лист для `to` | Лист результата, откуда читать получателей |
| `to_source_range` | edit | Диапазон для `to` | A1-диапазон; из всех ячеек берутся значения, затем split по `,` и `;` |
| `cc` | edit | Копия | |
| `bcc` | edit | Скрытая копия | |
| `subject` | edit | Тема | |
| `body` | edit multiline | Текст | |
| `os` | combo | Целевая ОС | auto / Windows / Linux / macOS — **настройка сценария**, не runtime-детектор |
| `client` | combo | Почтовый клиент | auto / Системный (UNO) / Outlook / Thunderbird |

Hints на русском: письмо **не** уходит само; пользователь нажимает «Отправить» в клиенте; при `sheets` нужна хотя бы одна вкладка; для `to_source_range` читаются все ячейки диапазона, затем значения делятся по `,` / `;`, а в `to` попадают только email или строки, похожие на ФИО.

Маппинг label↔code — `_block_field_to_text` / `_text_to_block_field` + словари `*_CHOICES` / `*_LABEL` в cfg (как `DEDUP_KEEP_CHOICES`).

Fallback: `_FALLBACK_FINAL_CHOICES` + `_FALLBACK_FINAL_REST_HINTS`.

## 4. Матрица ОС × клиент

| `os` (параметр) | `client` | Реализация |
| --------------- | -------- | ---------- |
| `auto`/`windows` | `auto`/`system`/`mapi` | `SimpleSystemMail` |
| `windows` | `outlook` | UNO MAPI; fallback `outlook.exe /a "path" /m "to&subject=…"` |
| `windows` | `thunderbird` | Shell `thunderbird -compose "…"` |
| `linux` / `macos` | `auto`/`system` | `SimpleCommandMail` |
| `linux` / `macos` | `thunderbird` | Shell `-compose` |
| любая | `outlook` на не-Windows | ошибка валидации / журнал «Outlook только Windows» |

Если параметр `os` ≠ реальная ОС — **предупреждение в журнале**, выполнить по реальной ОС (параметр — для документации сценария и подсказок визарда).

## 5. Подготовка вложения

### 5.1. `whole_book`

1. Временный путь: `tempdir/libre_macros_mail_<stamp>.{ods|xlsx}`.
2. `doc.storeToURL(url, FilterName=…)` **копии** (не `store` рабочей книги, чтобы не менять URL документа пользователя) — паттерн как в `libre_macros_split_lib` / convert_tables `storeToURL`.
3. Если книга не сохранена / dirty — всё равно экспорт копии текущего состояния.

### 5.2. `sheets`

1. Создать пустой документ Calc (`loadComponentFromURL("private:factory/scalc", …)`).
2. Скопировать указанные вкладки из `doc` (reuse `_lm_pp_copy_sheet_named` / UNO copy).
3. Удалить дефолтный пустой лист, если остался.
4. `storeToURL` временного файла → закрыть temp-doc без сохранения пользователю.
5. Если ни один лист не найден — ошибка шага, письмо не открывать.

### 5.3. `format`

| format | FilterName (ориентир) |
| ------ | --------------------- |
| `ods` | `calc8` |
| `xlsx` | `Calc MS Excel 2007 XML` |
| `pdf` | (v2) export PDF всей книги / листов |

### 6.1. Источник `to` из диапазона

Поведение `collect_to_recipients(doc, block)`:

1. Взять базовый список из `to`.
2. Если заданы `to_source_sheet` + `to_source_range`:
   - найти лист результата;
   - получить диапазон A1;
   - пройти все ячейки слева-направо, сверху-вниз;
   - взять отображаемый текст / строковое значение каждой непустой ячейки;
   - split по `,` и `;`;
   - провалидировать каждый токен как email или «похоже на ФИО».
3. Вернуть итоговый `to` без дублей и метаданные журнала: `source_cells`, `accepted`, `rejected`.

Рекомендуемые шаблоны v1:

- email: строгий базовый шаблон `local@domain.tld`;
- ФИО: `Слово Слово Слово`, допускаются кириллица/латиница и дефис внутри слова.

Если лист или диапазон не найден — ошибка блока. Если диапазон корректен, но валидных получателей нет, письмо можно открыть с пустым `to`, но в журнале должно быть явно видно `to_source: 0 valid`.

Регистрация:

1. `_FINAL_MAP_SPEC` → `("отправить_по_почте", "merge_final_send_mail")` (+ алиасы);
2. импорт `lm_final_send_mail` в `libre_macros_lib.py`;
3. `_SHEET_BLOCK_FORM_FNS` / schemas / fallbacks / hints;
4. docs: `05_POSTPROCESS.md`, `15_PARAM_REFERENCE.md` (кратко);
5. **не** в `_PP_RANGE_MAP_SPEC` / `_LM_FINAL_RANGE_SPEC`.

## 8. Безопасность / UX

- Только compose UI; без тихой отправки.
- Не логировать полные списки bcc в подробном виде без нужды (достаточно count).
- Временные файлы с предсказуемым префиксом; не класть в каталог исходников пользователя без явного `save_dir` (v1 — только temp).
- Consent: шаг финала уже в сценарии пользователя — отдельный диалог подтверждения **не обязателен** в v1; опционально `confirm: true` позже.

## 10. Вне scope v1

- SMTP / серверная отправка без клиента
- HTML-тело, встроенные картинки
- Несколько вложений разных форматов за один шаг
- Рассылка «по строкам» (каждый получатель из столбца)
- PDF-вложение (можно v1.1)
- Автоудаление temp сразу после Send в Outlook (ненадёжно)

## 11. Оценка

| Часть | Сложность |
| ----- | --------- |
| UNO compose + whole_book | низкая |
| sheets → temp book | средняя |
| матрица client/OS + fallbacks | средняя |
| визард | низкая–средняя |

Итого: **реально** как финальная функция; основной риск — качество вложений на Linux/Thunderbird через SimpleCommandMail (закрывается Shell-fallback).
