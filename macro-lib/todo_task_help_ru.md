# Справка по макросам задач

Макросы серии todo_task управляют таблицей задач в Calc / AlterOffice. Их запускают из контекстного меню ячейки (подменю «PythonMacros») или из диалога «Выполнить макрос».

Эта справка встроена в макрос. Команда «Задача: справка» записывает документ во временный файл и открывает его в Writer / Atext.

## Для кого эта серия

Книга задач обычно устроена так:

- несколько рабочих листов «Задачи…» (например «Задачи.01», «Задачи.02») — по категориям или направлениям;
- на каждом таком листе в ячейке B1 записана категория листа;
- лист свода сотрудников (по умолчанию «задачи_сотрудников») — задачи, пришедшие из книг подчинённых;
- скрытый архив удалённых задач «__Удаленные_Задачи»;
- лист справочников «__Справочники_задачи».

**Роль владельца** задаётся в настройках («Задача: настройки» → вкладка «Общие») и действует для всех книг на этом компьютере. От роли зависят доступные команды и поведение по умолчанию.

| | Сотрудник | Руководитель |
|---|---|---|
| Слияние с сводом | недоступно | доступно |
| Исполнитель по умолчанию при добавлении | ваше ФИО из настроек | пусто (выбираете сами) |
| Лист «задачи_сотрудников» | обычно нет | свод из книг подчинённых |
| Ручной перенос со свода | — | «Задача: переместить» |

## Как запустить

1. Откройте книгу Calc с таблицей задач.
2. Встаньте в ячейку таблицы (или выделите несколько строк).
3. Правая кнопка мыши → «PythonMacros» → нужная команда «Задача: …».

Большинство команд работают на активном листе. Исключения: слияние (берёт лист источника из настроек) и справка (открывает отдельный документ Writer).

# Роль сотрудника

Настройки: ФИО владельца = ваше имя, роль = **сотрудник**.

### Что вы делаете каждый день

Работаете на своих листах «Задачи…» обычными командами:

- **добавить** — новая задача с вашим GUID и вашим ФИО в «Создано» / «Отредактировано»;
- **редактировать** — правка полей; после сохранения обновляется «Отредактировано»;
- **копировать** — копия с новым GUID (это уже ваша задача, не исходная);
- **удалить** — с архивацией на «__Удаленные_Задачи»;
- **переместить** — между своими листами «Задачи…» (смена категории);
- **сортировать**, **раскрасить** — оформление и порядок на листе.

### Особенности для сотрудника

- При добавлении и копировании в «Исполнитель(и)» подставляется ваше ФИО из настроек.
- Команда **«Задача: слияние с сводом»** вам недоступна — макрос откажет и напомнит про роль.
- Ваша книга не перезаписывается слиянием «изнутри»: слияние запускает руководитель в **своей** книге, куда заранее собран свод задач.
- Если вы правите чужую задачу (в «Создано» указан другой человек), макрос предупредит: при последующем слиянии у руководителя ваши правки могут быть перезаписаны версией из свода.

### Как книга попадает к руководителю

Обычно сотрудник ведёт задачи в своём файле, а руководитель отдельно собирает их на лист «задачи_сотрудников» в своей книге (внешний сбор или копирование). Дальше руководитель либо запускает **слияние**, либо вручную **перемещает** строки со свода на рабочие листы.

# Роль руководителя

Настройки: ФИО владельца = ваше имя, роль = **руководитель**.

### Что делает руководитель

1. Ведёт свои задачи на листах «Задачи…» (как сотрудник, но исполнитель по умолчанию пуст).
2. Получает или собирает лист **«задачи_сотрудников»** — свод задач подчинённых.
3. Раскладывает задачи со свода на рабочие листы:
   - **автоматически** — «Задача: слияние с сводом»;
   - **вручную** — выделить строки на своде → «Задача: переместить» → нужный лист «Задачи…».
4. Правит, сортирует, раскрашивает задачи на своих листах.

### Лист «задачи_сотрудников»

- Имя задаётся в настройках (по умолчанию «задачи_сотрудников»).
- Это **не** рабочий лист категории: на нём нет категории в B1, зато в таблице должна быть колонка **«Категория»** — по ней макрос понимает, на какой лист «Задачи…» вставлять **новые** задачи при слиянии.
- Лист свода **не защищается** макросом (в отличие от «Задачи…»), чтобы было удобно править и переносить строки вручную.
- При слиянии и поиске GUID лист свода **не участвует** как «рабочий» — задачи ищутся только на листах «Задачи…».

### Два способа разложить задачи со свода

| Способ | Когда удобно |
|---|---|
| **Слияние** | Много задач, нужно обновить уже известные по GUID и добавить новые разом |
| **Перемещение вручную** | Нужен полный контроль: выбрать конкретные строки, лист, режим копирования |

Оба способа можно комбинировать: часть задач перенести вручную, остальное — слиянием.

# Структура таблицы

Макрос ищет строку заголовков в первых 20 строках листа. Обязательны три колонки:

- «№ п/п»
- «Наименование»
- «GUID Строки»

Без них макрос сообщит, что на активном листе нет таблицы задач.

## Полный набор колонок

- «№ п/п» — порядковый номер. Может быть заранее заполнен на много строк вниз; сам по себе номер не делает строку задачей.
- «Наименование» — признак задачи. Строка считается задачей, если это поле непустое.
- «Срок исполнения» — дата (после сохранения: ДД.ММ.ГГГГ и день недели).
- «Матрица приоритетов» — значение из справочника (колонка A листа справочников).
- «Реквизиты документа СЭД (при наличии)» — свободный текст.
- «Исполнитель(и)» — выбор из справочника или свой ввод.
- «Статус исполнения задачи» — выбор из справочника плюс уже встречавшиеся на листе статусы.
- «Комментарии» — многострочный текст.
- «GUID Строки» — уникальный идентификатор задачи. Его нельзя править вручную: макросы создают, копируют и сопоставляют задачи по GUID.
- «Дата и время создания задачи»
- «Дата и Время Редактирования»
- «Создано» — ФИО автора (владелец из настроек или пользователь ОС).
- «Отредактировано» — ФИО последнего, кто сохранил задачу через диалог.
- «Категория» — обычно на своде сотрудников; на рабочих листах «Задачи…» категорию листа макрос читает из B1.

Допускаются небольшие отличия в написании заголовков (например «Cрок» латинской C, «GUID» без слова «Строки»). Имена столбцов сопоставляются без учёта регистра и лишних пробелов.

## Что считается задачей

- Задача = заполненное «Наименование».
- Управляемая строка (удаление, копирование, редактирование) = есть наименование и/или GUID.
- Пустые строки с одним только «№ п/п» — запас нумерации, макрос их не считает задачами.

# Команды меню

## Задача: добавить

Создаёт новую строку сразу после последней задачи на активном листе (если задач ещё нет — сразу под заголовком).

Что происходит:

- копируются форматы с последней задачи (рамки, шрифт, выравнивание), затем сбрасываются жирность, курсив и заливка;
- в «GUID Строки» записывается новый уникальный идентификатор;
- «№ п/п» проверяется и при необходимости выравнивается;
- открывается диалог «Новая задача»;
- срок по умолчанию — сегодня плюс 4 дня, выходные пропускаются;
- исполнитель по умолчанию: для роли «сотрудник» — ФИО владельца из настроек; для «руководитель» — пусто (выбираете сами);
- после сохранения заполняются «Создано», «Отредактировано» и метки времени.

Если диалог отменить, GUID и служебные метки новой строки очищаются.

## Задача: редактировать

Открывает диалог по текущей строке. Курсор должен стоять в строке-задаче.

Поля диалога:

- Наименование — большое многострочное поле;
- Срок — день, месяц (список), год; можно очистить все три поля, чтобы убрать срок;
- Матрица приоритетов — выпадающий список из справочника;
- Реквизиты СЭД — одна строка;
- Исполнитель(и) — список из справочника, можно ввести своё значение;
- Статус — список из справочника плюс уникальные статусы, уже встречающиеся на листе;
- Комментарии — многострочное поле.

После сохранения обновляются «Отредактировано» и время редактирования. «Создано» не меняется. «№ п/п» и GUID не трогаются.

Кнопка **«Создать план»** / **«Редактировать план»** открывает полноэкранный визард плана (таблица `Grid`, любое число строк; правка — кнопка **«Правка строки…»**). План хранится на скрытом листе `__План_задач` по GUID задачи. При удалении задачи план архивируется на `__Архив_план`.

Если в «Создано» указан другой человек (не ФИО владельца из настроек), макрос предупредит: при следующем слиянии с сводом сотрудников ваши правки могут быть перезаписаны. Можно продолжить или отменить.

## Задача: копировать

Копирует текущую задачу в новую строку на том же листе.

Особенности копии:

- новый GUID;
- новый порядковый номер;
- срок очищается (в диалоге подставится срок по умолчанию);
- статус «Выполнено» не переносится;
- исполнитель подставляется по роли, как при добавлении;
- в «Создано» / «Отредактировано» записывается текущий владелец (это уже ваша копия, не исходная задача сотрудника).

Если на листе ещё нет задач, команда ведёт себя как «добавить».

## Задача: переместить

Переносит или копирует выделенные строки-задачи на другой лист «Задачи…» той же книги. Можно выделить несколько строк (мультиселект).

Источником может быть **любой лист с таблицей задач**, в том числе лист свода «задачи_сотрудников». Лист назначения — только рабочий «Задачи…» (свод в списке приёмников не показывается).

### Диалог перемещения

- список выбранных задач (наименование и GUID);
- лист назначения — имя листа и категория из B1;
  - если у задач на своде заполнена колонка «Категория» и есть лист с такой же категорией в B1 — он подставляется по умолчанию;
- **«Копировать»** — оставить исходные строки на своде; на приёмнике создаются копии (для обычных строк — с новыми GUID);
- **«Только значения»** — копировать содержимое ячеек без форматов и формул (по умолчанию включено);
- **«Добавить недостающие колонки»** — если на приёмнике нет колонки из источника, создать её в конце листа.

Без флажка «Копировать» задачи **переносятся**: GUID сохраняется, исходные строки удаляются со свода, на исходном листе восстанавливается пустая нумерованная строка.

При копировании на приёмнике проставляются актуальные «Создано» / «Отредактировано» и метки времени.

Колонки сопоставляются **по заголовкам**, а не по буквам столбцов.

### Совпадение GUID на других листах

Перед переносом макрос ищет такие же GUID на всех листах «Задачи…» (кроме свода и листа-источника). Если GUID уже есть — показывается диалог **«Совпадение GUID»**:

| Кнопка | Действие |
|---|---|
| **Перезаписать** | Заменить существующую строку на приёмнике данными из источника |
| **Слить комментарии** | Обновить поля, комментарии накопить блоками с датой (как при слиянии) |
| **Новая задача** | Добавить строку с **новым** GUID, существующую не трогать |
| **Прервать** | Отменить всё перемещение |

Если совпавшая задача лежит **не на листе назначения**, а на другом «Задачи…», макрос сначала **перенесёт** её на выбранный приёмник, затем применит выбранное действие.

Можно включить **«Для всех оставшихся совпадений»** — тот же выбор применится к следующим конфликтам без повторного вопроса.

### Ручной перенос со свода (типичный сценарий руководителя)

1. Откройте лист «задачи_сотрудников».
2. Выделите одну или несколько строк задач.
3. «Задача: переместить» → выберите лист «Задачи…» (категория подставится из колонки «Категория», если совпадает с B1).
4. Снимите «Копировать», если задачи должны **исчезнуть** со свода и остаться на рабочем листе с тем же GUID.
5. Оставьте «Копировать», если нужна **копия** на рабочем листе, а строка на своде должна остаться.

Ручной перенос удобен, когда нужно разложить **часть** задач, проверить каждую или обойти автоматическое слияние. Слияние же обрабатывает **весь** свод за один проход.

Лист назначения должен содержать ту же таблицу задач (хотя бы обязательные колонки).

## Задача: удалить

Удаляет текущую строку-задачу после подтверждения.

Перед удалением строка копируется на скрытый лист «__Удаленные_Задачи» (значения без форматирования) с датой удаления и именем исходного листа. Если архив сохранить не удалось, строка не удаляется.

После удаления:

- на исходном листе в конец добавляется пустая строка с форматами и новым «№ п/п»;
- нумерация оставшихся задач проверяется.

## Задача: раскрасить

Раскрашивает строки-задачи по сроку и статусу. Формулы на лист не пишутся — расчёт только в памяти.

По умолчанию красится активный лист. Можно включить «применить ко всем листам по шаблону» (обычно «Задачи*»).

Правила заливки:

- статус «Выполнено» — зелёный;
- срок уже прошёл — светло-красный, жирный шрифт;
- до срока меньше 3 дней — жёлтый;
- иначе обычная строка (белая заливка).

Дополнительно ячейка приоритета «1 — ВАЖНО и СРОЧНО» выделяется жёлтой заливкой и красной рамкой.

Параметры последнего запуска запоминаются в настройках серии.

## Задача: сортировать

Сортирует целые строки-задачи на активном листе (все столбцы, включая «Категория», если она есть). После сортировки «№ п/п» перенумеровывается 1…N.

Критерии:

- по исполнителю (А → Я);
- по сроку исполнения (сначала старые или сначала новые);
- по степени просрочки;
- по степени важности.

Выбор запоминается в настройках. Если задач меньше двух, сортировка не выполняется.

## Задача: слияние с сводом

Команда **только для руководителя**. Подтягивает задачи с листа «задачи_сотрудников» на рабочие листы «Задачи…».

Подробный алгоритм, режимы и конфликты — в разделе «Слияние с сводом» ниже.

## Задача: справочники

Открывает редактор листа «__Справочники_задачи».

На листе в первой строке — заголовки справочников. Блоки идут слева направо, между ними — пустой столбец. Данные начинаются со второй строки.

Типичные справочники:

- матрица приоритетов (колонка A, обычно A2:A5);
- исполнители (колонка C и ниже);
- статусы исполнения (колонка F, заголовок «Статусы исполнения»).

В диалоге можно добавить, обновить, удалить элемент и убрать дубликаты. Для справочника из нескольких колонок значения вводятся через « | ».

Исполнителей, введённых вручную в карточке задачи, макрос в справочник больше не дописывает — их удобно выбрать в диалоге, но список на листе правится только здесь.

## Задача: настройки

Две вкладки.

### Вкладка «Общие»

- пароль защиты листа (по умолчанию task; пустой — защита без пароля). Кнопка «Показать» открывает пароль на 10 секунд;
- **ФИО владельца** — подставляется в «Создано» / «Отредактировано». Если пусто, берётся пользователь ОС;
- **роль владельца**: руководитель или сотрудник;
- **лист с задачами сотрудников** для слияния (по умолчанию «задачи_сотрудников»);
- три флажка слияния — **значения по умолчанию** для профиля (см. раздел «Режимы слияния»);
- подробные логи в консоль.

Смена пароля сразу переприменяется ко всем листам «Задачи…» и к уже защищённым листам книги.

### Вкладка «Размеры полей»

- лист-шаблон заголовков (по умолчанию «Задачи.01»);
- шаблон имён рабочих листов (по умолчанию «Задачи*»);
- шаблон листов свода (по умолчанию «Свод*задач*»);
- ширины колонок в миллиметрах (0 или меньше — скрыть колонку);
- кнопка «Применить» выставляет ширины на листы задач; по желанию — и на листы свода.

Если на листах задач нет колонок «Создано» / «Отредактировано», «Применить» создаёт их сразу после GUID и заполняет ФИО владельца в строках с GUID.

Настройки хранятся не в книге, а в профиле пользователя (~/.config/libre-macros/todo_task/ на Linux, %APPDATA%\libre-macros\todo_task\ на Windows). Одна и та же роль и пароль действуют для всех книг на этом компьютере.

## Задача: справка

Открывает этот документ в Writer / Atext. Файл вшит в макрос, отдельно класть его рядом с книгой не нужно.

# Слияние с сводом

## Зачем это нужно

Руководитель собирает в свою книгу лист «задачи_сотрудников» — свод задач из файлов подчинённых. **Слияние** раскладывает эти задачи по своим листам «Задачи…»:

- **новые** GUID — вставка на лист, соответствующий категории из свода;
- **уже известные** GUID — обновление на том листе «Задачи…», где задача уже есть у руководителя.

Запускать можно только при роли «руководитель». Иначе макрос откажется и напомнит про настройки.

Альтернатива — ручное **перемещение** со свода (см. выше).

## Подготовка

1. В настройках роль — «руководитель», указано ваше ФИО.
2. Имя листа источника совпадает с полем «Лист с задачами сотрудников» (по умолчанию «задачи_сотрудников»).
3. На каждом рабочем листе «Задачи…» в **B1** указана категория. Для **новых** задач со свода эта формулировка должна совпадать с колонкой «Категория» в строке свода.
4. На своде есть колонки таблицы задач, в том числе «GUID Строки» и «Категория». Порядок и набор столбцов может отличаться от рабочих листов: макрос сопоставляет поля по заголовкам.

## Как работает алгоритм

1. Все задачи с листов «Задачи…» (по шаблону из настроек, **кроме** листа свода) читаются в память. Для каждой строится карта: GUID → лист, номер строки.
2. Читается лист-источник («задачи_сотрудников»).
3. Для каждой строки свода:
   - **нет GUID** — строка пропускается;
   - **GUID уже есть** у руководителя — поля обновляются **на том листе, где задача уже лежит** (категория свода для обновления не проверяется); «№ п/п» не меняется;
   - **GUID нет** — задача **вставляется** на лист, чья категория в B1 совпадает с колонкой «Категория» свода; выдаётся следующий порядковый номер; если включено «обновлять только существующие» — такая строка пропускается;
   - **неизвестная категория** или нет подходящего листа — строка пропускается (только для вставки новых).
4. На затронутых листах «№ п/п» перенумеровывается.
5. В конце — отчёт со списком: добавлено (+), обновлено (~), пропущено (−).

## Режимы слияния

Режимы делятся на **настройки профиля** (вкладка «Общие», действуют как умолчания и влияют на план слияния) и **параметры запуска** (диалог подтверждения перед каждым слиянием).

### Настройки профиля (вкладка «Общие»)

| Опция | Что делает |
|---|---|
| **Обновлять только существующие** | На листах «Задачи…» правятся только задачи, GUID которых уже есть. Новые строки со свода **не добавляются**. |
| **Контролировать дату-время редактирования** | Сравнивается «Дата и Время Редактирования». Обновление идёт только если дата во **входящей** строке **строго больше** локальной. Равные или более старые — пропуск. |
| **Накапливать комментарии** | Значение по умолчанию для режима комментариев при слиянии (см. ниже). |

### Параметры запуска (диалог перед слиянием)

Перед слиянием макрос показывает **сводку**: сколько задач добавить, обновить и пропустить. Там же можно выбрать режим **на этот запуск**:

**Метод слияния задач (комментарии):**

| Режим | Поведение |
|---|---|
| **Объединять комментарии** | Поле «Комментарии» не затирается. Если входящая дата редакции новее локальной, к тексту дописывается блок «====ДД.ММ.ГГГГ ЧЧ:ММ:СС====» и ниже — комментарий из свода. Старый текст оформляется своим блоком. Дубликаты не пишутся. |
| **Полная замена** | Комментарий целиком берётся из свода (вместе с остальными полями). |

**Копирование ячеек:**

| Режим | Поведение |
|---|---|
| **Только значения** | Копируется содержимое ячеек без форматов и формул (по умолчанию). |
| **С форматами** | Копируются и значения, и оформление ячеек. |

Эти параметры **не сохраняются** в настройках — выбираются при каждом слиянии. Настройки профиля влияют на **план** (сколько пропустить по дате и «только существующие»), а комментарии и форматы — на **фактическое** обновление в диалоге подтверждения.

### Конфликт редакторов

Если задача с таким GUID **уже есть** у руководителя и:

- в колонке «Отредактировано» на **вашем** листе указано **ваше** ФИО (вы правили задачу сами), а
- в своде сотрудника в «Отредактировано» указан **другой** человек,

макрос **останавливается** на этой задаче и спрашивает:

| Кнопка | Действие |
|---|---|
| **Оставить версию владельца** | Строка на вашем листе **не меняется** |
| **Взять версию сотрудника** | Все колонки обновляются из свода (форматы — как выбрали в диалоге слияния) |
| **Прервать** | Остановить всё слияние (уже сделанные изменения сохраняются) |

Можно отметить **«Для всех оставшихся таких конфликтов»** — тот же выбор применится к следующим конфликтам без вопроса.

Конфликт возникает только когда **оба** поля «Отредактировано» заполнены и указывают на **разных** людей, при этом локально последним редактором были вы (владелец книги).

## Что копируется при обновлении и вставке

Копируются значения по совпадающим заголовкам: наименование, срок, приоритет, СЭД, исполнитель, статус, комментарии, GUID, даты, «Создано», «Отредактировано» и другие общие колонки.

Не копируется «№ п/п» — нумерация остаётся нумерацией целевого листа.

Если включено объединение комментариев, колонка «Комментарии» при обновлении не копируется целиком: к ней дописывается новый датированный блок (см. выше).

Структура свода и рабочих листов может не совпадать столбец в столбец. Лишние колонки свода, которых нет на целевом листе, игнорируются; колонки целевого листа, которых нет в своде, не затираются пустотой.

## Как не потерять свои правки

- Включите **контроль даты редакции** — более старая строка свода не перепишет вашу.
- При конфликте редакторов выбирайте **«Оставить версию владельца»**.
- Свои поручения заводите командой **«добавить»** — у них ваш автор и свой GUID; слияние их не подменит, пока такого GUID нет в своде.
- Если правите задачу сотрудника (в «Создано» чужое ФИО), макрос предупреждает при редактировании.

Во время работы показывается окно прогресса. В конце — итог и прокручиваемый список по каждой задаче.

# Защита листов

Листы, имя которых начинается с «Задачи», макрос считает рабочими и после своих правок включает защиту.

- Пароль задаётся в настройках (по умолчанию task).
- Пустой пароль означает защиту без пароля: случайно не править ячейки, но снять защиту можно без секрета.
- Перед правкой макрос сам снимает защиту, после — ставит обратно.
- Лист свода «задачи_сотрудников» **не защищается** — на нём удобно готовить и переносить задачи вручную.
- Если снять защиту не удалось (другой пароль, чем в настройках и в «предыдущем» пароле после смены), команда останавливается с сообщением.

Не меняйте пароль защиты этих листов вручную в меню Calc, минуя «Задача: настройки»: макрос может не суметь снять защиту.

# Типичные сценарии

## Сотрудник ведёт свои задачи

1. В настройках укажите ФИО и роль «сотрудник».
2. Работайте на листах «Задачи…»: добавить, редактировать, копировать, удалить, сортировать, раскрасить.
3. При необходимости переносите задачи между своими листами («переместить»).
4. Слияние вам недоступно. Книгу передаёте руководителю — он соберёт задачи в свой свод.

## Руководитель: автоматическое слияние

1. Роль «руководитель», ФИО своё.
2. Соберите лист «задачи_сотрудников» (колонки как у таблицы задач + «Категория»).
3. Проверьте B1 на каждом «Задачи…».
4. «Задача: слияние с сводом» → проверьте план и выберите режим комментариев / копирования.
5. При конфликте редакторов решите, чья версия важнее.
6. Просмотрите отчёт: добавлено / обновлено / пропущено.

## Руководитель: ручной перенос со свода

1. Откройте «задачи_сотрудников», выделите нужные строки.
2. «Задача: переместить» → лист «Задачи…» (категория подставится из колонки «Категория»).
3. Без «Копировать» — задачи уйдут со свода с сохранением GUID.
4. С «Копировать» — копии на рабочем листе, свод не трогается.
5. При совпадении GUID на другом листе — выберите перезапись, слияние комментариев или новый GUID.

## Перенос задачи в другую категорию

Не делайте это слиянием. Выделите строку → «Задача: переместить» → лист нужной категории. GUID сохранится. При последующем слиянии задача **обновится на новом листе** (поиск по GUID), а не переедет обратно по категории свода.

# Частые сообщения

- «На активном листе не найдены обязательные колонки» — заголовки не в первых 20 строках или переименованы так, что макрос их не узнаёт.
- «Нет колонок автора» — добавьте «Создано» и «Отредактировано» вручную после GUID либо нажмите «Применить» на вкладке размеров.
- «Выберите ячейку в строке задачи» — курсор не на строке с наименованием/GUID.
- «Слияние доступно только руководителю» — смените роль в настройках.
- «В книге нет листа …» — имя листа источника не совпадает с настройкой.
- «Не удалось снять защиту» — пароль листа не совпадает с паролем в настройках.
- «Конфликт редактирования» — вы правили задачу, а в своде другой редактор; выберите приоритет или прервите.

# Краткая шпаргалка

- Задача определяется наименованием, идентичность — GUID.
- **Сотрудник** — свои листы, без слияния; исполнитель по умолчанию = ваше ФИО.
- **Руководитель** — слияние + ручной перенос со свода «задачи_сотрудников».
- Категория рабочего листа — B1; категория свода — колонка «Категория» (для **вставки** новых).
- Обновление при слиянии — **по GUID** на том листе, где задача уже есть.
- Слияние: настройки профиля (только существующие, дата, комментарии по умолчанию) + выбор при запуске (комментарии, значения/форматы).
- Конфликт редакторов: ваша правка vs версия сотрудника — спросит приоритет.
- Перемещение со свода: вручную, с выбором копии/GUID/перезаписи.
- Копия (на листе или через перемещение с «Копировать») получает новый GUID.
- Удаление сначала архивирует строку на «__Удаленные_Задачи».
- Настройки живут в профиле пользователя, не внутри книги.
