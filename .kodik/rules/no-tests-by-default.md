# Тесты по умолчанию не прогонять — проверка вручную

Область: весь проект (`libre-macros`). Применяется к любому запросу, кроме случая,
когда тесты запрошены явно.

## Правило

- По умолчанию **тесты не запускать** и **не писать**: ни `pytest`, ни `python -m pytest`,
  ни `unittest`, ни скрипты из `test/`, ни «прогон на всякий случай».
- Тесты запускаются **только** если пользователь явно попросил об этом в текущем
  запросе («прогони тесты», «запусти pytest», «проверь тестами», «сделай прогон» и т.п.).
  Разрешение на правки кода **не** является разрешением на запуск тестов.
- Подразумевается **ручное тестирование**: подготовить изменения, переустановить макросы
  при необходимости и описать пользователю, что и где проверить руками.
- Прогон тестов **не** входит в план работы по задаче и **не** является обязательным
  шагом завершения: не указывать его в списке шагов и не отчитываться «тесты не запускал»
  как о невыполненном пункте — это ожидаемое поведение.
- Если пользователь просит тесты — можно запускать существующие; новые pytest-скрипты
  в `test/` всё равно не добавлять (см. `.kodik/rules/json-only-manual-testing.md`).

## Что тестами не считается

- Статические/build-проверки, которые предписывают другие правила, — их запускать можно
  и нужно, это часть подготовки к установке, а не тест-ран:
  - `python3 macro-lib/aoffice_flatten_defs.py --in-place --tree macro-lib`
  - `PYTHONPATH=macro-lib/pythonpath python3 macro-lib/aoffice_compat_check.py --tree macro-lib --warn-assigns`
  - `python3 macro-lib/sync_macro_version.py`
- Чтение кода, grep по репозиторию, `git status`/`git diff` — обычная работа, не тесты.

## Почему

Макросы живут в LibreOffice Calc / AlterOffice: автотесты не воспроизводят ни UI-визарды,
ни фильтр AO 2026 (`pythonscript.py`), поэтому реальные регрессии ловит только ручной прогон
в приложении. Время на автотесты не окупается и создаёт ложную уверенность.
