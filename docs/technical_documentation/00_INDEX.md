| Параметр | Значение |
|----------|----------|
| Проект | **libre-macros** |

Классический комплект водопадной (каскадной) модели разработки ИС и ПО:

| № | Документ | Назначение этапа |
|---|---------|------------------|
| [01](01_TECHNICAL_REQUIREMENTS.md) | **Технические требования** | Требования к системе: цели, функции, ограничения, критерии приёмки |

| [03](03_EXPLANATORY_NOTE.md) | **Пояснительная записка** | Описание принятых проектных решений, архитектуры и алгоритмов по коду |
| [04](04_TEST_METHODOLOGY.md) | **Методика испытаний и тестирования** | Порядок проверки соответствия ТТ/ТЗ, сценарии, критерии «годно» |

## Связь с операционной документацией

Рабочие руководства пользователя и разработчика остаются в `docs/` (`01_QUICKSTART.md` … `17_POSTPROCESS_XML.md`). Настоящий комплект — **формальные проектные документы**; детальные примеры JSON и пошаговые инструкции не дублируются полностью, а ссылаются на операционные разделы.

## Порядок использования

1. Зафиксировать объект испытаний по **01** (объём функций и ограничения).
2. Сопоставить реализацию с **02** (что должно быть сделано) и **03** (как сделано).
3. Провести приёмку по **04** в LibreOffice Calc вручную (автотесты pytest не применяются).
