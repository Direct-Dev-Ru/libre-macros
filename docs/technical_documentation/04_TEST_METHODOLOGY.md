# Методика испытаний и тестирования

**Программный комплекс:** libre-macros  
**Версия объекта испытаний:** 3.10.523  
**Вид документа:** методика испытаний и тестирования (каскадная модель)  
**Связь:** [01 ТТ](01_TECHNICAL_REQUIREMENTS.md), [02 ТЗ](02_TECHNICAL_SPECIFICATION.md)  
**Операционная детализация сценариев:** `docs/12_MANUAL_TESTING.md`

---

## 1. Цель и объект испытаний

### 1.1. Цель

Установить соответствие программного комплекса техническим требованиям и техническому заданию в условиях реальной среды LibreOffice Calc / AlterOffice ACell.

### 1.2. Объект

Установленные макросы версии **3.10.523** (`MACRO_VERSION` в `collect_workbooks.py` / `version.txt` / строка «Версия» на листе параметров / запись в «Сбор_книг_лог»).

### 1.3. Принцип

**Только ручная проверка в Calc.** Автотесты pytest в приёмку не входят (политика проекта; каталог `test/` — шаблоны и генератор, не runner автотестов).

---

## 2. Условия проведения

### 2.1. Аппаратно-программная среда

| Компонент | Требование |
|-----------|------------|
| ОС | Linux или Windows |
| Офис | LibreOffice Calc или AlterOffice ACell с Python-макросами |
| Python | Встроенный в офис script provider; для генератора шаблонов — Python 3.10+ и `openpyxl` |
| Макросы | Установлены через `install.sh` или `MacroInstaller_bundled_*.ods` |
| Безопасность | Уровень, разрешающий выполнение Python-макросов |

### 2.2. Подготовка шаблонов

```bash
cd /path/to/libre-macros
python3 -m venv .venv && source .venv/bin/activate   # при необходимости
pip install openpyxl
./test/collect_workbooks/generate.sh
# опционально ODF:
# python test/collect_workbooks/generate_manual_workbooks.py --odf
```

Результат: `test/collect_workbooks/workbooks/*.xltx`, источники в `sources/`, чек-лист `workbooks/MANUAL_CHECK.md`.

### 2.3. Установка объекта

```bash
./macro-lib/install.sh collect_workbooks param_wizard pick_source_file
```

Либо установка из bundled ODS по `docs/02_INSTALL_USER.md`.  
Перезапустить Calc. Убедиться, что в журнале/на листе версия **3.10.523**.

## 3. Виды испытаний

| Вид | Содержание |
|-----|------------|
| Установочные | Макросы видны, версия совпадает, первый запуск без crash |
| Функциональные | Режимы сбора, фильтры, постобработка, ВПР, xml |
| Негативные | Неверные пути, невалидный JSON, несохранённая книга при xml |
| Регрессионные | Повтор обязательного набора после изменений кода |

---

## 4. Порядок проведения испытаний

Для каждого сценария:

1. Открыть шаблон (`workbooks/…` или `workbooks/ODF/…`).  
2. При необходимости исправить «Файлы-Источники» на абсолютные пути к `sources/`.  
3. При нескольких `Параметры_Объединения*` — активировать нужный лист.  
4. Для `xml_excel_ods` — **сохранить** книгу на диск.  
5. Выполнить **Сервис → Макросы → Python → collect_workbooks**.  
6. Сверить: листы результата, визуальный эффект, «Сбор_книг_лог» (нет неожиданных «ошибка»; «пропуск» — только по ожидаемому фильтру листа).  
7. Сохранить копию в `workbooks/results/` (для регрессии).  
8. Зафиксировать результат в протоколе (§8).

## 5. Программа испытаний (сценарии)

### 5.1. Обязательный минимум (критерии сдачи)

| ID | Шаблон / действие | Проверяемые требования ТТ | Критерий «годно» |
|----|-------------------|---------------------------|------------------|
| И-01 | Установка + запуск `01_merge_one_sheet` | Ф-01…Ф-03, Ф-12, С-04 | Есть лист результата; в логе версия 3.10.523; нет критичных ошибок |
| И-02 | `02_merge_many_sheets` | Ф-03 | Несколько листов результата / ожидаемые имена |
| И-03 | `03_columns_filter` | Ф-06 | В результате только выбранные столбцы |
| И-04 | `04_sheets_wildcard` | Ф-06 | Листы по шаблону отобраны корректно |
| И-05 | `06_sheets_by_index` или `07`/`08` столбцы | Ф-06 | Индексы/буквы столбцов верны |
| И-06 | `12_postprocess_json` | Ф-11, Ф-20, Ф-21 | Основные JSON-функции дали ожидаемый визуальный эффект; лог без «ошибка» кодека |
| И-07 | Один сценарий ВПР (`11_vlookup_1to1_low`) | Ф-24 | Добавлены столбцы join; ключи сматчены |
| И-08 | `11_direct_xml_excel_ods` (книга сохранена) | Ф-16…Ф-19 | Прямой перенос; после показа — UNO-фаза; нет ошибки «книга не сохранена» |
| И-09 | `param_wizard` / запись параметра | Ф-25 | Параметр записан на лист B/C |
| И-10 | Невалидный JSON в C (ручная порча одной строки) | Н-01 | Ошибка/пропуск зафиксирован; процесс не «роняет» Calc |

### 5.2. Расширенная программа (по возможности)

| ID | Шаблон | Назначение |
|----|--------|------------|
| И-11 | `05_all_columns`, `09_fixed_row_count` | Границы блока / все столбцы |
| И-12 | `10_product_groups` | Каталожный сценарий |
| И-13 | `11_vlookup_*_middle/high`, `1toN_*` | Нагрузка и дубли ключей |
| И-14 | `00_all_parameters` | Справочность параметров |
| И-15 | Копирование листов + `xml` + `MERGE_XML_CONVERT_TO_NUMBERS` | Текст→число/дата |
| И-16 | `pick_source_file`, `file_list_macro` | Вспомогательные макросы |
| И-17 | Оформление: градиент, сортировка, сетка (из И-06) | Поля JSON (`whole_row`, `keys`, …) |

Сверка эффектов постобработки — по `MANUAL_CHECK.md` и `docs/13_JSON_PARAMS.md`.

### 5.3. Негативные проверки

| ID | Действие | Ожидание |
|----|----------|----------|
| НГ-01 | Несуществующий путь в источниках | Запись в лог; диалог/итог без падения |
| НГ-02 | Несохранённая книга + `xml_excel_ods` | Сообщение о необходимости сохранить файл |
| НГ-03 | Неверный порядок pipeline (row до range) | Ошибка валидации на этапе parse, сбор не стартует |
| НГ-04 | Несколько листов параметров, активен «чужой» | Сбор по активному; неактивные игнорируются |

## 6. Критерии оценки

| Оценка | Условие |
|--------|---------|
| **Годно** | Все пункты §5.1 выполнены; версия 3.10.523; критичных дефектов нет |
| **Годно с замечаниями** | §5.1 выполнены; есть дефекты расширенной программы или косметика UI, не блокирующие основной сценарий |
| **Не годно** | Провал любого пункта §5.1; несовпадение версии; crash Calc; потеря/порча данных без предупреждения в ожидаемых безопасных сценариях |

Критичный дефект: невозможность выполнить сбор в режимах one/many при корректном шаблоне; необработанное падение; искажение данных без записи в лог в штатном сценарии И-01.

## 9. Регрессия после изменений кода

1. Синхронизировать `MACRO_VERSION`, переустановить макросы.  
2. Повторить §5.1.  
3. При затрагивании постобработки/codec — обязательно И-06.  
4. При затрагивании direct/xml — обязательно И-08.  
5. При затрагивании ВПР — минимум И-07 (+ один 1:N при изменениях join).

Автотесты не добавлять и не запускать для приёмки.

## 10. Типичные отклонения и действия

| Симптом | Действие |
|---------|----------|
| Макрос не виден | Переустановка; `libreoffice-script-provider-python`; перезапуск |
| Пустой результат | Пути источников; активный лист параметров |
| Постобработка пропущена | JSON; фильтр `sheet` |
| Старая версия в логе | Переустановка, сверка «Версия» на листе |
| xml: «книга не сохранена» | Save As на диск до запуска |
| Числа остались текстом (xml copy) | `MERGE_XML_CONVERT_TO_NUMBERS=Да` |

## 11. Заключение методики

Методика обеспечивает воспроизводимую ручную приёмку комплекса libre-macros версии 3.10.523 по критериям ТТ/ТЗ без автоматических unit/regression pytest. Положительное заключение — при оценке «годно» или «годно с замечаниями» по протоколу §8.
