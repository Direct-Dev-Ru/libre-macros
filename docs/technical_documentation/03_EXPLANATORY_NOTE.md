## 1. Введение

Пояснительная записка описывает **принятые проектные решения** программного комплекса libre-macros в состоянии рабочей ревизии 3.10.696. Документ опирается на исходный код каталога `macro-lib/` и операционную архитектуру `docs/09_ARCHITECTURE.md`. Требования и постановка — в [01](01_TECHNICAL_REQUIREMENTS.md) и [02](02_TECHNICAL_SPECIFICATION.md).

---

## 2. Назначение и область применения

Libre-macros автоматизирует сведение табличных данных из нескольких файлов в книгу LibreOffice Calc / AlterOffice ACell. Пользователь описывает задачу на листе `Параметры_Объединения*`; макрос `collect_workbooks` выполняет копирование и постобработку. Дополнительно поставляются визард параметров, выбор файла, список файлов каталога и настройка контекстного меню.

Типичный пользовательский цикл:

1. Подготовить (или открыть) книгу с листом параметров.  
2. Заполнить пути источников и опции (вручную / визард / pick_source_file).  
3. Запустить `collect_workbooks`.  
4. Получить листы результата и журнал «Сбор_книг_лог».

---

## 3. Обоснование выбора технических средств

| Решение | Обоснование |
|---------|-------------|
| Python + PyUNO | Нативная среда макросов LO; доступ к API Calc без внешнего сервера |
| Конфигурация на листе | Документ-шаблон переносится вместе с настройками; не требует отдельной БД |
| JSON в колонке C | Структурированные параметры функций; единый codec; отказ от legacy-текста |
| Двухэтапный запуск | После `loadComponentFromURL` продолжение в том же вызове Python часто обрывается — этап 2 через DispatchHelper |
| `xml_excel_ods` | Обход узких мест UNO-копирования крупных книг; работа с файлом через openpyxl/odf |
| Bundled openpyxl/odfpy | Автономная установка без `pip` в среде пользователя |
| Ручные испытания в Calc | Соответствие реальному UI и UNO; автотесты не гарантируют поведение офиса |

## 4. Архитектура системы

### 4.1. Слои

```text
┌──────────────────────────────────────────────────────────┐
│  Точки входа LO: collect_workbooks, param_wizard, …      │
├──────────────────────────────────────────────────────────┤
│  Оркестрация: collect_workbooks.py                       │
│    parse_collect_settings → run_collect_merge            │
│    merge_on_one / many / copy (+ xml pipeline)           │
├──────────────────────────────────────────────────────────┤
│  Библиотеки pythonpath/                                  │
│    libre_macros_lib      — lm_pp_*, ВПР                   │
│    libre_macros_direct   — файловый перенос / PP xml     │
│    libre_macros_param_codec — JSON ←→ блоки              │
│    pivot / values / sanitize / consent / global settings │
├──────────────────────────────────────────────────────────┤
│  Плагины: functions_pp.py, functions_final.py            │
└──────────────────────────────────────────────────────────┘
```

Ориентировочный объём кода (строки, ревизия 3.10.696):

| Модуль | ~LOC |
|--------|------|
| `collect_workbooks.py` | 21 500 |
| `param_wizard.py` | 19 300 |
| `libre_macros_lib.py` | 15 400 |
| `libre_macros_direct_lib.py` | 13 100 |

### 4.2. Поток управления сбором

1. **Этап 1:** валидация параметров, очистка лишних листов, планирование этапа 2.  
2. **Этап 2:** подтверждение (опционально), диспетчер режимов, копирование, оформление, pipeline, финал, показ результата.

Диспетчер `run_collect_merge` выбирает:

| Режим | Функция | Результат |
|-------|---------|-----------|
| На один лист | `merge_on_one_sheet` | Лист `Merge` (+ служебные колонки по флагам) |
| На разные листы | `merge_on_many_sheets` | `Merge_N` или имена источников; возможно «Индексы_Источников» |
| Копирование | `merge_on_copy_sheets` | Копии вкладок (`importSheet` или xml) |

После копирования (one/many/copy): `Ячейка_В_Столбец` (кроме copy) → встроенное оформление → pipeline постобработки. При `xml_excel_ods` оформление и UNO-шаги Диапазон/Строка — в отложенной фазе после показа книги.

### 4.3. Unified pipeline постобработки

Строки параметров собираются в `processing_pipeline`. Валидация порядка: `range` и splitters (`vlookup` / `merge_sheets` / `split_sheets`), затем `row`.

Выполнение на листе:

```text
блоки range ↔ ВПР / объединить_листы_в_один / разделить_листы → refresh → row-фаза построчно
```

`объединить_листы_в_один` и `разделить_листы` — **отдельные строки A** (JSON в C), не ключи B «Постобработка_Диапазон».

После всех листов — `Финальная_обработка`.

Разрешение функции из B: карта `merge_pp_*` → `lm_pp_*`; `functions_*.py#имя`; либо компилируемый Python-код (доверенный сценарий).

### 4.4. Режим `xml_excel_ods`

Обоснование: пакетная работа с zip/XML структуры ODS/XLSX быстрее или надёжнее в ряде сценариев, чем чистое UNO-копирование.

Схема:

1. Сбор в режиме direct с записью в файл (книга закрыта).  
2. `Постобработка_xml` в файле.  
3. Повторное открытие; показ; отложенная UNO-фаза (RANGE/ROW, freeze и др.).

Ограничение: книга результата должна существовать на диске до старта.

### 4.5. Кодек параметров

Модуль `libre_macros_param_codec.py` кодирует/декодирует только JSON. Исполнители `lm_pp_*` читают **dict-блоки**; у разных функций свой набор полей (`whole_row`/`sort` у градиента, `keys` у сортировки, `width`/`color` у сетки и т.д.). Фильтрация по `sheet`/`sheets` выполняется при применении.

### 4.6. Визард и глобальные настройки

`param_wizard` не запускает сбор: только помогает заполнить B/C/D… и пресеты. Глобальные умолчания шрифта и форматов — JSON в профиле (`libre_macros_global_settings_lib`, каталог `~/.config/libre-macros/collect_workbooks/`).

### 4.7. Установка

Для разработчика: `macro-lib/install.sh` копирует `.py` в `Scripts/python` профиля.  
Для пользователя: `MacroInstaller_bundled_*.ods` содержит встроенный архив макросов и `pythonpath/`; диалог выбора модулей; перезапуск офиса обязателен.

## 5. Информационное обеспечение

### 5.1. Лист параметров

Колонка A — ключ; B — основное значение; C+ — файловые значения, JSON, опции ВПР. Пустая A — конец таблицы. Несколько листов `Параметры_Объединения*` — конфигурации-варианты; активен один.

### 5.2. Журнал

Лист «Сбор_книг_лог» фиксирует версию, режим, план постобработки, проблемы. При отладке консоль может дублироваться на лист.

### 5.3. Источники и результат

Относительные пути разрешаются от каталога книги параметров. Маркер `Эта_Книга` избегает повторного открытия текущего документа.

---

## 6. Алгоритмические особенности

### 6.1. Слияние «на один лист»

См. `docs/10_MERGE_ALGORITHM.md`: накопление строк в целевой лист, согласование заголовков, опциональные колонки `#Путь` / `#ДатаВремяФайла`.

### 6.2. ВПР

Реализован как left outer join (`lm_vlookup_join_sheets`): составные ключи, 1:1 и 1:N, опции заливки добавленных ячеек, заполнения дублей, мульти-совпадения в одну ячейку, заменителя `#Н/Д`.

### 6.3. Производительность

Пакетное копирование (`MERGE_COPY_ROW_CHUNK`, `MERGE_BATCH_COPY_MIN_ROWS`), периодическая отдача UI, пороги отключения тяжёлой постобработки и оформления. На время сбора отключается автопересчёт формул документа.

## 7. Организация и безопасность

Модель доверия: **книга параметров = конфигурация с правами пользователя LO**.

Смягчения (см. `docs/19_SECURITY.md`, `docs/SECURITY_AUDIT.md`):

- **Pre-shell / функция_плагин** — гейт OS env ↔ зашифрованная глобальная переменная профиля.
- **«Файлы-Источники»** — режим strict: только доверенные корни (home / `H:\` / … + env/global); широкий glob вне корня не разворачивается.
- **Постобработка B/C** — AST-санация, fail-closed, builtins без `getattr`/…; не полная песочница (UNO API остаётся).
- **LDAP/AD** — удалён из поставки.
- Источники при закрытии — discard (не сохранять скрытую копию на диск).

Рекомендация: только свои шаблоны; не запускать сбор из чужих недоверенных `.ods` без понимания гейтов.

Consent / terms — модуль `libre_macros_consent_lib` и текст `terms_of_use_ru.txt`.

### 8.9. Сопровождение версии и поставки

1. Изменить `macro-lib/version.txt`.  
2. `python macro-lib/sync_macro_version.py`.  
3. При необходимости пересобрать bundled libs (`bundle_openpyxl.py` / `bundle_odfpy.py`).  
4. Установить в LO (`install.sh`) или собрать `installer/build_ods_bundled.py`.  
5. Сверить версию в журнале «Сбор_книг_лог» и на листе параметров.

## 9. Выводы

Реализованный комплекс соответствует целям сведения табличных данных в Calc без внешней BI-инфраструктуры. Ключевые проектные решения — лист параметров, двухэтапный запуск, JSON-кодек, библиотека `lm_pp_*`, режим direct `xml_excel_ods` и bundled-поставка — согласованы с ограничениями среды LibreOffice и подтверждаются ручными испытаниями (см. [04](04_TEST_METHODOLOGY.md)). Раздел 8 фиксирует ответственность каждого файла репозитория по состоянию ревизии 3.10.696.
