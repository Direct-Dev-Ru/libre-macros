## 1. Общие положения

### 1.1. Полное наименование

Комплекс макросов Python для табличного процессора LibreOffice Calc / AlterOffice ACell: сбор и объединение книг, постобработка, визард параметров, вспомогательные утилиты и bundled-установщик.

### 1.2. Краткая характеристика

ПО представляет собой набор сценариев Python, исполняемых средой PyUNO LibreOffice. Конфигурация основного процесса задаётся **таблицей параметров** на листе книги результата. Реализация — интерпретируемый код без отдельного серверного backend.

### 1.3. Основание для разработки

Разработка велась итеративно; настоящее ТЗ описывает **достигнутый объём** (as-built). Операционные детали — в `docs/04_DATA_COLLECTION.md`, `05_POSTPROCESS.md`, `13_JSON_PARAMS.md`, `15_PARAM_REFERENCE.md`, `17_POSTPROCESS_XML.md`.

## 2. Назначение и цели создания

### 2.1. Назначение

Обеспечить пользователей Calc инструментом сведения табличных данных из множества файлов с гибкими фильтрами, режимами слияния/копирования/вовлечения, несколькими способами переноса, единым pipeline постобработки (включая ВПР, merge/split листов) и расширяемыми пользовательскими функциями.

### 2.2. Цели

1. Единый макрос `collect_workbooks` для режимов сбора; `collect_pack` — оркестратор нескольких листов параметров.
2. Декларативная настройка без правки кода.
3. Предсказуемый порядок постобработки и журнал выполнения.
4. Доставка конечным пользователям через `MacroInstaller_bundled.ods`.
5. Режим «Вовлечь листы» для обработки уже существующих вкладок без копирования.

---

## 3. Характеристика объекта автоматизации

### 3.1. Объект

Процессы подготовки сводных табличных отчётов в Calc: открытие источников, отбор листов/столбцов/строк, копирование, оформление, соединение по ключам, финальная чистка книги.

### 3.2. Условия эксплуатации

- Локальная рабочая станция с установленным офисным пакетом и Python script provider.
- Права пользователя ОС на чтение источников и запись книги результата (и при необходимости — запись профильных каталогов макросов).
- Для `xml_excel_ods` — файл результата на диске.

### 4.2. Требования к функциям (постановка на реализацию)

#### 4.2.1. Этапы выполнения `collect_workbooks`

1. **Этап 1** (`collect_workbooks`): определить документ и лист параметров; `parse_collect_settings`; при ошибке — сообщение; запланировать этап 2 (`schedule_collect_run` / прямой вызов). Очистка листов — **не** на этапе 1.
2. **Этап 2** (`collect_workbooks_run`): повторно прочитать settings; UI подтверждения при режиме «Диалог»; `maybe_clear_sheets` (кроме INVOLVE / suppress pack); `run_collect_merge` → `merge_on_one_sheet` / `merge_on_many_sheets` / `merge_on_copy_sheets` / **`merge_involve_sheets`** (ветка `xml_excel_ods` — для режимов сбора).

#### 4.2.2. Режимы и способы переноса

Задать на листе:

- **Режим** (B): На один лист | На разные листы | Копирование листов | **Вовлечь листы**
- **Способ_переноса** (отдельная строка B или C строки «Режим»): По_API | Буфер_по_заголовкам | Буфер_по_позиции | xml_excel_ods  

Приоритет способа: отдельная строка `Способ_переноса` над C «Режим». Для «Вовлечь листы» способ переноса игнорируется.

#### 4.2.3. Таблица параметров (минимум обязательных для типового сбора)

| Параметр (A) | Содержание |
|--------------|------------|
| `Файлы-Источники` | Пути / маски / маркер текущей книги (`Эта_книга` / `ThisWorkbook` / …) |
| `Режим` | Режим сбора (+ опционально способ в C; для вовлечения — не нужен) |
| `Листы` / `Столбцы` | Фильтры (по файлам в B, C, D…) |
| Блок границ | `Начало_*`, `Число_*`, `Строка_Заголовков` |

Полный реестр — `docs/15_PARAM_REFERENCE.md`. Оркестратор — `docs/18_ORCHESTRATOR.md`.

#### 4.2.4. Pipeline постобработки

Строки листа (повторяемые):

- `Постобработка_Диапазон` — B = ключ функции, C = JSON  
- `ВПР` — B–F или JSON в C (**отдельная строка A**)  
- `объединить_листы_в_один` — A = имя параметра, C = JSON (**не** ключ B Диапазон)  
- `разделить_листы` — A = имя параметра, C = JSON (`run_phase`, `source`, `split_*`, шаблоны)  
- `Постобработка_Строка` — B + JSON  
- `Постобработка_xml` — только при `xml_excel_ods`  
- `Финальная_обработка` — после всех листов  

Правило порядка: блоки `range` и splitters (`vlookup` / `merge_sheets` / `split_sheets`) могут чередоваться; затем все `row`.

Формат JSON блока (общие поля):

```json
[{"v": 1, "fn": "<ключ>", "sheet": "<опц.>", "sheets": ["…"]}]
```

Поля специфичны для `fn` (см. `libre_macros_param_codec.py`, `docs/13_JSON_PARAMS.md`).

#### 4.2.5. Встроенные функции постобработки (объём ТЗ)

Реализовать и поддерживать не менее следующего набора ключей RANGE (см. реестр в коде / `15_PARAM_REFERENCE`):  
`сетка`, `тонкая_сетка`, `толстая_сетка`, `заголовок_плюс_высота`, `перенос`, `перенос_и_авто_высота`, `авто_высота`, `авто_ширина`, `высота_строки`, `левое_выравнивание`, `отступ`, `шрифт`, `зебра_диапазон`, `формат_деньги`, `формат_даты`, `формат_столбцы`, `подсветка_по_порогу`, `градиент`, `удалить_столбцы`, `конкатенация_столбцов`, `добавить_столбец`, `применить_формулу`, `удаление_строк`, `сброс_стрипов`, `группировка_по_столбцу`, `закрепить_заголовок`, `ширина_столбцов`, `автофильтр`, `стиль_печати`, `заполнение_вниз`, `заполнение_вниз_вычислить`, `копировать_значения`, `замена_значений`, `переименовать_лист`, `переименовать_столбцы`, `переставить_столбцы`, `количество_значений`, `копировать_лист`, `сводная_таблица`, `сортировка`, `раскрасить_блоки`, `функция_плагин`, …

### 4.4. Требования к интерфейсам

1. **Пользовательский:** меню макросов; диалоги визарда; индикатор прогресса; сообщения.
2. **Файловый:** чтение/запись ODS/XLSX (и родственных); правка меню XML профиля.
3. **Программный (внутренний):** вызовы `libre_macros_lib.lm_pp_*`, `lm_vlookup_join_sheets`, API `libre_macros_direct_lib` для xml-режима.
4. Внешний REST/сетевой API **не предусматривается**.

### 4.5. Требования к надёжности и диагностике

- Журнал «Сбор_книг_лог»: версия, режим, план постобработки, ошибки/пропуски.
- `MERGE_DEBUG` / `MERGE_DEBUG_CONSOLE_LOG_TO_WORKSHEET` — расширенная диагностика.
- Валидация параметров на этапе `parse_collect_settings` с выдачей текста ошибки.

### 4.6. Требования к безопасности (в рамках ТЗ)

1. Не открывать и не запускать макросы из **недоверенных** книг параметров с произвольным `code`.
2. Документировать опасность необратимой записи источников при «Пропуск_строк_источника».
3. Санация пользовательского кода (`libre_macros_sanitize_lib`) — по состоянию реализации; не считать полной песочницей.

### 4.7. Требования к документированию

Поставить документацию:

- операционную (`docs/00_INDEX.md` …);
- каскадную (`docs/technical_documentation/`);
- шаблоны ручной проверки (`test/collect_workbooks/`).

### 4.8. Требования к маркировке версии

Во всех поставляемых `.py` синхронизировать `MACRO_VERSION` со значением в `macro-lib/version.txt` (сборка bundled — через `build_ods_bundled` / `sync_macro_version`). Текущее значение ТЗ: **3.10.523**.
