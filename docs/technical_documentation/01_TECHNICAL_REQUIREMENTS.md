# Технические требования

**Программный комплекс:** libre-macros  
**Объект:** набор макросов Python для LibreOffice Calc / AlterOffice ACell  
**Версия (состояние реализации):** 3.10.696  
**Основание:** исходный код ревизии `215511d` (каталог `macro-lib/`)  
**Вид документа:** технические требования (каскадная модель)

---

## 1. Общие сведения

### 1.1. Назначение системы

Система предназначена для **автоматизированного сбора, объединения и постобработки табличных данных** из одной или нескольких электронных книг (`.ods`, `.xlsx`, `.xlsm`, `.xls` и др., поддерживаемых драйверами Calc / direct-библиотек) в книгу результата по конфигурации, заданной на листе параметров.

### 1.2. Цели внедрения

1. Сократить ручной труд при сведении отчётов из нескольких файлов-источников.
2. Обеспечить воспроизводимость сбора за счёт декларативной таблицы параметров.
3. Поддержать оформление, сортировку, фильтрацию, ВПР-подобные соединения и пользовательские расширения постобработки без отдельной BI-платформы.
4. Допустить установку конечным пользователем через единый bundled-пакет без доступа к репозиторию исходников.

### 1.3. Область применения

| Роль | Использование |
|------|----------------|
| Пользователь Calc | Запуск сбора, визард параметров, выбор файлов |
| Методист / аналитик | Подготовка шаблонов «Параметры_Объединения» |
| Администратор / разработчик | Установка в профиль LO, отладка, сборка установщика |

### 1.4. Нормативные и проектные ограничения

- Документ фиксирует **фактически реализованные** требования (as-built), а не перспективный backlog.
- Проверка соответствия — **ручная** в LibreOffice Calc; автоматические pytest в приёмке не используются (политика проекта).
- Параметры постобработки в колонке **C** — **только JSON**; legacy-текстовая кодировка блоков недопустима для новых конфигураций.

## 2. Требования к функциональности

### 2.1. Основной процесс сбора (`collect_workbooks`)

Система **должна**:

| ID | Требование |
|----|------------|
| Ф-01 | Читать конфигурацию с листа, имя которого начинается с `Параметры_Объединения` |
| Ф-02 | При нескольких листах группы и запуске `collect_workbooks` читать параметры **только с активного** листа и использовать тот же лист на этапе 2 |
| Ф-02a | Макрос `collect_pack` — оркестратор: выбор/порядок нескольких листов параметров, опциональный сброс DatabaseRange, журналы `Сбор_книг_лог_N` |
| Ф-03 | Поддерживать режимы: «На один лист», «На разные листы», «Копирование листов», **«Вовлечь листы»** |
| Ф-03a | Режим «Вовлечь листы»: только маркер текущей книги; без копирования/слияния; без предварительного удаления листов; постобработка и финал на указанных вкладках |
| Ф-04 | Поддерживать способы переноса данных: `По_API`, `Буфер_по_заголовкам`, `Буфер_по_позиции`, `xml_excel_ods` (не для режима «Вовлечь листы») |
| Ф-05 | Принимать список файлов-источников (пути, маски, маркер текущей книги: `Эта_книга` / `ThisWorkbook` и гибкие синонимы) |
| Ф-06 | Фильтровать листы и столбцы источников (имя, индекс, шаблон `*`) |
| Ф-07 | Ограничивать блок данных: начало строки/столбца, число строк/столбцов, строка заголовков |
| Ф-08 | Поддерживать пропуск строк источника по списку столбцов или формуле |
| Ф-09 | Добавлять служебные колонки источника (путь, дата/время файла) по параметрам листа |
| Ф-10 | Выполнять отображение «Ячейка_В_Столбец» после копирования (режимы one/many) |
| Ф-11 | Применять цепочки постобработки Диапазон / ВПР / `объединить_листы_в_один` / `разделить_листы` / Строка и финальную обработку |
| Ф-12 | Вести журнал «Сбор_книг_лог» (или `Сбор_книг_лог_N` при multi-pack) с версией макроса и сведениями о ходе/ошибках |
| Ф-13 | Обеспечивать двухэтапный запуск (этап 1 — валидация; этап 2 — подтверждение, очистка листов, сбор), с fallback при недоступности dispatch |
| Ф-14 | Показывать прогресс (диалог или статустая строка) согласно параметру листа |
| Ф-15 | Сохранять листа, перечисленные в «Листы_не_удалять», при очистке |

### 2.2. Способ переноса `xml_excel_ods`

| ID | Требование |
|----|------------|
| Ф-16 | Книга результата должна быть **сохранена на диск** до запуска |
| Ф-17 | Фаза A: перенос и `Постобработка_xml` выполняются в файле на диске (direct) |
| Ф-18 | Фаза B: UNO-операции (`Постобработка_Диапазон` / `Строка`, закрепление и т.п.) — **после показа** книги |
| Ф-19 | При `MERGE_XML_CONVERT_TO_NUMBERS=Да` преобразовывать текстовые числа и даты в числовые значения по правилам реализации |

### 2.3. Постобработка и расширения

| ID | Требование |
|----|------------|
| Ф-20 | Колонка C строк постобработки — JSON-массив блоков (`v`, `fn`, `sheet`/`sheets`, поля функции) |
| Ф-21 | Набор встроенных функций RANGE/ROW/FINAL соответствовать реестру в коде (`libre_macros_lib`, codec) |
| Ф-22 | Поддерживать плагины `функция_плагин` через `functions_pp.py#…` / `functions_final.py#…` |
| Ф-23 | Соблюдать порядок pipeline: range+vlookup, затем row; после первого row запрещены снова range/vlookup |
| Ф-24 | ВПР: left outer join по ключам, опции цвета, дублей, мульти-совпадения, заполнителя |

### 2.4. Вспомогательные макросы

## 3. Требования к данным и интерфейсу

### 3.1. Входные данные

- Книга Calc с листом `Параметры_Объединения*`.
- Файлы-источники, доступные по указанным путям.
- Для `xml_excel_ods` — сохранённый файл книги результата.

### 3.2. Выходные данные

- Листы результата (Merge / Merge_N / копии листов / именованные листы источников).
- Лист журнала «Сбор_книг_лог».
- При необходимости — лист «Индексы_Источников» (режим «На разные листы» по индексам).

### 3.3. Пользовательский интерфейс

| ID | Требование |
|----|------------|
| И-01 | Запуск через меню макросов Python и/или контекстное меню |
| И-02 | Визард параметров — модальные диалоги UNO |
| И-03 | Сообщения об ошибках параметров — диалог / log |
| И-04 | Текст на русском языке в UI пользователя |

### 3.4. Согласие и условия использования

| ID | Требование |
|----|------------|
| И-05 | При необходимости показывать условия использования / consent (модуль `libre_macros_consent_lib`) перед чувствительными операциями согласно реализации |

## 4. Требования к надёжности и производительности

| ID | Требование |
|----|------------|
| Н-01 | Ошибки открытия источника, отсутствия листа/столбца — фиксация в журнале без аварийного завершения всего процесса, где реализация предусматривает продолжение |
| Н-02 | Параметры производительности (`MERGE_*_ROWS`, chunk sizes) должны быть переопределяемы с листа |
| Н-03 | При числе строк выше `MERGE_ROW_POSTPROCESS_MAX_ROWS` / `MERGE_FORMATTING_MAX_ROWS` допускается пропуск соответствующих тяжёлых этапов с записью в лог |
| Н-04 | Автопересчёт книги на время сбора отключается и восстанавливается |

## 5. Требования к безопасности

| ID | Требование |
|----|------------|
| Б-01 | Система работает **локально**; сетевых вызовов в штатном коде сбора нет |
| Б-02 | Книга параметров считается **доверенной конфигурацией** с правами процесса LibreOffice |
| Б-03 | Пользовательский Python (`code` / eval) допустим только из доверенных шаблонов |
| Б-04 | Режим с изменением файлов-источников («Пропуск_строк_источника» с записью) должен применяться осознанно |
| Б-05 | Уровень безопасности макросов LO должен допускать выполнение Python-макросов |

Подробный анализ рисков: операционный документ `docs/SECURITY_AUDIT.md` (версия отчёта может отставать от `MACRO_VERSION`).

## 8. Критерии приёмки (уровень ТТ)

Система считается **соответствующей техническим требованиям**, если:

1. Установлена версия **3.10.696** (или явно согласованная последующая) и строка версии в журнале совпадает.
2. Выполнены обязательные сценарии ручной приёмки из [04_TEST_METHODOLOGY.md](04_TEST_METHODOLOGY.md) с результатом «годно» по чек-листу.
3. Конфигурации постобработки с **валидным JSON** в колонке C выполняются без «ошибок» кодека (пропуски по фильтру листа допускаются и фиксируются в логе).
4. Режим `xml_excel_ods` при сохранённой книге завершает фазы A и B без блокирующей ошибки «книга не сохранена».

Детализация проверок — в методике испытаний; детализация постановки — в техническом задании.
