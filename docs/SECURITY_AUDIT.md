# Отчёт по безопасности: libre-macros

**Дата:** 2026-09-07  
**Версия макросов:** `macro-lib/version.txt` (**3.10.698**)  
**Предыдущий аудит:** 2026-09-07 / 3.10.697  
**Область:** `macro-lib/`, `installer/`, `pythonpath/` (без полного разбора bundled ldap3/openpyxl/odf/segno)  
**Метод:** статический анализ, поиск опасных API, сверка с прошлыми находками, оценка модели доверия

---

## Краткое резюме

Проект — локальный набор макросов LibreOffice/AlterOffice Calc (сбор книг, постобработка, AD, почта, QR и др.). **Модель доверия не изменилась:** книга параметров выполняется с правами пользователя ОС. Изменилась **поверхность** и часть **mitigations**.

| Уровень | Кол-во | Суть |
|---------|--------|------|
| Критический | 1 | «Предварительный_скрипт» — RCE при совпадении env + зашифрованной глобальной |
| Высокий | 5 | Обход/слабость санации eval; abs `file_ref`; произвольные источники; лог путей; LDAP/AD |
| Средний | 6 | Почта (локальный клиент); пароль инсталлятора; zip/XML DoS; glob; MERGE_DEBUG; XML меню |
| Низкий | 3 | Конфиги в `~/.config`; временные файлы; безопасные eval формул |
| Закрыто с прошлого аудита | 1 | C-2: сохранение источников при пропуске строк — исправлено |

**Вывод:** для своих шаблонов и данных риски управляемы. Для **чужих `.ods`/`.xltx`** риск **высокий–критический**: параметры = конфигурация с правами LO, плюс явный канал запуска внешних команд и (отдельно) LDAP.

## Модель доверия

```
┌─────────────────────────────────────────────────────────────┐
│  Книга параметров (.ods / .xltx)                            │
│  ├── Файлы-Источники (пути, glob)                           │
│  ├── Постобработка B/C (Python + JSON + file#func)          │
│  ├── Предварительный_скрипт → argv / cwd / env              │
│  ├── Финал: отправить_по_почте (локальный MUA)              │
│  └── (отдельный макрос) AD: server/OU/учётка с листа        │
└──────────────────────────┬──────────────────────────────────┘
                           │ процесс LO / AO
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Права пользователя ОС                                      │
│  ├── ФС: чтение источников, запись результата/лога/tmp      │
│  ├── eval/exec после AST-санации (не полная песочница)      │
│  ├── subprocess (pre_shell, mailto/thunderbird/outlook)     │
│  └── LDAP/LDAPS к указанному серверу (AD-макрос)            │
└─────────────────────────────────────────────────────────────┘
```

Макрос **не изолирует** параметры от привилегий пользователя. Согласия (terms / pre_shell confirm) снижают риск случайного запуска, но не защищают от «нажал Продолжить» на вредоносном шаблоне.

## Находки по критичности

### Критический

#### C-3. Произвольная внешняя команда: «Предварительный_скрипт»

**Где:** `libre_macros_pre_shell_lib.run_pre_shell`, `collect_workbooks.merge_run_pre_shell_from_doc`, параметр в визарде (`mode: pre_shell`)

**Описание:** JSON в параметрах книги задаёт `argv` (и опционально `cwd`, `timeout`, `env`, `clean_env`). Запуск через `subprocess.run` / `Popen` с **`shell=False`**.

**Гейт допуска (с 3.10.698):** без него сбор **прерывается до** диалога подтверждения:
1. OS env `MERGE_ALLOW_PRE_SCRIPT` задана и не пуста;
2. в runtime-карте есть **только глобальное** значение `Merge_Allow_Pre_Scripts` (сегмент «Глобальные_переменные»; ручной ввод / файл не учитываются);
3. в JSON глобальных настроек эта переменная с `encrypt=True` и значением `lm1:`;
4. plaintext после расшифровки **совпадает** с env.

Имя глобальной переменной: любые регистры, `_` / `-` / слитно (`MergeAllowPreScripts` и т.п.). При сохранении в визарде шифрование для этого имени **принудительное**.

Дополнительно: модальное подтверждение и журнал в `~/.config/libre-macros/pre_shell_consent/`.

**Последствия:** RCE от имени пользователя LO **только если** атакующий также контролирует OS env и зашифрованную глобальную настройку профиля (или жертва сама настроила допуск).

**Смягчения:** `shell=False`; env+encrypted global gate; confirm UI; `clean_env`.

**Рекомендации:** не экспортировать значение допуска в шаблоны книг; держать ключ шифрования глобальных переменных вне общих каталогов.

#### C-3b. «функция_плагин» — гейт допуска (с 3.10.701, defaults 3.10.702)

**Где:** `libre_macros_allow_gate_lib.verify_plugin_allow_gate`, `collect_workbooks.merge_verify_plugin_allow_gates` (в `parse_collect_settings`), визард `_show_plugin_function_dialog`

**Описание:** в JSON/визарде опционально задаются **имена** `allow_env` и `allow_global`. Если поле пусто:

- env → `MERGE_ALLOW_PLUGINS`
- глобальная → `Merge_Allow_Plugins` (при сохранении — принудительный encrypt, как у pre-shell)

Перед сборкой цепочек PP/final:

1. эффективные имена (из JSON или defaults) непусты;
2. OS env с этим именем задана и не пуста;
3. глобальная в настройках с `encrypt=True` и `lm1:`;
4. в runtime-карте (только сегмент «Глобальные_переменные») расшифрованное значение **совпадает** с env.

Пустое значение env/глобальной или незашифрованная глобальная — **fail**. Ошибка — крупный красный диалог (`show_collect_error`).

### Высокий

#### H-5 (бывш. C-1). Eval/exec постобработки — санация есть, песочницы нет

**Где:** `collect_workbooks._merge_pp_compile_postprocess_code`; также `libre_macros_lambda_column_lib`, `libre_macros_sheet_filter_lib`, `libre_macros_normalize_lib`

**Описание:** Inline `lambda`/`def` и поле `code` в JSON проходят `lm_sanitize_code` (запрет import, `getattr`/`__subclasses__`, сети, FS write, crypto-маркеров и т.д.), затем `eval`/`exec` с builtins без `_MERGE_PP_EVAL_BUILTIN_BLOCKLIST`.

**Остаточные риски:**
1. **Fail-open:** если импорт sanitize падает с исключением, compile **продолжается** без санации (`except Exception: … недоступна`).
2. Builtins blocklist макроса **не** включает `getattr` (его режет AST); рассинхрон политик.
3. Санация — статический фильтр, не изоляция ОС; новые обходы AST/эвристик возможны.
4. UNO/`doc`/`sheet` в namespace постобработки дают мощный API внутри процесса LO.

**Статус vs прошлого C-1:** классический обход через `__subclasses__` для типичного кода **заблокирован** → критичность снижена до **высокой**, не «закрыто».

**Рекомендации:** fail-closed при недоступной санации; расширить blocklist builtins (`getattr`, `setattr`, …); политика `strict` для недоверенных книг; долгосрочно — только whitelist именованных плагинов.

---

#### H-2. Загрузка Python с абсолютного пути (`file_ref`) — не закрыто

**Где:** `collect_workbooks._merge_pp_resolve_script_path`

```python
if os.path.isabs(p):
    return p if os.path.isfile(p) else None
```

**Описание:** `lm_sanitize_file_ref(..., allow_absolute=False)` в sanitize_lib готов, но **resolve в макросе его не использует**. Abs `file.py#func` по-прежнему загружается; тело функции затем санируется при compile.

**Последствия:** книга указывает на заранее положенный `.py` вне каталога макроса (в связке с пробелами санации / fail-open).

**Рекомендации:** заменить resolve на `lm_sanitize_resolve_script_path` / `lm_sanitize_load_file_function` с `base_dir=_merge_macro_script_dir()`.

---

#### H-1. Чтение произвольных файлов через «Файлы-Источники»

**Где:** `resolve_source_path`, `expand_source_files`, `open_source`

**Статус:** без существенных изменений — abs paths и glob без whitelist каталогов.

**Рекомендации:** опциональный whitelist; предупреждение вне каталога книги; в логе — basename / относительный путь.

---

#### H-3. Утечка путей и метаданных в «Сбор_книг_лог»

**Где:** `append_collect_log`, `merge_pp_user_log`, debug-зеркало на лист

**Статус:** актуально. Дополнительно: при `MERGE_DEBUG` временные xlsx могут **не удаляться**, путь пишется в журнал.

**Рекомендации:** режим «безопасный лог»; не оставлять temp при обычном запуске.

---

#### H-6. Сеть: Active Directory / LDAP

**Где:** `libre_macros_ad_lib`, `libre_macros_ad_winldap`, `ldap3_bundled`, entry `ad_list_users.py`; пароль — диалог (`libre_macros_ad_dialog_lib`)

**Описание:** Намеренный LDAP/LDAPS к серверу из листа конфигурации. Не «телефон домой» автора макроса, но **первый штатный сетевой канал** в дереве макросов.

**Последствия:** вредоносный шаблон AD может направить запрос на чужой LDAP (утечка учётки при вводе пароля); чтение каталога организации.

**Рекомендации:** предупреждение при нестандартном host; не сохранять пароль в книге; документировать доверие к листу AD-конфига.

### Средний

#### M-6. Финал «отправить_по_почте»

**Где:** `libre_macros_mail_lib` — `subprocess.Popen` для системного mailto / Thunderbird / Outlook compose

**Описание:** SMTP из макроса **нет**; открывается локальный почтовый клиент, возможны вложения (временные файлы книги/листов).

**Последствия:** удобный канал экспорта данных вовне через UI пользователя; запуск внешнего процесса.

**Рекомендации:** подтверждение списка получателей/вложений; не логировать полные пути вложений лишний раз.

### Закрытые находки

#### ✓ C-2 (было: необратимое изменение файлов-источников)

**Где:** `close_source` → `_merge_close_doc_discard` (`setModified(False)`, затем `doc.close(True)` — в UNO это **DeliverOwnership**, не «сохранить»). Отдельный `_merge_close_doc_save` для явного store.

Комментарии в `_merge_skip_spec_needs_writable` / `close_source`: изменения пропуска строк на **скрытой копии в памяти**, файл на диск не пишется.

**Остаточный риск (низкий):** сбой API/порта LO, если `setModified`/`close` поведут себя иначе — стоит периодически проверять на AO/LO вручную.

## Положительные меры (актуально на 3.10.701)

1. **AST-санация** подключена к compile постобработки и ряду лямбд/фильтров.
2. **Consent** перед сбором + предупреждение о plugin refs.
3. **Pre-shell:** `shell=False`, confirm UI, журнал согласий, `clean_env`; **гейты** env `MERGE_ALLOW_PRE_SCRIPT` + encrypted global `Merge_Allow_Pre_Scripts` (только сегмент глобальных в runtime-карте).
4. **функция_плагин:** гейт `allow_env`/`allow_global` (опционально в визарде; пусто → `MERGE_ALLOW_PLUGINS` / `Merge_Allow_Plugins`) ↔ env + encrypted global.
5. **Источники:** discard без сохранения; ReadOnly по умолчанию.
6. **C-2 закрыт** (пропуск строк не сохраняет внешний файл).
7. **JSON-only** параметры постобработки в C.
8. **defusedxml** в ODF/openpyxl-пути (с оговорками).
9. **ast.literal_eval** для статических структур где применимо.
10. **installer_password.txt** в `.gitignore`.
11. Лимиты объёма постобработки/форматирования (`MERGE_*_MAX_ROWS`).
12. Почта без встроенного SMTP.
13. Документация санации: [16_CODE_SANITIZE.md](16_CODE_SANITIZE.md).

## Рекомендации по приоритету

1. Подключить **ограничение путей `file_ref`** к каталогу макроса (H-2) — код уже в sanitize_lib.
2. **Fail-closed**, если санация недоступна (H-5).
3. Зафиксировать в пользовательской доке: B/C + AD-конфиг = **полный trust** к книге; pre-shell — только при настроенном env/глобальном допуске.

4. Whitelist / предупреждение для источников и `argv[0]` pre_shell (H-1, C-3).

6. Выровнять builtins blocklist с AST-запретами (`getattr` и др.).

### P2

8. Лимиты размера/времени на файлы (M-2).
9. Убрать дефолтный пароль инсталлятора из production (M-1).
10. defusedxml для меню (M-5); подтверждение glob (M-3).

- Статический разбор; динамическая эксплуатация обходов санации в LO/AO не воспроизводилась.
- Автотесты безопасности не запускались (правило проекта — ручная проверка в Calc).

## Заключение

Архитектура по-прежнему — **полное доверие к книге параметров** для B/C и источников. Pre-shell с **3.10.698** требует совпадения OS env и зашифрованной глобальной переменной профиля — чужой шаблон сам по себе скрипт не запустит. Главный незакрытый P0 — **ограничение `file_ref`**; отдельно держать в поле зрения AD и политику ключа глобальных переменных.

*Отчёт обновлён по состоянию репозитория на дату и версию выше.*
