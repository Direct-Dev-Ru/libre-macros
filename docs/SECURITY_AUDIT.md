# Отчёт по безопасности: libre-macros

**Дата:** 2026-07-08  
**Версия макросов:** см. `macro-lib/version.txt` (**3.10.523**)  
**Область:** `macro-lib/`, `installer/`, встроенные библиотеки `pythonpath/`  
**Метод:** статический анализ исходного кода, поиск опасных API, оценка модели доверия

---

## Краткое резюме

Проект **libre-macros** — локальный макрос LibreOffice Calc для сбора данных из файлов и постобработки. **Сетевых вызовов в коде макросов нет** — прямой канал утечки «наружу» отсутствует. Основные риски связаны с **моделью доверия к параметрам книги** (лист «Параметры_Объединения»), **выполнением пользовательского Python** (колонки B/C) и **доступом к произвольным файлам на диске** через пути источников.

| Уровень | Кол-во | Суть |
|---------|--------|------|
| Критический | 2 | Песочница Python обходима; внешние источники могут быть изменены на диске |
| Высокий | 4 | Произвольное чтение файлов; произвольная загрузка `.py`; утечка путей в журнал |
| Средний | 5 | Пароль инсталлятора; zip/XML DoS; широкие glob-маски; отладочный вывод |
| Низкий | 3 | Конфиги в `~/.config`; временные файлы; парсинг XML меню LO |

**Вывод:** для доверенных сценариев (свои шаблоны, свои данные) риски управляемы. Для **чужих `.ods`/`.xltx` с макросом** — уровень риска **высокий**: книга параметров фактически является конфигурацией с правами процесса LibreOffice.

---

## Модель доверия

```
┌─────────────────────────────────────────────────────────────┐
│  Книга параметров (.ods / .xltx)                            │
│  ├── Файлы-Источники (абсолютные/относительные пути, glob)  │
│  ├── Постобработка: колонка B (Python), C (JSON + code)     │
│  └── Пропуск_строк_источника → изменение внешних файлов     │
└──────────────────────────┬──────────────────────────────────┘
                           │ выполняется в процессе LO
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  LibreOffice Calc + Python (права пользователя ОС)          │
│  ├── Чтение/запись файлов (источники, результат, лог)       │
│  ├── eval/exec пользовательского кода                       │
│  └── Журнал «Сбор_книг_лог» внутри книги результата         │
└─────────────────────────────────────────────────────────────┘
```

Макрос **не изолирует** параметры от привилегий пользователя. Любой, кто может заставить жертву открыть вредоносный шаблон и запустить сбор, получает тот же доступ к ФС, что и пользователь LO.

## Находки по критичности

### Критический

#### C-1. Обход «песочницы» eval/exec в постобработке (колонка B и JSON `code`)

**Где:** `collect_workbooks.py` — `_merge_pp_compile_postprocess_code`, `_MERGE_PP_EVAL_BUILTIN_BLOCKLIST`, `_merge_pp_postprocess_eval_namespace`

**Описание:** Пользовательский Python из колонки B (`lambda`/`def`) и inline-поля `code` в JSON колонки C компилируется через `eval`/`exec`. Из builtins исключён ограниченный blocklist (`__import__`, `open`, `eval`, …), но **остаются** `getattr`, `type`, `isinstance`, `super` и др. Классический обход через цепочку `__subclasses__()` позволяет снова получить `__import__` и модули `os`/`subprocess`.

**Последствия:** произвольный код в контексте пользователя LO (чтение секретов, запись файлов, запуск команд — при успешном обходе).

**Рекомендации:**
- Не полагаться на blocklist builtins; рассмотреть **полный отказ от eval/exec** для недоверенного ввода.
- Для доверенных плагинов — только `file_ref` на файлы **внутри каталога макроса** (см. H-2).
- Документировать: колонки B/C с `code` = **полный доверенный код**, не открывать чужие книги с неизвестными параметрами.

---

#### C-2. Необратимое изменение файлов-источников (параметр «Пропуск_строк_источника»)

**Где:** `collect_workbooks.py` — `_merge_source_apply_skip_rows`, `open_source(writable=…)`, `close_source` → `doc.close(True)`

**Описание:** Для **внешних** (не «эта_книга») источников при активном «Пропуск_строк_источника» макрос:
1. открывает файл **без ReadOnly** (`writable=True`);
2. добавляет служебный столбец, формулы, автофильтр;
3. **удаляет строки** на листе источника (`removeByIndex`);
4. закрывает документ через `doc.close(True)` — **с сохранением на диск**.

Комментарий в коде утверждает «закрывается без сохранения», но фактическое поведение — **сохранение**.

**Последствия:** вредоносный или ошибочный шаблон может **уничтожить или повредить** чужие `.xlsx`/`.ods` на диске пользователя, если указать их как источники.

**Рекомендации:**
- Закрывать источники с `close(False)` или копировать файл во временный каталог перед модификацией.
- Явное подтверждение пользователя перед деструктивной операцией.
- Разделить «фильтрация при копировании» (без записи на диск) и «очистка источника» (отдельный режим).

### Высокий

#### H-1. Чтение произвольных файлов через «Файлы-Источники»

**Где:** `resolve_source_path`, `expand_source_files`, `open_source`

**Описание:** Поддерживаются **абсолютные пути** и **glob-маски** без whitelist расширений на этапе развёртки. Проверка расширения (`.xlsx`, `.xls`, `.ods`) происходит только при выборе фильтра LO в `open_source`, но путь уже попадает в журнал и UI.

**Последствия:** шаблон может заставить LO открывать/обрабатывать пути вне рабочей папки; пути и ошибки попадают в лог; при режиме direct XML — чтение через openpyxl/odf.

**Рекомендации:** опциональный whitelist каталогов; предупреждение при абсолютных путях вне каталога книги; логировать только basename для чувствительных путей.

---

#### H-2. Загрузка Python из произвольного абсолютного пути (`file_ref`)

**Где:** `_merge_pp_resolve_script_path` в `collect_workbooks.py`

```python
if os.path.isabs(p):
    return p if os.path.isfile(p) else None
```

**Описание:** Ссылка вида `/any/path/evil.py#handler` загружает и компилирует функцию из **любого** читаемого `.py` на диске (не только из каталога макроса).

**Последствия:** цепочка с C-1 — выполнение кода, подготовленного заранее на диске, по инициативе книги параметров.

**Рекомендации:** разрешать только пути под `_merge_macro_script_dir()`; отклонять `..` и абсолютные пути вне каталога.

---

#### H-3. Утечка метаданных и путей в лист «Сбор_книг_лог»

**Где:** `append_collect_log`, `merge_pp_user_log`, `_merge_log_postprocess`

**Описание:** Журнал хранит timestamp, **полный путь источника**, имя листа, статус, примечание (до 500 символов). Пользовательский код через `merge_pp_user_log` может записать произвольный текст. Лист сохраняется **в книге результата**.

**Последствия:** при передаче результирующего файла третьим лицам утекают структура каталогов, имена проектов, фрагменты данных из сообщений об ошибках/traceback.

**Рекомендации:** режим «безопасный лог» (только относительные имена); не включать traceback в пользовательский лог по умолчанию; предупреждение перед отправкой файла с логом.

---

#### H-4. Inline Python в JSON колонки C (`"code": "…"`)

**Где:** `_merge_pp_resolve_plugin_block`, `_merge_pp_parse_plugin_function_text`

**Описание:** Постобработка может задаваться не только в B, но и полем `code` в JSON C — тот же механизм eval/exec.

**Последствия:** атакующий может спрятать код в JSON, оставив B безобидным (`функция_плагин`).

**Рекомендации:** те же, что для C-1; при аудите проверять **и B, и C**.

---

### Средний

#### M-1. Слабый пароль защиты инсталлятора по умолчанию

**Где:** `installer/ods_modify_password.py` — `DEFAULT_INSTALLER_PASSWORD = "macros_libre_123456"`

**Описание:** ODS-инсталлятор защищается от изменений паролем ModifyPassword; при отсутствии env/файла используется **предсказуемый** пароль. Пароль записывается в `installer/installer_password.txt` (в `.gitignore`, но на диске в открытом виде).

**Последствия:** подмена макросов в инсталляторе при знании дефолтного пароля.

**Рекомендации:** обязательный ввод пароля при сборке; не использовать дефолт в production; документировать смену пароля.

---

#### M-2. Zip / XML bomb при разборе таблиц

**Где:** `openpyxl_bundled.py` (`ZipFile`, `iterparse`), `odf_bundled.py` (defusedxml с оговорками о decompression bombs)

**Описание:** Нет лимитов на размер распаковки, число записей в zip, глубину XML. Вредоносный `.xlsx`/`.ods` может вызвать исчерпание памяти/CPU (DoS).

**Положительно:** openpyxl по умолчанию включает `DEFUSEDXML=True` при наличии bundled defusedxml; ODF-путь использует defusedxml.sax.

**Рекомендации:** лимиты размера файла и времени обработки; обработка только из доверенных каталогов.

---

#### M-3. Широкие glob-маски

**Где:** `expand_source_files` → `glob.glob(resolved_path)`

**Описание:** Маска вроде `*.xlsx` в домашнем каталоге или `**` (если поддерживается путём) соберёт все совпадения.

**Последствия:** массовое чтение файлов, непреднамеренное включение конфиденциальных книг в сбор.

**Рекомендации:** подтверждение списка файлов перед запуском; лимит числа источников.

---

#### M-4. Отладочный вывод `MERGE_DEBUG`

**Где:** `merge_debug`, `_merge_debug_memory_snapshot` (читает `/proc/self/status`)

**Описание:** При `MERGE_DEBUG=True` в stdout попадают пути, фазы, снимок памяти процесса.

**Последствия:** утечка контекста в общий терминал/логи CI.

**Рекомендации:** держать флаг выключенным в production; не логировать полные пути.

---

#### M-5. Парсинг XML меню без defusedxml

**Где:** `context_menu.py` — `xml.etree.ElementTree.parse`

**Описание:** Парсится `cell.xml` / `menubar.xml` профиля LibreOffice (не произвольный ввод из сети). Риск XXE низкий, но при компрометации файлов профиля — стандартные XML-риски.

**Рекомендации:** defusedxml для единообразия; проверка прав на запись в каталог user LO.

---

### Низкий

#### L-1. Локальные настройки с путями

**Где:** `file_list_macro.py` → `~/.config/libre-macros-file-list/settings.json`; `param_wizard.py` → `~/.config/libre-macros/.../merge_param_presets.json`

**Описание:** Сохраняются последние пути из диалогов и пресеты параметров.

**Последствия:** локальная утечка структуры рабочих каталогов при доступе к профилю пользователя.

---

#### L-2. Временные файлы при конвертации `.xls`

**Где:** `_merge_run_collect_direct_xml_excel_ods` — `tempfile.mkstemp(prefix="libre_macros_xls_")`

**Описание:** Временный `.xlsx` удаляется в `finally`, но при аварийном завершении может остаться в `/tmp` с фрагментами данных.

---

#### L-3. Безопасные подмножества eval для формул пропуска

**Где:** `libre_macros_lib.py` — `_lm_safe_eval_bool`, `_lm_safe_eval_row_index_expr` (whitelist символов перед `eval`)

**Описание:** Для выражений `{row_id±N}` используется ограниченный eval — **хорошая практика**, не относится к постобработке B/C.

## Утечка данных: сводная таблица

| Канал | Что утекает | Кому | Управление |
|-------|-------------|------|------------|
| Лист «Сбор_книг_лог» | Пути, статусы, сообщения кода | Получатель `.ods` результата | Очистка листа; безопасный режим |
| `merge_pp_user_log` / traceback в B | Произвольный текст, стек | Тот же файл + консоль | Не логировать секреты в B |
| `MERGE_DEBUG` | Пути, память | stdout / терминал | Флаг выключен |
| `~/.config/libre-macros*` | Пути, пресеты | Локальный пользователь | Права на home |
| Индексы / служебные листы | Имена файлов, даты | Книга результата | Осознанный обмен файлами |
| Сеть | — | — | **Не используется** |

**Прямой exfiltration по сети в коде макросов не обнаружен.** Риск появляется только после обхода C-1 (произвольный Python).

## Положительные меры (уже реализованы)

1. **Нет сетевых библиотек** в `macro-lib/` (urllib/requests/socket) — нет встроенного «телефона домой».
2. **Источники по умолчанию ReadOnly** (`open_source(..., writable=False)`), кроме сценария пропуска строк.
3. **JSON-only** для параметров постобработки в C (`param_decode` / правило проекта).
4. **defusedxml** в bundled ODF; **OPENPYXL_DEFUSEDXML** по умолчанию True.
5. **ast.literal_eval** для статических структур (`context_menu`, codec fallback).
6. **installer_password.txt** в `.gitignore`.
7. **Ограничения объёма** постобработки (`MERGE_ROW_POSTPROCESS_MAX_ROWS`, `MERGE_FORMATTING_MAX_ROWS`).

## Матрица угроз (кратко)

| Угроза | Вероятность | Влияние | Итог |
|--------|-------------|---------|------|
| Чужой шаблон + запуск сбора | Средняя (соц. инж.) | Критическое | **Высокий риск** |
| Ошибка в путях/glob своего шаблона | Высокая | Среднее | Средний риск |
| DoS через огромный xlsx | Низкая | Среднее | Средний риск |
| Подмена инсталлятора (дефолт-пароль) | Низкая | Высокое | Средний риск |
| Утечка путей через лог при обмене файлом | Средняя | Низкое–среднее | Средний риск |

## Рекомендации по приоритету

### P0 (срочно)

1. Исправить **сохранение источников** при пропуске строк: `close(False)` или работа с копией файла (C-2).
2. Ограничить **загрузку `file_ref`** каталогом макроса (H-2).
3. Задокументировать **отсутствие песочницы** для B/C и запрет на запуск чужих книг без ревью параметров.

### P1 (важно)

4. Усилить или заменить eval/exec (C-1, H-4): AST-интерпретатор, только именованные плагины из whitelist.
   Черновик библиотеки: `pythonpath/libre_macros_sanitize_lib.py` + [16_CODE_SANITIZE.md](16_CODE_SANITIZE.md) (в макрос пока не подключена).
5. Опциональный **whitelist каталогов** для источников (H-1).
6. Режим **«безопасный журнал»** без полных путей (H-3).

### P2 (желательно)

7. Лимиты размера/времени на обработку файлов (M-2).
8. Убрать дефолтный пароль инсталлятора из production-сборок (M-1).
9. Диалог подтверждения деструктивных операций и широких glob (M-3, C-2).

## Ограничения анализа

- Проведён **статический** разосмотр; динамическая эксплуатация обхода eval не воспроизводилась в LO.
- **Автотесты безопасности не запускались** (в соответствии с правилами проекта — ручная проверка в Calc).
- Зависимости `.venv` и полный bundled openpyxl/odf анализировались выборочно (точки входа и XML/zip).
- Изменения в рабочей копии (uncommitted diff) в отчёт не включались.

## Заключение

**libre-macros** — мощный инструмент автоматизации с **намеренным** доступом к файловой системе и исполнением логики из ячеек. Это не уязвимость реализации «в вакууме», а **архитектурная модель полного доверия к книге параметров**. Для корпоративного или мультипользовательского использования необходимы: ревью шаблонов, исправление сохранения источников, ограничение путей к `.py` и явная политика по пользовательскому коду в B/C.

*Отчёт подготовлен автоматически по состоянию репозитория на дату указана выше.*
