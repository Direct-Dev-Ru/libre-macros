# Справочник параметров листа «Параметры_Объединения»

Единый реестр всех имён параметров, допустимых значений и колонок. Канонический источник имён в коде: `param_wizard._build_wizard_catalog()` и константы `P_MERGE_*` в `collect_workbooks.py`.

**Версия макроса**: `MACRO_VERSION` в `macro-lib/collect_workbooks.py` / `macro-lib/version.txt` (**3.10.696**).

Подробные описания поведения — в [04_DATA_COLLECTION.md](04_DATA_COLLECTION.md), оркестратор — [18_ORCHESTRATOR.md](18_ORCHESTRATOR.md), постобработка — [05_POSTPROCESS.md](05_POSTPROCESS.md), JSON — [13_JSON_PARAMS.md](13_JSON_PARAMS.md).

## Раскладка листа

| Колонка | Назначение |
|---------|------------|
| **A** | Имя параметра (ключ) |
| **B** | Основное значение (или «смотри в C» для параметров с JSON) |
| **C, D…** | Дополнительные значения: пути к файлам, способ переноса (в строке «Режим»), JSON постобработки, колонки ВПР |
| Пустая **A** | Конец таблицы параметров |

Лист: имя начинается с `Параметры_Объединения`.
- **`collect_workbooks`**: при нескольких листах группы параметры — с **активного**.
- **`collect_pack`**: выбор листов в диалоге оркестратора ([18_ORCHESTRATOR.md](18_ORCHESTRATOR.md)).
На этапе 2 используется запомненный лист параметров (`set_run_param_sheet`).

### `Доп_Параметры_Источника`

JSON в ячейках B, C, D… (как у источников). Пустая ячейка → JSON из B.
Наборы ключей **не смешивать** в одном объекте из визарда: CSV — свои, книга ODS/XLS(X/M) — свои.

#### CSV

```json
{"delimiter":";","encoding":"windows-1251","copy_whole_sheet":false}
```

- `delimiter`: `;`, `,`, табуляция (`\t`), `|` (по умолчанию `;`)
- `encoding`: `windows-1251` (по умолчанию), `utf-8`, `utf-8-sig`, `cp866`, `koi8-r`, …
- `copy_whole_sheet`: `true` / `false` (по умолчанию `false`). В режиме **«Копирование листов»**:
  - `false` — CSV в память → числа/даты → `setDataArray`;
  - `true` — открыть CSV в Calc (фильтр + `delimiter`/`encoding`) и перенести лист целиком (`importSheet`), как у xlsx/ods.
    Отдельная конвертация текст→число/дата **не выполняется** (ни UNO, ни xml),
    независимо от `MERGE_XML_CONVERT_TO_NUMBERS` — Calc уже распознаёт типы при открытии.

Синонимы `copy_whole_sheet`: `переносить_листом`, `переносить_всем_листом`, `whole_sheet`.

Общие ключи отбора файлов (CSV, книга и XML):

| Ключ | Default | Смысл |
|------|---------|--------|
| `exclude_mask` | — | Маски исключения имён (*, через `,`) поверх `MERGE_SOURCE_EXCLUDE_MASK` |
| `file_pick` | `all` | `all` / `newest_ctime` / `oldest_ctime` / `newest_mtime` / `oldest_mtime` / `lambda` |
| `file_pick_scope` | `all` | `all` — по всему списку; `per_subdir` — в каждом подкаталоге |
| `file_pick_lambda` | — | Лямбда-фильтр (`path`/`имя`/`mtime`/`ctime`/`size`, `<<Переменные.…>>`) |

Дата создания (`*_ctime`): по возможности ОС; на Linux `st_ctime` — смена метаданных (если недоступен — fallback `mtime` + запись в журнал).

Визард: субдиалог по расширению источника (CSV / XML / книга — **разные** формы).

#### Книга (`.ods` / `.xls` / `.xlsx` / `.xlsm`)

```json
{
  "prepare_source_in_memory": true,
  "values_mode": "cached",
  "merged_cells": "top_left",
  "trim_empty": true,
  "convert_types": "in_memory",
  "chunk_rows": 50000
}
```

| Ключ | Default | Смысл |
|------|---------|--------|
| `prepare_source_in_memory` | `false` | Бандл → матрица → `setDataArray` **без** `open_source` (UNO). Синонимы: `подготовка_источника_в_памяти`, `prepare_in_memory`, `source_in_memory`, `матрица_в_памяти` |
| `values_mode` | `cached` | `cached` / `formulas` / `prefer_cached` — кэш, текст формул или кэш иначе формула |
| `merged_cells` | `top_left` | `top_left` (как Calc) / `fill` (размножить значение на всё объединение) |
| `trim_empty` | `true` при флаге | Обрезать пустые края used-range |
| `convert_types` | `in_memory` | `in_memory` / `uno` / `no` / `keep_text` — **ровно одно** место конвертации чисел/дат (не оба) |
| `chunk_rows` | `50000` | Лимит строк накопителя; `0`/отрицательное → 50000 |

**Когда действует** (все сразу): флаг `true` + режим `На один лист` / `На разные листы` + способ `Буфер_по_заголовкам` / `Буфер_по_позиции` + локальный путь книги. Иначе флаг игнорируется (лог «не применимо»): `Копирование листов`, `Вовлечь листы`, `По_API`, `xml_excel_ods`, URL/smb, `эта_книга`.

`.xls`: однократная UNO-конвертация во временный `.xlsx`, далее openpyxl → матрица (temp удаляется).

Визард: субдиалог по расширению источника (CSV, XML и книга — **разные** формы); «Параметры…»; курсор в C/D пишет JSON в эту колонку.

### `Ручной_ввод_в_карту_переменных`

Алиасы: `ручной_ввод`, `manual_variable_input`. B — «смотри в С»; JSON в C.

```json
[{"v":1,"fn":"ручной_ввод_в_карту_переменных","name":"Филиал","value_kind":"scalar","data_type":"text","choices":["Север","Юг"],"prompt":"Филиал","required":true}]
```

Ключ карты: `Имя~ручной_ввод~ручной_ввод` (пишется в журнал сбора). Строка **выше** «Файлы-Источники» — диалог до разворота масок (значение доступно в путях/`<<Переменные.Имя>>` и `file_pick_lambda`). В оркестраторе `collect_pack` prevalidate **не** проверяет наличие таких файлов до диалога. `list` → одна строка через `;`. `choices` — без кавычек столбцов.


## Допустимые значения (выбор из списка)

### `Режим` (B)

| Значение | Смысл |
|----------|-------|
| `На один лист` | Слияние в книгу результата (листы по имени или `Merge_N`) |
| `На разные листы` | Отдельный лист на каждый индекс/имя |

| `Вовлечь листы` | Без копирования: вкладки `эта_книга` / `ThisWorkbook` сразу в постобработку и финал; предварительное удаление листов отключено. Синонимы: `вовлечь_листы`, `involve_sheets`, `passthrough`, `без_копирования`, `только_обработка` |

### Способ переноса (C в строке «Режим» или отдельная строка `Способ_переноса`)

| Значение | Смысл |
|----------|-------|
| `По_API` | Пакеты `getDataArray` / `setDataArray` (по умолчанию) |
| `Буфер_по_заголовкам` | Copy/Paste по столбцам с матчингом заголовков |
| `Буфер_по_позиции` | Copy/Paste прямоугольника без матчинга |
| `xml_excel_ods` | Прямая запись через файлы (.xlsx / .xlsm / .xls / .ods) |

| Режим сбора | Способ переноса |
|-------------|-----------------|
| На один / разные листы | Любой из таблицы |
| **Копирование листов** | Обычно `По_API`; **`xml_excel_ods`** — через `Способ_переноса` / C «Режим» |
| **Вовлечь листы** | Не используется (переноса нет; `xml_excel_ods` игнорируется с предупреждением) |

Подробно: [17_POSTPROCESS_XML.md](17_POSTPROCESS_XML.md).

### `MERGE_XML_CONVERT_TO_NUMBERS` / `MERGE_XML_DATETIME_FORMATS`

Только при **`Способ_переноса` = `xml_excel_ods`** (и тот же разбор дат при UNO-конверте чисел/дат).

| Параметр | По умолчанию | Смысл |
|----------|--------------|-------|
| `MERGE_XML_CONVERT_TO_NUMBERS` | **Да** | Текст «700», «1 000 000,00», «02.02.1976» → число/дата при direct-чтении или проходе по copy-листам |
| `MERGE_XML_DATETIME_FORMATS` | *(пусто)* | Список форматов через `,` или `;`. Пусто — базовый набор (DD.MM.YYYY, ISO, …) + локаль ru/en-US |

Кириллические алиасы в списке форматов: `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`, …

**Month-only** (ячейка целиком `Январь` / `янв.` / `January`): шаблон `день.MMMM.год`, не голый `MMMM`:

| Часть | Значения |
|-------|----------|
| День | `01` / `FIRST_DAY` / `LAST_DAY` |
| Месяц | `MMMM` / `ММММ` / `MMM` / `МММ` (из ячейки) |
| Год | `YEAR` (текущий) / `NEXT_YEAR` / литерал `2027` |

Примеры: `FIRST_DAY.MMMM.YEAR`, `LAST_DAY.MMMM.NEXT_YEAR`, `01.ММММ.2027`.

Тот же синтаксис — поле `parse_formats` у `формат_даты` / `формат_столбцы` (при `convert_existing`).

### `Постобработка_xml`

Только при **`Способ_переноса` = `xml_excel_ods`**. Колонка **C** — JSON-массив блоков (как у RANGE/ROW). Выполняется **в файле** на диске (фаза A); часть ключей — UNO-пилот в фазе B. Полный список ключей и пайплайн: [17_POSTPROCESS_XML.md](17_POSTPROCESS_XML.md).

### Лямбды в JSON-параметрах

Используются, в частности, в:

- `замена_значений` → `row_filter`, `match_expr`;
- `текстовые_операции` / `нормализация_текста` → `row_filter_lambda` у каждого `op`;
- `Листы_не_удалять` → `filter` в JSON;
- `столбец_по_лямбде` → `expr`, `new_column_expr`, `sheet_expr`.

Для строковых лямбд стандартный sugar:

- `rows("Колонка")` — текущая строка;
- `rows("Колонка")[-1]` — предыдущая строка листа;
- `upd_rows("Колонка")` — последняя уже обработанная строка выше;
- `upd_rows_seen("Колонка", value)` — было ли такое значение выше;
- `upd_rows_count("Колонка", value)`, `upd_rows_len()` — статистика по уже обработанным строкам.

Примеры:

```json
{"row_filter":"lambda rows: str(rows(\"Отдел\") or \"\").strip() != \"\""}
{"row_filter_lambda":"lambda rows: not upd_rows_seen(\"ИНН\", rows(\"ИНН\"))"}
{"match_expr":"lambda rows: idx == 0 or text != upd_rows(\"Комментарий\")"}
{"fn":"столбец_по_лямбде","new_column":"Первый_ИНН","expr":"lambda rows: rows(\"ИНН\") if not upd_rows_seen(\"ИНН\", rows(\"ИНН\")) else \"\"","position":"_конец_","on_error":"empty","result_type":"auto","output_policy":"new"}
```

Для `столбец_по_лямбде`:

- `expr` — обязательная лямбда `lambda rows: ...`, возвращает значение новой/целевой ячейки;
- `new_column_expr` — опциональная лямбда `lambda sheet, headers: ...`, вычисляет заголовок;
- `sheet_expr` — опциональная лямбда `lambda sheets: ...`, выбирает один или несколько листов;
- `on_error` — что делать при ошибке в строке: `empty`, `keep`, `fail`;
- `result_type` — приведение результата: `auto`, `text`, `number`;
- `output_policy` — если столбец уже найден: `new` или `replace`.

Практические примеры `rows` / `upd_rows`:

```python
lambda rows: rows("Фамилия") + " " + rows("Имя")
lambda rows: rows("Статус") != rows("Статус")[-1]
lambda rows: not upd_rows_seen("ИНН", rows("ИНН"))
lambda rows: upd_rows_len() == 0 or rows("Сумма") != upd_rows("Сумма")
lambda rows: rows("Сумма") if upd_rows_len() == 0 else rows("Сумма") - upd_rows("Сумма")
```

## Форматы текстовых параметров

### `Файлы-Источники`

- Абсолютный или относительный путь; маски `*.xlsx`, `отчёт_*`.
- Относительно каталога книги с листом параметров.
- В пути/маске допускается `<<Переменные.имя>>` из runtime-карты (подстановка до разворота glob). Для ручного ввода строка `Ручной_ввод_в_карту_переменных` должна быть **выше** «Файлы-Источники».
- Маркер текущей книги — сбор / вовлечение без повторного открытия файла. Допустимы формы: `Эта_Книга`, `эта_книга`, `эта-книга`, `этакнига`, `ThisWorkbook`, `This_Workbook`, `current` и т.п. (без учёта регистра, пробелов, `_`, `-`).

### `Листы`

- `Все` — все листы источника.
- Имя, шаблон (`Отчет*`, `*2024`), номер (`1`, `2`).
- В одной ячейке — список через `,` или `;` (без смешения типов в одной ячейке).

### `Столбцы`

- `Все` или пусто — все столбцы.
- Номер (1 = A), буква, имя заголовка, шаблон (`Сумма*`).

### `Ячейка_В_Столбец`

```
индекс_столбца:индекс_строки -> имя_столбца_в_результате
```

Пример: `A:1 -> Филиал`. Лист источника для строки — из `#Путь` (часть после `#`).

**JSON** (колонка C, визард «Параметры…»):

```json
[{"col":"A","row":1,"column":"Квартал","sheet":"Merge","source_sheet":"Отчет*"}]
```

| Поле | Назначение |
|------|------------|
| `col` / `row` | Адрес ячейки на листе источника (1-based) |
| `column` | Имя нового столбца в результате |
| `sheet` | Лист результата (`Merge`, `Merge_*`); пусто — все листы |
| `source_sheet` | Фильтр листа источника (`Отчет*`, список через `,`); пусто — все листы |

### `Пропуск_строк_источника`

| Режим | Формат | Поведение |
|-------|--------|-----------|
| Столбцы | `1,A,ФИО` | Строка копируется, если хотя бы один столбец не пуст |
| Формула | `E{row_id}+F{row_id}=0` | **ИСТИНА** = строка пустая → не копировать |

### `удаление_верхних_строк`

**Предпочтительно JSON в C** (кнопка «Параметры…» в визарде):

```json
[{"v":1,"fn":"удаление_верхних_строк","rules":[{"sheet":"1_Заказы","rows":5}]}]
```

**Legacy в B/C/D:** `ИмяЛиста -> N` (разделители `->`, `=`, `\`; несколько правил через `,` или `;`).

## ВПР (JSON в C; legacy B–F)

Строка в A: `ВПР` (или `VLookup`). Несколько строк — несколько join-операций (между шагами «Постобработка_Диапазон», до «Постобработка_Строка»).

**Рекомендуется JSON в C** (см. [13_JSON_PARAMS.md](13_JSON_PARAMS.md) § ВПР):

| Поле | Смысл |
|------|--------|
| `left` / `right` | `sheet` + опционально `range` (A1); иначе used-area; header = первая строка `range` |
| `join_type` | `left` (по умолчанию), `inner` или `full` |
| `multi_match` | `all` (по умолчанию), `first` или `last` |
| `extract_columns` | Колонки в левую из правой |
| `extract_columns_right` | При `full` — колонки в правую из левой |
| ключи / цвет / not_found / дубли / мульти / trim / suffix | как в визарде |

Legacy B–F (если ещё записан):

| Колонка | Поле | Формат |
|---------|------|--------|
| **B** | Левая таблица | `Лист\|Начало_Строка\|Начало_Столбец\|Строка_Заголовков` |
| **C** | Правая таблица | тот же формат |
| **D** | Ключи сравнения | столбцы через `,` или `Ключ_левый: … # Ключ_правый: …` |
| **E** | Столбцы для извлечения | имена столбцов правой таблицы |
| **F** | Опции | цвет, дубли, мульти, заполнитель «не найдено» |

Опции: `_ПУСТО_` / `_EMPTY_` — пустая ячейка вместо `#Н/Д`; цвет `Нет` — без подсветки. **`range`, `full`, `inner`, `multi_match` — только JSON.**

Альтернатива: JSON в C — `[{"v":1,"fn":"впр",…}]`.

## объединить_листы_в_один / разделить_листы (отдельные строки pipeline)

Как **ВПР**: это **не** ключ B в «Постобработка_Диапазон» / «Финальная_обработка», а имя параметра в колонке **A**.

| Колонка | `объединить_листы_в_один` | `разделить_листы` |
|---------|---------------------------|-------------------|
| **A** | `объединить_листы_в_один` | `разделить_листы` |
| **B** | обычно пусто | обычно пусто |
| **C** | только JSON | только JSON |

### объединить_листы_в_один

```json
[{"v":1,"fn":"объединить_листы_в_один","sheets":["Отчет_Q1","Отчет_Q2","Отчет_Q3"],"dest_sheet":"Отчет_Q123","header_row":1,"with_formatting":false}]
```

| Поле | Смысл |
|------|--------|
| `sheets` | Листы-источники в книге результата |
| `dest_sheet` | Лист-приёмник |
| `header_row` | Строка заголовков на результате (1-based); пусто — авто |
| `with_formatting` | `true` — копировать оформление столбцов |

### разделить_листы

Реализация: `libre_macros_split_lib.py`. В pipeline: `kind=split_sheets`.

| `run_phase` | Когда |
|-------------|--------|
| `after_collect` | После первичного сбора, до оформления/pipeline |
| `after_postprocess` | **По умолчанию.** В pipeline (порядок по строке на листе) |
| `after_final` | После `Финальная_обработка`; **единственный** допустимый при `xml_excel_ods` |

```json
[{
  "v": 1,
  "fn": "разделить_листы",
  "run_phase": "after_postprocess",
  "source": {"book": "эта_книга", "sheet": "Общий"},
  "split_books": ["Организация"],
  "split_sheets": ["Подразделение"],
  "header_row": 1,
  "pre_sort": true,
  "book_template": "эта_книга",
  "sheet_template": "[Подразделение]",
  "split_mode": "copy_range",
  "copy_header": true,
  "overwrite_sheets": true
}]
```

Поля: `source.sheet`, `split_books` / `split_sheets`, `book_template` / `sheet_template` (подстановки `[Поле]`), `split_mode`, `paste_formats`, `create_folders`, `append_if_exists`, `save_immediately`. Источник книги — только **эта_книга**. Подробные поля — [13_JSON_PARAMS.md](13_JSON_PARAMS.md).

В `processing_pipeline`: `kind` = `merge_sheets` / `split_sheets` (segment-splitter вместе с `vlookup`). Legacy: те же `fn` могут встретиться как B под «Финальная_обработка»; рекомендуемый UX — отдельная строка A.

## Порядок выполнения на листе результата

```
копирование данных
  → Ячейка_В_Столбец
  → удаление_верхних_строк / автообрезка (copy)
  → встроенное оформление (автофильтр / закрепление — из флагов листа)
  → pipeline range-фаза (сверху вниз по листу параметров):
       блоки Постобработка_Диапазон
       ↔ ВПР / объединить_листы_в_один / разделить_листы (splitters)
       ↔ следующие блоки Диапазон
  → Постобработка_Строка (сверху вниз; только после всех range/splitter)
```

После всех листов: **Финальная_обработка** → диалог завершения.
