# Руководство по функциям постобработки collect_workbooks

**Версия макроса**: **3.10.523** (`macro-lib/version.txt`). Постобработка настраивается на листе группы `Параметры_Объединения*` (см. [04_DATA_COLLECTION.md](04_DATA_COLLECTION.md); при `collect_pack` — на каждом листе плана).

### Формат параметров (колонка C)

**Только JSON** — массив объектов `[{"v":1,"fn":"…",…}]`. Текстовая legacy-кодировка (`|`, `->`, `;` между блоками) **удалена**.

- Справочник полей: [13_JSON_PARAMS.md](13_JSON_PARAMS.md)
- Кодек: `libre_macros_param_codec.py`
- Ключ **`раскрасить`** → **`раскрасить_блоки`**
- Алиас **`условное_форматирование`** → **`подсветка_по_порогу`**
- `раскрасить_блоки` заливает **непрерывные блоки** одинакового ключа (не построчно по ячейкам)

### Режим `xml_excel_ods`

При **`Способ_переноса` = `xml_excel_ods`** часть шагов — в файле (`Постобработка_xml`), UNO Диапазон/Строка/финал — **после показа** книги. Подробно: [17_POSTPROCESS_XML.md](17_POSTPROCESS_XML.md).

### Отдельные параметры pipeline (не RANGE)

| A (имя параметра) | kind | C |
|-------------------|------|---|
| `ВПР` | `vlookup` | опции B–F или JSON |
| `объединить_листы_в_один` | `merge_sheets` | JSON |
| `разделить_листы` | `split_sheets` | JSON (`run_phase`, `source`, `split_*`, шаблоны) |

Это **не** ключи колонки B в «Постобработка_Диапазон» / «Финальная_обработка». Поля JSON — [13_JSON_PARAMS.md](13_JSON_PARAMS.md), реестр — [15_PARAM_REFERENCE.md](15_PARAM_REFERENCE.md).

Пример на листе параметров:

```
Постобработка_Диапазон    тонкая_сетка    [{"v":1,"fn":"тонкая_сетка"}]
Постобработка_Диапазон    градиент        [{"v":1,"fn":"градиент","marker":"Сумма_руб","color_min":"зеленый","color_max":"красный","whole_row":true}]
объединить_листы_в_один                    [{"v":1,"fn":"объединить_листы_в_один","sheets":["Отчет_Q1","Отчет_Q2"],"dest_sheet":"Отчет_Q12","header_row":1}]
```

## Общая концепция

На каждом листе результата макрос выполняет этапы в таком порядке:

1. **Сбор данных** — копирование из источников **или** вовлечение существующих вкладок (`Режим = Вовлечь листы`).
2. **«Ячейка_В_Столбец»** (опционально; не для вовлечения / COPY).
3. **Встроенное форматирование** — для **новых** листов сбора; preexisting / вовлечённые — без оформления «по умолчанию» и без UNO текст→число.
4. **Pipeline** — `Постобработка_Диапазон` ↔ splitters (`ВПР`, `объединить_листы_в_один`, `разделить_листы`) ↔ `Постобработка_Строка`.
5. **`Финальная_обработка`** (при вовлечении — только вовлечённые листы).

Далее в этом руководстве — в основном ключи B секций Диапазон/Строка/Финал. Splitters — в [15_PARAM_REFERENCE.md](15_PARAM_REFERENCE.md).

### Параметр «Ячейка_В_Столбец»

Отдельный параметр на активном листе группы `Параметры_Объединения*` (имя в колонке A, значения в B, C, D…). Нужен, чтобы **до** постобработки появился столбец с меткой из источника — его можно указать в `отступ`, `условное_форматирование`, `формат_столбцы` и т.д.

**Формат значения:**

```
индекс_столбца:индекс_строки -> имя_столбца_в_результате
```

**Пример** (три файла-источника, два правила):

```
Ячейка_В_Столбец    A:1 -> Филиал
```

(В тестовых источниках строка 1 — метаданные, строка 2 — заголовки; в **A1** — имя филиала, подтягивается в столбец «Филиал» результата.)

- Строк с одинаковым именем в A может быть несколько — выполняются сверху вниз.
- `индекс_столбца` — номер (1 = A) или буквы; `индекс_строки` — с 1 (как в Calc).
- Лист источника **не задаётся** в правиле — берётся из `#Путь` каждой строки результата (часть после `#`).
- Для файла N: своё значение в столбце (B+N) → иначе B → иначе пропуск.
- Столбец в результате добавляется **в конец** листа, если заголовка ещё нет.
- Значение пишется в строки, где в `#Путь` совпадает идентификатор файла (часть до `#`).

Подробнее: шапка `collect_workbooks.py`, `04_DATA_COLLECTION.md` §6.1.

### Два типа колбэков

| Тип | Когда вызывается | Аргументы | Лист параметров |
|-----|------------------|-----------|-----------------|
| **RANGE** | **Один раз** после форматирования всего диапазона данных | `(doc, sheet, data_range, header_row_range)` | `Постобработка_Диапазон` |
| **ROW** | **Для каждой строки** данных | `(doc, sheet, data_row_range, header_row_range, row_index)` | `Постобработка_Строка` |

### Подключение через лист параметров

На активном листе `Параметры_Объединения*` создайте секции:

```

Постобработка_Диапазон    зебра_диапазон  [{"v":1,"fn":"зебра_диапазон","roles":{"header":{"bg":"excel_header","fg":"белый"},"even":{"bg":"голубой","fg":"синий"},"odd":{"bg":"белый","fg":"синий"}}}]
Постобработка_Диапазон    формат_столбцы  [{"v":1,"fn":"формат_столбцы","items":[{"column":"Сумма","format":"# ##0,00"}]}]

Постобработка_Диапазон    перенос         [{"v":1,"fn":"перенос","wrap":true}]
Постобработка_Строка      преобразовать_числа    [{"v":1,"fn":"преобразовать_числа","columns":["Сумма","Количество"]}]
```

## Параметры колбэков

### Общие для всех колбэков

| Параметр | Тип | Описание |
|----------|-----|----------|
| `doc` | `XSpreadsheetDocument` | Книга результата (объект LibreOffice UNO) |
| `sheet` | `XSpreadsheet` | Лист с результатами слияния |

### Специфичные для RANGE

| Параметр | Тип | Описание |
|----------|-----|----------|
| `data_range` | `XCellRange` | Диапазон **всех данных** без заголовка (строки 1…N) |
| `header_row_range` | `XCellRange` | Строка заголовков (обычно строка 0) |

### Специфичные для ROW

| Параметр | Тип | Описание |
|----------|-----|----------|
| `data_row_range` | `XCellRange` | **Одна строка** данных (текущая обрабатываемая) |
| `header_row_range` | `XCellRange` | Строка заголовков |
| `row_index` | `int` | Номер строки в листе (0-based) |

### Работа с ячейками (UNO)

```python
# Получение адреса диапазона
addr = data_range.getRangeAddress()
sc, sr, ec, er = addr.StartColumn, addr.StartRow, addr.EndColumn, addr.EndRow

# Доступ к ячейкам
single_cell = sheet.getCellByPosition(col, row)
value = single_cell.Value          # Числовое значение
string = single_cell.String        # Текст
formula = single_cell.Formula      # Формула

# Форматирование ячейки
single_cell.CellBackColor = 0xRRGGBB    # Фон (RGB)
single_cell.CharColor2 = 0xRRGGBB        # Цвет текста (CharColor2 надёжнее CharColor)
single_cell.CharWeight = 150             # Жирность (150 = bold)
single_cell.HoriJustify = 2              # 0=left, 1=center, 2=right
single_cell.VertJustify = 2              # 0=top, 1=middle, 2=bottom
single_cell.IsTextWrapped = True         # Перенос по словам
single_cell.NumberFormat = fmt_key       # Числовой формат
```

## Настройка через лист параметров

Перед цепочкой `merge_pp_*` на каждом листе результата выполняется **встроенное оформление**: шрифт **PT Sans**, размер **`MERGE_FONT_SIZE` pt** (по умолчанию **11**) для заголовка и данных, ширина/высота столбцов, автофильтр и закрепление заголовка. Подробнее — [04_DATA_COLLECTION.md](04_DATA_COLLECTION.md).

Строки постобработки можно добавлять вручную или через визард **[param_wizard](06_PARAM_WIZARD.md)** (`set_merge_param` → «Постобработка_Диапазон» / «Постобработка_Строка»). Пресеты наборов параметров — только во вкладке «Пресеты» визарда.

### Формат строки на активном листе `Параметры_Объединения*`

| Колонка | Содержимое |
|---------|------------|
| **A** | Ключ секции: `Постобработка_Диапазон` или `Постобработка_Строка` |
| **B** | Псевдоним функции (см. таблицы ниже) или `файл.py#функция` |
| **C** | Дополнительные параметры (опционально); для **`зебра_диапазон`** — строка `роль:заливка/шрифт` через `;` или `,` (см. ниже) |

### Функция `зебра_диапазон` (RANGE и финальная обработка)

Ключ **`зебра_диапазон`** в секции `Постобработка_Диапазон` и в `Финальная_обработка`. Колонка **C** задаёт оформление **заголовка**, **чётных** и **нечётных** строк данных.

**Синтаксис колонки C:** члены через **`;`** или **`,`**, в каждом — **`роль:заливка/шрифт`**. Регистр не важен. Запятая внутри RGB (`240,240,240`) и в `заливка/шрифт` не разбивает строку — только перед следующей ролью.

| Роль (англ. / рус.) | Что красится |
|---------------------|--------------|
| `header` / `заголовок` | Строка заголовков таблицы |
| `even` / `четные`, `чётные` | **2-я, 4-я, 6-я…** строка **данных** |
| `odd` / `нечетные`, `нечётные` | **1-я, 3-я, 5-я…** строка **данных** |

**Чётность** — порядковый номер строки **внутри данных** (счёт с 1 под заголовком): 1-я строка данных = нечётная (`odd`), 2-я = чётная (`even`). Строка заголовков в нумерацию не входит.

Пример (заголовок на строке 1 Calc):

| Строка Calc | Строка данных | Роль |
|-------------|---------------|------|
| 1 | заголовок | `header:` |
| 2 | 1-я | `odd` / `нечетные` |
| 3 | 2-я | `even` / `четные` |
| 4 | 3-я | `odd` |
| 5 | 4-я | `even` |

Членов может быть любое число; неуказанные роли не меняются. Порядок членов не важен.

**Заливка/шрифт** в правой части:
| Фрагмент | Значение |
|----------|----------|
| `синий/белый` | синий фон, белый текст |
| `серый/` | только заливка |
| `/черный` | только шрифт |
| `240,240,240` | RGB как заливка |
| `#F2F2F2` | hex как заливка |

**Имена цветов:** `белый`, `черный`, `серый`, **`светлыйсерый`** (#F2F2F2), `синий`, **`темныйсиний`** (#1F4E79), `голубой`, `красный`, `желтый`, `зеленый`, `оранжевый`, `фиолетовый`, `бежевый`, `кремовый`, `navy`, `excel_header` (то же, что `темныйсиний`; и англ. аналоги).

**`темныйсиний`** / **`excel_header`** — **#1F4E79**. **`светлыйсерый`** — **#F2F2F2** (классическая зебра). Пример: `header:темныйсиний/белый; четные:светлыйсерый/черный`.

**По умолчанию** (колонка C пуста): 1-я, 3-я… строка данных (`odd`) — светло-серый фон; 2-я, 4-я… — прозрачный; заголовок не трогается.

**Финальная обработка:** в колонке C можно указать `имя_листа|роль:заливка/шрифт; …` — зебра применяется к перечисленным листам книги.

**RANGE vs row-код:** RANGE (`зебра_диапазон`) быстрее (один проход). Функция `merge_pp_row_zebra_stripes` доступна только через `_MERGE_CODE_POSTPROCESS_ROW` в коде, не через ключ листа.

### Примеры записей в колонке C

| Функция | Колонка B | Колонка C | Описание |
|---------|-----------|-----------|----------|
| Зебра | `зебра_диапазон` | *(пусто)* | Только чётные строки — серые |
| Зебра | `зебра_диапазон` | `even:серый/` | Явно чётные — серый фон |
| Зебра | `зебра_диапазон` | `header:excel_header/белый, even:голубой/синий, odd:белый/синий` | Как таблица Excel (разделитель `,`) |
| Зебра | `зебра_диапазон` | `Заголовок:синий/белый; Чётные:голубой/; Нечётные:/черный` | Русские роли, любой регистр |
| Зебра | `зебра_диапазон` | `even:синий/белый` | Только чётные строки данных |
| Формат столбцов | `формат_столбцы` | `Сумма,# ##0,00` | Формат денег для столбца "Сумма" |
| Формат столбцов | `формат_столбцы` | `3,0,00%` | Формат процентов для столбца 3 (C) |
| Формат даты | `формат_даты` | `дата,время,deadline` | Маркеры для поиска столбцов |

> **Примечание про индексы**: Во всех функциях, где используются числовые индексы столбцов или листов (например, `формат_столбцы,3` или фильтр `Листы: 1,2`), применяется **1-based нумерация** как в интерфейсе Calc: 1 = первая колонка (A), 2 = вторая (B), и т.д. Внутри кода они автоматически конвертируются в 0-based.
| Условное форматирование | `условное_форматирование` | `итог,1000` | Подсветка если значение > 1000 |
| Конкатенация столбцов | `конкатенация_столбцов` | `Полный_Код,\|,1,3` | Новый столбец из значений A и C через `\|` |
| Применить формулу | `применить_формулу` | `Итого=E{row_id}+F{row_id}` | Столбец с формулами Calc, протягивание вниз |
| Пропуск пустых строк | `пропуск_пустых_строк` | `1,A,ФИО` или `E{row_id}+F{row_id}=0` | ИСТИНА по формуле = строка пустая → удалить |
| Удалить столбцы | `удалить_столбцы` | `#Путь,ФИО` | Удалить столбцы с этими подстроками |
| Преобразовать числа | `преобразовать_числа` | `Сумма,Количество` | Только указанные столбцы |
| Цвет текста по значению | `цвет_текста_по_значению` | `статус` | Столбец-источник для цвета |
| Стиль печати | `стиль_печати` | `landscape,1` | Альбомная, вписать в 1 страницу |

## Функции постобработки диапазона (RANGE)

Вызваются **один раз** для всего диапазона данных. Работают быстрее row-функций.

### 1. `сетка` — merge_pp_range_grid_borders
**Назначение:** Универсальная сетка по ячейкам данных и заголовка.

**Rest из C:** `толщина/цвет` (как `заливка/шрифт` у «зебра_диапазон») или по листам:

| Колонка C | Эффект |
|-----------|--------|
| *(пусто)* | тонкая (15), серый `#666666` — **все листы** |
| `толстая/` | толстая (35), серый по умолчанию — все листы |
| `/темныйсиний` | тонкая, цвет `темныйсиний` |
| `толстая/серый` | толстая, именованный цвет |
| `25/#CCCCCC` | 25 (1/100 мм), hex-цвет |
| `Сводная \| 25/#CCCCCC` | только лист «Сводная» |
| `Сводная \| 25/#CCCCCC ; Orders : толстая/синий` | несколько листов (блоки через `;` или `,`) |
| `Сводная / 25/#CCCCCC` | то же (разделитель лист/параметры: `\|`, `:` или `/`) |

**Толщина:** `тонкая`/`thin` (15), `толстая`/`thick` (35), `средняя`/`medium` (25) или число (1/100 мм).  
**Цвет:** те же имена, что у «зебра_диапазон» (`серый`, `темныйсиний`, `excel_header`, hex…).

**Когда вызывать:** В начале цепочки; до «зебры». Не вместе с `тонкая_сетка`/`толстая_сетка`.

**Финальная обработка:** ключ `сетка`, C — как выше (по всей книге).

---

### 2. `тонкая_сетка` — merge_pp_range_thin_grid_borders
**Назначение:** Тонкая серая сетка (алиас `сетка` с пустым C). Ширина 15, цвет `#666666`, с заголовком.

**Rest из C (JSON):**

```json
[{"v":1,"fn":"тонкая_сетка"}]
[{"v":1,"fn":"тонкая_сетка","sheets":["Отчет_январь","Сводка"]}]
```

| Колонка C | Эффект |
|-----------|--------|
| *(пусто)* / без `sheets` | все листы |
| `"sheets":["Отчет_январь"]` | только указанные листы |

Legacy (без JSON): имена через `,` / `;`. JSON с `sheets` обрабатывается и в UNO-pipeline (фильтр по листу через `param_decode`).

**Финальная обработка:** ключ `тонкая_сетка`, C — то же.

---

### 3. `толстая_сетка` — merge_pp_range_thick_grid_borders
**Назначение:** Толстая серая сетка (ширина 35, цвет `#333333`, с заголовком).

**Rest из C:** как у `тонкая_сетка` — JSON `sheets` или legacy-список имён (пусто = все).

```json
[{"v":1,"fn":"толстая_сетка","sheets":["Отчет_январь"]}]
```

**Финальная обработка:** ключ `толстая_сетка`, C — то же.

---

### 4. `заголовок_плюс_высота` — merge_pp_range_header_row_height_pad
**Назначение:** Увеличить высоту строки заголовков и выровнять ячейки заголовка (горизонтально и вертикально).

**Rest из C** (одна строка; та же нотация в `Финальная_обработка`):

| Формат | Поведение |
|--------|-----------|
| *(пусто)* | Все листы: **+12,7 мм** (как прежние 0,5″), выравнивание `center/center` |
| `+13 center-center` | Все листы с указанными параметрами |
| `лист \| +13 center/bottom` | Только указанный лист |
| `Сводная \| +13 center-center ; 2 \| +8 left-top` | Несколько листов (блоки через `;` или `,`) |
| `Все \| +13 center-center` | Все листы с параметрами блока |

- **Лист:** имя, 1-based индекс (`1`, `2`…) или `Все`.
- **Разделитель лист/параметры:** `|` или `:`.
- **Высота:** число в **миллиметрах** (`+13`, `13`, `12,7`); суффикс `мм`/`mm` необязателен. Старый формат `+0,5″` по-прежнему понимается (перевод в мм).
- **Выравнивание:** `left` / `center` / `right` и `top` / `center` / `bottom`; русские: **лево**, **центр**, **право**, **верх**, **низ**; сокращения: **Л**, **Ц**, **П**, **В**, **Н**. Между горизонталью и вертикалью — `-`, `_` или `/`.

**Примеры:**
| Колонка B | Колонка C |
|-----------|-----------|
| `заголовок_плюс_высота` | *(пусто)* |
| `заголовок_плюс_высота` | `+8 center/bottom` |
| `заголовок_плюс_высота` | `Сводная \| +13 center-center ; Orders: +8 left-top` |

**Что меняет:**
- Высоту строки заголовка (`OptimalHeight` снимается в `_lm_pp_pad_row_height`);
- `HoriJustify` и `VertJustify` для каждой ячейки строки заголовка.

### 12. `сортировка` — merge_pp_range_sort_data
**Назначение:** Отсортировать строки данных диапазона (строка заголовков не меняется).

### 11. `формат_даты` — merge_pp_range_format_date_columns
**Назначение:** Применить формат даты к столбцам по маркерам/именам; опционально конвертировать текст → дата.

**JSON в C:**

```json
[{
  "v": 1,
  "fn": "формат_даты",
  "format": "DD.MM.YYYY",
  "columns": ["'Дата'"],
  "markers": ["дата", "время"],
  "convert_existing": true,
  "parse_formats": "FIRST_DAY.MMMM.YEAR, DD.MM.YYYY"
}]
```

| Поле | Смысл |
|------|--------|
| `format` | NumberFormat Calc (отображение); пусто — из глобальных настроек |
| `columns` / `markers` | отбор столбцов (`columns_pick`); пустые markers → `дата`, `date`, `время`, `time` |
| `convert_existing` | текст в ячейках → дата перед форматом |
| `parse_formats` | шаблоны разбора текста (как `MERGE_XML_DATETIME_FORMATS`), в т.ч. month-only |

**Month-only** (ячейка `Январь` / `янв.` / `January`): в `parse_formats` или в `MERGE_XML_DATETIME_FORMATS` указать полный шаблон, не голый `MMMM`:

- `FIRST_DAY.MMMM.YEAR` → 01.<месяц>.текущий_год  
- `LAST_DAY.MMMM.NEXT_YEAR` → последний день месяца, следующий год  
- `01.ММММ.2027` → фиксированный день и год  

Если `parse_formats` пуст при convert — берётся bound `MERGE_XML_DATETIME_FORMATS` (если был при сборе).

**Примеры:**
| Колонка B | Колонка C |
|-----------|-----------|
| `формат_даты` | JSON с `markers` / `columns` |
| `формат_даты` | + `convert_existing` + `parse_formats` для «Январь» → дата |

### 17. `конкатенация_столбцов` — merge_pp_range_concat_columns
**Назначение:** Добавить столбец с заданным именем; в каждой строке данных — склейка значений указанных столбцов через разделитель.

**Назначение:** Добавить столбец с формулами Calc: шаблон в первой строке данных, затем заполнение вниз с автосмещением ссылок по строкам.

**Rest из C:** `Имя_Столбца=Текст_Формулы` *(или старый формат `Имя_Столбца,Текст_Формулы`)*

- Плейсхолдер **`{row_id}`** или **`${row_id}`** — номер **первой строки данных** в нотации Calc (**1-based**, без учёта заголовка).
- Если заголовок на строке 2, первая строка данных — строка 3 → `{row_id}` = `3`, формула `E{row_id}+F{row_id}` станет `=E3+F3`.
- Запятые внутри формулы (`SUM(E{row_id},F{row_id})`) сохраняются.
- Знак `=` в шаблоне можно не писать — макрос добавит сам.

**Алгоритм:** клон формата (заголовок + данные) → заголовок → формула в первой ячейке данных → **Copy + спецвставка `pasteCellRange` (только `FORMULA`)** вниз (Calc смещает строки; форматы не затираются) → повторный клон формата данных и заголовка → `OptimalWidth`.

**Примеры:**
| Колонка B | Колонка C | Описание |
|-----------|-----------|----------|
| `применить_формулу` | `Итого=E{row_id}+F{row_id}` | Сумма столбцов E и F по строкам |
| `применить_формулу` | `Разница=E{row_id}-F{row_id}` | Разность |
| `применить_формулу` | `Сумма=SUM(E{row_id},F{row_id})` | Функция SUM с запятой |

**Когда вызывать:** После сбора данных; до удаления столбцов, на которые ссылается формула.

### 19. `пропуск_пустых_строк` — merge_pp_range_skip_empty_rows
**Назначение:** Удалить **пустые** строки данных на **листе результата** по тем же правилам, что параметр **«Пропуск_строк_источника»** при сборе, но **после** копирования (постобработка диапазона).

**Семантика «пустая строка»:**

- **Столбцы** — пустая, если во **всех** перечисленных столбцах нет значения.
- **Формула** — вы задаёте критерий «эта строка пустая»: формула должна быть **ИСТИНА (True)** именно для пустых строк; такие строки **удаляются**. Если формула **ЛОЖЬ** — строка остаётся.

**Rest из C:**

| Режим | Пример C | Поведение |
|-------|----------|-----------|
| Столбцы | `1,A,ФИО` | Удалить, если во всех перечисленных столбцах пусто |
| Формула | `E{row_id}+F{row_id}=0` | ИСТИНА, когда сумма E+F равна нулю → строка пустая → удаляется. Временный столбец Calc справа от `data_range`, пересчёт, удаление строк с ИСТИНА, столбец убирается |

**Примеры:**
| Колонка B | Колонка C | Описание |
|-----------|-----------|----------|
| `пропуск_пустых_строк` | `1,3` | Пустая, если нет данных в столбцах A и C |
| `пропуск_пустых_строк` | `Сумма,Количество` | Пустая, если пусты оба столбца по заголовкам |
| `пропуск_пустых_строк` | `E{row_id}+F{row_id}=0` | Пустая по формуле: нулевая (или пустая) сумма E и F |

**Когда вызывать:** После сбора и «Ячейка_В_Столбец»; **до** row-постобработки (зебра) и **до** `удалить_столбцы`, если столбцы условия ещё нужны.

**Отличие от «Пропуск_строк_источника»:** тот параметр фильтрует при **копировании** из файла; `пропуск_пустых_строк` работает на **уже собранном** листе (в т.ч. после объединения нескольких источников).

### 22. `группировка_по_столбцу` — merge_pp_range_group_by_column
**Назначение:** Промежуточные итоги при смене значения в столбце (как Data → Subtotals): формулы `=ИТОГ(…)` / SUBTOTAL, подписи в столбце группировки (`Отдел Количество`, `Отдел Сумма`), опционально outline и общие итоги внизу.

**JSON в C (один уровень):**

```json
[{"v":1,"fn":"группировка_по_столбцу","marker":"'Отдел'","agg_fn":"sum","agg_columns":["'Сумма_руб'"],"sort":true,"outline":true,"sheet":"МСУЗ"}]
```

| Поле | Описание |
|------|----------|
| `marker` | Столбец группировки (`columns_pick`; имена в `'…'` = точное совпадение заголовка) |
| `agg_fn` | Функция итога: `sum`, `count`, `average`, `max`, `min`, `product` |
| `agg_columns` | Столбцы, в которые пишутся формулы итога |
| `aggs` | Несколько уровней в одном блоке: `[{"fn":"count","columns":["'Сумма_руб'"]},{"fn":"sum","columns":["'Сумма_руб'"]}]` |
| `sort` | Сортировка по `marker` перед группировкой (по умолчанию `true`) |
| `outline` | Сворачиваемые группы строк (по умолчанию `true`) |
| `grand_total` | Общие итоги внизу (по умолчанию `true`) |
| `sheet` | Лист результата (опционально) |

**Склейка подряд идущих шагов (важно):**

Если на листе параметров подряд идут две (и более) строки `Постобработка_Диапазон` / `группировка_по_столбцу` с **одним и тем же** `marker` и `sheet`, они **склеиваются в один проход** с несколькими уровнями итогов (`aggs[]`). В журнале: `склеено уровней=N`, у исполнителя `agg=count+sum`.

Пример двух строк параметров (count + sum по одному столбцу):

```
Постобработка_Диапазон    группировка_по_столбцу    [{"v":1,"fn":"группировка_по_столбцу","marker":"'Отдел'","sheet":"МСУЗ","agg_fn":"count","agg_columns":["'Сумма_руб'"],"sort":true,"outline":true}]
Постобработка_Диапазон    группировка_по_столбцу    [{"v":1,"fn":"группировка_по_столбцу","marker":"'Отдел'","sheet":"МСУЗ","agg_fn":"sum","agg_columns":["'Сумма_руб'"],"sort":true,"outline":true}]
```

Эквивалент одной строкой с `aggs`:

```json
[{"v":1,"fn":"группировка_по_столбцу","marker":"'Отдел'","sheet":"МСУЗ",
  "aggs":[{"fn":"count","columns":["'Сумма_руб'"]},{"fn":"sum","columns":["'Сумма_руб'"]}],
  "sort":true,"outline":true}]
```

Ожидаемый вид: после группы — `Продажи Количество` / `Продажи Сумма`; внизу — `Общее количество` / `Общая сумма`.

Без склейки (разный `marker`/`sheet` или шаг между ними) каждый шаг выполняется отдельно: второй проход снова сортирует лист уже с итогами → «плывут» формулы и появляются лишние строки (`… Количество Сумма`). Между склеиваемыми строками не должно быть других постобработок.

Повторный прогон: перед сортировкой удаляются ранее вставленные строки итогов (подписи вроде `… Сумма` / `Общее …`).

**По умолчанию `marker`:** `группа` (если не задан).

### `замена_значений` — merge_pp_range_replace_values / merge_final_replace_values

**Назначение:** Заменить подстроки в **текстовых** столбцах (прямоугольник диапазона в память → Python → один `setDataArray`).
Столбец пропускается, если первая значащая ячейка — число/дата/логическое.

**JSON в C:**

```json
[{"v":1,"fn":"замена_значений",
  "columns":["ФИО","Комментарий"],
  "find":["ООО","  "],
  "replace":["ОБЩЕСТВО"," "],
  "case_insensitive":true,
  "squeeze_spaces":true,
  "row_filter":"lambda rows: rows(\"Статус\") != \"\"",
  "match_pick":"all"
}]
```

`replace`: либо **одно** значение (заменяет все `find`), либо список той же длины.
Если список **короче** `find` — меняются только первые пары, в журнал пишется **предупреждение** (не ошибка).
Пустое `replace` / `_ПУСТО_` — стирание. Токены с `,`/`;` — в `'…'`.

Либо `replace_mode":"lambda"` + `replace_expr` (`lambda rows: …`): выражение один раз возвращает строку или **кортеж/список** значений под `find` (та же логика длин и warning).

```json
[{"v":1,"fn":"замена_значений","columns":["'Boss'"],
  "find":[";",",","-"],
  "replace_mode":"lambda",
  "replace_expr":"lambda rows: (\"\", \"\")"}]
```
(три find, два replace из лямбды → две замены + warning)

В `find` / `replace` допускается **`<<Переменные.имя>>`** из runtime-карты (подстановка при сборе).  
В **одинарных кавычках** `'<<Переменные.имя>>'` плейсхолдеры **не** подставляются (литерал).

`row_filter` — лямбда `lambda rows: …` с sugar `rows("Col")` / `rows("Col")[-1]` / `upd_rows("Col")` (какие строки искать); в лямбдах тоже `<<Переменные.…>>`.

`match_pick` — если совпало несколько **строк** столбца: `all` (по умолчанию), `first`, `last`, `odd`/`even` (1,3… / 2,4…), `lambda` + `match_expr`. В выбранной ячейке заменяются все вхождения `find`.

`upd_rows` — это уже обработанные строки **выше** текущей. Дополнительно доступны:

- `upd_rows_seen("Колонка", value)` — встречалось ли значение выше;
- `upd_rows_count("Колонка", value)` — сколько раз встречалось;
- `upd_rows_len()` — сколько строк уже накоплено.

Примеры:

```json
[{"v":1,"fn":"замена_значений","columns":["ИНН"],"find":[" ","-"],"replace":["",""],"row_filter":"lambda rows: not upd_rows_seen(\"ИНН\", rows(\"ИНН\"))"}]
[{"v":1,"fn":"замена_значений","columns":["Статус"],"find":["дубль"],"replace":[""],"row_filter":"lambda rows: upd_rows_len() == 0 or rows(\"Статус\") != upd_rows(\"Статус\")"}]
[{"v":1,"fn":"замена_значений","columns":["Комментарий"],"find":["ООО"],"replace":["Общество"],"match_pick":"lambda","match_expr":"lambda rows: idx == 0 or text != upd_rows(\"Комментарий\")"}]
```

### `текстовые_операции` / `нормализация_текста` — merge_pp_range_normalize_text / merge_final_normalize_text

**Назначение:** Стек текстовых преобразований по выбранным столбцам: trim, collapse_ws, substring, clear, `case`, омоглифы, reverse, base64, `sha256`, `guid`, `encrypt`/`decrypt`.

В визарде «Параметры…» — конструктор ops; кнопка **«Справка»** — полный каталог полей и ops.

**JSON в C:**

```json
[{"v":1,"fn":"текстовые_операции","columns":["ФИО"],
  "ops":[
    {"op":"collapse_ws","row_filter":"non_empty"},
    {"op":"case","mode":"proper","row_filter":"lambda","row_filter_lambda":"lambda rows: not upd_rows_seen(\"ФИО\", rows(\"ФИО\"))"}
  ],
  "non_text":"skip",
  "on_error":"keep"
}]
```

| Поле / op | Смысл |
|-----------|--------|
| `columns` | Столбцы (`'Имя'` = exact) |
| `ops[].op` | `trim`, `collapse_ws`, `substring` (`start` 1-based, `length`), `clear`, `case` (`mode`), `lang_homoglyphs`, `reverse`, `base64_encode`/`decode`, `sha256`, `guid`, `encrypt`/`decrypt` |
| `ops[].row_filter` | `all` / `non_empty` / `empty` / `lambda` (+ `row_filter_lambda`) |
| `non_text` | `skip` \| `coerce` \| `error` |
| `on_error` | `keep` \| `empty` \| `stop` |
| `key` / `key_cell` / `key_file` | Ровно один канал ключа для encrypt/decrypt (`<<Переменные…>>` допустимы) |

Лямбда-фильтр у **каждого op** понимает те же helper'ы:

- `rows("Колонка")`, `rows("Колонка")[-1]`;
- `upd_rows("Колонка")`, `upd_rows_seen(...)`, `upd_rows_count(...)`, `upd_rows_len()`.

Типовые примеры:

```json
[{"v":1,"fn":"текстовые_операции","columns":["ФИО"],"ops":[{"op":"case","mode":"proper","row_filter":"lambda","row_filter_lambda":"lambda rows: str(rows(\"ФИО\") or \"\").strip() != \"\""}]}]
[{"v":1,"fn":"текстовые_операции","columns":["Отдел"],"ops":[{"op":"collapse_ws","row_filter":"lambda","row_filter_lambda":"lambda rows: rows(\"Отдел\") != rows(\"Отдел\")[-1]"}]}]
[{"v":1,"fn":"текстовые_операции","columns":["ИНН"],"ops":[{"op":"trim","row_filter":"lambda","row_filter_lambda":"lambda rows: not upd_rows_seen(\"ИНН\", rows(\"ИНН\"))"}]}]
```

## Функции постобработки строки (ROW)

Вызваются **для каждой строки** данных. Медленнее range-функций, но позволяют контекстно-зависимую обработку.

### 1. `merge_pp_row_zebra_stripes` (только из кода)
**Назначение:** «Зебра» построчно: чередование оформления строк данных по чётности `row_index`.

**Ключ листа:** не зарегистрирован в `MERGE_RESULT_POSTPROCESS_ROW_MAP`. Подключение — через `_MERGE_CODE_POSTPROCESS_ROW` в `collect_workbooks.py`.

**Rest из C:** тот же формат, что у `зебра_диапазон` — `роль:заливка/шрифт` через `;` или `,` (см. раздел в начале документа).

**Что меняет:** `CellBackColor` и `CharColor` строки по чётности.

**Примечание:** Медленнее range-`зебра_диапазон`, но совместима с другими row-функциями.

### 2. `высота_строки` — merge_pp_row_height_pad
**Назначение:** Добавить запас высоты строке данных (~2 мм) **построчно** (медленно на больших листах).

**Rest из C:** не используется.

**Что меняет:** `Height` строки `row_index`.

**Примечание:** Предпочтительно range-функция `высота_строки` (`merge_pp_range_row_height_pad`) — автофит и единая высота для всех строк данных без цикла.

### 4. `полосы_по_пути` — merge_pp_row_stripe_on_path_change

### 10. `преобразовать_числа` — merge_pp_row_convert_numeric_strings
**Назначение:** Преобразовать числа, записанные как текст (в т.ч. с апострофом), в `cell.Value` + формат.

```python
def pp_range_zagotovka(doc, sheet, data_range, header_row_range, *extra_args):
    """
    Заготовка диапазонной постобработки: один проход по строкам данных,
    статус в строке Calc — раз в MERGE_UI_STATUS_EVERY_ROWS, отдача UI — чаще.

    Сигнатура как у merge_pp_range_*: (doc, sheet, data_range, header_row_range, *extra_args).
    Параметры из колонки C передаются в extra_args (через запятую).

    Примеры колонки C:
        «functions_pp.py#pp_range_zagotovka,42»           → extra_args = ("42",)
        «functions_pp.py#pp_range_zagotovka,100,200,тест» → extra_args = ("100", "200", "тест")

    Замените тело цикла while r <= er на свою логику.
    """
    # Пример работы с extra_args (параметры из колонки C)
    # extra_args — кортеж строк, например ("42",) или ("100", "200", "test")
    param1 = extra_args[0] if len(extra_args) > 0 else ""
    param2 = extra_args[1] if len(extra_args) > 1 else ""

    try:
        start_col, start_row, end_col, end_row = _merge_pp_range_address(data_range)
        _hdr_col, header_row, _hdr_end_col, _hdr_end_row = _merge_pp_range_address(
            header_row_range
        )
        if start_row <= header_row:
            start_row = header_row + 1
        if end_row < start_row:
            merge_pp_user_log(doc, sheet, "нет строк данных", "пропуск")
            return

        row_index = start_row
        rows_done = 0
        while row_index <= end_row:
            # --- Твоя логика на одну строку данных (0-based row_index) ---
            # Пример использования extra_args: проверка условия из параметра
            col_index = start_col
            while col_index <= end_col:
                cell = sheet.getCellByPosition(col_index, row_index)
                # Пример: закрасить ячейку если param1 == "highlight"
                # if param1 == "highlight":
                #     cell.CellBackColor = 16776960  # yellow
                col_index = col_index + 1
            rows_done = rows_done + 1
            # Статус: 1-я строка, каждые MERGE_UI_STATUS_EVERY_ROWS (500), последняя
            is_last_row = row_index == end_row
            if rows_done <= 1 or is_last_row or (
                rows_done % MERGE_UI_STATUS_EVERY_ROWS == 0
            ):
                merge_ui_status_set(
                    rows_done,
                    "диапазон — строка %d/%d"
                    % (row_index + 1, end_row + 1),
                )
            # Отдача UI (внутри — каждые MERGE_UI_YIELD_EVERY_ROWS, по умолчанию 10)
            merge_ui_yield(counter=rows_done)
            row_index = row_index + 1
        total_rows = end_row - start_row + 1
        # В лог можно вывести использованные параметры из extra_args
        params_info = ", extra_args: %s" % str(extra_args) if extra_args else ""
        merge_pp_user_log(
            doc,
            sheet,
            "готово, строк %d (статус каждые %d)%s"
            % (total_rows, MERGE_UI_STATUS_EVERY_ROWS, params_info),
            "ok",
        )
    except Exception as err:
        tb = ""
        try:
            tb = traceback.format_exc()
        except Exception:
            pass
        merge_pp_user_log(doc, sheet, "ОШИБКА: %s\n%s" % (err, tb), "ошибка")
        raise
```

## Заполнение вниз (fill-down)

Два похожих шага для обработки пропущенных значений в столбцах после сбора данных из нескольких источников.

### заполнение_вниз

Пустые ячейки заполняются **копией значения из строки выше**.

**Колонка C:** список столбцов через `,` или `;` — номер (1=A), буква (`B`) или имя заголовка (`ФИО`).

Пример:
```
Постобработка_Диапазон    заполнение_вниз    ФИО;Отдел;3
```

**Поведение:**
- Для каждого указанного столбца проход сверху вниз;
- Если ячейка пуста — копируется значение из предыдущей строки;
- Первая строка данных не изменяется.

**Пример до/после:**

| #Путь | ФИО | Отдел |
|-------|-----|-------|
| src_01 | Иванов | Продажи |
| src_01 | *(пусто)* | *(пусто)* |
| src_02 | Петров | IT |

→ после `заполнение_вниз` с `C = ФИО;Отдел`:

| #Путь | ФИО | Отдел |
|-------|-----|-------|
| src_01 | Иванов | Продажи |
| src_01 | Иванов | Продажи |
| src_02 | Петров | IT |

---

### заполнение_вниз_вычислить

Пустые ячейки заполняются **вычисленным значением** (формула или константа).

**JSON (рекомендуется):** блок с `columns` и `rules`; legacy-текст — пары `столбец/формула` через `,` или `;`.

- **`columns`** — столбцы, в которых ищутся пропуски (номер 1=A, буква, имя заголовка);
- **`rules`** — для каждого столбца: `column`, `formula`, опционально `expand_to_right`;
- **`formula`** (на уровне блока) — одна формула для всех `columns`, если нет rule на столбец.

**Шаблоны формулы:** `{row_id}` / `{row}` → номер строки (1-based); `{row_id-1}` / `{row-1}` → предыдущая строка; `R[-1]C` / `R{-1}C` (в A1-документе конвертируется в A1).

**`expand_to_right`:** после вертикального `fillSeries` — протяжка вправо через `fillSeries(TO_RIGHT)` по пустым ячейкам (до `end_col` диапазона); запасной путь — поячеечная запись.

Примеры JSON:

```json
[{"v":1,"fn":"заполнение_вниз_вычислить","columns":["ФИО"],"rules":[{"column":"ФИО","formula":"=A{row_id}&\" \"&B{row_id}"}]}]
[{"v":1,"fn":"заполнение_вниз_вычислить","columns":[1],"rules":[{"column":"A","formula":"=A{row-1}","expand_to_right":true}]}]
```

Legacy-пары:

| Пара C | Что делает |
|--------|-----------|
| `ФИО/=A{row_id}&" "&B{row_id}` | Конкатенация колонок A и B с пробелом |
| `Сумма/=C{row_id-1}*2` | Удвоить значение из предыдущей строки |
| `Категория/общий` | Константа "общий" во все пустые ячейки |
| `3/=SUM(C{row_id-1}:E{row_id-1})` | Сумма диапазона в столбце 3 (C) |

Пример строки листа параметров (legacy):
```
Постобработка_Диапазон    заполнение_вниз_вычислить    ФИО/=A{row_id}&" "&B{row_id};Сумма/=C{row_id-1}*2
```

**Поведение:**
- В каждом столбце из `columns` ищутся непрерывные **вертикальные** пробеги пустых ячеек (со 2-й строки данных);
- в первую ячейку пробега записывается формула, затем протяжка вниз (`fillAuto` или построчно);
- при `expand_to_right` — `fillSeries` вправо по блоку/строке (как `formula_fill`);
- формула с `=` → `cell.Formula`, иначе `cell.String`.

**Пример:**

До:

| ФИО | Имя | Сумма |
|-----|-----|-------|
| Иванов | Алексей | 100 |
| *(пусто)* | *(пусто)* | *(пусто)* |
| Петров | Сергей | 200 |
| *(пусто)* | *(пусто)* | *(пусто)* |

→ после `C = ФИО/=A{row_id-1}&" "&B{row_id-1};Сумма/=C{row_id-1}*2`:

| ФИО | Имя | Сумма |
|-----|-----|-------|
| Иванов | Алексей | 100 |
| Иванов Алексей | Алексей | 200 (100*2) |
| Петров | Сергей | 200 |
| Петров Сергей | Сергей | 400 (200*2) |
