# Оркестратор `collect_pack`

**Версия:** **3.10.696** (`macro-lib/version.txt`).  
**Код:** `collect_workbooks.collect_pack` → `pythonpath/libre_macros_pack_orchestrator_lib.py` (+ `…_cfg.py`).

Имя экспорта и пункт меню **не менялись**: макрос по-прежнему называется `collect_pack`, по смыслу это **оркестратор** запусков сбора по листам группы `Параметры_Объединения*`.

Связано: [04_DATA_COLLECTION.md](04_DATA_COLLECTION.md), [09_ARCHITECTURE.md](09_ARCHITECTURE.md), [06_PARAM_WIZARD.md](06_PARAM_WIZARD.md) (каталог пресетов).

---

## 1. Назначение

| Было (legacy) | Сейчас |
|---------------|--------|
| `collect_workbooks` → всегда `collect_reset_db_ranges` | Диалог: выбрать **один или несколько** листов параметров, **порядок**, опционально сброс DatabaseRange |
| Один активный лист параметров | Для pack активный лист заранее не обязателен |

Отдельный макрос **`collect_workbooks`** по-прежнему работает с **одним** конфигом (при нескольких листах группы нужен активный).

## 2. UI

Заголовок окна: **«Оркестратор сбора (collect_pack)»**. Тема — soft gray (как у остальных диалогов пакета).

### Несколько листов `Параметры_Объединения*`

1. Список вкладок (порядок по умолчанию — **слева направо** в книге); в строке префикс `☑` / `❌`.
2. Мультивыбор + **«Вкл/Выкл»**; двойной клик по пункту — переключить; **«Выше»** / **«Ниже»** — порядок.
3. Галочка **«Сброс именованных диапазонов (простой автофильтр)»** → `collect_reset_db_ranges` (persist; без сохранённых настроек — выкл.).
4. Галочка **«Автопродолжение шагов…»** — без диалога «Запуск» между шагами и без промежуточного MessageBox при успехе; **по умолчанию вкл.** Сбой шага обрывает очередь (итог ошибки показывается).

## 3. Persist настроек

| | |
|--|--|
| Каталог | `%APPDATA%/libre-macros/collect_workbooks/` (Windows) или `~/.config/libre-macros/collect_workbooks/` |
| Файл | `collect_pack_orchestrator.json` |
| Ключ | абсолютный путь к файлу книги |
| Книга не сохранена | «Сохранить настройки» → ошибка |

Черновик JSON: `{ "v": 1, "books": { "/abs/path.ods": { "sheets": [{"name":"…","enabled":true}, …], "reset_db": true, "auto_continue": true } } }`.

## 4. Цикл выполнения

1. **Превалидация** `parse_collect_settings` по каждому листу плана — при ошибке цикл не стартует.
2. Consent / лицензия — **один раз** на сессию pack.
3. Для каждого листа плана: активировать → `set_run_param_sheet` → назначить журнал → `collect_workbooks_for_param_sheet`.
4. Прогресс «Диалог» — на каждую итерацию. При **автопродолжении** (план ≥2) диалог «Запуск» не показывается; промежуточный итог при успехе — без MessageBox (только журнал). При ошибке / без автопродолжения — как раньше. Отмена на шаге (если спрашивали) обрывает очередь.
5. Книгу результата между шагами **не закрывать**.
6. Успех шага для продолжения — фактический `ok` сбора (`_MERGE_LAST_COLLECT_OK`), не только «запуск начат».

### Предварительное удаление листов

| План | Поведение |
|------|-----------|
| 1 лист | `maybe_clear_sheets` по правилам этого листа |
| ≥2 листа | Очистка только на **первом**; на последующих — `suppress_pre_clear=True` |
| Режим «Вовлечь листы» | Pre-clear **всегда** подавлен (даже при одном листе) |

Удаление/скрытие в `Финальная_обработка` на каждом шаге — по конфигу, без ограничений оркестратора.

### Журналы

| План | Лист журнала |
|------|----------------|
| 1 | `Сбор_книг_лог` |
| N≥2, i-я итерация | `Сбор_книг_лог_i` |

### Сброс DatabaseRange

- Один раз **в конце**, если галочка вкл. и **хотя бы одна** итерация успешна.
- `collect_reset_db_ranges`: снять именованные DatabaseRanges, затем простой автофильтр через меню.
- После режима **«Вовлечь листы»** автофильтр ставится **только на вовлечённые** листы (`_MERGE_INVOLVED_SHEET_NAMES`); иначе — на все неслужебные.

### Код возврата

`True`, только если **все** итерации плана успешны; иначе `False`. Reset при `reset_db && any_ok` — независимо от полного успеха цепочки.

---

## 5. Связь с «Вовлечь листы»

Типичный план из двух конфигов:

1. `Параметры_Объединения_1` — сбор из внешних файлов (COPY / ONE / MANY).
2. `Параметры_Объединения_2` — `Режим = Вовлечь листы`, `Файлы-Источники = эта_книга`, постобработка/финал по уже созданным вкладкам.

**Prevalidate:** при ручном вводе выше «Файлы-Источники» или плейсхолдерах `<<Переменные.…>>` в путях проверка наличия файлов **не** выполняется на этапе prevalidate (иначе подставился бы `default` до диалога). Проверка — при реальном сборе листа, после ввода.

В диалоге оркестратора есть кнопка **«Справка»**.

Подробнее: [04_DATA_COLLECTION.md](04_DATA_COLLECTION.md) §4.6.

## 6. Ручная проверка (кратко)

1. Один лист параметров → подтверждение → сбор + (опц.) reset; журнал `Сбор_книг_лог`.
2. Несколько → два отмечены, автопродолжение вкл. → журналы `_1`, `_2` без повторных «Запуск» / промежуточных OK.
3. Автопродолжение выкл. → «Запуск» на каждом шаге.
4. Отмена диалога оркестратора → ничего не запускается.
5. Битый JSON на выбранном → превалидация, цикл не начинается.
6. Галочка reset снята → без `collect_reset_db_ranges`.
7. Ошибка на шаге 1 при автопродолжении → шаг 2 не стартует.
